## 一、业务域定位

### 1.1 打印系统在POS中的位置

```
┌─────────────────────────────────────────────────────────────────┐
│                         POS 系统                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐   │
│   │   点餐    │→ │   收银    │→ │   打印    │→ │   结算    │   │
│   └───────────┘  └───────────┘  └─────┬─────┘  └───────────┘   │
│                                       │                        │
│                                       ▼                        │
│                               ┌───────────────┐                │
│                               │   后厨联动    │                │
│                               └───────────────┘                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**核心价值**：
- 顾客凭证：小票是退换货、报销的依据
- 后厨指令：厨打单是厨房备餐的唯一依据
- 运营数据：打印记录可用于审计和分析

### 1.2 核心角色

| 角色 | 操作 | 接触系统 |
|------|------|----------|
| **收银员** | 结账打印、补打、重打 | nms4pos-ui |
| **店长/运营** | 配置打印机、配置样式、开关管理 | nms4cloud-biz-ui |
| **厨师** | 接收厨打票据 | 打印机（硬件） |
| **顾客** | 接收小票 | 打印机（硬件） |

│                  ──────→ 钱箱弹出                                │
│                                                                 │

│                                                                 │
│   交班操作 ──────→ 报表联（交班报告）                            │

## 三、票据分类（6大类，73种）

### 3.1 顾客联（Customer）- 交付给顾客

| 票据类型 | 触发时机 | 业务价值 |
|----------|----------|----------|
| CheckOut | 结账完成 | 顾客凭证，交付给顾客 |
| Nodiscount | 结账完成（不打折） | 完整金额凭证 |
| Discount | 结账完成（有折扣） | 折扣明细凭证 |
| CashboxPop | 结账完成 | 钱箱弹出（硬件指令） |

### 3.2 厨房联（Kitchen）- 交付给后厨

| 票据类型 | 触发时机 | 业务价值 |
|----------|----------|----------|
| OrderMenu | 点菜完成 | 厨房备餐依据 |
| OrderMenuEx | 点菜完成（扩展） | 扩展版点菜单 |
| TotalBill | 整单打印 | 菜品汇总 |
| HurryMenu | 催菜操作 | 紧急优先，厨师优先处理 |
| BackMenu | 退菜操作 | 通知厨房取消/变更 |
| ReplaceItem | 换品操作 | 换品通知 |

**关键设计**：厨房联按**出品部门**分发，一道菜可能触发多张票据（不同做法送不同部门）。

### 3.3 传菜联（Waiter）- 交付给传菜员

| 票据类型 | 触发时机 | 业务价值 |
|----------|----------|----------|
| WaiterBill | 点菜完成 | 传菜员划菜依据 |

**关键设计**：传菜联按**传菜间**分发，每个传菜间只看到属于自己的菜品。

### 3.4 标签联（Label）- 贴在菜品上的标签

| 票据类型 | 触发时机 | 业务价值 |
|----------|----------|----------|
| FoodLabel | 点菜完成（按数量点单） | 区分同名菜品 |

**关键设计**：标签单只在 `byQuantityOrder=true` 时生成，用于区分数量。

### 3.5 报表联（Report）- 运营报表

| 票据类型 | 触发时机 | 业务价值 |
|----------|----------|----------|
| ShiftReport | 交班操作 | 班次结算依据 |
| DateSalesReport | 日结操作 | 日销售汇总 |
| BuMenReport | 日结操作 | 部门销售明细 |

### 3.6 会员联（Member）- 会员业务

| 票据类型 | 触发时机 | 业务价值 |
|----------|----------|----------|
| MemberSavingBill | 会员储值 | 储值凭证 |
| TuiKaDan | 退卡操作 | 退卡凭证 |

## 四、核心用例

### UC-1：结账打印（最常见场景）

```
场景：顾客买完单，收银员需要打印小票
前置：结账流程已完成（收款、保存支付、更新账单状态）
流程：
  1. 收银员点击「结账」→ 系统自动触发打印
  2. 系统查询 PrintJobTypeSwitch → 检查开关是否开启
  3. 获取 numOfCustomer（默认1份，可配置）
  4. 查询 PosCustomerBillSetting → 获取打印队列
  5. 创建打印任务 → 投递到队列
  6. PrinterWorker 异步执行 → 打印机吐出小票
后置：顾客收到小票
异常：
  - 打印机离线 → 重试3次（1→2→4分钟）→ 告警
  - 纸张用完 → 暂停队列 → 人工处理
```

### UC-2：厨房联打印（多部门场景）

```
场景：顾客点了川菜和粤菜，分别由川菜部和粤菜部负责
前置：点菜流程已完成
流程：
  1. 服务员完成点菜 → 系统自动触发厨房打印
  2. 查询 PrintJobTypeSwitch → 检查开关是否开启
  3. 获取菜品和做法数据
  4. CookwayPrintDeptPlanner 按做法分组
     - 有做法且做法有独立出品部门 → 按做法分单（一菜多单）
     - 否则 → 按菜品分单（一菜一单）
  5. 获取每个部门的打印队列
  6. 创建任务 → 投递到对应队列
  7. 各部门打印机同时打印
后置：每个部门只收到自己负责的菜品
异常：
  - 菜品无出品部门 → 跳过该菜品的厨房联，记录错误
  - 做法出品部门无队列 → 按菜品出品部门打印
```

### UC-3：催菜打印（高优先级）

```
场景：顾客催菜，服务员触发催菜
前置：存在已点菜品
流程：
  1. 服务员点击「催菜」
  2. 查询该菜品的原始打印任务
  3. 创建新的打印任务（类型=HurryMenu）
  4. 任务标记为高优先级
  5. PrinterWorker 优先处理高优先级任务
后置：后厨立即看到催菜通知
```

### UC-4：补打票据（人工介入）

```
场景：顾客说没收到小票，收银员需要补打
前置：存在历史订单
流程：
  1. 收银员查找历史订单
  2. 点击「补打」按钮
  3. 系统重新加载原始订单数据
  4. 创建新的打印任务（与原任务相同的数据和样式）
  5. 执行打印
后置：票据重现
业务规则：
  - 补打记录需审计（谁、什么时候、为什么补打）
  - 补打次数可能有限制
```

### UC-5：配置打印开关

```
场景：店长需要关闭某类票据的打印
前置：拥有配置权限
流程：
  1. 店长进入 nms4cloud-biz-ui 的打印开关配置
  2. 选择票据类型（如 OrderMenu）
  3. 设置 disabledKitchen=true（禁用厨房联）
     或设置 numOfKitchen=2（打印2份）
  4. 保存配置
后置：新触发的打印任务按新配置执行
```

### UC-6：配置打印机

```
场景：新店开业，需要配置厨房打印机
前置：打印机已连接网络
流程：
  1. 店长进入设备管理
  2. 添加打印机 → 填写名称、型号、连接方式
  3. 如果是网络打印机 → 配置 IP 和端口
  4. 关联到出品部门（在 PosDept 中设置 prnQueue）
  5. 测试打印 → 验证连接正常
后置：打印机就绪，可接收厨房联任务
```

## 五、打印份数控制

### 5.1 基本份数规则

```
PrintJobTypeSwitch {
    numOfKitchen: 1  // 默认1份
    numOfWaiter: 1   // 默认1份
    numOfCustomer: 1 // 默认1份
}
```

**关键规则**：
- `null` → 默认1份
- `disabledX=true` → 禁用该联，忽略份数设置
- `numOfX < 0` → 视为0份

### 5.2 按数量出单

```
场景：顾客点了10份小龙虾，需要打印10张小标签
条件：kitchenEnabled && byQuantityOrder == true
规则：
  IF food.paidNumber 是有效正整数 THEN
      number = food.paidNumber
  ELSE
      number = 默认份数（1）
```

### 5.3 多联打印示例

```
结账场景（默认配置）：
  - 顾客联 × 1 → 交付顾客
  - 厨房联 × 0 → 关闭（结账时不打印厨房联）

点餐场景（默认配置）：
  - 顾客联 × 0 → 关闭（点餐时不打印顾客联）
  - 厨房联 × 1 → 发送到厨房
  - 传菜联 × 1 → 发送到传菜间
```

## 六、异常场景处理

### 6.1 打印机离线

```
检测方式：PrinterWorker 轮询检查打印机状态
处理流程：
  1. 检测到 PrinterStatus != NORMAL
  2. redirect() 将队列中的任务重定向到备用打印机
  3. 记录故障日志
  4. 等待5秒后继续检查
  5. 如果主打印机恢复，记录恢复日志
人工介入：
  - 检查打印机电源/网络
  - 确认 IP 配置正确
  - 修复后测试打印
```

### 6.2 打印任务超时

```
超时时间：30分钟（从任务创建开始计算）
检测时机：PrinterWorker 从队列取任务时
处理流程：
  1. 检查任务创建时间距今是否超过30分钟
  2. 如果超时 → 标记为 FAILED
  3. 删除任务文件
  4. 记录超时日志
人工介入：
  - 检查打印机是否长期离线
  - 确认是否需要重打
```

### 6.3 打印失败重试

```
重试策略：
  - 失败后重新加入队列
  - 10秒后再次尝试
  - prnCount+1 记录打印次数
  - Redis 中 prnCount TTL=15分钟

降级策略：
  - 主打印机故障 → 切换备用打印机
  - 备用打印机也故障 → 任务留在队列等待
  - Redis 不可用 → 从数据库加载 prnCount
```

## 七、业务规则汇总

| 规则编号 | 规则内容 | 约束级别 | 违反后果 |
|----------|----------|----------|----------|
| BR-01 | 客单打印必须在结账完成后触发 | MUST | 顾客无凭证 |
| BR-02 | 厨房联按出品部门分组，每部门一个任务 | MUST | 厨师收到错误菜品 |
| BR-03 | 催菜打印优先级高于普通厨打 | SHOULD | 厨师不知道哪个优先 |
| BR-04 | 打印开关关闭时跳过该联 | MUST | 打印无效票据 |
| BR-05 | 补打记录需要审计 | MUST | 无法追溯操作 |
| BR-06 | 菜品必须有出品部门才能打印厨房联 | MUST | 厨房联丢失 |
| BR-07 | 一道菜同一时刻只能打印一次 | MUST | 重复打印浪费 |
