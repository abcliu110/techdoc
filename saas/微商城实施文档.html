微商城功能实施文档

一、功能概述

微商城是面向顾客的积分+商品兑换平台，顾客可通过小程序使用积分（部分情况可加钱）兑换商品。商品分为两种类型：

类型 说明
商品（P） 实物商品，顾客下单后由商家配送
券（C） 积分兑换优惠券，后台需要关联一张优惠券模板并设置兑换数量
重要区分：微商城与"积分兑换规则"是两套独立系统，功能对比见文末附表。

二、完整实施步骤

步骤1：创建商品类别（可选）

后台路径：微商城 → 类别

操作说明：

  1. 点击「新增」
  2. 填写类别名称、排序号（越小越靠前）
  3. 选择父级类别（支持多级分类）
  4. 选择状态：启用/停用
  5. 上传类别图标（可选）
  6. 保存
说明：类别是可选的。如果不创建类别，商品将无法在"分类模式"下展示；可以直接创建商品（不选类别）在"首页模式"下展示。

步骤2：创建商品

后台路径：微商城 → 商品

操作说明：

#### 2.1 基础信息

  • 产品类型：选择「商品」或「券」
  • 选择「券」时，需要额外选择关联的优惠券模板并填写优惠券数量
  • 分类：下拉选择步骤1创建的类别（支持多级）
  • 名称（必填）
  • 单位（必填，如：个、份、瓶）

#### 2.2 价格与积分

字段 说明 示例
售价 金额（元），整数输入，自动转为分存储 输入 78 → 存储 7800（分）
原价 市场价，展示用划线价格 同上
所需积分 兑换所需积分，整数输入 输入 780 → 直接存储 780

价格分位说明：

  • 金额字段：前端输入元，后端固定乘 100 转分（priceScale = 2），实际金额 = priceFee / 100
  • 积分字段：前端输入整数，后端直接存储（pointsScale = 0），实际积分 = pointsFee

兑换模式：

售价 所需积分 小程序展示
> 0 > 0 积分 + 金额组合支付
0 > 0 纯积分兑换
> 0 0 纯金额购买
0 0 不允许（后端会拦截报错）

#### 2.3 库存与限购

字段 说明
库存 必须填写，为 0 则小程序显示"已售空"
成本 内部记录用，小程序不展示
每人总限购数 同一手机号用户累计可购买数量，不填=不限制
每人每天限购数 同上，按每日统计，不填=不限制

#### 2.4 展示设置

字段 说明
显示在首页 开启后，该商品会出现在小程序首页推荐区域
显示顺序 越小越靠前
商品主图 必填，建议 750x750px
banner图片 最多10张，逗号分隔

#### 2.5 保存

步骤3：上架商品（重要！）

后台路径：微商城 → 商品

操作说明：

  1. 商品默认状态为"停用"（obsolete = false 才是上架）
  2. 在商品列表点击「启用/下架」按钮切换状态
  3. 发布数据：点击顶部「发布微商城数据」按钮，清空 Redis 缓存，使小程序获取最新数据
发布的作用：release() 方法会清除以下 Redis 缓存：
- micro_mall_in_home（首页推荐商品）
- micro_mall_all_spu（全部商品）
- micro_mall_cate（类别）
- micro_mall_spu（单品）

不点击发布 → 数据仍在 Redis 缓存中 → 小程序看不到新增/修改

步骤4：类别也需要发布

后台路径：微商城 → 类别

新增/修改/删除类别后，也需要点击「发布微商城数据」，清空类别缓存。

步骤5：小程序端查看

  1. 打开小程序
  2. 进入「积分商城」页面
  3. 切换模式：分类浏览 / 首页推荐
  4. 选择商品 → 加入购物车 → 结算 → 支付

商品主表（mall_spu）

数据库字段 后台字段 必填 说明
name 名称 是 商品名称
category_id 分类 否 关联 mall_category，支持多级
unit 单位 是 个/份/瓶等
main_url 商品主图 是 小程序展示图
banner_url banner图片 否 最多10张，逗号分隔
show_in_home 显示在首页 否 true=首页推荐，false=否
show_order 显示顺序 否 越小越靠前
purchase_limit_per_person 每人总限购数 否 null=不限
purchase_limit_per_person_per_day 每人每天限购数 否 null=不限
obsolete 上下架状态 是 false=上架，true=下架
type_ 产品类型 是 P=商品，C=券

SKU表（mall_sku）

数据库字段 后台字段 说明
price_fee 售价 分存储，实际金额=priceFee/100
price_scale 售价分位 固定为2
market_price_fee 原价 同上
market_price_scale 原价分位 固定为2
points_fee 所需积分 直接存储
points_scale 积分分位 固定为0，实际积分=pointsFee
sales_volume 已售数量 展示用

库存表（mall_sku_stock）

数据库字段 后台字段 说明
sku_id - 关联 mall_sku.lid
quantity 库存 为0则显示"已售空"

类别表（mall_category）

数据库字段 后台字段 说明
name 类别名称 是
parent_id 父级 支持多级分类，null=顶级
pic_url 类别图标 小程序分类展示
show_order 排序号 越小越靠前
obsolete 状态 false=启用，true=停用

四、积分计算规则

实际金额（元）= price_fee / 10^price_scale   （price_scale 固定为2）
实际积分     = points_fee / 10^points_scale （points_scale 固定为0）

示例：

售价输入 price_fee 存储 实际金额 所需积分输入 points_fee 存储
78 7800 78.00元 780 780
0.5 50 0.50元 100 100

五、常见问题

Q1：小程序不显示商品

排查顺序：

  1. 商品状态是否为"上架"？（obsolete = false）
  2. 是否点击了「发布微商城数据」？（清缓存）
  3. 关联的类别是否"停用"？（obsolete = true）
  4. 库存数量是否为 0？
  5. 商品是否设置了"显示在首页"，但想看分类模式？
  6. 小程序是否选择了正确的门店？

Q2：分类模式不显示商品

排查：商品是否绑定了正确的分类？未绑定分类的商品不会出现在分类模式。

Q3：首页模式不显示商品

排查：商品是否开启了"显示在首页"开关？

Q4：积分兑换规则（积分营销-积分兑换）不显示

原因：这是另一套系统，与微商城无关。该功能目前小程序未对接。

Q5：后端报错"积分和价格不能同时为0"

原因：priceFee > 0 || pointsFee > 0 校验，至少要填一个。

Q6：新增商品后需要重复操作？

是。每次新增/修改商品或类别后，都需要点击「发布微商城数据」，否则小程序因 Redis 缓存看不到最新数据。

六、附：两套积分系统对比

对比项 微商城 积分兑换规则
后台路径 微商城 - 商品/类别 积分营销 - 积分兑换
数据库表 mall_spu / mall_sku / mall_category crm_point_exchange
小程序入口 积分商城 未对接
兑换内容 实物商品或优惠券（通过"券"类型） 优惠券
状态控制 obsolete（上下架） status（生效中/已失效）
限购 每人总限购数 / 每天限购数 限制每人兑换最大次数（当前未实现）
