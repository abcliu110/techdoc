### 1.2 PayCashHandler → BasePayService

#### 1.2.1 验证项描述
验证 DA7 声称的 PayCashHandler → BasePayService 映射是否正确。

#### 1.2.2 源码验证步骤

**Step 1：读取 PayCashHandler**
源码路径：`com.shouqianba.localserver.web.handler.pay.PayCashHandler`

```java
@RequestHandler({ "/pay/cash" })
```

**Step 2：分析实际调用链**

DA7 声称：`PayCashHandler → BasePayService`

实际源码：
```java
// PayCashHandler 不直接依赖 BasePayService，而是通过 PaySelector 选择
PayInterface payInterface = this.paySelector.select(request.getPaySubjectGroupCode());
payInterface.pay(request);
```

PaySelector 实现：
```java
// PaySelector.java 行37-48
public PaySelector() {
    this.map.put(PaySubjectCategoryEnum.CASH.getCode(), PosContext.getBean(CashPayService.class));
    // ...
}

@Override
public PayInterface select(final String key) {
    final PayInterface payInterface = this.map.get(key);
    if (payInterface == null) throw new BusinessException("0101010904");
    return payInterface;
}
```

#### 1.2.3 发现

| 维度 | DA7 声称 | 源码实际 | 匹配状态 |
|---|---|---|---|
| Handler | PayCashHandler | PayCashHandler | ✓ 通过 |
| 直接调用 | BasePayService | PaySelector.select() | ✗ **矛盾** |
| 最终服务 | BasePayService.pay() | CashPayService.pay()（实现 PayInterface） | 间接通过 |

**矛盾分析**：DA7 描述为 `PayCashHandler → BasePayService`，但源码实际是 `PayCashHandler → PaySelector.select() → CashPayService.pay()`。BasePayService 是 CashPayService 的**父类**，不是直接调用目标。

#### 1.2.4 结论
**有条件通过** — 最终调用链确实经过 BasePayService.pay()（通过多态），但 DA7 忽略了中间的 PaySelector 路由层。

## 验证项 2：分布式锁前缀验证

### 2.1 验证项描述
验证 DA7 声称的分布式锁前缀（`order_lock_{billNo}`）是否在源码中存在。

### 2.2 源码验证步骤

**Step 1：读取 DA7 声称**
DA7 声称：`LockUtil.lock(order_lock_{billNo})`

**Step 2：读取 LockUtil 源码**
源码路径：`com.shouqianba.localserver.biz.common.util.LockUtil`

```java
public class LockUtil {
    public static final String UNION_TABLE_LOCK_PREFIX = "union_table_lock_";
    public static final String CASH_PLEDGE_LOCK_PREFIX = "cash_pledge_lock_";
    public static final String BASIC_INFO_LOCK_PREFIX = "basic_info_lock_";
    
    public static void lock(final String key) {
        if (!tryLock(key)) {
            throw new BusinessException("0101010124");
        }
    }
    
    public static boolean tryLock(final String key) {
        final long threadId = Thread.currentThread().getId();
        Long value = null;
        try {
            value = Holder.INSTANCE.get(key, () -> threadId);
        } catch (final Exception e) {
            LockUtil.log.error("guava get cache error, threadId: {}, value: {}", threadId, key, e);
        }
        return value != null && value.equals(threadId);
    }
    
    private static class Holder {
        private static final Cache<String, Long> INSTANCE;
        static {
            INSTANCE = CacheBuilder.newBuilder().expireAfterAccess(5L, TimeUnit.MINUTES).build();
        }
    }
}
```

**Step 3：搜索锁使用模式**
```bash

```

实际调用：
```java

// BasePayService.java 行102

```

### 2.3 发现

| 维度 | DA7 声称 | 源码实际 | 匹配状态 |
|---|---|---|---|
| 锁前缀 | `order_lock_` | 无前缀 | ✗ **矛盾** |
| 锁 key 格式 | `order_lock_{billNo}` | `{billNo}` | ✗ **矛盾** |
| 预定义前缀 | 3个（union_table_lock_, cash_pledge_lock_, basic_info_lock_） | 源码有定义 | 部分验证 |
| 实际使用 | — | 直接用 billNo | ✗ **矛盾** |

### 2.4 结论
**失败** — DA7 声称的 `order_lock_{billNo}` 前缀**不存在**于源码。实际锁 key 直接使用 billNo，没有 `order_lock_` 前缀。LockUtil 中定义的三个前缀（union_table_lock_, cash_plledge_lock_, basic_info_lock_）也未被使用。
