### 验证项描述
验证 DA4 中描述的订单状态枚举值是否与源码一致

### 源码验证步骤
1. 读取 `OrderStatusEnum.java` 源码文件
2. 对比 DA4 第 12-25 行枚举定义

### 源码证据
**文件**: `kaci-pos-localserver/src/com/shouqianba/localserver/biz/common/enums/order/OrderStatusEnum.java`

```java
public enum OrderStatusEnum implements IIntegerEnum {
    ORDER_DJZ(Integer.valueOf(10), "待结账"),    // 10
    ORDER_YJZ(Integer.valueOf(20), "已结账"),    // 20
    ORDER_DTD(Integer.valueOf(29), "待退单"),    // 29
    ORDER_YTD(Integer.valueOf(30), "已退单"),    // 30

```

### DA4 声称的枚举值 (L16-24)
| 枚举 | 值 | 含义 |
|------|-----|------|
| ORDER_DJZ | 10 | 待结账 |
| ORDER_YJZ | 20 | 已结账 |
| ORDER_DTD | 29 | 待退单 |
| ORDER_YTD | 30 | 已退单 |
| ORDER_YCX | 40 | 已冲销 |
| ORDER_YQX | 50 | 已取消 |

### 发现 (反例/矛盾)
DA4 附录 9.1 (L489-500) 的枚举值列表与源码完全一致。

但 DA4 状态机图 (L28-39) 中错误地使用了 `ORDER_WJD` 标识符:
```
[待结账]───[结账]──→[已结账]←─[反结账]──[待退单]──→[已退单]
                │                   │
                │                   │
                └─────[取消]───┴───────[取消]───────┘
```

状态机图中"待结账"状态使用了 `ORDER_WJD` 标识符，但源码中该标识符不存在。

### 结论
**有条件通过** - 枚举值定义正确，但状态机图中标识符错误

    if (orderSale.getTableId() == null || orderSale.getTableId() == 0L) {
        return;
    }
    TableInfo tableInfo = this.tableInfoService.getTableInfoByTableId(orderSale.getTableId());

    else if (!TableStatusEnum.TOSETTLEMENT.getCode().equals(tableInfo.getTableStatus())) {

### 关键反例汇总

1. **状态机图标识符错误**: DA4 状态机图中使用 `ORDER_WJD` 但源码中不存在
2. **BR-005a 状态目标错误**: 声称加菜后更新为"已预结"(TOSETTLEMENT)，实际为"待结账"(PRESETTLEMENT)
3. **E-SRC 行号引用偏差**: BR-005b 的 E-SRC 指向 `OrderDomainService.java:214-230`，实际应为 `TableService.java:813-858`
4. **隐式前置条件未标注**: 反结账状态转换有5个前置条件，状态机图未体现

### 建议
1. 修正 DA4 状态机图中所有 `ORDER_WJD` -> `ORDER_DJZ`
2. 修正 BR-005a 规则: "加菜后更新桌台为**待结账**(PRESETTLEMENT)" 而非"已预结"
3. 修正 BR-005b 的 E-SRC 引用: `TableService.java:813-858` 或 `BasePayService.java:292`
4. 在状态转换矩阵中增加前置条件列，标注隐式约束
