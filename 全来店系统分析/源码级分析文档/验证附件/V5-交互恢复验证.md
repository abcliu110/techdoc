#### 场景 2.2：支付超时

**DA6 声称**：轮询，重试10次

**源码验证**：
```java
// LockUtil.java 行32-50
public static boolean tryWaitLock(final String key) {
    for (int retries = 0; retries < 10; ++retries) {
        if (tryLock(key)) return true;
        TimeUnit.MILLISECONDS.sleep(1000L);
    }
    return false;
}
```

**发现**：✗ **矛盾** — LockUtil 确实有 10 次重试机制，但这是**锁获取**超时，不是支付超时。DA6 将锁等待超时误描述为支付超时。支付流程（BasePayService.pay）中未发现重试逻辑。

## 验证项 3：反例发现

### 3.1 验证项描述
找出 DA6 中声称有失败处理但源码中没有实现的情况。

### 3.2 反例：打印机离线恢复

**DA6 失败恢复矩阵**：
| 失败场景 | 检测方式 | 自动恢复 | 人工介入 | 升级路径 |
|---|---|---|---|---|
| 打印机离线 | PrintService 异常 | **跳过/记录** | 修复后重打 | 运维处理 |

**源码实际实现**：
```java
// KdsMakeCreateManager.java 行265-313
private void makeCreateAfterPrintHandler(...) {
    try {
        // ... 打印逻辑 ...
        if (CollectionUtils.isNotEmpty(mergedPrintNoticeMap.values())) {
            mergedPrintNoticeMap.values().forEach(this::makeCreatePrintNotice);
        }
    } catch (final Exception e) {
        // 只记录日志，不跳过，不重试
        KdsMakeCreateManager.log.error("[makeCreate] - makeCreateAfterPrintHandler error", e);
    }
}
```

### 3.3 反例分析

| 维度 | DA6 声称 | 源码实际 |
|---|---|---|
| 检测方式 | PrintService 异常 | ✗ 无特定异常捕获 |
| 自动恢复 | 跳过/记录 | ✗ 仅 log.error 记录 |
| 人工介入 | 修复后重打 | ✗ 无重打队列/重打标记 |
| 升级路径 | 运维处理 | ✗ 无告警/通知机制 |

### 3.4 结论
**失败** — DA6 声称的打印机离线"跳过/记录/重打"恢复机制在源码中**不存在**。实际行为是打印异常后仅记录日志，业务流程继续（不阻塞），无重试机制。
