# 会员模块详细文档

## 1. 模块概述

会员模块提供完整的会员生命周期管理，包括开卡、充值、消费、积分、储值卡、礼品卡、权益卡等功能。

**源码路径**: `service/member/`

## 4. 核心服务详解

### 4.1 BaseCardTradeService — 基础卡交易服务

所有卡交易（会员卡、礼品卡）继承此基类，共享消费、退款逻辑：

```java
public class BaseCardTradeService<T extends CardConsumeRequest> {
    // 消费流程
    public PayResponse cardConsume(final T request) {
        // 1. 分布式锁
        LockUtil.lock(billNo);

        // 2. 验证卡信息
        validateCardInfo(request, commonObject);

        // 3. 支付状态检查
        paymentCheck(orderMasterDO);

        // 4. 支付主体检查
        paySubjectCheck(request);

        // 5. 积分抵扣检查
        pointDeductCheck(request, cardInfo, orderMasterDO, commonObject);

        // 6. 调用云端消费接口
        JSONObject consumeResult =
            HttpClientUtil.doPostWithHeader(consumeUrl, params);

        // 7. 轮询支付结果（最多30秒）
        while (!vo.getSuccess()) {
            vo = getPayResult(request, commonObject, counter, startTime);
        }

        // 8. 支付成功处理
        paySuccessHandler(request, vo, commonObject);

        // 9. 异步上传订单
        followUpService.asyncUploadOrder(orderNo);

        // 10. 计算获得积分
        calculateObtainedPoint(orderMasterDO);

        return response;
    }

    // 卡消费回滚（退款）
    public PayCancelResponse cardConsumeRollback(PayCancelRequest request) {
        // 调用云端撤销接口
        // 更新本地状态
    }
}
```

## 7. 关键发现

### 发现1: BaseCardTradeService 是会员/礼品卡共享的交易基类

```java
MemberCardTradeService extends BaseCardTradeService<MemberCardConsumeRequest>
GiftCardTradeService extends BaseCardTradeService<GiftCardConsumeRequest>
```

两者共享消费、退款核心逻辑，仅在 URL 和参数构建上有差异。

### 发现2: 积分抵扣规则完全由云端计算

```java
// POS 仅做展示和校验，规则由云端决定
CalcPointDeductRequest deductRequest = new CalcPointDeductRequest();
deductRequest.setUnpaidAmount(unpaidAmount);
deductRequest.setPointBalance(transPoint);
CalrPointVo calrPointVo = this.calcPointDeductAmount(deductRequest);
```

### 发现3: 权益卡销售是独立体系

- `EquitySaleOrderHandler` — 权益卡销售下单
- `EquitySaleRefundHandler` — 权益卡退款

权益卡与会员储值卡是独立的两个体系，商户可以选择单独启用权益卡销售功能。
