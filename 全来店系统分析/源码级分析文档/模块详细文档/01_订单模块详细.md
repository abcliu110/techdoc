# 订单模块详细文档

## 1. 模块概述

订单模块是 KACI POS 的核心模块，管理餐饮订单的完整生命周期，包括加菜、落单、结账、反结账、撤单、退款等操作。

**源码路径**: `service/order/`

### 3.3 OrderStatusDO (订单状态)

public class OrderStatusDO {
    private Long id;                           // 主键ID
    private Integer orderStatus;               // 订单状态
    private Integer isPay;                     // 是否支付
    private Long payTime;                      // 支付时间
    private Integer payMethod;                 // 支付方式
    private String checkoutBy;                 // 结账人
    private Long checkoutTime;                 // 结账时间
    private Long firstCheckoutTime;            // 首次结账时间
    private Integer revCheckoutCount;          // 反结账次数

    public void payComplete() {
        this.isPay = IsPayEnum.YZF.getCode();           // 1=已支付
        this.orderStatus = OrderStatusEnum.ORDER_YJZ.getCode(); // 20=已结账
        this.payTime = TimeUtil.currentDateTime();
        this.checkoutBy = RequestContext.getUser().getUserName();
        this.checkoutTime = this.payTime;
        if (this.revCheckoutCount == null || this.revCheckoutCount == 0) {
            this.firstCheckoutTime = this.payTime;
        }
    }
}

## 5. 核心服务详解

### 5.1 PlaceOrderService — 加菜落单

**文件**: `service/order/PlaceOrderService.java:62`

```java
public ExecutePromotionResponse placeOrder(final PlaceOrderRequest request)
```

**核心流程**:
1. 获取订单主表
2. `orderPass=IN` 时执行：做法检查 → 标签检查 → 估清检查
3. 校验重复商品（已落单商品不能重复加单，错误码 `0101010149`）
4. `mergeGoods()` 合并新旧商品
5. `executePromotion()` 促销重算
6. 事务内更新订单状态 → `ORDER_DJZ`
7. 事务内更新菜品 `ldStatus=1`
8. 估清库存占用
9. 异步上传订单
10. 刷新桌台 (WebSocket `tp_order_refresh`)
11. 打印厨房小票（快餐模式不打印）

### 5.2 RevCheckoutService — 反结账

**文件**: `service/order/RevCheckoutService.java:100`

```java
public RevCheckoutResponse revCheckout(final RevCheckoutRequest request)
```

**前置校验**:
- 订单状态必须为 `ORDER_YJZ` (否则 `0101010913`)
- 无进行中的退款 (`isExistRefunding()` 否则 `0101012004`)
- `revFlag=0` 时不允许跨日反结账 (`0101010953`)
- 结账后超过 `closedBillModifyTimeLimit` 小时（默认12小时）不允许反结账 (`0101010915`)

**事务处理**:
- 状态 → `ORDER_DJZ` (待结账)
- 支付状态 → `WZF` (未支付)
- `revCheckoutCount++`
- 恢复桌台状态 → `PRESETTLEMENT`

**异步处理**:
- 上传云端桌台信息
- 删除上传失败记录
- 退积分和礼品
- 发票红冲

## 7. 金额计算体系

```
orderTotalAmount (订单总金额)
    │
    ├── orderDiscountAmount ──── 不计入实收 (isJoinReceived=NO)
    │                               抹零、整单折扣等
    │
    ├── payDiscountAmount ─────── 计入实收 (isJoinReceived=YES)
    │                               优惠券、积分抵扣等
    │
    └── actualReceiptAmount ───── 实收金额
                                    用户实际支付

未付金额 = orderTotalAmount - orderDiscountAmount - payDiscountAmount - actualReceiptAmount
```

## 8. 关键发现

### 发现1: 订单状态独立于 OrderMaster

所有状态操作都在 `OrderStatusDO` 上进行，而非 `OrderMasterDO`：
```java
// PlaceOrderService, RevCheckoutService, RevokeOrderService
orderStatus.setOrderStatus(OrderStatusEnum.ORDER_DJZ.getCode());
orderStatus.setIsPay(IsPayEnum.YZF.getCode());
```
数据修复时需同时关注两张表。

### 发现2: 批次号支撑"先定后退"

`goodsBatchNo` 贯穿订单、订单明细、支付记录：
- 堂食可先结账、后加菜（加菜批次号 > 结账批次号）
- 反结账时根据批次号区分处理
- 退款时校验批次一致性

### 发现3: 订单上传异步化 + 失败重试

所有订单操作都异步上传云端，失败时记录到 `FailTaskRecords`，后续通过 `failTaskRecordsDao` 清理/重试：
```java
ThreadPoolConfig.orderUploadTaskThreadPool.execute(() -> {
    uploadOrderDomainService.uploadOrder(...);
});
```
本地结账后云端可能有延迟，需考虑幂等性设计。
