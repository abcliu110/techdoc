# 桌台模块详细文档

## 1. 模块概述

桌台模块管理餐饮门店的桌台资源，支持开台、并台、联台、换台、拆台、清台等多种操作。

**源码路径**: `service/table/` + `service/table/operate/`

## 5. 核心操作详解

### 5.1 开台 (OpenTableService)

```java
public void openTable(OpenTableRequest request) {
    // 1. 获取餐段信息
    getOrgMealTimeSlotInfo();

    // 2. 校验桌台状态
    tableValidateService.validateTableWhenOpen();

    // 3. 构建订单结构
    structureKongOrderMaster();

    // 4. 设置开台属性
    setWhenOpen();

    // 5. 事务更新
    updateWhenOpen();
        // tableStatus → PREORDER(1)
        // orderKey → 订单号
        // currPerson → 人数
        // orderCreateTime → 开台时间

    // 6. 发送 WebSocket 刷新消息
    sendRefreshMessage();

    // 7. 异步上传订单到云端
    uploadOrder();
}
```

### 5.2 并台 (MergeTableService)

```java
public void merge() {
    // 1. 锁定源桌台和目标桌台
    LockUtil.tryLock();

    // 2. 校验桌台状态
    //  - 双方 tableStatus ∈ USEING
    //  - 自助餐台不能并台
    //  - 无联台关系
    //  - 区域价格类型一致

    // 3. 事务处理
    mergeOrderData();         // 合并商品明细/支付记录
    updateTargetOrder();      // 更新目标桌台人数
    updateSourceOrder();      // 更新源桌台（转单）
    executePromotion();       // 重新计算促销优惠
    mergeCashPledge();      // 合并押金记录

    // 4. 发送刷新消息
    // 5. 异步上传云端
}
```

### 5.3 联台 (UnionTableService)

与并台的核心区别：
- 联台**不合并订单数据**，各桌台保持独立订单
- 共享主桌的 `orderKey`
- 共享联台组名 `unionTableGroupName`
- 各自独立促销计算

### 5.4 快餐模式 (OpenNonTableService)

## 6. TableOperateSelector — 策略模式

```java
// TableOperateSelector.java
public class TableOperateSelector {
    private List<ITableOperateService> serviceList;

    public ITableOperateService select(TableOperateTypeEnum type) {
        for (ITableOperateService service : serviceList) {
            if (service.supports(type)) {
                return service;
            }
        }
        return null;
    }
}

// 注册的策略
serviceList.add(PosContext.getBean(OpenTableService.class));
serviceList.add(PosContext.getBean(MergeTableService.class));
```

## 7. 关键发现

### 发现1: 联台与并台是本质不同的操作

| 特性 | 并台 | 联台 |
|------|------|------|
| 订单合并 | ✅ 合并到单一订单 | ❌ 各桌独立订单 |
| 共享 orderKey | ❌ | ✅ 主桌的 orderKey |
| 促销重算 | ✅ | ❌ |
| 押金处理 | 合并 | 可选合并 |
| 适用场景 | 收银台结账 | 小程序分开结账 |

### 发现2: 桌台标记是多维度聚合

```java
// TableService.settingMarkers()
// 8个独立字段聚合为标记
if (hasNotLd) markers.add("notSubmitted");
if (isWaitCall) markers.add("waitingDish");
if (actualReceipt > 0 && unpaidAmount > 0)
    markers.add("partialPaid");
if (totalAmount > 0 && unpaidAmount == 0)
    markers.add("moneyPaid");
```

### 发现3: 快餐模式是"无桌台"设计

快餐订单不使用真实的桌台表记录，而是：
- 使用账单号后 4 位作为 `tableCode`
- 使用 `BizType = FAST_GOODS` 标识
- 不走桌台状态机
