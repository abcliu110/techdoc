**源码路径**: `service/cashPledge/`

| 文件 | 说明 |
|------|------|
| `CashPledgeService.java` | 押金牌照核心服务 |
| `CashPledgeTransService.java` | 押金交易处理 |
| `CashPledgeRecordService.java` | 押金记录服务 |
| `selector/CashPledgePaySelector.java` | 押金支付选择器 |
| `offline/CashPledgeCashService.java` | 现金押金服务 |
| `online/CashPledgeScanCardService.java` | 扫码押金服务 |

### 枚举

| 枚举 | 值 | 说明 |
|------|---|------|
| `PledgeTypeEnum` | 1/2/3/4 | 餐位押金/自助押金/订金/定金 |
| `CashPledgeStatusEnum` | 0/1/2/5/10/15/18/20 | 待支付→支付中→未使用→已使用→已作废→退款中→已退款 |
| `PledgeRecordTypeEnum` | PAY/REFUND/USE/CANCEL_USE/CARRYOVER/CHANGE_ORDER | 押金记录类型 |

### 状态流转

```
PENDING(0) → PAYING(1) → UNUSED(5) → USED(10) → NULLIFY(15)
                     ↓                ↓
                REFUNDED_ING(18)  REFUNDED(20)
```

### 核心流程

```java
// CashPledgeService.pay()
// 1. 创建押金记录
// 2. 根据 paySubjectGroupCode 选择支付服务
CashPledgePaySelector.select(paySubjectGroupCode).pay()

// 3. 打印押金小票 (开钱箱)
// 4. 异步上传云端
```

## 7. 关键发现

### 发现1: 估清系统的"预留-确认-回滚"机制

```
下单 → occupy_num += qty (预占用)
结账 → 更新可用库存
退款 → occupy_num -= qty (回滚)
```
估清模块通过占用数量与可用数量分离，实现了超售保护。

### 发现2: 团购的降级容错设计

云端核销超时10次后，本地自动创建支付记录降级处理：
```java
OrderPay orderPay = new OrderPay();
orderPay.setPayStatus(PayStatusEnum.PAYMENT.getCode());
this.orderPayDao.create(orderPay);
```
保证了订单流程的连续性，不因外部系统故障而阻塞。

### 发现3: 押金支持结转

押金可以从当前订单结转到下一笔订单：
```java
// CashPledgeCarryoverHandler
carryover_amount += 金额;
```
支持押金跨订单使用。
