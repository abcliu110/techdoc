## 一、业务因果叙事

### 场景：晚上 9 点，店长发现中午有一笔结账金额有误

晚上 9 点，店长小李在盘点时发现中午有一笔订单金额算错了——顾客本来应该付 288 元，但收银员按了 298 元。多收了 10 块钱，顾客已经走了。

店长决定反结账，重新结一次。

**第一步：系统验证这张订单能不能反结账。**

系统查到这笔订单的结账时间是"中午 12:15"，现在是"晚上 9:00"，已经过去了将近 9 个小时。如果系统配置的"结账单距今允许修改时间"是 12 小时，那这张单还在允许范围内。

但还有另一个检查：这张单是今天的营业日（2026-08-30）结的账吗？店长店开了跨夜经营吗？如果开了跨夜，系统可能认为这是"昨天"的单。

**第二步：检查有没有正在进行中的退款。**

如果顾客吃完饭后已经退了一个菜（退款流程），系统会拒绝反结账——因为退款是独立的流程，不能和反结账同时进行。

**第三步：系统开始"反结"。**

反结账本质上是一个"撤销所有支付 + 撤销结账状态"的操作：

- 订单状态从"已结账"（ORDER_YJZ）变回"待结账"（ORDER_DJZ）
- 支付状态从"已支付"变回"未支付"
- 桌台状态从"已预结"（TOSETTLEMENT）恢复为"待结账"（PRESETTLEMENT）
- 反结账次数（revCheckoutCount）+1

系统同时重新执行一遍促销计算——因为当初结账时的促销优惠可能已经过期或者数量变了。

**第四步：如果原来开过发票，需要红冲。**

如果这笔订单已经开了发票，反结账后发票要"作废"（红冲）。系统异步调用发票服务，把发票状态改为"已红冲"。

**第五步：退还积分和礼品。**

如果结账时顾客用了积分抵扣或兑换了礼品，反结账后这些也要退回去。

**第六步：恢复原状，等着重新结账。**

桌台现在又回到了"待结账"状态，账单上显示的是原始金额，收银员可以重新操作。

## 二、关键校验逻辑

### BR-REV-001：订单必须处于已结账状态

```
规则：只有 ORDER_YJZ（已结账）状态的订单才能反结账
证据：E-SRC: service/order/RevCheckoutService.java:103
代码：if (!OrderStatusEnum.ORDER_YJZ.getCode().equals(orderStatus.getOrderStatus()))
```

### BR-REV-002：跨日限制

```
规则：ORG_PARAM CROSS_WORK_DATE_BILL_ALLOW_REV_CHECKOUT=0 时，
      非当日营业日的订单不允许反结账
证据：E-SRC: service/order/RevCheckoutService.java:113-122
```

### BR-REV-003：时间窗口限制

```
规则：结账后超过 closedBillModifyTimeLimit（默认12小时）不允许反结账
证据：E-SRC: service/order/RevCheckoutService.java:116-126
计算：hours = 当前时间 - checkoutTime
```

### BR-REV-004：进行中退款禁止反结账

```
规则：存在进行中的退款（isExistRefunding=true）时禁止反结账
证据：E-SRC: service/order/RevCheckoutService.java:107
```

## 四、失败恢复手册

### 场景一：反结账后未及时重新结账

```
表现：桌台长时间停留在"待结账"状态
原因：收银员反结账后去做其他事情，忘记重新结账
影响：桌台被锁定，无法开新订单；日结时会有待结账订单提示
后果：日结前必须完成这笔订单的结账，否则影响营业报表准确性

处理：
1. 日结前检查待结账订单列表
2. 联系原收银员完成结账
3. 如果确实无法追回，由店长授权后做特殊处理
```

### 场景二：反结账时发票红冲失败

```
表现：反结账成功，但发票红冲失败
原因：云端发票服务不可用或发票状态异常
影响：原发票仍然有效，税务风险
后果：需要手动在发票系统中处理红冲

处理：
1. 反结账操作本身不受影响，继续完成
2. 系统异步重试发票红冲
3. 如果多次重试失败，人工介入
```

### 场景三：重新结账时促销优惠已变化

```
表现：重新结账的金额与原金额不同
原因：促销规则在反结账期间被修改，或者商品价格被调整
影响：顾客可能需要补款或退款

处理：
1. 按新的促销规则重新计算优惠
2. 告知顾客金额变动原因
3. 如果金额减少（多收了），需要退款
```

## 五、与加菜的对比

| 方面 | 加菜（SC-ORDER-001） | 反结账（SC-ORDER-002） |
|---|---|---|
| 订单状态变化 | ORDER_DJZ → ORDER_DJZ | ORDER_YJZ → ORDER_DJZ |
| 触发时机 | 落单 | 反结账按钮 |
| 促销重算 | ✅ | ✅ |
| 估清处理 | 占用库存 | 估清库存释放（取消占用） |
| 桌台状态 | 更新占用 | 恢复占用 |
| 发票处理 | 无 | 红冲（如已开票） |
| 积分/礼品 | 无 | 退还 |
| 权限要求 | 普通收银员 | 通常需要授权 |
