## 一、业务因果叙事

### 场景：3 号桌顾客吃完饭，收银员小王开始收款

晚上 8 点，3 号桌的顾客吃完饭，叫小王来结账。小王点击"结账"，屏幕上显示"应付 288.00 元"。顾客说"微信支付"。

**第一步：系统对这个账单加锁。**

支付是资金相关的关键操作，系统用分布式锁锁住这个 billNo，防止两个收银员同时给同一桌结账。锁的 key 是 `order_lock_{billNo}`。

**第二步：系统检查这个账单还有多少钱没付。**

小王的屏幕显示"应付 288.00 元"，但系统需要实时计算：

```
未付金额 = 订单总金额 - 订单优惠 - 支付优惠 - 已付金额
```

如果未付金额 ≤ 0，说明已经付过了，系统直接拒绝。

**第三步：系统检查有没有其他支付正在进行。**

如果另一个收银员刚刚正在扫码支付（payStatus=PAYMENT），系统拒绝重复支付。

**第四步：收银员选择支付方式。**

小王选择了"微信支付"，系统将这次支付路由到对应的支付服务。

**第五步：系统执行支付，记录支付流水。**

系统在这个数据库事务内：
- 创建一条 OrderPay 支付记录（流水号、金额、支付方式、操作员、时间）
- 检查是否满足自动结账条件
- 保存订单

**第六步：打印结账单。**

如果这次支付后账单全部结清（isPayed=true），系统打印结账单给小王。

**第七步：推送通知。**

系统通过 WebSocket 推送支付完成消息，通知前端刷新订单金额显示。如果是小程序点餐，系统也通知小程序"支付完成"。

## 二、三层优惠与未付金额计算

```
订单总金额 orderTotalAmount = 288.00 元
    │
    ├── 商品优惠 goodsDiscountAmount = 20.00 元    ← 单品折扣/特价（isJoinReceived=N）
    │       用途：直接扣减商品单价，不参与找零计算
    │
    ├── 订单优惠 orderDiscountAmount = 10.00 元   ← 抹零/整单折扣（isJoinReceived=N）
    │       用途：订单级别减让，不参与找零计算
    │
    ├── 支付优惠 payDiscountAmount = 0.00 元       ← 优惠券/积分抵扣（isJoinReceived=Y）
    │       用途：参与实收金额计算
    │
    ├── 已付金额 actualReceiptAmount = 0.00 元     ← 历史已支付
    │
    └── 未付金额 unpaidAmount = 258.00 元
            计算：288 - 20 - 10 - 0 - 0 = 258

实收金额计算（用于找零）：
    = 订单总金额 - 订单优惠 - 已付金额
    = 288 - 10 - 0 = 278.00 元
```

### isJoinReceived 语义（重要！）

| isJoinReceived | 含义 | 影响 |
|---|---|---|
| `N`（不计入实收） | 商品优惠/订单优惠 | 不参与"已收够没有"的计算；不参与找零 |
| `Y`（计入实收） | 优惠券/积分抵扣 | 参与实收金额；计入找零计算 |

> ⚠️ **已知潜在问题 U-01**：源码中 isJoinReceived 同时用于"是否计入实收"和"是否参与找零计算"两套语义，尚未交叉验证是否完全一致。

## 三、自动结账逻辑

```java
// 源码：service/pay/extension/BasePayService.java:296
// E-SRC: service/pay/extension/BasePayService.java:296

protected void autoCheckout(OrderMasterDO orderMaster, String paySubjectGroupCode) {
    String autoCheckout = BizBaseUtil.getOrgParamValue(
        OrgParamEnum.AFTER_PAY_AUTO_FINISH_CHECKOUT.getCode());

    if (isMatch(autoCheckout, orderMaster, paySubjectGroupCode)) {
        if (checkPayComplete(orderMaster, true)) {
            orderMaster.payComplete();           // 状态变更
            followUpService.calculateObtainedPoint(orderMaster); // 计算积分
        }
    }
}

// 匹配条件：
// autoCheckout == "1" ─────────────── 全部支付后自动结账
// autoCheckout == "2" && 扫码支付 ── 仅扫码支付后自动结账
// FAST_GOODS ─────────────────────── 快餐全部自动结账
// DCF (挂账) ───────────────────── 不自动结账
```

### checkPayComplete 校验逻辑

```java
// 源码：service/pay/extension/BasePayService.java:365
// E-SRC: service/pay/extension/BasePayService.java:365

public boolean checkPayComplete(OrderMasterDO orderMaster, boolean autoCheckout) {
    // 1. 未付金额为 0
    if (unpaidAmount != 0) return false;

    // 2. 异常金额检查
    if (totalAmount == 0 &&
        (actualReceipt != 0 || discount != 0 || payDiscount != 0))
        return false;

    // 3. 无进行中支付
    if (hasPayingPay()) return false;

    // 4. 堂食订单：必须所有菜已落单
    if (isMealType(orderMaster)) {
        if (hasUnLdGoods()) {
            if (autoCheckout) return false;
            throw BusinessException("0101010954");
            // "堂食订单存在未落单商品，不允许结账"
        }
    }

    return true;
}
```

## 五、失败恢复手册

### 场景一：扫码支付后顾客手机无网络

```
表现：收银员看到"支付中"，但长时间无响应
原因：顾客手机网络问题，微信/支付宝回调未到达
影响：POS 本地显示"支付中"，但顾客实际上已经付了

处理步骤：
1. 收银员询问顾客是否看到微信/支付宝的"支付成功"页面
2. 如果顾客已支付成功：收银员点击"手动确认"
   系统调用 pollingPayResultService.reCallPayResult() 重新查询支付状态
3. 如果顾客未支付成功：等待顾客重试或改用其他支付方式
4. PollingPayResultService 会在后台轮询（最多重试10次），超时后降级为本地支付记录
   证据：E-SRC: service/pay/extension/online/PollingPayResultService.java
```

### 场景二：收银员选错支付金额

```
表现：超收金额（实收 > 未付金额）
原因：收银员输入金额错误，顾客多付了
影响：多收的钱需要找零给顾客

处理步骤：
1. 系统计算找零金额（overAmount）
2. 打印结账单上显示"实收 XXX 元，找零 XXX 元"
3. 收银员将找零金额交给顾客
4. 如果超收金额过大（如 100 元以上），建议店长确认
```

### 场景三：堂食订单有未落单商品

```
表现：系统弹出"堂食订单存在未落单商品，不允许结账"
原因：收银员跳过了落单步骤直接结账，或者还有菜品未点击"落单"
影响：订单无法结账

处理步骤：
1. 收银员回到订单页面
2. 点击"落单"把所有菜品落下去
3. 重新点击"结账"
4. 如果是等叫菜品无法落单，需联系店长确认
```

### 场景四：组合支付中部分支付失败

```
表现：第一笔扫码付了 100 元后，第二笔现金付 200 元时系统报错
原因：可能因为超时或操作失误
影响：100 元已经在订单上，但顾客不想再付了

处理步骤：
1. 系统保留已成功的 100 元支付记录
2. 收银员点击"整单退款"取消整笔订单
3. 或者收银员重新选择正确的支付方式完成剩余金额
4. 如果无法取消，找店长授权后做整单退款
```

## 六、支付方式路由

| 支付方式 | 路由键 | 服务类 | 特点 |
|---------|--------|--------|------|
| 现金 | `CASH` | `OfflinePayService` | 支持抹零/超收/找零 |
| 扫码（微信/支付宝） | `SCAN_CARD_PAY` | `OnlinePayService` | 支持轮询/回调 |
| 会员卡 | `MEMBERSHIP_CARD` | `MemberPayService` | 支持积分累计 |
| 银行卡 | `BANK_CARD` | 银行卡服务 | — |
| 挂账 | `DCF` | 挂账服务 | 不自动结账 |
| 优惠券 | `COUPON` | 优惠券服务 | 触发优惠重算 |

路由实现：`PaySelector.select(paySubjectGroupCode)` — 根据支付科目组代码选择对应服务。
