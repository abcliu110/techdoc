## 对象一：OrderMasterDO（订单聚合根）

### 身份
- **类型**：订单聚合根（Aggregate Root）
- **包路径**：`service/order/domain/entity/OrderMasterDO.java`
- **职责**：承载订单全部财务和状态信息，是所有跨模块交互的唯一锚点

### 结构

| 字段分组 | 核心字段 | 类型 | 说明 |
|---|---|---|---|
| 标识 | billNo | String | 全局唯一键 |
| 标识 | orderKey | String | 联台共享键 |
| 金额 | orderTotalAmount | BigDecimal | 订单总金额 |
| 金额 | actualReceiptAmount | BigDecimal | 实收金额（已付） |
| 金额 | goodsDiscountAmount | BigDecimal | 商品优惠 |
| 金额 | orderDiscountAmount | BigDecimal | 整单优惠 |
| 金额 | payDiscountAmount | BigDecimal | 支付优惠（优惠券） |
| 金额 | unpaidAmount | BigDecimal | 未付金额 |
| 状态 | orderStatus | String | 订单状态 |
| 状态 | isPay | String | 支付状态 |

### 关系
- ↔ BO-ORDER_DETAIL：1:N（一个订单包含多个菜品）
- ↔ BO-ORDER_PAY：1:N（一个订单有多次支付）
- ↔ BO-TABLE：N:1（billNo/orderKey关联）

### 行为
- `payComplete()`：结账，状态→ORDER_YJZ，触发积分累计
- `cashPay()`：现金支付，计算找零
- `recalcUnpaidAmount()`：重新计算未付金额

### 生命时间线

```
创建 ──▶ 待结账(ORDER_WJD) ──▶ 待结账(ORDER_DJZ) ──▶ 已结账(ORDER_YJZ)
                  │                                    │
                  └── 取消(ORDER_YQX) ◀──────────────┘
                                               │
                                          反结账(ORDER_DJZ)
```

### 实现
- E-SRC：`service/order/domain/entity/OrderMasterDO.java`
- 充血模型：金额计算在DO内完成
- 无ORM注解：依赖外部DAO

### 失败
- 未付金额 ≠ 0 → 无法结账
- 并发更新 → 依赖分布式锁 order_lock_{billNo}
- 金额不变量被破坏 → 财务差异

## 对象二：OrderDetailDO（订单明细）

### 身份
- **类型**：订单子实体
- **包路径**：`service/order/domain/entity/OrderDetailDO.java`
- **职责**：记录订单中每个菜品的详细信息

### 结构

| 字段分组 | 核心字段 | 类型 | 说明 |
|---|---|---|---|
| 关联 | billNo | String | 订单号 |
| 关联 | dataId | String | 商品规格ID |
| 数量 | goodsQty | BigDecimal | 数量 |
| 数量 | ldStatus | Integer | 落单状态（0=未落单，1=已落单） |
| 价格 | goodsPrice | BigDecimal | 商品单价 |
| 价格 | goodsDiscountAmount | BigDecimal | 商品优惠金额 |
| 套餐 | isPackage | Integer | 是否套餐 |
| 套餐 | parentDataId | String | 套餐父ID |

### 关系
- ↔ BO-ORDER：N:1
- → BO-GOODS：N:1（归因链接）
- → BO-SOLDOUT_STOCK：N:1（归因链接）
- → BO-SCREEN_MAKE：1:N（轨迹链接）

### 行为
- `updateLdStatus(1)`：标记已落单
- `modifyGoodsQty()`：修改数量（需校验ldStatus）

### 生命时间线

```
创建(ldStatus=0) ──▶ 已落单(ldStatus=1) ──▶ 部分退款(goodsQty减少)
                                      │
                               全部退款(删除记录)
```

### 实现
- E-SRC：`service/order/domain/entity/OrderDetailDO.java`
- 贫血模型：行为由Service层驱动

### 失败
- 已落单(ldStatus=1)时尝试修改数量 → 拒绝
- 退款数量 > goodsQty → 拒绝

## 对象四：OrderPay（支付记录）

### 身份
- **类型**：支付事实聚合
- **包路径**：`service/order/domain/entity/OrderPay.java`
- **职责**：记录每次支付行为，是资金审计的核心

### 结构

| 字段 | 类型 | 说明 |
|---|---|---|
| payOrderNo | String | 支付流水号 |
| billNo | String | 关联订单号 |
| payAmount | BigDecimal | 支付金额 |
| payMethod | String | 支付方式 |
| isJoinReceived | Integer | 是否计入实收 |
| payStatus | String | 支付状态（1=成功/2=处理中/3=失败） |

### 关键发现

> ⚠️ **U-01**：`isJoinReceived` 字段的语义存在多义性
> - 部分代码用它判断"是否计入实收金额"
> - 部分代码用它判断"是否参与找零计算"
> - 两套语义是否完全一致，需要交叉验证所有赋值点

### 实现
- E-SRC：`service/order/domain/entity/OrderPay.java`

## 对象五：PrintTicketTypeEnum（打印票据类型）

### 身份
- **类型**：超级枚举（策略工厂）
- **包路径**：`print/enums/PrintTicketTypeEnum.java`
- **职责**：O(1) 路由到打印策略，是整个打印系统的设计枢纽

### 行为
- 每个枚举实例同时持有三个策略对象：
  - `PrinterStrategy`：打印机选择策略
  - `TicketPrintStrategy`：票据数据构建策略
  - `TemplateTicketGenerator`：模板生成策略

### 实现
- E-SRC：`print/enums/PrintTicketTypeEnum.java`
- 编译期穷举，无反射开销
- 新增票据类型需修改枚举（无运行时扩展）
