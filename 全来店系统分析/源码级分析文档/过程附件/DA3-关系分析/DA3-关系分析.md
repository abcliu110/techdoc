## 一、业务对象识别

### 1.1 核心业务对象清单

| 对象ID | 名称 | 业务定义 | 生命周期 | 边界 |
|---|---|---|---|
| BO-ORDER | 订单 | 记录一笔用餐交易的所有信息 | 开台创建 → 结账关闭 | 核心聚合根 |
| BO-ORDER_DETAIL | 订单明细 | 订单中的一道菜品 | 创建 → 上菜/退款 | 依赖 BO-ORDER |
| BO-ORDER_STATUS | 订单状态 | 订单当前的业务状态和支付状态 | 随订单生命周期 | 独立存在，由 BO-ORDER 引用 |
| BO-ORDER_PAY | 支付记录 | 顾客的一笔支付行为 | 创建 → 退款 | 依赖 BO-ORDER |
| BO-TABLE | 桌台 | 餐厅的物理座位资源 | 空闲 ↔ 使用 ↔ 清台 | 独立存在 |
| BO-TABLE_AREA | 区域 | 桌台的逻辑分组 | 创建 → 删除 | 独立存在 |
| BO-GOODS | 商品 | 可售卖的菜品或套餐 | 上架 → 下架 | 独立存在 |
| BO-PRINT_JOB | 打印任务 | 一次打印操作请求 | 创建 → 打印成功/失败 | 独立存在 |
| BO-SCREEN_MAKE | KDS制作单 | 一次菜品制作请求 | 创建 → 完成/废弃 | 依赖 BO-ORDER |
| BO-MEMBER | 会员 | 在店注册的消费会员 | 开卡 → 注销 | 独立存在 |
| BO-CASH_PLEDGE | 押金 | 餐桌押金的收取和核销记录 | 收取 → 核销/退款 | 依赖 BO-ORDER |
| BO-SOLDOUT_STOCK | 估清库存 | 商品的可售数量控制 | 设置 → 日结重置 | 独立存在 |
| BO-BOOK_ORDER | 预订 | 顾客的预约记录 | 创建 → 到店/取消 | 独立存在 |
| BO-TAKEOUT_ORDER | 外卖订单 | 第三方平台的外卖交易 | 创建 → 完成/取消 | 独立存在 |
| BO-DELIVERY | 配送 | 一次配送任务 | 创建 → 完成/取消 | 依赖 BO-TAKEOUT_ORDER |
| BO-SHIFT | 班次 | 一次交班记录 | 交班创建 | 独立存在 |
| BO-SETTLEMENT | 日结 | 一天营业的结算记录 | 日结创建 | 独立存在 |
| BO-INVOICE | 发票 | 一张发票的完整生命周期 | 开具 → 红冲/作废 | 依赖 BO-ORDER |

## 二、关键业务路径

### 2.1 核心路径图（加菜→结账）

```
收银员 ──▶ BO-ORDER（创建/更新）
                 │
                 ├── BO-ORDER_DETAIL（添加菜品）
                 │       ├── ──▶ BO-GOODS（商品引用）
                 │       ├── ──▶ BO-SOLDOUT_STOCK（估清预占）
                 │       └── ──▶ BO-PRINT_JOB（厨房小票）
                 │
                 ├── BO-ORDER_STATUS（状态变更）
                 │       └── ──▶ BO-TABLE（桌台状态同步）
                 │
                 └── BO-SCREEN_MAKE（KDS制作单）
                         └── ──▶ BO-PRINT_JOB（打印任务）

顾客付款 ──▶ BO-ORDER_PAY（支付记录）
                 │
                 └── BO-ORDER（actualReceiptAmount 更新）
                         │
                         ├── BO-ORDER_STATUS（支付状态变更）
                         │
                         ├── BO-TABLE（桌台状态 → 清台就绪）
                         │
                         ├── BO-PRINT_JOB（结账单）
                         │
                         ├── BO-MEMBER（积分累计）
                         │
                         └── BO-INVOICE（发票可开具）
```

### 2.2 路径与业务场景映射

| 路径编号 | 路径（对象→对象） | 跳数 | 关键业务场景 | 为什么需要这条路径 |
|---|---|---|---|---|
| BP-01 | BO-ORDER → BO-ORDER_DETAIL | 1跳 | 加菜/退菜 | 明细记录菜品的增减变化 |
| BP-02 | BO-ORDER → BO-ORDER_PAY | 1跳 | 支付/退款 | 支付记录与订单金额挂钩 |
| BP-03 | BO-ORDER → BO-TABLE | 1跳 | 开台/清台 | 桌台状态反映订单状态 |
| BP-04 | BO-ORDER_DETAIL → BO-SOLDOUT_STOCK | 1跳 | 估清预占/释放 | 库存保护 |
| BP-05 | BO-ORDER_DETAIL → BO-SCREEN_MAKE | 1跳 | KDS分单 | 厨房知道做什么菜 |
| BP-06 | BO-ORDER → BO-SCREEN_MAKE | 1跳 | 落单触发 | 制作单关联订单 |
| BP-07 | BO-ORDER → BO-INVOICE | 1跳 | 开票/红冲 | 发票关联订单 |
| BP-08 | BO-ORDER → BO-MEMBER | 1跳 | 积分累计 | 会员权益计算 |
| BP-09 | BO-TABLE → BO-ORDER | 1跳 | 查询桌台账单 | 桌台查找当前订单 |
| BP-10 | BO-BOOK_ORDER → BO-ORDER | 1跳 | 预订开台 | 预订关联正式订单 |
| BP-11 | BO-TAKEOUT_ORDER → BO-DELIVERY | 1跳 | 外卖配送 | 配送管理 |
| BP-12 | BO-SHIFT → BO-SETTLEMENT | 1跳 | 班结汇总 | 日结统计 |

## 三、核心关系契约

### REL-01：订单 ↔ 订单明细

```
┌─────────────────────────────────────────┐
│ REL-01: BO-ORDER ↔ BO-ORDER_DETAIL      │
├─────────────────────────────────────────┤
│ 【关系定义】                             │
│   类型：1:N                             │
│   方向：BO-ORDER → BO-ORDER_DETAIL     │
│   关联路径：直接                        │
│                                         │
│ 【字段连接】                             │
│   OrderMaster.billNo → OrderDetail.billNo│
│                                         │
│ 【建立时机】                             │
│   加菜时建立（PlaceOrderService）        │
│                                         │
│ 【约束条件】                             │
│   ✓ 同一 billNo 下同一 dataId 已落单则禁止重复│
│   ✓ 套餐明细必须跟随套餐头一起操作        │
│                                         │
│ 【为什么要经过中间对象】                   │
│   不适用（直接关系）                     │
│                                         │
│ 【修改影响】                             │
│   修改订单 → 不影响明细                  │
│   删除订单 → 级联删除明细                │
│   删除明细 → 不影响订单主表              │
│                                         │
│ 【代码位置】                             │
│   后端：PlaceOrderService.java           │
│                                         │
│ 【证据】                                 │
│   E-SRC: service/order/PlaceOrderService.java │
└─────────────────────────────────────────┘
```

### REL-02：订单 ↔ 桌台

```
┌─────────────────────────────────────────┐
│ REL-02: BO-ORDER ↔ BO-TABLE             │
├─────────────────────────────────────────┤
│ 【关系定义】                             │
│   类型：N:1（多订单共用一桌台）          │
│   方向：BO-TABLE → BO-ORDER             │
│   关联路径：直接                        │
│   billNo ↔ orderKey（表字段连接）        │
│                                         │
│ 【建立时机】                             │
│   开台时：BO-TABLE.orderKey = billNo    │
│   清台时：BO-TABLE.orderKey = ""         │
│                                         │
│ 【约束条件】                             │
│   ✓ 一个桌台同一时刻最多一个有效订单     │
│   ✓ 订单必须绑定桌台（或快餐 billNo）    │
│   ✓ 联台时多桌台共享 orderKey          │
│                                         │
│ 【为什么要经过中间对象】                   │
│   不适用（直接关系）                     │
│                                         │
│ 【级联行为】                             │
│   结账完成 → BO-TABLE 状态恢复 FREE     │
│   撤单 → BO-TABLE 状态恢复 OCCUPIED    │
│   反结账 → BO-TABLE 状态恢复 PRESETTLEMENT│
│                                         │
│ 【代码位置】                             │
│   后端：OpenTableService.java,          │
│           ClearTableService.java          │
│   证据：E-SRC                           │
└─────────────────────────────────────────┘
```

### REL-03：菜品 ↔ 打印机（间接关联）

```
┌─────────────────────────────────────────┐
│ REL-03: BO-GOODS ↔ 打印机（间接，3跳） │
├─────────────────────────────────────────┤
│ 【关系定义】                             │
│   类型：N:1（通过中间对象间接关联）      │
│   关联路径：间接（3跳）                │
│                                         │
│ 【关联路径（共3跳）】                    │
│   菜品 → 出品部门（商品归属哪个部门）    │
│     → 打印队列（部门关联哪个队列）      │
│     → 打印机（队列选择哪台打印机）      │
│                                         │
│ 【为什么需要经过中间对象】（业务原因）    │
│   1. 简化配置：只需为每个部门配一个队列  │
│      而不是为每道菜单独配置打印机        │
│   2. 自然分组：同一部门的菜自动合打一张  │
│   3. 故障转移：队列层可以配主/备打印机  │
│      若菜品直绑打印机，坏了一台无法切换   │
│                                         │
│ 【如果直接关联（菜品→打印机）会怎样】    │
│   新增/更换打印机需修改所有关联菜品配置； │
│   跨部门合单无法实现                    │
│                                         │
│ 【中间对象职责】                         │
│   出品部门：业务分组边界                │
│   打印队列：路由与容错（主/备打印机）   │
│                                         │
│ 【级联行为】                             │
│   删除菜品 → 不影响部门/队列/打印机     │
│   删除部门配置 → 该部门菜品无法路由     │
│   删除队列 → 关联部门菜品无法打印       │
│   删除打印机 → 队列自动切换到备用       │
│                                         │
│ 【代码位置】                             │
│   后端：KitchenPrintSolutionService       │
│   证据：E-SRC                           │
└─────────────────────────────────────────┘
```

## 四、关系总览

| 关系ID | 对象A | 对象B | 类型 | 基数 | 业务含义 |
|---|---|---|---|---|---|
| REL-01 | 订单 | 订单明细 | 结构 | 1:N | 一个订单包含多道菜品 |
| REL-02 | 订单 | 支付记录 | 结构 | 1:N | 一个订单有多次支付 |
| REL-03 | 订单 | 桌台 | 结构 | N:1 | 多个订单共用桌台 |
| REL-04 | 订单明细 | 估清库存 | 结构 | N:1 | 明细菜品占用估清数量 |
| REL-05 | 订单明细 | KDS制作单 | 轨迹 | 1:N | 一道菜一个制作状态 |
| REL-06 | 订单 | 发票 | 结构 | 1:N | 一个订单可开多张发票 |
| REL-07 | 桌台 | 区域 | 结构 | N:1 | 多个桌台属于一个区域 |
| REL-08 | 预订 | 订单 | 轨迹 | 1:1 | 预订到店后转化为正式订单 |
| REL-09 | 外卖订单 | 配送 | 轨迹 | 1:1 | 一个外卖对应一个配送任务 |
| REL-10 | 班次 | 日结 | 结构 | N:1 | 多个班次归属一个日结 |

## 五、关系类型判定

| 判定规则 | 关系对 | 结果 |
|---|---|---|
| 两端皆事实 → 轨迹 | BO-ORDER → BO-ORDER_PAY | 轨迹 |
| 两端皆维度 → 结构 | BO-TABLE → BO-AREA | 结构 |
| 事实指向维度 → 归因 | BO-ORDER_DETAIL → BO-GOODS | 归因 |
| 两端皆事实 → 轨迹 | BO-ORDER → BO-SCREEN_MAKE | 轨迹 |
| 两端皆事实 → 轨迹 | BO-BOOK_ORDER → BO-ORDER | 轨迹 |
