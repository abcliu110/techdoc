# Obsidian 本地知识库凭据止血设计

## 目标

停止在受 Git 跟踪文件和查询脚本中保存 Obsidian API 凭据或 TLS 私钥，使查询脚本只从环境变量读取凭据，并在本地 API 不可用时提供可重复的只读降级路径。

## 已确认问题

- 查询脚本、Obsidian API 配置和插件运行数据包含真实凭据；插件运行数据还包含 TLS 私钥。
- 这些文件受 Git 跟踪，秘密已进入仓库历史。
- 查询脚本缺少请求超时、HTTP 状态检查和收敛后的错误信息。
- 本地 API 关闭时脚本直接输出完整 traceback，没有按工作区记忆降级到 Markdown 检索。
- 使用指南包含与当前插件不一致的 API 路径。

本文不记录任何秘密正文、指纹或可复用凭据值。

## 备选方案

### 方案 A：立即自动重写 Git 历史并推送

可清除历史对象，但会重写共享提交，需要远端协调、备份和所有协作者重新同步。当前代理没有足够权限和协作上下文，不自动执行。

### 方案 B：当前树止血、取消跟踪、提供轮换与历史清理清单

先阻止秘密继续扩散，使脚本和仓库默认配置安全；明确把 API Key、证书和私钥轮换以及历史重写列为人工协调项。该方案风险最低，采用此方案。

### 方案 C：只把脚本改成读环境变量

历史和受跟踪运行配置仍会泄露凭据，不能完成止血。该方案不采用。

## 组件设计

### 查询脚本

- `obsidian_query.py` 只读取 `OBSIDIAN_API_KEY`，缺失时返回简短、可行动的错误。
- HTTP 请求设置有限超时，调用 `raise_for_status()`，捕获连接、TLS、超时和 HTTP 错误。
- API 可用时沿用插件实际支持的 `/vault/`、`/search/` 或 `/search/simple/` 路径。
- API 不可用时，只读扫描知识库根目录下的 Markdown 文件；排除 `.obsidian`、缓存和生成目录，限制结果数，并标明结果来自本地降级检索。
- 使用 Python 标准库或仓库已有依赖，不新增包。

### 仓库边界

- `.gitignore` 忽略 Obsidian workspace、插件运行数据、API 配置、证书和私钥。
- 对已跟踪的敏感运行文件取消跟踪但保留本地副本，避免破坏当前 Obsidian 环境。
- 如共享配置确有必要，只增加不含秘密的示例文件；示例值必须是明显占位符。

### 文档

- 使用指南改为插件实际端点和环境变量方式。
- 明确本地 API 启动条件、离线降级行为、超时和常见失败信息。
- 增加人工安全处置清单：立即轮换 API Key、重新生成证书和私钥、评估历史重写、通知仓库协作者。

## 数据流与错误处理

正常路径：命令参数 → 校验环境变量 → HTTPS 请求 → 校验状态码 → 限量输出结果。

降级路径：连接/TLS/超时失败 → 输出单行原因 → 本地 Markdown 限量检索 → 标明降级来源。凭据缺失不尝试匿名 API 请求；本地目录不可读时以非零退出码结束。

所有错误信息只包含错误类别、目标地址和下一步动作，不打印 Authorization 头、配置对象、私钥或完整 traceback。

## 测试设计

- 先运行秘密扫描，确认当前受跟踪文件会失败；修正后同一扫描通过。
- 使用标准库单元测试覆盖：环境变量缺失、HTTP 成功、超时、HTTP 错误和本地降级。
- 测试中使用假的固定 token，不读取或回显真实本地凭据。
- 验证取消跟踪后本地运行文件仍存在，并验证 `git ls-files` 不再列出它们。
- 验证使用指南中的端点与脚本常量一致。

## 安全边界

- 本轮不自动轮换真实凭据，不重写历史，不推送远端。
- 当前树止血不等于历史秘密失效；在人工轮换完成前，凭据仍视为已泄露。
- 不删除用户的 Obsidian 笔记、插件或本地运行配置。
