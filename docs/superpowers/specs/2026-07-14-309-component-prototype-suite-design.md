# 309 个复杂 UI 组件独立交互原型套件设计

## 1. 目标

把 `00通用/数据模型界面模式映射` 下现有 13 册、309 个组件条目改造成 309 套逐项手写、可操作、可重置、可自动验证的独立交互原型。

本次不是“换标题和说明文字”的视觉去重。每个组件都必须通过自己的关键操作体现其数据模型、核心状态和与相邻组件的决定性差异。

## 2. 已确认范围

- 保留现有 13 个类别、309 个组件、文件名、总索引和视觉外壳。
- 第 10-14 类仍不在本轮范围内。
- 现有 HTML 是兼容入口，修复后仍为无外部依赖、可直接打开的独立文件。
- 允许共享页面外壳、基础 CSS、DOM 安全函数、无业务含义的控件构造函数。
- 禁止共享会掩盖组件差异的行为级原型模板。
- 禁止默认 renderer、兜底 renderer 或“其他类型统一进入普通表格/表单/画布”的分支。

## 3. “逐项手写”的验收定义

每个组件 ID 必须同时拥有以下内容：

1. 一个显式登记的 renderer 函数。
2. 一组与组件语义一致的初始数据。
3. 至少一个专属关键操作。
4. 至少一个由该操作触发、用户可观察的状态变化。
5. 一个明确的重置结果。
6. 一个自动化 interaction contract，说明点击或输入什么、观察哪个状态、预期如何变化。
7. 无控制台异常、无未转义用户 HTML、无缺失可访问名称的交互控件。

两个 renderer 可以调用相同的基础控件 helper，但不能仅通过传入不同标题、标签或样例数据生成同一行为。例如：

- 虚拟滚动表格必须改变可视窗口和起始索引，不能只是普通表格换标题。
- 无限加载表格必须体现 cursor/loading/end 状态，不能复用虚拟滚动的状态机。
- 服务端分页表格必须体现 page/pageSize/total/request 状态。
- 异步校验表单必须体现 pending/success/error 和过期响应处理。
- 发布控制台必须体现环境、前置校验、发布进度和结果，不能复用版本修订列表。

## 5. 运行时设计

### 5.1 统一外壳

共享外壳只负责：

- 左栏目录和搜索。
- 上一项、下一项、键盘切换。
- Hash 深链接、`hashchange` 和浏览器前进/后退同步。
- 移动端目录开关和 Esc 关闭。
- renderer 的 mount/unmount/reset 生命周期。
- 错误隔离和状态栏。

外壳不得判断组件业务类型，也不得含 `else -> generic form/grid/canvas`。

### 5.2 Renderer 接口

每个组件 renderer 都是独立函数：

```js
export function renderVirtualGrid(context) {
  // 独立初始数据、结构、事件和状态。
  return {
    reset() {},
    destroy() {}
  };
}
```

`context` 只提供安全 DOM helper、舞台根节点、状态输出、toast 和清理注册。renderer 不直接修改页面目录或其他组件状态。

### 5.3 状态生命周期

- 进入组件时创建新的局部状态。
- 切换组件前执行 `destroy()`，取消 timer、监听器和异步任务。
- 重置时销毁并重新 mount 当前 renderer，不能只重绘 DOM 而保留闭包状态。
- 延迟聚焦必须绑定当前 mount token，避免切换组件后访问已移除 DOM。
- 键盘切换在 input、textarea、select、button、contenteditable 和组合输入期间禁用。

## 6. 安全与可访问性

- 所有用户输入默认通过 `textContent` 渲染。
- 只有固定、受控模板可以进入 `innerHTML`；动态值必须先转义。
- 消息、评论、编辑器预览等原型不得通过用户字符串构造可执行 DOM。
- 所有输入、选择器和按钮必须有可访问名称。
- 状态变化使用可见状态文本；必要时增加 `aria-live`。
- 移动端主要操作目标不小于 44×44 CSS 像素，紧凑表格内部控件除外但需保留可聚焦区域。

## 7. 逐册行为覆盖原则

- 01 布局：尺寸、分割、停靠、拖拽、断点、抽屉、窗口和工作区持久化分别实现。
- 02 表格：编辑、选择、分页、窗口化、加载、排序、筛选、列管理、汇总、对比和差异分别实现。
- 03 树：选择策略、懒加载、搜索、拖拽、编辑、菜单、不同层级领域和图谱结构分别实现。
- 04 表单：动态 Schema、嵌套、重复、步骤、条件、联动、计算、同步/异步校验、草稿、上传、签名和审批分别实现。
- 05 查询：条件树、分面、全文、保存查询、DSL、建议、范围、跨字段和聚合条件分别实现。
- 06 选择器：单选、多选、级联、树、表、穿梭、组织、人员、日期、时间、颜色、图标和复合对象分别实现。
- 07 编辑器：富文本、Markdown、代码、JSON/YAML、公式、SQL、模板、邮件、规则、图形和标注分别实现。
- 08 低代码：页面、表单、报表、仪表盘、移动页、数据源、事件、动作、组件、主题、导航、Schema、版本和发布分别实现。
- 09 流程规则：流程、BPMN、状态机、规则、决策表、表达式、审批、编排、ER/UML、网络拓扑和无限画布分别实现。
- 15 导航：侧栏、顶栏、Tabs、Ribbon、命令面板、全局搜索、面包屑、历史、收藏、快捷键、上下文菜单和多工作区分别实现。
- 16 权限：矩阵、角色、组织、行列数据范围、授权、继承、模拟、审计、策略、租户、ACL 和凭证分别实现。
- 17 协作：聊天、群聊、评论、回复、批注、通知、在线状态、协作光标、冲突、时间线、工单、反馈和活动流分别实现。
- 18 业务：SKU、订单、库存、价格、促销、发票、凭证、排班、薪资、销售、物流、工单、排课、库位、座位、预订、设备和告警分别实现。

## 8. 测试策略

### 8.1 静态契约测试

构建前必须验证：

- 类别数为 13，组件数为 309。
- 组件 ID、renderer 和 interaction contract 三组 key 完全相等。
- 不存在默认 renderer 或缺失 renderer。
- 每个 renderer 是独立的函数引用。
- 每项 contract 都包含入口、操作、状态观察和重置断言。
- 总索引计数和文件映射正确。

### 8.2 浏览器逐项回归

对 309 项逐一执行：

1. 从 Hash 打开组件并确认标题、模型和状态。
2. 记录初始状态指纹。
3. 执行该项 contract 声明的专属操作。
4. 验证状态指纹按预期改变。
5. 点击重置并验证恢复初始状态。
6. 验证切换组件后旧 timer、焦点和状态不泄漏。
7. 收集控制台错误和页面异常。

套件级额外覆盖：搜索、上一项/下一项、前进/后退、键盘保护、移动目录、桌面和移动视口、局部滚动、安全输入与可访问名称。

## 9. 分阶段交付

实现按类别分批，但每批都必须是可构建、可回归的完整状态：

1. 基础设施、安全缺陷和 01-04。
2. 05-09。
3. 15-18。
4. 309 项全量浏览器回归与文档更新。

不得以占位原型、默认模板或“后续补齐”通过阶段验收。

## 10. 兼容与回滚

- 保留现有文件名、链接和组件 ID，旧书签继续有效。
- 保留当前视觉外壳和文字说明，行为实现以扩展为主。
- 构建前保存当前产物清单和校验值；回滚时可恢复原 HTML 文件。
- 新源码层不引入第三方依赖，删除新增源码并恢复原 HTML 即可完整回滚。

## 11. 已拒绝方案

- 拒绝“按能力族共用行为模板”：无法满足用户明确要求的 309 套逐项手写原型。
- 拒绝“只修确定性 Bug”：无法解决左栏切换后内容和交互差异不足的问题。
- 拒绝“直接在 13 个 HTML 产物中散改”：安全、导航和回归逻辑会重复，且后续难以确认 309 项覆盖完整性。
- 拒绝新增前端框架或组件库：独立 HTML 和无外部依赖是现有套件契约。

## 12. 完成标准

只有同时满足以下条件才可报告完成：

- 309/309 renderer 已显式实现。
- 309/309 interaction contract 通过。
- 13 册和总索引构建成功。

- 桌面与移动端无阻断性布局、滚动、焦点或控制台错误。
- 套件说明更新为真实实现能力，不再依赖“允许复用模板”解释组件差异。
