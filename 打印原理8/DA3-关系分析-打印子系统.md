### 2.3 间接路径分析要点

#### BP-01：菜品 → 打印机（3跳间接关联）

**为什么需要经过出品部门（中间跳1）**：
1. **业务分组边界**：出品部门代表厨房的业务分区（如"炒菜区"、"凉菜区"），厨师只关心自己区域的菜。菜品必须知道"这道菜归谁做"，才能路由到正确的打印机。
2. **简化配置**：如果菜品直接绑定打印机，新菜上架需要配置打印机；通过部门间接绑定，新菜只需选部门，打印机配置由部门统一管理。
3. **自然合单**：同一部门的菜自动合打一张单，厨师按部门收单处理。如果菜品直连打印机，跨部门合单需要额外逻辑。

**为什么需要经过打印队列（中间跳2）**：
1. **故障转移能力**：打印队列配置主/备打印机，主机故障时自动切换。如果菜品直连打印机，打印机故障时无法自动切到备用机。
2. **统一路由入口**：部门只需要知道"我的菜去哪个队列"，队列内部的主备切换对部门透明。
3. **负载均衡（潜在）**：未来队列可扩展为支持多台打印机轮询，提高吞吐。

**如果直接关联（菜品→打印机）会怎样**：
- 新增/更换打印机需修改所有关联菜品配置
- 无法按部门合单，跨部门菜要分多张单
- 打印机故障时无备用机可切，任务直接失败

## 四、关联关系详细契约

### REL-01：菜品 ↔ 出品部门

```
┌─────────────────────────────────────────────────────────────────┐
│ REL-01: 菜品 ↔ 出品部门                                         │
├─────────────────────────────────────────────────────────────────┤
│ 【关系定义】                                                    │
│   类型：N:1（一个部门 → N道菜品）                              │
│   方向：菜品 → 出品部门                                         │
│   关联路径：直接（0跳）                                        │
│                                                                 │
│ 【字段连接】                                                    │
│   菜品.lid → PosDishToPrnDept.dish_lid                         │
│   PosDishToPrnDept.prn_dept_lid → 出品部门.lid                 │
│                                                                 │
│ 【建立时机】                                                    │
│   配置时建立：管理员为菜品（或按菜类/区域批量）配置出品部门     │
│   运行时路由：结账时查询菜品归属部门，用于打印路由              │
│                                                                 │
│ 【约束条件】                                                    │
│   ✓ 同一道菜只能归属一个出品部门（1:1 实际效果）               │
│   ✓ 可按菜类批量配置（新菜自动继承菜类配置）                    │
│   ✓ 可按桌台区域批量配置（同一区域的桌台用同一部门）            │
│                                                                 │
│ 【使用方式】                                                    │
│   结账时：系统查询菜品归属部门，为每道菜创建打印任务            │
│   监控时：按部门统计打印任务数量和失败率                        │
│                                                                 │
│ 【修改影响】                                                    │
│   修改菜品归属部门：不影响历史订单，但影响未来订单路由          │
│   删除部门配置：该部门菜品无法路由，需先重新配置菜品归属         │
│                                                                 │
│ 【异常场景】                                                    │
│   场景1：菜品未配置出品部门 → 无法路由，日志警告，跳过该菜打印  │
│   场景2：部门被删除 → 该部门下菜品自动失去归属，需要重新配置    │
│   场景3：批量配置覆盖单个配置 → 按菜类/区域配置会覆盖单品配置   │
│                                                                 │
│ 【级联行为】                                                    │
│   删除菜品 → 不影响出品部门                                    │
│   删除出品部门 → 该部门菜品失去归属，打印路由失败               │
│                                                                 │
│ 【代码位置】                                                    │
│   后端：PrinterWorkerService.createJob()                        │
│   前端：PosDishToPrnDept 配置页面                              │
│                                                                 │
│ 【证据】                                                        │

### REL-03：打印队列 ↔ 打印机

```
┌─────────────────────────────────────────────────────────────────┐
│ REL-03: 打印队列 ↔ 打印机                                       │
├─────────────────────────────────────────────────────────────────┤
│ 【关系定义】                                                    │
│   类型：1:N（一个队列 → N台打印机，支持主备）                  │
│   方向：打印队列 → 打印机                                       │
│   关联路径：直接（0跳）                                        │
│                                                                 │
│ 【字段连接】                                                    │
│   打印队列.primary_printer (BLOB) → 打印机.lid 列表            │
│   打印队列.standby_printer (BLOB) → 打印机.lid 列表            │
│                                                                 │
│ 【建立时机】                                                    │
│   配置时建立：管理员为队列配置主打印机和备用打印机列表         │
│   运行时路由：Worker 优先选主打印机，主故障时选备用打印机        │
│                                                                 │
│ 【约束条件】                                                    │
│   ✓ 主打印机列表和备用打印机列表都是逗号分隔的 lid              │
│   ✓ 主备列表可以包含多台打印机（逗号分隔）                     │
│   ✓ 同一台打印机可同时在主列表和备列表中                       │
│                                                                 │
│ 【使用方式】                                                    │
│   任务执行时：Worker 先尝试主打印机，失败后按顺序尝试备用       │
│   状态监控：Worker 实时监控主备打印机状态                      │
│                                                                 │
│ 【修改影响】                                                    │
│   修改主打印机：影响后续任务的路由目标                          │
│   删除主打印机：Worker 自动切换到备用打印机                    │
│                                                                 │
│ 【异常场景】                                                    │
│   场景1：主打印机故障 → Worker 立即切换到备用打印机            │
│   场景2：主备全故障 → 任务休眠 2 秒后重试，直到超时放弃       │
│   场景3：主打印机恢复 → 后续任务优先使用主打印机              │
│                                                                 │
│ 【级联行为】                                                    │
│   删除打印机 → 从队列的主备列表中移除                          │
│   删除队列 → 不影响打印机实体（打印机可属于其他队列）           │
│                                                                 │
│ 【代码位置】                                                    │
│   后端：PrinterWorkerServiceLocalImpl.getPrinter()             │
│   前端：打印队列配置页面                                        │
