# 00-十分钟读懂 — 打印子系统

> 读者视角主文档（理解层），依据 SOP-00 §9.1 结构要求生成

## 一句话业务本质

**打印子系统是餐饮 POS 的"输出神经"——把业务事件（点菜、结账、划菜）转化为物理小票，确保厨房按单做菜、顾客拿到凭证、传菜有据可依。**

## 分析对象的业务位置

```
餐饮 POS 业务流：
点菜 → 厨房制作 → 传菜 → 结账 → 离店
  │        │         │       │
  └──┬─────┴────┬────┴───┬──┘
     │          │        │
  厨房联      传菜联   顾客联
```

打印子系统不直接产生营收，但它是 POS 业务闭环的"最后一公里"——没有打印，厨房不知道做什么菜，顾客不知道付了多少钱，传菜员不知道送到哪桌。

## 范围与边界

**范围内**：餐饮 POS 的厨房联/传菜联/顾客联打印、打印配置管理（打印机/队列/样式/开关）、打印任务监控。
**范围外**：WMS 库存单据打印、排队叫号打印、短信通知、微信物流打印机。

## 角色和责任

| 角色 | 在打印系统中做什么 |
|------|------------------|
| 服务员/收银员 | 点菜、结账自动触发打印；查看打印状态、重打 |
| 厨师 | 接收厨房小票，按单做菜 |
| 传菜员 | 接收传菜小票，按单传菜 |
| 门店管理员 | 配置打印机、队列、样式、开关 |
| 顾客 | 接收小票 |

## 一个主故事：厨房联打印

服务员小王在 POS 上给 3 号桌点了"宫保鸡丁"和"酸辣汤"。

1. 提交点菜后，系统自动判断是否需要打印厨房联（打印开关控制）
2. 系统查看"宫保鸡丁"属于"热菜部"、"酸辣汤"属于"汤品部"
3. 为每个部门创建一个打印任务，发到对应打印队列
4. 每个队列选一台健康打印机（主备切换，故障自动换）
5. 热菜部打印机输出"宫保鸡丁"小票，汤品部输出"酸辣汤"小票
6. 两个部门的厨师同时看到小票，开始制作

整个过程不到 1 秒，小王继续接待下一桌，完全不需要等待打印完成。

## 主要失败后果

- **打印机故障**：自动切换备用；全部故障延迟重试，最多 45 分钟
- **打印任务失败**：不影响核心业务（点菜/结账），可在监控页面重打
- **配置错误**：样式或条件配置错误时容错显示（宁可多打不可少打）

## 系统拥有与不拥有的事实

**拥有**：打印任务、打印队列、打印样式、打印机状态、打印次数。
**不拥有**：业务订单数据（账单、菜品、支付）——由业务模块维护，打印系统通过数据源读取。

## 快速问答

| 问题 | 答案 |
|------|------|
| 打印任务存在哪里？ | 数据库 + 本地 .job 文件（双保险） |
| 支持哪些打印机？ | 8 种连接类型（驱动/网口/串口/USB/并口/芯烨云/佳博云/驱动指令） |
| 打印机离线怎么办？ | 切备用机；全故障延迟 2 秒重试，45 分钟超时放弃 |
| 如何新增打印类型？ | 配置打印开关 + 配置打印样式 |
| 打印卡住怎么办？ | 查看打印任务监控、检查打印机状态、重打任务 |
