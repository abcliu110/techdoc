# 02-典型业务故事与关键规则 — 打印子系统

> 读者视角主文档（理解层），100% 叙事要求（SOP-00 §9.4.2）

## 故事一：点菜后厨房联如何到达厨师

### 场景

中午 12 点，餐厅忙碌。服务员小王在 POS 上给 3 号桌的 4 位客人点菜：宫保鸡丁、酸辣汤、回锅肉、米饭×2。

### 故事

小王在 POS 上选择菜品，点击提交。系统立即开始处理：

**第一步：判断要不要打印**

系统先检查"点菜单"这种类型是否启用了厨房联打印。如果门店管理员在后台关掉了厨房联，或者设置张数为 0，就不打印。今天没关，默认打印 1 份。

**第二步：菜品分到哪个部门**

系统查看每道菜的"出品部门"：
- 宫保鸡丁、回锅肉 → 热菜部
- 酸辣汤 → 汤品部
- 米饭 → 主食部

每个部门都关联了一个打印队列：热菜部→热菜打印机，汤品部→汤品打印机，主食部→主食打印机。

**第三步：创建打印任务**

系统为每个部门创建一个打印任务，写入数据库，同时在本地磁盘生成 `.job` 文件——这是双保险，即使数据库出问题，打印 worker 也能从文件恢复。

**第四步：初始化任务内容**

系统加载"点菜单"的打印样式模板，把门店信息、账单信息、菜品明细填充进去，应用条件过滤（比如过滤掉已退菜的记录），生成最终可打印行。

**第五步：分发到打印机**

系统查看热菜部队列配了哪些打印机。主打印机列表有 2 台，都正常，随机选一台；备用打印机有 1 台，暂时用不上。

**第六步：打印**

打印机 worker 读取 `.job` 文件，通过对应的处理器（驱动/端口/云 API）驱动硬件。热菜部的打印机吐出小票："3号桌 - 宫保鸡丁、回锅肉"。汤品部和主食部的打印机同时吐出各自小票。

三个部门的厨师同时看到小票，开始制作。整个过程不到 1 秒，小王已经去接待下一桌客人了。

### 关键规则

| 规则 | 说明 |
|------|------|
| 打印开关控制 | 门店可配置每种类型是否启用和张数 |
| 按出品部门分发 | 每道菜属于一个部门，每个部门关联一个队列 |
| 主备切换 | 主打印机故障自动切备用 |
| 异步执行 | 打印不阻塞点菜，创建任务后立即返回 |

### 失败场景

**热菜部打印机坏了**：自动切到备用。备用也坏了：等 2 秒再试，持续 45 分钟；还不行就放弃并记录日志。
**队列没配打印机**：记录错误日志，任务无法打印，管理员需要在后台配置。
**打印内容不对**：可能是样式模板或数据源配置问题，管理员可在后台调整。

## 故事二：结账后顾客小票如何打印

### 场景

3 号桌客人吃完准备结账。收银员小张在 POS 上发起结账。

### 故事

小张选择现金结账，系统完成支付后触发打印：

**第一步：找顾客联设置**

系统先看 3 号桌有没有专门设置；没有就看所在区域；再没有就看桌型；最后看当前收银机。优先级：**桌台 > 区域 > 桌型 > PC**。

今天 3 号桌属于"大厅"区域，区域有一个顾客联设置，指向"前台打印机"队列。

**第二步：判断打印张数**

检查"结账单"类型启用了顾客联，打印 1 份。

**第三步：创建任务**

创建两个任务：顾客联任务（结账单，打印到前台打印机）+ 钱箱弹出任务（不需要模板）。

**第四步：分发和打印**

前台打印机吐出结账单（菜品明细、金额、支付方式、优惠信息），钱箱同时弹开。小张把账单递给客人，完成结账。

### 关键规则

| 规则 | 说明 |
|------|------|
| 顾客联优先级 | 桌台 > 区域 > 桌型 > PC |
| 结账/点菜区分 | forCheckout 字段区分场景 |
| 钱箱联动 | 结账时自动弹出钱箱 |

### 失败场景

**找不到顾客联设置**：跳过不打印，结账正常完成，但顾客没有小票。
**前台打印机故障**：切备用或延迟重试。

## 故事三：传菜员如何拿到传菜小票

### 场景

厨房做好菜，传菜员小李需要把菜送到对应桌台。

### 故事

厨师在 POS 上划菜（标记制作完成），系统触发传菜联打印：

**第一步：找传菜联设置**

加载所有传菜联设置。每个传菜间设置包含：覆盖哪些出品部门（如"热菜部"和"汤品部"）、使用哪个打印队列。

**第二步：匹配菜品**

遍历已完成的菜，看它们的出品部门属于哪个传菜间。热菜部的菜归"1号传菜间"，汤品部的归"2号传菜间"。

**第三步：创建任务**

为每个传菜间创建打印任务，打印到对应队列。

**第四步：打印**

1 号传菜间打印："3号桌 - 宫保鸡丁、回锅肉"；2 号传菜间打印："3号桌 - 酸辣汤"。小李分别拿到小票开始传菜。

### 关键规则

| 规则 | 说明 |
|------|------|
| 按传菜间分发 | 每个传菜间覆盖一组出品部门 |
| 菜品分组 | 同一传菜间的菜合并打印 |

## 故事四：管理员如何配置打印样式

### 场景

新店开业，管理员需要配置打印样式。

### 故事

管理员登录 SaaS 后台，进入打印设置页面：

1. 选择"结账单"类型
2. 添加一行，数据源绑定"门店信息"，显示店名和地址
3. 添加一行，数据源绑定"账单信息"，显示桌号、人数、时间
4. 添加一行，数据源绑定"菜品明细"（TABLE 类型），显示菜品名称、数量、单价、小计
5. 在菜品明细行加条件：过滤已退菜记录（foodStatus != CANCELLED）
6. 添加一行，数据源绑定"支付信息"，显示支付方式和金额
7. 添加汇总行，自动计算合计
8. 添加一行，只在结账时才显示二维码（条件：orderStatus = CLOSED）
9. 保存

下次结账时新样式自动生效（热生效，不影响历史任务）。

### 关键规则

| 规则 | 说明 |
|------|------|
| 数据源绑定 | 行绑定数据源，列从数据源取字段值 |
| 条件过滤 | 控制行或记录是否可见 |
| 汇总行 | 自动计算合计/小计 |
| 热生效 | 修改后下次打印立即生效 |
