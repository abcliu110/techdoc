# 01-业务全景

## 一、模块定位

打印模块是POS系统的关键基础设施，负责：
- 将业务单据转换为可打印格式
- 可靠地分发到物理打印机或云打印服务
- 保证打印的可用性和可靠性

### 1.1 在系统中的位置

```
┌──────────────────────────────────────────────────────────────┐
│                         业务系统                               │
│   订单模块 │ 结账模块 │ 会员模块 │ 仓储模块 │ 报表模块          │
└────────────────────────────┬─────────────────────────────────┘
                             │ MQ消息
                             ↓
┌──────────────────────────────────────────────────────────────┐
│                      打印模块 (pos2plugin + pos3boot)          │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐           │
│  │  打印队列    │  │  打印任务    │  │  打印样式    │           │
│  └─────────────┘  └─────────────┘  └─────────────┘           │
│  ┌─────────────┐  ┌─────────────┐                            │
│  │  打印机     │  │  转发规则    │                            │
│  └─────────────┘  └─────────────┘                            │
└────────────────────────────┬─────────────────────────────────┘
                             │
              ┌──────────────┼──────────────┐
              ↓              ↓              ↓
        ┌──────────┐  ┌──────────┐  ┌──────────┐
        │ 物理打印机│  │ 云打印API │  │ Windows驱动│
        │ (NET/USB)│  │(芯燚/精打)│  │           │
        └──────────┘  └──────────┘  └──────────┘
```

### 1.2 模块边界

**输入**：
- MQ消息（业务单据创建/更新事件）
- API调用（手动打印请求）

**输出**：
- 物理打印（热敏纸/标签纸）
- 云打印（芯燚云/精打云）

## 三、业务场景

### 3.1 场景1：前台结账打印小票

```
结账完成
    ↓
创建 PosPrnJob (type=CheckOut, prnQueueLid=前台队列)
    ↓
加载打印样式模板
    ↓
分发到"前台小票打印机"(主)
    ↓
打印结账单
    ↓
归档任务
```

### 3.2 场景2：后厨打印点菜单

```
点菜完成
    ↓
创建 PosPrnJob × N (type=OrderMenu, purpose=厨房联)
    ↓
分发到"后厨打印机"(主)
    ↓
打印点菜单
    ↓
同时分发到"划菜打印机"(备)
    ↓
打印划菜总单
```

### 3.3 场景3：打印机故障自动切换

```
主打印机Printer-A故障
    ↓
PrinterWorker检测到FAULT状态
    ↓
将Pending任务重定向到Printer-B(通过Transfer规则)
    ↓
Printer-B接收并处理任务
    ↓
Printer-B故障恢复后，重新接收新任务
```

### 3.4 场景4：云打印标签

```
标签打印请求
    ↓
创建 PosPrnJob (type=FoodLabel)
    ↓
分发到"芯燚云打印机"(type=XY_CLOUD)
    ↓
XpCloudPrinter.handle() 调用云API
    ↓
云服务商打印标签
```

## 四、关键业务流程

### 4.1 打印分发流程

```
                    开始
                      │
                      ↓
            ┌─────────────────┐
            │  获取打印队列    │
            └────────┬────────┘
                      │
                      ↓
            ┌─────────────────┐
            │  解析主打印机   │
            │  (逗号分隔→Set) │
            └────────┬────────┘
                      │
                      ↓
            ┌─────────────────┐
            │  应用转发规则   │
            │ resolveTargets()│
            └────────┬────────┘
                      │
                      ↓
            ┌─────────────────┐
            │  过滤故障打印机 │
            └────────┬────────┘
                      │
            ┌─────────┴─────────┐
            ↓                   ↓
        有健康打印机         无健康打印机
            │                   │
            ↓                   ↓
    ┌───────────────┐   ┌───────────────┐
    │ 随机负载均衡  │   │ 解析备用打印机 │
    │ 分发到打印机  │   └────────┬───────┘
    └───────────────┘            │
                                 ↓
                    ┌─────────────────────┐
                    │    有健康备用？      │
                    └──────────┬──────────┘
                               │
              ┌────────────────┴────────────────┐
              ↓                                 ↓
           是                                   否
              │                                 │
              ↓                                 ↓
    ┌───────────────┐                 ┌───────────────┐
    │ 分发到备用打印机│                 │  2秒后重试     │
    └───────────────┘                 └───────────────┘
```

### 4.2 打印执行流程

```
PrinterWorker.run() (虚拟线程)
    │
    ├─→ getStatus() 检查打印机状态
    │       │
    │       ├─→ NORMAL: 继续处理
    │       ├─→ FAULT: redirect() → 重发任务，sleep 5秒
    │       └─→ BUSY: 继续等待
    │
    └─→ runInner(dispatchJob)
            │
            ├─→ 从Redis加载任务 PrnJobCreateDTO
            │
            ├─→ 超时检查（30分钟）
            │       │
            │       └─→ 超时: archiveFailed() → 结束
            │
            ├─→ buildPrintJob() 渲染内容
            │       │
            │       ├─→ 遍历打印行
            │       ├─→ 条件判断 (displayCondition)
            │       ├─→ 零值隐藏 (hideWhenZero)
            │       └─→ 补打提示 (prnCount > 0)
            │
            └─→ handler.handle(Prn_PrintJob)
                    │
                    ├─→ GraphicsHandler (Driver)
                    ├─→ PortHandler (NET/COM/USB/LPT)
                    ├─→ XpCloudPrinter (XY_CLOUD)
                    └─→ JBCloudPrinter (JB_CLOUD)
```

## 五、技术架构

### 5.1 模块分布

| 仓库 | 模块 | 职责 |
|---|---|---|
| `nms4pos` | pos2plugin-api | API定义、枚举、DTO |
| `nms4pos` | pos2plugin-biz | 业务逻辑、处理器 |
| `nms4pos` | pos2plugin-dal | 实体、Mapper |
| `nms4pos` | pos3boot | 打印Worker、MQ监听 |
| `nms4pos` | pos10printer | Windows桌面打印客户端 |
| `nms4cloud` | pos-api | 云端打印API |

### 5.2 技术选型

| 组件 | 技术 | 用途 |
|---|---|---|
| 消息队列 | ActiveMQ | 打印任务异步分发 |
| 缓存 | Redis (JetCache) | 打印队列缓存、任务数据存储 |
| 持久化 | MySQL (MyBatisFlex) | 打印机/队列/任务元数据 |
| 并发 | Java虚拟线程 | PrinterWorker线程 |
| 打印协议 | OPOS/ESC/POS | 串口/网口打印机通信 |
| 云API | HTTP | 云打印服务通信 |

### 5.3 关键设计模式

| 模式 | 应用场景 |
|---|---|
| **策略模式** | PrintJobHandlerBase 根据type/model选择处理器 |
| **生产者-消费者** | MQ消息 → 内存队列 → PrinterWorker |
| **主备模式** | primaryPrinter + standbyPrinter |
| **重试模式** | 指数退避重试（2秒间隔，上限45分钟） |

## 六、关键指标

| 指标 | 阈值 | 说明 |
|---|---|---|
| 打印机状态检查耗时 | >400ms | 触发告警日志 |
| 任务分发耗时 | >100ms | 触发性能日志 |
| 队列等待超时 | 45分钟 | 任务丢弃 |
| 任务创建超时 | 30分钟 | 不再处理 |
| 历史任务保留 | 30天 | 自动清理 |

---

## 七、总结

打印模块的核心价值：
1. **可靠性**：主备冗余 + 故障重定向 + 超时重试
2. **灵活性**：支持多种打印机类型和云服务
3. **可观测性**：关键路径日志记录，便于问题排查
4. **可配置性**：每门店可独立配置打印队列和样式
