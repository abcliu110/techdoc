## 二、未覆盖项

| 项 | 原因 | 影响 | 优先级 |
|----|------|------|--------|
| Virtual Thread 并发上限参数未找到具体配置值 | PrinterWorkerServiceLocalImpl 使用 Virtual Thread 但未找到线程数量限制配置 | 无法评估高并发场景下的吞吐上限 | P2 |
| 打印机 BUSY 状态无显式超时机制 | BUSY 由打印完成回调清除，属于事件驱动而非超时驱动 | 极端情况下（打印机卡纸但不报错）BUSY 状态永不解除 | P1 |
| 前端轮询间隔和 WebSocket 推送机制未分析 | 前端模块（nms4pos-ui / nms4cloud-biz-ui）未纳入本次侦察范围 | 无法评估前端实时性体验和性能影响 | P3 |
| 消息消费幂等性保障机制未验证 | ActiveMQ 配置和消息处理逻辑未深入分析 | 消息重复消费可能导致重复打印 | P1 |
| PENDING 状态超时自动转 FAILED 逻辑未发现 | 45 分钟机制仅用于启动时加载未完成任务，不执行状态变更 | 长时间卡住的任务不会自动失败，需要人工干预 | P2 |
| 打印机状态（PrinterStatus）持久化方式未确认 | DA5 数据模型中 PosPrnPrinter 表未列出 status 字段，但 E-006 定义了状态枚举 | 状态如何跨进程/重启保持未知 | P1 |
| PrinterWorkerService 的 Spring Bean 注入配置未分析 | 三套实现（Local/Offline/Online）通过什么机制路由未知 | 无法确认实际运行时使用的是哪套实现 | P2 |

## 三、风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| **PrinterWorkerServiceOnlineImpl 为空实现，云打印功能不可用** | 高 | 高 | 标记为已知技术债，建议优先级 P0 尽快实现 |
| 消息重复消费导致重复打印 | 中 | 中 | 增加幂等性检查（如在 PrinterWorkerService 中检查任务是否已打印） |
| PENDING 任务长期卡住不转 FAILED | 低 | 中 | 监控系统可定期扫描 PENDING 状态超时任务并告警 |
| 打印机 BUSY 状态永不解除（卡纸不报错） | 低 | 高 | 增加 BUSY 状态超时告警和强制恢复机制 |
| 打印机状态跨进程/重启不持久 | 低 | 中 | 确认 PrinterStatus 持久化方式，或改为状态上报+持久化设计 |
| 循环打印机转移（source→target, target→source） | 低 | 高 | 增加转移规则创建时的循环检测逻辑 |
| Redis 不可用导致打印次数统计不准确 | 低 | 低 | 已设计 DB 回退机制，影响可接受 |
