单个组件：七道强制关口

每个组件有唯一责任人、风险等级、契约卡和证据包；缺关口不得以“后补”方式进入发布分支。

01 INTAKE

登记与定级

关联旧 ID；标注 B/C、R1-R3、使用者、依赖、最坏失败后果与版本目标。

门禁：责任与范围明确
02 CONTRACT

契约冻结

Props、事件、受控状态、插槽、键盘、焦点、异步与异常恢复写成可验证契约。

门禁：API / UX / A11y 评审
03 RED

先证明缺失

先写最小失败测试，确认因目标行为尚未实现而失败；记录 RED 证据。

门禁：失败原因准确
04 GREEN

最小生产实现

复用令牌与基础设施；覆盖加载、空、错误、只读、禁用及恢复，不加入未立项能力。

门禁：契约测试通过
05 HARDEN

风险加固

按 R 等级验证竞态、重复操作、虚拟化、失败注入、草稿恢复、安全边界与性能预算。

门禁：风险证据齐全
06 DOCS

规范与迁移

文档站提供真实业务场景、状态矩阵、错误示例、API、迁移关系和限制。

门禁：只消费公开 API
07 RELEASE

准入与发布

运行全量质量门禁，生成变更集、版本、产物清单、安装验证、回滚和弃用说明。

门禁：批准角色签署

测试证据

责任边界

React 组件负责防重复触发、交互状态、输入约束、恢复入口、焦点管理、确认语义、事件与观测钩子。
业务服务负责权限与租户最终校验、幂等、并发控制、金额/库存/订单约束、事务、审计与跨系统一致性。
停止线：契约未冻结、RED 未观察到、R2/R3 证据缺失、存在未解释的回归、回滚不可执行或文档站绕过公开 API，任一命中都禁止发布。
