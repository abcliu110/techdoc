从“流程合规”升级为“组件认证”

组件只有通过可复核认证才进入发布清单。无证据等同未完成，口头确认和截图描述不能代替自动化结果。

默认拒绝：任一强制检查缺失、失败、超预算或证据不可追溯，流水线直接阻断；不得先发版后补票。

机器强制门禁

01严格类型、公开 API 类型测试、循环依赖、重复导出、包边界与 Tree Shaking 检查。
02单元、契约、交互、键盘、焦点、异常恢复、响应式、暗色与视觉回归全部通过。
03A11y 自动扫描零严重/高危；关键流程必须人工键盘与读屏复核并留证。
04运行时无未处理异常、无控制台错误、无 React 警告；性能与包体积不得超预算。
05从打包产物创建隔离消费项目，验证 ESM、类型、CSS、SSR/浏览器边界和子路径导入。
06变更必须声明兼容级别；破坏性修改只能经弃用周期与主版本发布进入。

治理与可追溯

01每个组件指定 Owner、备份 Owner、风险等级、评审人和支持期限；无人负责不得发布。
02需求、契约、代码、测试、Story、旧 ID、变更集和发布产物使用同一追踪标识关联。
03依赖固定版本并经过许可证、安全与维护状态审查；高危漏洞阻断发布。
04发布采用不可变产物、来源证明、完整性校验；测试对象与实际发布对象必须是同一产物。
05每次发布生成兼容报告、风险清单、回滚步骤和消费方升级说明；证据按版本归档。
06发布后有问题分级、响应时限、撤回/降级规则；R3 需演练而非只写文档。

偏差机制：只适用于不影响功能、安全、无障碍、数据正确性和兼容性的非红线项；必须记录原因、影响、责任人、补偿措施、到期时间（最长一个小版本），到期自动阻断。R3 不接受偏差。
绝对红线：跨租户/越权、敏感信息泄露、金额/库存/订单错误、不可恢复数据丢失、未处理异常、关键键盘路径不可达、发布产物未验证、已知高危漏洞、破坏性变更未走主版本。任何等级均不得豁免。
