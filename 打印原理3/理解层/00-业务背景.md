## 1. 业务背景

### 1.1 餐饮POS系统概述

餐饮POS系统是连接前台收银、后厨生产、传菜协调的核心业务平台。打印功能作为系统的重要输出通道，承担着将数字信息转化为物理凭证的关键职责。

**典型餐饮业务流程**：

```
顾客点餐 ──→ 系统记录 ──→ 打印厨房联 ──→ 后厨制作
    │                              │
    │                              ▼
    │                         打印传菜联 ──→ 传菜间传递
    │
    ▼
结账操作 ──→ 打印顾客联 ──→ 顾客留存
    │
    ▼
打印交班/日报 ──→ 运营管理
```

### 1.2 打印功能的业务价值

| 价值维度 | 具体体现 |
|----------|----------|
| **服务保障** | 顾客联作为消费凭证，保障顾客权益 |
| **生产协同** | 厨房联传递菜品信息，确保后厨准确制作 |
| **运营效率** | 传菜联协调前后台，减少沟通成本 |
| **管理依据** | 交班/日报提供经营数据，支持决策分析 |

### 1.3 业务特点

1. **多场景**：点菜、结账、预结、退菜、催菜、划菜、充值等场景
2. **多类型**：顾客联、厨房联、传菜联、设备指令、报表等票据
3. **多目标**：不同票据分发到不同的打印机/队列
4. **高可靠**：餐饮高峰期集中打印，不能丢单、不能乱序

## 2. 业务边界

### 2.1 功能边界

**已覆盖**：
- POS收银相关打印（点菜单、结账单、厨房联、传菜联）
- 运营报表打印（交班报表、日报表）
- 会员服务打印（充值小票）
- WMS仓储打印（订货单、入库单、出库单）
- 设备控制（钱箱弹出）

**未覆盖**：
- 第三方外卖平台小票（由平台方处理）
- 电子发票（需对接税控系统）
- 电子签名（移动端数字化凭证）

### 2.2 用户角色

| 角色 | 使用场景 | 关注点 |
|------|----------|--------|
| 顾客 | 查看结账单 | 信息完整、清晰易读 |
| 服务员 | 点菜、划菜 | 操作便捷、响应快速 |
| 收银员 | 结账、预结 | 票据规范、打印稳定 |
| 厨师 | 查看厨房联 | 内容准确、字体清晰 |
| 传菜员 | 查看传菜联 | 桌号清晰、金额小计 |
| 店长 | 查看报表 | 数据准确、格式规范 |
| 运维 | 设备管理 | 配置灵活、故障易排查 |

## 3. 业务规则概述

### 3.1 票据分发规则

| 票据类型 | 分发依据 | 说明 |
|----------|----------|------|
| 顾客联 | 桌台/区域/桌型/PC | 优先精确匹配，依次降级 |
| 厨房联 | 菜品出品部门 | 一个部门对应一个队列 |
| 传菜联 | 传菜间设置 | 按部门匹配，汇总金额 |

### 3.2 打印开关控制

支持按打印类型独立控制：
- 是否启用（disabled）
- 打印份数（numOfXxx）

### 3.3 故障处理策略

```
主打印机故障 → 备打印机 → 延迟重试(2秒) → 超时放弃(45分钟)
```

## 4. 业务指标

### 4.1 关键业务指标

| 指标 | 期望值 | 说明 |
|------|--------|------|
| 打印成功率 | ≥99.5% | 成功打印/总任务数 |
| 平均打印耗时 | ≤500ms | 从任务创建到完成 |
| 高峰并发能力 | ≥100张/分钟 | 持续打印能力 |
| 故障恢复时间 | ≤2分钟 | 从故障到恢复 |

### 4.2 业务量预估

| 场景 | 单店日均打印量 | 高峰QPS |
|------|----------------|---------|
| 点菜 | 200-500张 | 5-10 |
| 结账 | 50-150张 | 2-5 |
| 厨房联 | 200-500张 | 5-10 |
| 传菜联 | 100-300张 | 3-8 |

## 5. 业务发展趋势

### 5.1 当前痛点

1. **配置复杂**：队列、打印机、样式配置分散
2. **调试困难**：打印问题排查依赖经验
3. **扩展不便**：新增票据类型需改代码

### 5.2 未来方向

1. **可视化配置**：拖拽式打印模板设计器
2. **智能化路由**：根据打印机状态动态分配
3. **云打印支持**：扩展更多云打印机品牌
4. **移动打印**：支持移动端扫码打印
