# 企业级免费开源系统分析工具方案

> **版本**: V1.0  
> **日期**: 2026-09-05  
> **目标**: 为大型遗留系统分析提供可落地的免费开源工具链

---

## 一、工具选型原则

### 1.1 必须满足的条件

| 条件 | 说明 |
|------|------|
| 完全免费 | 核心功能无需付费，无企业版限制 |
| 开源可审计 | 源码开放，可本地部署，无数据上传风险 |
| 可扩展 | 支持大型代码库（>50万行） |
| 可集成 | 可与现有工具链集成 |
| 活跃维护 | 社区活跃，持续更新 |

### 1.2 不选择的工具类型

❌ **排除理由**:
- AWS Transform、Alchemize Suite：商业付费产品
- Structure101：已停止维护且需付费
- Qlerify：需要MCP连接和付费订阅
- SonarQube Enterprise：架构功能仅企业版

```java
// 测试1: 分层架构
@ArchTest
static final ArchRule layer_dependencies_are_respected = layeredArchitecture()
  .consideringAllDependencies()
  .layer("Controller").definedBy("..controller..")
  .layer("Service").definedBy("..service..")
  .layer("Persistence").definedBy("..dao..")
  
  .whereLayer("Controller").mayNotBeAccessedByAnyLayer()
  .whereLayer("Service").mayOnlyBeAccessedByLayers("Controller")
  .whereLayer("Persistence").mayOnlyBeAccessedByLayers("Service");

// 测试2: 聚合根约束
@ArchTest
static final ArchRule aggregates_must_be_in_domain_package = 
  classes()
    .that().areAnnotatedWith(AggregateRoot.class)
    .should().resideInAPackage("..domain..")
    .because("聚合根必须在领域层");

// 测试3: 禁止循环依赖
@ArchTest
static final ArchRule no_cycles = slices()
  .matching("com.nms4cloud.(*)..")
  .should().beFreeOfCycles();

# 3. 生成Level 0产物

## 查询1: 统计系统规模
MATCH (t:Type) RETURN count(t) as 类总数
MATCH (p:Package) RETURN count(p) as 包总数
MATCH (m:Method) RETURN count(m) as 方法总数

## 查询2: 识别核心包（高入度）
MATCH (p:Package)<-[r:DEPENDS_ON]-()
RETURN p.fqn as 包名, count(r) as 被依赖次数
ORDER BY count(r) DESC
LIMIT 20

## 查询3: 识别上帝类（高复杂度）
MATCH (c:Class)-[:DECLARES]->(m:Method)
WITH c, sum(m.cyclomaticComplexity) as totalComplexity
WHERE totalComplexity > 100
RETURN c.fqn, totalComplexity
ORDER BY totalComplexity DESC

## 查询4: 循环依赖
MATCH (p1:Package)-[:DEPENDS_ON*]->(p2:Package)-[:DEPENDS_ON*]->(p1)
WHERE p1 <> p2
RETURN p1.fqn, p2.fqn

# 4. 导出CSV
CALL apoc.export.csv.query(
  "MATCH (p:Package)<-[r:DEPENDS_ON]-() RETURN p.fqn, count(r) as deps",
  "package-dependencies.csv",
  {}
)
```

### 4.5 Phase 4: 架构治理（ArchUnit）

```java
// 在 src/test/java 创建 ArchitectureTest.java

@AnalyzeClasses(packages = "com.nms4cloud")
public class ArchitectureTest {

  // 测试1: 分层架构
  @ArchTest
  static final ArchRule layered_architecture = layeredArchitecture()
    .consideringAllDependencies()
    .layer("API").definedBy("..api..")
    .layer("Application").definedBy("..app..")
    .layer("Domain").definedBy("..domain..")
    .layer("Infrastructure").definedBy("..dao..", "..infrastructure..")
    
    .whereLayer("API").mayNotBeAccessedByAnyLayer()
    .whereLayer("Application").mayOnlyBeAccessedByLayers("API")
    .whereLayer("Domain").mayOnlyBeAccessedByLayers("Application", "API")
    .whereLayer("Infrastructure").mayNotAccessAnyLayer();

  // 测试2: 聚合根只能在domain包
  @ArchTest
  static final ArchRule aggregates_in_domain = classes()
    .that().haveSimpleNameEndingWith("Aggregate")
    .or().areAnnotatedWith(AggregateRoot.class)
    .should().resideInAPackage("..domain..")
    .because("聚合根必须在领域层");

  // 测试3: Repository只能被Service调用
  @ArchTest
  static final ArchRule repositories_should_only_be_accessed_by_services = 
    classes()
      .that().haveSimpleNameEndingWith("Repository")
      .should().onlyBeAccessed().byClassesThat().haveSimpleNameEndingWith("Service");

  // 测试4: 无循环依赖
  @ArchTest
  static final ArchRule no_cycles_by_method_calls_between_slices = 
    slices().matching("com.nms4cloud.(*)..")
      .should().beFreeOfCycles();

  // 测试5: Entity不能依赖Controller
  @ArchTest
  static final ArchRule entities_should_not_depend_on_controllers = 
    noClasses()
      .that().resideInAPackage("..domain..")
      .should().dependOnClassesThat().resideInAPackage("..controller..");
}

// 运行测试
mvn test -Dtest=ArchitectureTest
```

## 五、关键对比：免费 vs 商业方案

| 维度 | 免费开源方案 | 商业方案 (AWS/Alchemize) |
|------|-------------|-------------------------|
| **成本** | $0 | $50k-$500k/年 |
| **数据安全** | 本地部署，无上传 | 需上传代码到云端 |
| **扩展性** | 手工集成，需编码 | 开箱即用 |
| **AI能力** | 本地LLM（Ollama） | 商业LLM (GPT-4/Claude) |
| **业务语义** | 需人工判断 | 部分自动化 |
| **学习曲线** | 陡峭，需技术背景 | 较平缓 |
| **适用规模** | <100万行 | 无限制 |

**结论**: 
- 小型项目（<10万行）: 免费工具完全够用
- 中型项目（10-50万行）: 免费工具 + 人工校准
- 大型项目（>50万行）: 考虑商业方案，或组建专门团队使用免费工具

## 七、常见问题

### Q1: jQAssistant vs Understand，选哪个？

**回答**:
- **jQAssistant**: 适合Java项目，支持自定义查询，免费无限制
- **Understand**: 多语言支持更好，UI更友好，但免费版有文件数限制

**建议**: Java项目优先jQAssistant，多语言项目考虑Understand学术版

### Q2: 本地LLM（Ollama）效果如何？

**回答**:
- **优势**: 无成本、无数据泄露风险
- **劣势**: 推理速度慢、准确率低于GPT-4

**建议**: 
- 用于辅助判断（聚合根识别、代码解释）
- 不要依赖其最终结论，需人工校准
- 核心决策仍需人类架构师

### Q3: 如何处理100万行以上代码？

**回答**:
1. **分批扫描**: 按业务域拆分，逐个分析
2. **增量分析**: 先分析核心域（P0），再分析周边
3. **并行处理**: 多台机器同时运行jQAssistant
4. **剪枝策略**: 排除测试代码、生成代码、第三方库

### Q4: Context Mapper生成的模型准确吗？

**回答**:
- **准确率**: 60-70%（基于Spring注解和目录结构）
- **需要人工**:
  - 合并重复的Bounded Context
  - 校准聚合根判定
  - 补充业务语义

**建议**: 把生成结果当作"初稿"，不是"最终稿"
