# 状态转换追踪的数据库可检索性分析

> 分析 setStatus() 等状态变更的静态追踪能力

---

## 一、问题定义

### 1.1 常见状态变更模式

```java
// 模式A: 直接赋值
order.setStatus(OrderStatus.PAID);

// 模式B: 枚举比较后赋值
if (current == OrderStatus.CREATED) {
    order.setStatus(OrderStatus.PAID);
}

// 模式C: 变量传递
OrderStatus newStatus = determineNextStatus(order);
order.setStatus(newStatus);

// 模式D: Map 存储
statusMap.put(orderId, OrderStatus.PAID);
```

### 1.2 追踪难点

| 模式 | 难点 | 可追踪性 |
|------|------|----------|
| A | 直接调用 | ✅ 可追踪 |
| B | 需要数据流分析 | ⚠️ 困难 |
| C | 变量来源复杂 | ❌ 静态难 |
| D | 间接存储 | ❌ 无法追踪 |

## 二、数据库可检索性评估

### 2.1 可存储到数据库的内容

```sql
-- 1. 方法调用记录（已知）
INSERT INTO method_calls (method, target, line)
VALUES ('setStatus', 'Order', 125);

-- 2. 目标枚举值（如果字面量）
INSERT INTO state_transitions (from_state, to_state, trigger)
VALUES ('UNKNOWN', 'PAID', 'OrderService.pay()');

-- 3. 置信度标记
UPDATE state_transitions
SET confidence_level = 'L2', needs_review = TRUE
WHERE from_state = 'UNKNOWN';
```

### 2.2 核心限制

```
静态分析能做到的：
├── 识别 setStatus() 调用
├── 提取目标枚举值（如果是字面量）
├── 关联触发方法
└── 标记 from_state = 'UNKNOWN'

静态分析做不到的：
├── 确定运行时 from_state（需要数据流分析）
├── 追踪变量来源（需要符号执行）
└── 分析 Map 间接存储
```

### 2.3 数据库查询能力

```sql
-- 可查询：哪些方法调用了 setStatus
SELECT method_id, target_field, target_value
FROM method_calls
WHERE method_name LIKE '%setStatus%';

-- 可查询：按触发方法筛选
SELECT * FROM state_transitions
WHERE trigger LIKE '%pay%';

-- 可查询：标记需要人工确认的项
SELECT * FROM state_transitions
WHERE needs_review = TRUE;
```

## 三、替代方案

### 3.1 方案A：枚举+方法名模式（推荐）

```python
def identify_transitions_enum_pattern(entity_class_id):
    """
    通过枚举值和方法名匹配识别转换

    例如：
    - OrderStatus.PAID
    - void payOrder() { order.setStatus(PAID); }
    → payOrder() → PAID
    """
    results = []

    # 1. 找到状态枚举
    enum = find_status_enum(entity_class_id)

    # 2. 提取枚举值
    enum_values = [e.name for e in get_enum_values(enum)]

    # 3. 找类中的方法
    methods = get_methods(entity_class_id)

    # 4. 方法名包含枚举值 → 识别为转换触发
    for method in methods:
        for value in enum_values:
            if value.upper() in method.name.upper():
                results.append({
                    'from_state': 'PREVIOUS',  # 已知
                    'to_state': value,
                    'trigger': method.name,
                    'confidence': 'L4',
                    'evidence': f"方法名包含状态名 {value}"
                })

    return results
```

**数据库存储**：
```sql
INSERT INTO state_transitions (entity_class_id, from_state, to_state, trigger, confidence, evidence)
VALUES (123, 'PREVIOUS', 'PAID', 'payOrder', 'L4', '方法名包含枚举值');
```

### 3.2 方案B：数据库实际值查询（需连接数据库）

```sql
-- 查询实际存在状态值
SELECT DISTINCT status FROM t_order WHERE deleted = 0;
```

**优点**：L5 置信度
**缺点**：需要数据库连接，只能获取值，不能获取转换

### 3.3 方案C：半自动流水线（生产推荐）

```python
def semi_auto_state_analysis(entity_class_id):
    """
    机器识别 + 人工确认
    """
    candidates = []

    # 1. 机器识别
    auto_results = identify_transitions_enum_pattern(entity_class_id)
    for r in auto_results:
        r['needs_review'] = False
        candidates.append(r)

    # 2. 机器无法确定的，标记待确认
    unknown_calls = find_status_calls_without_enum()
    for call in unknown_calls:
        candidates.append({
            'from_state': 'UNKNOWN',
            'to_state': call.arguments[0],
            'trigger': call.method,
            'confidence': 'L2',
            'needs_review': True,
            'review_url': f"/review/transition/{call.id}"
        })

    # 3. 存储到数据库
    for c in candidates:
        save_to_database(c)

    return candidates
```

**数据库表设计**：
```sql
CREATE TABLE state_transitions_review (
    id INTEGER PRIMARY KEY,
    entity_class_id INTEGER,
    from_state TEXT,
    to_state TEXT,
    trigger TEXT,
    confidence TEXT,
    needs_review BOOLEAN,
    reviewed BOOLEAN DEFAULT FALSE,
    reviewer_comment TEXT,
    confirmed_from_state TEXT
);
```

## 四、综合评估

### 4.1 数据库可检索性矩阵

| 分析维度 | 数据库可存储 | 可精确检索 | 说明 |
|----------|-------------|-----------|------|
| 枚举值列表 | ✅ | ✅ | 完整 |
| 状态字段 | ✅ | ✅ | 完整 |
| 转换触发方法 | ✅ | ✅ | 如果是枚举+方法名模式 |
| 转换 from_state | ⚠️ 部分 | ⚠️ 部分 | 需要人工确认 |
| 转换 to_state | ✅ | ✅ | 如果是字面量 |
| 转换条件 | ⚠️ 部分 | ⚠️ 部分 | 简单条件可解析 |
| 运行时状态值 | ❌ | ❌ | 需要数据库查询 |

### 4.2 置信度影响

| 场景 | 置信度 | 数据库可检索 |
|------|--------|-------------|
| 枚举值 + 方法名匹配 | L4 | ✅ |
| 字面量 setStatus(PAID) | L4 | ✅ |
| 变量 setStatus(status) | L2 | ⚠️ 需人工 |
| Map 存储 | L1 | ❌ |

### 4.3 建议

```
┌─────────────────────────────────────────────────────────────┐
│  状态转换追踪的数据库检索策略                             │
├─────────────────────────────────────────────────────────────┤
│                                                           │
│  1. 优先使用枚举+方法名模式（自动推断）                  │
│     → 置信度 L4，80%场景可覆盖                           │
│                                                           │
│  2. 字面量 setStatus(XxxStatus.YYY)                       │
│     → 置信度 L4，可精确检索                               │
│                                                           │
│  3. 变量参数 setStatus(var)                              │
│     → 置信度 L2，标记 needs_review                        │
│     → 人工补充后可达 L4                                   │
│                                                           │
│  4. Map/反射等间接方式                                   │
│     → 置信度 L1，跳过或单独处理                          │
│                                                           │
└─────────────────────────────────────────────────────────────┘
```

## 五、数据库查询示例

```sql
-- 1. 查询某实体的所有状态
SELECT DISTINCT to_state
FROM state_transitions
WHERE entity_class_id = 123;

-- 2. 查询某状态的入边（什么转换到该状态）
SELECT * FROM state_transitions
WHERE to_state = 'PAID'
ORDER BY confidence DESC;

-- 3. 查询需要人工确认的转换
SELECT * FROM state_transitions
WHERE needs_review = TRUE
ORDER BY confidence ASC;

-- 4. 按置信度筛选
SELECT * FROM state_transitions
WHERE entity_class_id = 123
AND confidence IN ('L4', 'L5')
ORDER BY trigger;

-- 5. 生成状态机 DOT 图
SELECT
    '    ' || from_state || ' -> ' || to_state || ' [label="' || trigger || ' (' || confidence || ')"];'
FROM state_transitions
WHERE entity_class_id = 123;
```

## 六、总结

**可以做到**：
- ✅ 枚举值存储和检索
- ✅ 状态字段识别
- ✅ 枚举+方法名模式的转换追踪（L4）
- ✅ 置信度标记和筛选
- ✅ 人工确认流程支持

**有限制**：
- ⚠️ 变量参数需要人工补充
- ⚠️ 复杂数据流无法追踪
- ⚠️ Map/反射等间接方式无法追踪

**建议**：
1. 先实现枚举+方法名模式（覆盖 60-80% 场景）
2. 变量参数场景标记 needs_review = TRUE
3. 人工补充后可更新置信度
4. 连接数据库查询实际状态值作为补充
