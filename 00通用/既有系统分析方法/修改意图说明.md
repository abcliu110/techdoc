# code-review-graph 增强方案修改意图说明

## 修改背景

原文档提出了一个 **AI 推理版（v2.0）** 方案，核心思路是：
- 扩展 code-review-graph 建图能力，采集字段、注解、枚举等数据
- **在图谱中存储 AI 推理结论**（如：AI 推理的状态机、聚合根、业务规则）
- 通过 AI 推理引擎自动推理业务语义

### 原方案的问题

1. **AI 推理结论和代码事实混存**：图谱中既有代码静态事实，又有 AI 推理的结论，难以区分
2. **可重复性差**：AI 推理不稳定，同一输入可能产生不同输出
3. **可追溯性弱**：AI 推理链复杂，难以追溯结论的来源
4. **可维护性差**：修改推理逻辑需要改代码，成本高
5. **成本高**：需要大量 AI 推理调用

---

## 修改后的方案：AI 文档生成版（v3.0）

### 核心理念变更

**不再让 AI 推理业务语义并存入图谱，而是：**

1. **图数据库只存代码事实**
   - 类、字段、方法、注解、枚举、异常、状态转换、规则等
   - 只存静态解析的确定性事实，不存 AI 推理结论

2. **编写专门的 SOP 文档**（标准作业程序）
   - 每个文档生成任务对应一个 SOP
   - SOP 包含：查询指令 + AI 分析提示词 + 输出格式要求
   - 例如：`SOP-既有系统深度分析.md`、`SOP-更高维业务设计.md`

3. **AI Agent 执行 SOP 生成文档**
   - AI 根据 SOP 步骤查询图数据库
   - 使用 AI 分析查询结果
   - 生成结构化的 Markdown 文档
   - AI 只负责分析和组织文档，不负责推理并存储业务语义

### 架构对比

**原方案（AI 推理版）**：
```
代码解析 → 图谱增强 → AI 推理层（推理状态机、规则、聚合根）→ 存入图谱
```

**新方案（AI 文档生成版）**：
```
代码解析 → 图数据库（只存事实）→ AI Agent 执行 SOP → 查询+分析+生成文档
```

---

## 关键变更点

### 1. 图谱职责变化

| 方面 | 原方案 | 新方案 |
|------|--------|--------|
| 存储内容 | 代码事实 + AI 推理结论 | **只存代码事实** |
| AI 推理 | 推理后写入图谱 | **不写入图谱** |
| 数据性质 | 混合（事实+推理） | **纯事实** |

### 2. AI 职责变化

| 方面 | 原方案 | 新方案 |
|------|--------|--------|
| 主要任务 | 推理业务语义（状态机、规则、聚合根）| **执行 SOP、查询图谱、分析数据、生成文档** |
| 输出 | 推理结论（存入图谱）| **Markdown 文档** |
| 可重复性 | 低（AI 不稳定）| **高（SOP 确定性）** |

### 3. 新增 SOP 层

这是新方案的核心创新：

**SOP 文档结构示例**：
```markdown
# SOP-既有系统深度分析执行手册

## 步骤 1.1：候选对象扫描

**查询指令**：
```sql
SELECT id, name, package FROM class_nodes WHERE is_entity = true;
SELECT table_name FROM db_table_nodes;
```

**AI 分析提示词**：
分析以下查询结果，生成候选对象清单...

**输出要求**：
```markdown
| 对象名 | 类型 | 数据库表 | 判断 |
|--------|------|----------|------|
```
```

**AI Agent 执行流程**：
1. 读取 SOP 文档
2. 逐步执行 SOP 步骤
3. 执行 SQL 查询
4. 使用 AI 分析查询结果
5. 生成符合要求的 Markdown 文档

---

## 核心优势

| 优势 | 说明 |
|------|------|
| **职责清晰** | 图谱存事实、SOP 指导、AI 执行 |
| **高度可重复** | 同样的图谱 + SOP = 同样的文档 |
| **完全可追溯** | 每个结论可追溯到 SQL 查询和代码位置 |
| **易于维护** | 修改 SOP 文档即可，无需改代码 |
| **支持多方法论** | 写新 SOP 即可支持新方法论 |
| **成本可控** | 按需 AI 分析，不需要大量推理 |

## 实施对比

| 维度 | 原方案（AI推理版）| 新方案（AI文档生成版）|
|------|-----------------|---------------------|
| 实施时间 | 21-24周 | **15-17周** |
| 核心工作 | AI 引擎开发（4周）| **SOP 文档编写（4周）** |
| 实施难度 | 高 | **中** |
| 可维护性 | 低（改代码）| **高（改 SOP）** |
| 可扩展性 | 低（新方法论改代码）| **高（写新 SOP）** |

## 核心修改总结

**从"AI 推理并存储业务语义"转变为"AI 执行 SOP 生成文档"**

- ✅ 图谱只存事实（清晰）
- ✅ SOP 指导分析（可维护）
- ✅ AI 生成文档（灵活）
- ✅ 可重复、可追溯（质量保证）
