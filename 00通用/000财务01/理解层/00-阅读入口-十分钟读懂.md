# 00 阅读入口 · 十分钟读懂金蝶财务域

## 一句话本质

财务域是企业的 **"记账封箱机"** ——把每一次经营动作（采购、销售、收付款）翻译成"借=贷"的记账凭证，按**科目**和**会计期间**叠成账簿，并在每月末把本期"封箱"（结账），从此历史账目不许再被改动；万一发现错账，只能走"开箱复查"（改期/反结）这条受控通道。

> 它不是"管一堆表单的软件"，而是**让"钱/账"只有一套可信的权威记录、且历史不可篡改**的机制。

## 业务位置、范围与边界

- **位置**：供应链/制造产生"业务事实"→ 财务域把事实变成"会计事实"（凭证/余额）→ 报表与审计读取。财务域是核算中枢（总账 GL、应收 AR、应付 AP、现金 CB、票据 CN）。
- **拥有**：账簿事实的记账与期间封闭；往来核销与对账；资金日记账与票据；口径化的报表。
- **不拥有**：业务事实的产生（那是供应链/制造的事）；钱的真身（网银资金执行在系统之外）；税局申报（外部）。

## 角色和责任

| 角色 | 干什么 | 关键风险点 |
|---|---|---|
| 会计（如小李） | 生成/审核凭证、结账 | 凭证不平、期间冲突 |
| 出纳（如小王） | 现金/银行收付、对账 | 资金账实不符 |
| 往来会计（如小赵） | 核销、催收、对账 | 呆账、重复核销 |
| 财务负责人（如张总） | 批准结账、审计追溯 | 结账把关、治理 |
| 系统管理员 | 权限、异常改期、修复 | 越权改账 |

## 业务结果族 / 能力地图（简）

```
业务事实 ──凭证生成(记账)──▶ 凭证 ──过账──▶ 科目余额
                                            │
收付款/发票 ──核销/对账──▶ 往来与差异 ──▶ 账龄/催收
                                            ▼
                结转 ──▶ 期末结账(封箱) ──▶ 下期开始 ──▶ 报表/审计
```

## 一个主故事（请代入：会计小李，月末 28 号）

小李在 28 号晚上提交一笔采购入库存与供应商发票的过账：系统按凭证模板自动生成一笔"借：原材料，贷：应付账款"，金额各 10000，借=贷，科目合法，期间没结 → 过账成功，科目余额 +10000。半小时后他发现供应商号码选错了一位数——幸好本月还没结账，他反审核、改掉往来户、重新过账。到 31 号，财务负责人张总要结账：系统先检查上月已结、本期结转已完成、试算平衡，全过才"封箱"。张总点了结账，本期数据立即锁死——**从此这笔账进报表，去审计，也没人能再改**；若后来审计真发现错，只能走"反结账"权限通道重开修正（每次都有痕迹）。

**如果失败会怎样？** 凭证不平 → 过账被拒；上月没结 → 本月结不了；已结期间想改 → 被拦，只能走受控反结。这些"拦"与"放"就是这套系统的护城河。

## 系统拥有/不拥有的事实

- 拥有：记账规则（借=贷、期间锁、核销上限）、单据→凭证自动翻译、对账差异登记。
- 不拥有：业务单据本身是否合理（那是业务域）；银行里的真钱（系统只是记录）。

## 快速问答表（新人最常问）

| 问题 | 一句话答案 |
|---|---|
| 凭证存哪里？ | 记账后落到账簿（凭证+科目余额），期间没结前可改；表结构在服务端（**待补证 U-DA0-1**） |
| 结账后想改账怎么办？ | 默认不允许；走"反结账/改期"受控通道，需权限，每次留痕 |
| 一张收付款怎么对应多张发票？ | 通过"核销单"中间件做匹配，支持合并、部分核销、差异记录 |
| 卡住/过账失败怎么办？ | 看是"校验拒绝"（借不平/期间已结）还是"结果未知"（超时）——前者修数据，后者查状态再重试，勿盲发 |
| 支持哪些端/设备？ | 财务功能经金蝶桌面客户端/Web 使用，底部是同一套元数据+操作框架 |
| 谁能结账/改期？ | 财务负责人与授权管理员；改期需审计留痕（强制程度**待补证 U-DA4-2**） |
