| BO-07 收付款单 | 资金收付事实 | 收付→被核销 | 资金事实 |

## 三、关键业务路径（从核心对象出发，所有可达路径，每跳写语义）

### 3.1 路径 1（P0：S1 凭证过账）——3 跳
```
业务单据 ─(轨迹①审核即触发)─▶ 会计凭证 ─(轨迹②过账)─▶ 分录/科目余额 ─(归因③期间)─▶ 会计期间
   跳1 语义：单据审核通过是"可记账"的授权；凭证按模板+科目映射生成，借=贷
   跳2 语义：凭证过账把分录写入账簿、驱动科目余额增减
   跳3 语义：分录归属期间；已结期间拒绝写入 → 余额按期间固化
为什么需要中间对象凭证/BALANCE：
   1) 凭证是把"业务事实"与"账簿状态"解耦的中转——没有凭证，其余额无法批量复核/审计追溯；
   2) 科目余额是可合计的聚合态，凭证是明细事件，二者分工使"明细可查、总额可汇"；
   3) 期间给余额切时间片，历史不可变(结账)与未来可写分离。
```

### 3.2 路径 2（P0：S3 往来核销）——3 跳
```
往来发票/应收 ─(轨迹①入账)─▶ 往来户 ─(轨迹②核销匹配)─▶ 核销单 ─(归因③收付款)─▶ 收付款单
   跳1 语义：发票/收款确认把债权债务写入往来户
   跳2 语义：核销把往来明细与收款逐笔/批量匹配，未核额减少
   跳3 语义：核销单与收付款单绑定 → 资金事实与债权消灭闭环
为什么需要中间对象核销单/往来户：
   1) 往来户是"债权债务状态"的收敛点，避免每次核销都重读全部发票；
   2) 核销单承载匹配规则(先后/批号/金额)与防重——直接 发票→收款 无法表达"部分核销"与审计追溯；
   3) 若发票直接抵收付款，多单据合并收款、部分冲销、外币差异都无法建模。
```

### 3.3 路径 3（P0：S2 结账与期间）——2 跳 + 补偿通道
```
凭证/余额 ─(轨迹①结账)─▶ 期间(已结) ─(补偿②改期/反结)─▶ 期间(重开)
   跳1 语义：结账校验前序已结+结转完成+期终平衡 → 锁期并固化余额
   跳2 语义：改期/反结是受控补偿通道，重开期间修正错账，需权限与留痕
```

### 3.4 路径 4（P1：S4 资金对账）——2 跳
```
收付款/银行流水 ─(轨迹①)─▶ 资金日记账 ─(轨迹②对账/余额调节)─▶ 对账差异→调平
```

## 四、REL 契约（核心关系 6 要素/9 维；间接路径范例深写）

### REL-01：业务单据 → 会计凭证（轨迹）
```
类型：轨迹（事实→事实）；方向：单据1→凭证N；建立时机：单据审核后生成
变更影响：单据反审核→凭证需作废/红冲处理（不追溯则留下孤儿凭证）
业务语义：业务完成并经审核后，按凭证模板翻译为一笔"借=贷"的记账事实
维护入口：单据操作-生成凭证(自动) / 会计手工补凭证；校验：借贷平衡+科目合法
字段连接：单据事实字段→分录（单据ID/FDATE/金额/往来/科目映射）(E-SRC: BuildBusinessVoucher)
异常：①已过账单据再生成→防重 ②模板缺失→手动凭证 ③期间已结→禁过账
证据：E-SRC: FIN/01.Core VoucherGenerateService/BuildBusinessVoucher；运行未证(U-DA0-2)
```

### REL-02：会计凭证 → 科目/分户账（归因+轨迹）
```
类型：归因（分录→科目）+轨迹（过账驱动余额）
方向：凭证N→余额1(按科目)；建立时机：过账执行期
变更影响：反过账/红冲→余额回退或对冲（正向与负向记录）
业务语义：每笔分录指向科目，过账后科目余额按方向增减，余额=Σ分录(按期间)
约束：借贷平衡、科目期间可写、防重复过账
证据：E-SRC 平台过账(OperationController) + FIN 余额过滤；Schema 候选(U-DA0-1)
```

### REL-04（范例深写）：往来发票 ↔ 收付款单（间接，3 跳）
```
类型：轨迹（间接，经 往来户→核销单→收付款单）
关联路径：
  往来发票 → 往来户(债权债务入账，结构-归属)
    → 核销单(匹配载体，结构-桥接 + 轨迹-核销)
      → 收付款单(资金事实，归因-核销关联)
为什么需要经过中间对象（至少2条）：
  1) 多单合并：一张收付款可能核销多张发票，必须经"核销单"聚合，否则 1:N 无法表达；
  2) 部分核销与审计：发票可分批核销，核销单保留每次匹配痕迹，支持反核销与追溯；
  3) 外币/折扣差异：核销差异(汇率/折让)需在核销单上记录，直接在发票上改会污染债权金额。
如果直接关联(发票→收付款)：无法部分核销、无法合并匹配、差异无处落账 → 需重建匹配载体。
级联行为：删除核销单→来回应收退回未核；删除往来发票→关联核销需先冲销；
  删除收付款→核销回退，资金事实缺失需人工对账。
异常场景：
  1) 超额核销→拒绝(余额不足)；2) 重复核销→防重拦截；3) 期间已结后核销→需反结或作废重来。
证据：E-SRC: MatchServiceHelper / StatementServiceHelper(对账单)；核销匹配模型(U-DA0-1)
```
