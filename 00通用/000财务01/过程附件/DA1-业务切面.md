## 一、业务域定位

### 1.1 系统位置
```
业务事件(采购/销售/生产/费用) → 业务单据(供应链/制造) ──过账──▶ [财务领域]
  财务领域 = 总账(GL)+应收(AR)+应付(AP)+现金(CB)+票据(CN)
   = BOS平台(元数据单据) + FIN插件/服务门面 + 操作框架(过账/结账)
   ──▶ 账簿(科目×期间×币别) ──▶ 报表/审计/披露
```

### 1.2 业务价值
| 价值维度 | 说明 |
|---|---|
| 核算中枢 | 全企业"钱/账"的单一权威记录（账簿事实） |
| 合规 | 满足会计准则对期间、平衡、凭证的强制 |
| 控制 | 期间封闭、审批流、对账/核销防止错账与舞弊 |
| 决策 | 报表/账龄/现金流支撑经营判断 |

## 二、核心角色
| 角色 | 操作 | 接触系统 |
|---|---|---|
| 会计 | 录入/审核凭证、结账、往来核销、改期 | 凭证/账务界面 |
| 审核人 | 批准/驳回单据与凭证 | 审批流 |
| 出纳 | 现金/银行收付、银企对账、票据收付 | 资金界面 |
| 往来会计 | 发票核销、对账差异调整、账龄催收 | 往来界面 |
| 财务负责人/审计 | 结账审批、报告导出、审计追溯 | 报表/审计 |
| 系统管理（异常处理角色） | 权限、账套期间修复、异常改期/反结 | 管理端 |

## 三、业务分类（按业务语义）

### 3.1 记账与期间（S1/S2 主轴）

## 四、核心用例（SC，P0 详细卡）

### UC-1（=SC-P0-1）：凭证生成与过账
```
用例编号：UC-1；参与者：会计；前置：单据已审核、期间未结
基本流程：
  1. 会计打开待生成凭证单据
  2. 系统按凭证模板/科目映射生成凭证分录（借=贷、科目合法）
  3. 会计提交→审核
  4. 过账：分录写入账簿、更新科目余额
  5. 系统确认"已过账"，单据与凭证打上过账标记
后置：凭证过账、余额更新、可被报表读取
异常：借贷不平→拒绝；科目/核算维度非法→拒绝；期间已结→禁止过账
```

### UC-2（=SC-P0-2）：期末结账与期间封闭
```
用例编号：UC-2；参与者：财务负责人；前置：本期间业务基本完成、账核对
基本流程：
  1. 会计做结转（成本结转/损益结转→生成结转凭证）
  2. 系统校验：前序期间已结、本期期末平衡
  3. 结账：期间状态→已结，期间内数据锁定
  4. 系统确认"已结账"
后置：本期不可再改；可开下期
异常：未结转/账不平→阻止结账；已结后又需改→走反结/改期(补偿通道)，需权限
```

### UC-3（=SC-P0-3）：往来核销与对账
```
用例编号：UC-3；参与者：往来会计；前置：存在未核应收/应付与收付款
基本流程：
  1. 会计选择应收/应付明细与收款/付款单
  2. 系统执行核销匹配（金额/单据合法性校验）
  3. 产生核销记录；往来余额减少
  4. 对账：比对账面与对方/银行 → 差异登记并调整
后置：往来已(部分)核销；差异可追溯
异常：超额核销→拒绝；重复核销→拒绝；核销不足→部分核销标记
```

## 五、业务规则汇总（明细在 DA4）
| 规则编号 | 规则内容 | 约束级别 | 证据 |
|---|---|---|---|
| BR-01 | 凭证必须借贷平衡方可过账 | MUST | E-SRC: 平台过账校验（机制级，运行未证 U-DA0-2） |
| BR-02 | 仅"已结"的前序期间可作为本期前置 | MUST | E-SRC: AdjustPeriodServiceHelper(期间查询门面) + 平台机制推断（结账写入口 U-DA0-5） |
| BR-03 | 已结期间内数据一般禁止修改；改动走改期/反结补偿通道 | MUST | 机制推断（结账写入口 U-DA0-5；强制程度 U-DA4-2） |
| BR-04 | 核销金额不得超过未核余额 | MUST | E-SRC: MatchServiceHelper（推断支持） |
| BR-05 | 结账需要先完成结转（未结转不得结账） | SHOULD | 推断（登记 U-DA4-1） |
