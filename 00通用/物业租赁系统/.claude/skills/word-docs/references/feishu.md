# 飞书文档规范

飞书文档不支持自定义字体，靠**结构和块**取胜。输出为 Markdown（用户粘贴到飞书后自动转换为对应的块），并遵循以下习惯。

## 结构

- 标题层级最多用到 H3；H1 只做文档名，正文从 H2 开始
- 结论先行：文档开头用一个引用块或高亮块放「TL;DR / 核心结论」（3 条以内）
- 长文档在开头列一个简短目录（飞书也可开启自动目录，提醒用户即可）

## 块的用法

| 场景 | 用法 |
|---|---|
| 核心结论、风险提示 | 高亮块（Markdown 中用 `> ⚠️ ...` / `> 💡 ...`，粘贴后建议转高亮块） |
| 数据 | 表格；金额右对齐做不到时，统一格式（千分位 + 单位写进表头） |
| 流程/审批链 | 有序列表，每步一行：`审批人 → 时限 → 通过条件` |
| 待办、跟进项 | 任务列表 `- [ ]`，写明责任人和截止日 |
| 附录、长解释 | 提醒用户粘贴后可折叠（折叠块），Markdown 中先用 H3 分节 |

## 财务内容习惯

- 每个数据表上方一句话说明口径（期间、单位、含税与否）
- 用 emoji 做状态标记且全文统一：✅ 完成 / 🟡 进行中 / 🔴 风险，不混用其他
- @人 和 #日期# 是飞书原生能力，文中用「@张三」「7 月 25 日前」占位并提醒用户替换为真实提及
- 表格列数控制在 6 列以内，超过就拆表或转纵向

## 交付方式

生成 `.md` 文件交给用户，并附一句粘贴提示：在飞书文档中直接粘贴 Markdown 内容即可自动转换；高亮块和折叠块需粘贴后手动转换。
