# 短期租赁豁免详解：为什么"≤12 个月"就可以不算未确认融资费用

> 本文回答一个问题：**12 个月明明就是一年，为什么准则说"不用算"？**
> 全部结论都标了代码依据（Cosmic `InterestDetailGenerator` / `LeaseContractCal` / `LeaseContractValidator` 等），不是教科书转述。

---

## 0. 一句话答案

> **豁免掉的不是利息，是"把利息拆出来单独核算"这套动作。**

12 个月的租赁照样有融资成分（下面例子里是 279.25 元），准则允许你不折现、不挂"未确认融资费用"、不在表内列负债，**把每期租金直接当租赁费用**——利息"留在租金里一起进损益"了。

代价是：费用的**确认节奏**不再精确配比（不再是前重后轻的利息曲线），换来的是**成本效益**和**可比性**。

---

## 1. 断崖有多陡：12 个月 vs 13 个月

同样条件（每月 1000 元、年折现率 4.5%），只差一个月：

| | 12 个月（可豁免） | 13 个月（不豁免） |
|---|---:|---:|
| 付款合计 | 12 000.00 | 13 000.00 |
| 使用权资产 / 租赁负债（表内） | **0** | **12 719.34** |
| 未确认融资费用（利息池） | **0** | **280.66** |
| 每月费用确认方式 | 租金 1 000 直接进费用 | 折旧 + 利息（前重后轻） |
| 要不要出摊销计划 | 不需要 | 需要（月度摊销表） |

**经济实质只差 8.3% 的付款额，账务却多出一整套资产负债和摊销表。** 这就是明线规则的代价——标准接受了这个突兀，换来"可操作、可审计、可比较"。

## 2. 准则边界（两个独立的门槛，别混）

| 门槛 | 判断标准 | 常见误区 |
|---|---|---|
| **短期租赁** | 租赁期 **≤ 12 个月**，**且不含购买选择权** | 以为"12 个月 = 一个会计年度"；忽略免租期和续租选择权 |
| **低价值资产租赁** | 标的资产价值较低（按**全新资产价值**判断，实务量级常提 **5 万人民币 / 5000 美元**） | 以为是"租金小"；其实是**资产价值**小（如笔记本电脑、小打印机），与租期无关 |

四条配套规则（很容易被忽略）：

1. **这是"权利"不是"义务"**：准则说的是"**可以**选择不确认"。企业完全可以对所有租赁都资本化——dczh 现在就是这么做的，**并不违反准则**。
2. **必须按租赁资产类别一致适用**：不能挑合同——"这一类都用豁免、那一类都不用"，防止用豁免调节报表。
3. **要在附注披露**：短期租赁费用 / 低价值资产租赁费用要与折旧、利息、租金支出等分开披露。
4. **两条门槛互不替代**：一台 3 万元设备租 3 年 → 不满足"低价值"，也不满足"短期" → **必须资本化**。

## 3. "12 个月"到底怎么数（工程实现最容易错的地方）

### 3.1 准则侧要点

| 要点 | 正确做法 | 典型错误 |
|---|---|---|
| 判断对象 | **租赁期**，不是付款期数 | 只数付款次数（付 12 次 ≠ 租期 12 个月） |
| 免租期 | **计入**租赁期 | 免租 2 个月 + 租 10 个月 → 实际 12 个月（仍可豁免）；若只算 10 个月就错了 |
| 续租选择权 | 若**合理确定会行使** → 计入 | "12 个月 + 肯定续的 6 个月" = 18 个月 → **不豁免** |
| 购买选择权 | **有则一律不豁免**（无论多短） | 以为租 6 个月就一定能豁免 |
| 判断时点 | **起租日**（IFRS 16 §5 明确 "at the commencement date"） | 在签订日或期末判断 |
| 边界 | 12 个月**含本数**；12 个月 + 1 天 → 不豁免 | 用"日历月"近似导致差一天差一套账 |
| 与会计年度无关 | 2026-03-01 至 2027-02-28 也是 12 个月 | 以为"跨年就不行" |

### 3.2 Cosmic 的具体实现（代码事实）

**判定入口** `LeaseContractCal.setIsExempt:82-91`：

```java
setIsExempt(wrapper) {
    initConfirmDate = wrapper.getValue("initconfirmdate");   // = max(起租日/免租期起租日, 首次执行日)
    leaseEndDate    = wrapper.getValue("leaseenddate");
    monthRoundUp    = 系统参数 leasemonthroundup（默认 false）
    if (initConfirmDate != null && leaseEndDate != null
        && DateUtil.getDiffMonthsByLocalDate(initConfirmDate, leaseEndDate, true, monthRoundUp) <= 12) {
        wrapper.setValue("isexempt", TRUE);
    } else {
        wrapper.setValue("isexempt", FALSE);
    }
}
```

四个值得注意的实现选择：

1. **判定基准是 `initconfirmdate`，不是 `leasetermstartdate`**。而 `initconfirmdate = max(起租日或免租期起租日, 首次执行日)`（`setInitConfirmDate:55-69`，首次执行日来自系统参数 `firstexecday`，默认 2021-01-01）→ 对**存量合同**，判定用的是"**从首次执行日起的剩余租期**"，而不是合同原始租期。这与折现起算日口径一致（同一套日期基准贯穿全文）。
2. **月数差有两个开关**：`getDiffMonthsByLocalDate(a, b, /*向上取整*/ true, /*月末进位*/ monthRoundUp)`，其中 `monthRoundUp` 由系统参数 **`leasemonthroundup`** 控制（默认 `false`）。这就是标准里"12 个月怎么数"落到系统里的实现方式——**用参数化取整规则处理"月中起租、跨月末"这类边界**，而不是硬编码。
3. **同一套规则算 `leasemonths`**（`setLeaseMonths:43-53`）：`leasestartdate → leaseenddate` 的月数，同样是 `getDiffMonthsByLocalDate(..., true, monthRoundUp)` → 合同列表上的"适用租赁期（月）"和豁免判定同源，不会出现"列表显示 12 个月、系统判成 13 个月"。
4. **`isexempt` 是落库字段**（`FaLeaseContract.IS_EXEMPT = "isexempt"`，第 84 行），在合同生成时写入（`LeaseContractGenerator:120` 调 `setIsExempt`），之后全系统读这个标记。

**配套校验（`LeaseContractValidator`）**——把口径焊死在录入环节：

| 校验 | 位置 | 规则 |
|---|---|---|
| 期限与豁免互斥 | `:459-463` | 豁免合同若"适用租赁期（月）"> 12 → **报错**："不能设为豁免合同" |
| 折现率必填 | `:407-411` | **非**豁免才要求年折现率 > 0、日折现率 > 0 |
| 锁定字段 | `:595-643`（`validateLockedFields4Exempt`） | 豁免合同**不允许**录入：年折现率、日折现率、租赁负债原值、租赁负债现值、本年累计利息……（必须为 0） |
| 财务信息免检 | `:519-523` | 豁免合同**跳过**全部财务信息校验，只跑锁定字段校验 |
| 负债与付款计划 | `:757-760` | 豁免合同**跳过**"负债原值 vs 付款计划"校验 |
| 付款规则 | `:649` | **非**豁免才要求"付款规则不能为空"→ **豁免合同可以没有付款规则** |
| 存量合同判定 | `LeaseUtil.isStockContract:182-184` | `leasetermstartdate < 2021-01-01 && !isExempt` → **豁免合同永远不算存量合同**，因此不需要过渡方案 |
| 终止校验 | `TerminationValidator:144,179` | `!isExempt && assetQtyCreate > 0` 才校验 → 豁免合同不受"已生成资产"约束 |
| 折现率计算 | `LeaseContractCal.setDiscountRate:100` | `if (isExempt) return;` → **豁免合同直接跳过折现率计算** |

> 这套设计的意思很清楚：**豁免合同在数据层面就被"清空"了**——折现率、负债、利息、累计值全部为 0，系统不允许你往豁免合同里塞这些数，从源头杜绝"半豁免"状态。

**豁免法**（只有一条线）

```
每月计提租金：
  借：管理费用 / 销售费用 —— 租赁费        1 000.00
      贷：银行存款 / 其他应付款              1 000.00

```

**资本化法**（三条线）

```
① 起租日初始确认：
  借：使用权资产                        11 720.75
      未确认融资费用                       279.25          ← 轧差项
      贷：租赁负债（原值）                          12 000.00

② 每月计提折旧（11 720.75 / 12）：
  借：管理费用 / 制造费用 —— 折旧费         976.73

③ 每月计息并付款（以 1 月为例）：
  借：财务费用 —— 利息支出                    42.48
      租赁负债（原值）                      1 000.00
      贷：未确认融资费用                              42.48     ← 利息池被"消耗"
```

### 4.3 报表与指标影响

| 维度 | 豁免法 | 资本化法 |
|---|---|---|
| 资产负债表 | 无使用权资产、无租赁负债 | 首日负债 11 720.75（占年租金 **97.7%**），逐月递减 |
| 资产负债率 | 不受影响 | 上升（对已高杠杆企业敏感） |
| 利润表节奏 | 全年均等 1 000 | 前重后轻（首月 1 019、末月 980） |
| EBITDA | **低**（租金全额在费用里） | **高**（折旧、利息被排除在 EBITDA 外）→ 这也是很多企业倾向资本化的原因 |
| 现金流量表 | 全部进"经营活动" | 支付租金分拆：本金 → **筹资**；利息 → 经营或筹资（政策可选） |
| ROI / 资产周转率 | 分母小、比例好看 | 分母大、比例难看 |
| 税会差异 | 与税法接近（税法不认资本化） | 需要做纳税调整 |

## 5. 豁免在 Cosmic 里"到底做了什么"（代码级）

### 5.1 分派点

`InterestDetailGenerator.generateByLeaseContract:87-93`：

```java
boolean isExempt = leaseContract.getBoolean("isexempt");
if (isExempt) return this.generateForExemptContract(leaseContract);
return            this.generateForNotExemptContract(leaseContract);
```

**两条完全独立的路径**，豁免合同根本不进入折现/计息算法。

### 5.2 豁免路径生成了什么

`generateForExemptContract:155-199`：

```java
interestDetail.set("dailyrate", BigDecimal.ZERO);            // ← 整单日利率 = 0
while (rowDate <= detailEndDate) {
    if (amountMap.containsKey(dateStr)) {                    // ← 只在"有付款的日期"建行！
        row.set("beginbalance",  ZERO);
        row.set("leaseliabpay",  amount);                    // ← 只有付款额
        row.set("leaseliabint",  ZERO);                      // ← 利息恒为 0
        row.set("endbalance",    ZERO);                      // ← 余额恒为 0
        row.set("realdailyrate", ZERO);
        row.set("amortizationperiod", ...);                  // ← 仍然挂摊销期间
    }
    rowDate = addDay(rowDate);
}
```

对比非豁免路径（`:123-151`，**每天一行**、有余额有天数）：豁免合同**逐日明细被压缩成"付款日一行"**，所有余额/利息列清零。

### 5.3 付款额怎么来（两种模式，`getLeaseLiabPayAmountMapForExemptContract:268-338`）

| 摊销方案 | 行为 | 代码 |
|---|---|---|
| **schema A** | 按**实际付款日、实际金额**逐条列示（只取会计分类 `A` 类付款） | `:292-296` |
| **schema B** | **把租赁付款总额按自然月在租赁期内平均分摊**（从 `leasetermstartdate` 逐月递推，受 `leaseenddate` / `depremonths` 限制），**尾差落最后一期** | `:304-336` |

schema B 就是**准则要求的"直线法"**落地：

```java
tempAmount = unpaidrentSum / payTimes;                       // 平均
sumAmount  = tempAmount × (payTimes − 1);
tailDiff   = unpaidrentSum − sumAmount;                      // 尾差
amMap.put(最后一期, tailDiff);                                // 尾差落最后一期
```

### 5.4 豁免合同仍然生成 / 不再生成什么

| 产出物 | 豁免合同 | 依据 |
|---|---|---|
| 利息明细 `fa_interest_detail` | **生成**（仅付款日行，利息 0） | `generateForExemptContract` |
| 月度结算单 `fa_lease_rent_settle` | **生成**（按月汇总租金，`interestSum` 恒 0，`interestDays` 不累加） | `RentSettleGenerator.generateByInterestDetail:119-149`（`:141 if (latestData && !isExempt) ++interestDays;`） |
| 负债余额表 `fa_lease_debit_balance` | **不生成** | `RentSettleGenerator.getNotExemptLeaseContract:91-100`、`:181-184`（按 `isexempt=false` 过滤） |
| 摊销成本报表 | **排除** | `FaAmortisedCostRptHelper:170`：`QFilter("isexempt", "=", FALSE)` |
| 终止处理 | **跳过** | `LeaseTerminationHandler:158-159, 257-258`；`LeaseUndoTerminationHandler:169` |
| 变更处理 | 有专门分支 | `LeaseChangeHandler:238, 562-563` |
| 冲销补行 | 仅在 **豁免 + schema B** 时执行 | `InterestDetailGenerator:496-505` |
| 付款规则 | **可以为空** | `LeaseContractValidator:649` |

一句话：**豁免合同只保留"付款 + 按月费用化"这两件事**，负债、利息、余额表、摊销报表全部不参与。

## 6. 为什么标准要开这个口子

| 理由 | 说明 |
|---|---|
| **成本效益** | 短期租赁多为小额、高频、笔数多（场地、展会、临时工位）。逐日折现 + 摊销 + 建卡，工作量远大于信息增量 |
| **信息重要性** | 租期 ≤ 12 个月 → 负债**全部落在流动负债区间**（一年是流动/非流动的分界），对长期偿债能力、资产负债结构的影响本来就小 |
| **可比性** | 明线（12 个月 / 低价值）让不同企业、不同期间的处理**可比较、可预期**，避免"金额较小或期限较短"这类主观判断 |
| **可审计** | 有硬门槛就能程序化校验（Cosmic 就是这么做的：`isexempt` 字段 + 录入即锁定 + 报表过滤） |

**明线的代价**：12 个月与 13 个月的账务断崖（第 1 节）。这和税法里"小微 300 万""一次性扣除 500 万"是同一类设计——接受突兀，换取可执行。

## 7. dczh 的现状与最小改造清单

### 7.1 现状（诚实修正前面的说法）

dczh **没有豁免概念**：所有合同一律走折现 + 摊销 + 计划生成。这在准则下**是允许的**（等于"选择不使用简化处理"），但：

1. **与 Cosmic 口径不一致**：同一批合同在两侧做出来，一个进表、一个不进表，无法对账；
2. **多做很多无用功**：小额短租合同也生成使用权资产、租赁负债、月度摊销计划；
3. 若业务上确实存在大量短租，**报表会凭空多出一堆不重大的资产负债**，也让财务解释成本上升。

### 7.2 最小实现清单（如果要做）

| # | 事项 | 具体内容 |
|---|---|---|
| 1 | **字段** | `isexempt`（豁免标记）、`lease_month_count`（适用租赁期月数）、`has_purchase_option`（购买选择权）、`asset_class`（资产类别，用于"按类别一致适用"）、`low_value_flag`（低价值资产） |
| 2 | **判定** | 起租日判断：`租赁期月数 ≤ 12 且无购买选择权`；租赁期需**含免租期**、含"合理确定行使"的续租期；月数取整规则参数化（对齐 Cosmic 的 `leasemonthroundup` 双开关） |
| 3 | **旁路** | 计算入口按 `isexempt` 分流：**不折现、不计息、不生成负债/未确认融资费用**；租金按直线法按月分摊（尾差落末期）或按实际付款日；`daily_rate = 0`、余额列恒 0 |
| 4 | **校验** | 豁免合同禁止录入折现率/负债/累计利息（对齐 `validateLockedFields4Exempt`）；非豁免必须有折现率与付款规则；豁免可放宽付款规则必填 |
| 5 | **下游过滤** | 负债余额类报表、摊销成本类报表、终止/变更处理，都要**按 `isexempt` 过滤或跳过** |
| 6 | **披露** | 短期租赁费用、低价值资产租赁费用单独披露（Excel 导出模板加两列/两行） |
| 7 | **一致性守卫** | 同一合同**改租期导致跨过 12 个月边界**时，必须强制重算/重判（dczh 已有"初始单变更 → 测算与计划失效"的联动机制，可直接复用） |

> ⚠️ 注意 dczh 与 Cosmic 的**免租期口径不同**：dczh 的 `freeRentPeriod` 支持**小数**（按单位天数折算），Cosmic 是按月取整 + 参数化进位。做豁免判定时，"免租期怎么折算成月"必须先对齐，否则会出现"12 个月 vs 12.5 个月"的边界分歧。

## 8. 常见坑清单（做题/做需求时最容易踩）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 把"付 12 次款"当"租期 12 个月" | 判断对象是**租赁期**（含免租期） |
| 2 | 忘记免租期计入租期 | 免租 2 个月 + 租 10 个月 = **12 个月**，仍可豁免 |
| 3 | 忽略续租选择权 | "合理确定会行使"的续租期必须加上，很可能直接超 12 个月 |
| 4 | 以为有购买选择权还能豁免 | **有购买选择权一律不豁免** |
| 5 | 12 个月 + 1 天 | 严格按天判断，多一天就不豁免（别用"约等于一个月"） |
| 6 | 在签订日/期末判断 | 应在**起租日**判断 |
| 7 | 以为跨年就不行 | 2026-03-01 ～ 2027-02-28 也是 12 个月，与会计年度无关 |
| 8 | 混合适用 | 必须**按资产类别一致**适用，并披露 |
| 9 | 豁免后又按资本化记账 | 用了豁免就不确认负债和折旧，费用按租金直线法 |
| 10 | 漏掉下游联动 | 明细表、结算单、余额表、摊销报表、终止/变更处理都要按标记分流（见 5.4） |
| 11 | 存量合同的判断基准搞错 | Cosmic 用 `initconfirmdate`（含首次执行日），对新签合同等价于起租日，对存量合同等于"剩余租期" |
| 12 | 把"低价值"理解成"租金低" | 低价值看**资产全新价值**（量级 5 万），与租金、租期都无关 |

## 9. 一页速查

| 问题 | 答案 |
|---|---|
| 12 个月有融资成分吗？ | **有**（示例 279.25 元），豁免只是允许你不单独核算 |
| 豁免掉的是什么？ | 折现、负债确认、利息拆分与摊销——**整套资本化动作** |
| 总额会变吗？ | **不会**：豁免法 12 000 = 资本化 11 720.75 + 279.25 |
| 变的是什么？ | **确认节奏**（均匀 vs 前重后轻）、**报表科目**（费用 vs 折旧＋利息）、**是否进表** |
| 必须豁免吗？ | **不必**，是政策选择；但必须按资产类别一致适用并披露 |
| 系统怎么实现？ | 一个 `isexempt` 标记 + 一条**完全独立的计算路径**（Cosmic 的做法），外加上下游过滤 |
| dczh 现在？ | 一律资本化（合规），但与 Cosmic 口径不一致，且短租场景成本高 |

## 10. 科目与报表视角：豁免法与资本化法的科目地图

> 前面的差异（是否折现、是否摊销）落到账上就是一句话：**该出现的科目出不出、金额多少、报表放哪儿。**
> 四层结构（概念 → 科目 → 报表 → 系统字段）的完整说明见《从租户角度的租金入表逻辑》§3.3.7～§3.3.8。

### 10.1 科目地图：哪些科目"消失"了

| 会计科目 | 豁免法（短期／低价值） | 资本化法 |
|---|---|---|
| 使用权资产 | — **不确认** | 借：负债现值 ＋ 初始直接费用 ＋ 预付租金 ＋ 复原成本现值 − 租赁激励 |
| 使用权资产累计折旧 | — **不提折旧** | 贷方逐期计提（直线法） |
| 租赁负债—租赁付款额 | — **不确认** | 贷：付款总额（原值） |
| 租赁负债—未确认融资费用 | — **不确认**（这就是"不算未确认融资费用"的准确含义） | 借：差额（利息池） |
| 财务费用—利息费用 | — **不确认**（利息仍在租金里，只是不单独核算） | 逐期摊销（借） |
| 管理费用／销售费用／制造费用—租赁费 | 每期租金**全额**计入 | — 不使用（由折旧＋利息替代） |
| 银行存款 | 付款时冲减 | 付款时冲减（借租赁付款额／贷银行存款） |

### 10.2 分录对照（12 期 × ¥1,000，数字见本文第 4 节）

**豁免法**——只有一笔，全年一致
```
每月：借 管理费用—租赁费           1,000.00
          贷 银行存款                        1,000.00
```

**资本化法**——三笔并行
```
起租日：借 使用权资产               11,720.75
            借 租赁负债—未确认融资费用    279.25
            　贷 租赁负债—租赁付款额            12,000.00
每月：  借 管理费用—使用权资产折旧     976.73
            　贷 使用权资产累计折旧                  976.73
        借 财务费用—利息费用            42.48        ← 逐月递减
            　贷 租赁负债—未确认融资费用                42.48
        借 租赁负债—租赁付款额        1,000.00
            　贷 银行存款                         1,000.00
```

两法**全年费用相同（¥12,000）**，差别在科目集合与确认节奏（详见 4.1、4.2）。

### 10.3 列报与披露

| 项目 | 豁免法 | 资本化法 |
|---|---|---|
| 资产负债表 | 无使用权资产、无租赁负债 | 使用权资产（净额）＋ 租赁负债（现值，分流动／非流动） |
| 利润表 | 管理费用—租赁费（均匀） | 折旧 ＋ 财务费用—利息（前重后轻） |
| 现金流量表 | 付款额**全部进经营活动**（CAS 21 第五十三条） | 偿还本金与利息进**筹资活动**；简化处理的短期／低价值租赁付款额进经营活动 |
| 附注披露 | **短期租赁费用、低价值资产租赁费用单独披露**（第五十四条） | 各类使用权资产余额与折旧、租赁负债利息费用、未折现付款额到期分析、总现金流出等 |

> IFRS 16 与 CAS 21 的差别只有一处：IFRS 16 允许租赁负债利息在"经营活动或筹资活动"之间选择列报；CAS 21 明确本金与利息均计入筹资活动。

### 10.4 系统落地与对账断言

| 事项 | 要求 |
|---|---|
| 建卡 | 豁免合同**不建固定资产卡片**、不生成负债类凭证 |
| 凭证 | 只生成费用凭证（借 租赁费／贷 银行存款） |
| **对账断言** | 豁免合同不应出现 `使用权资产／使用权资产累计折旧／租赁负债／未确认融资费用` 的任何余额——建议做成定时对账规则 |
| 报表过滤 | 负债余额类、摊销成本类报表按豁免标记过滤（见 5.4） |
| 边界变更 | 租期／续租选择权变化导致**跨过 12 个月边界**时必须重判：由豁免切到资本化（或反向），历史已入账部分按会计估计变更处理 |

### 10.5 一句话

> 豁免的准确含义是"**科目不落地、费用走租金**"：没有使用权资产、租赁负债、未确认融资费用三个科目，也没有折旧与利息两条线；
> 换来的是"费用按租金直线法、现金流进经营活动"。**利息仍然存在（本文示例 ¥279.25），只是不再单独核算。**
