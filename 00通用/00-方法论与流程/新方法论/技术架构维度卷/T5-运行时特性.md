# T5 运行时特性

> **架构维度 5**：业务系统在运行时的非功能需求——性能、可用性、可观测性、可恢复性。

---

## 1. 维度目标

**在 T5，分析者要回答以下问题：**

- 业务系统的**性能目标**是什么？
- 业务系统的**可用性目标**是什么？
- 业务系统的**可观测性**如何设计？
- 业务系统的**可恢复性**如何保证？
- 不同业务场景的运行时需求有何不同？
- 如何在业务复杂度和运行时需求之间做取舍？

---

## 2. 运行时需求的 4 个维度

### 维度 1：性能（Performance）

| 指标 | 描述 | 业务影响 |
|------|------|---------|
| **响应时间** | 从请求到响应的时间 | 用户体验 |
| **吞吐量** | 单位时间处理的请求数 | 业务承载能力 |
| **并发数** | 同时处理的请求数 | 业务峰值承载 |
| **资源利用率** | CPU、内存、IO 使用率 | 成本效率 |

### 维度 2：可用性（Availability）

| 指标 | 描述 | 业务影响 |
|------|------|---------|
| **可用率** | 系统正常运行时间比例 | 业务连续性 |
| **MTTR** | 平均恢复时间 | 故障影响时长 |
| **MTBF** | 平均故障间隔时间 | 故障发生频率 |
| **故障率** | 系统故障的频率 | 业务稳定性 |

### 维度 3：可观测性（Observability）

| 指标 | 描述 | 业务影响 |
|------|------|---------|
| **日志覆盖率** | 关键操作的日志记录比例 | 问题定位能力 |
| **指标完整性** | 关键指标的覆盖程度 | 性能分析能力 |
| **链路追踪** | 全链路追踪的覆盖程度 | 问题定位能力 |
| **告警及时性** | 告警的及时程度 | 问题响应速度 |

### 维度 4：可恢复性（Recoverability）

| 指标 | 描述 | 业务影响 |
|------|------|---------|
| **RTO** | 恢复时间目标 | 业务中断时长 |
| **RPO** | 数据恢复点目标 | 数据丢失量 |
| **备份频率** | 数据备份的频率 | 数据安全性 |
| **故障转移** | 故障转移的速度 | 业务连续性 |

## 3. 业务场景与运行时需求

### 3.1 不同业务场景的运行时需求

| 业务场景 | 性能要求 | 可用性要求 | 可观测性 | 可恢复性 |
|---------|---------|----------|---------|---------|
| **支付交易** | 极高（< 100ms）| 极高（99.99%）| 必须 | 必须（RPO=0）|
| **实时库存** | 高（< 500ms）| 高（99.9%）| 必须 | 必须 |
| **订单查询** | 中（< 1s）| 中（99.5%）| 推荐 | 推荐 |
| **批量处理** | 低（无严格要求）| 低（99%）| 推荐 | 可选 |
| **日志记录** | 低（异步）| 低（99%）| 必须 | 可选 |
| **报表生成** | 低（可延迟）| 低（99%）| 推荐 | 可选 |

### 3.2 不同业务领域的运行时需求

| 业务领域 | 典型性能 | 典型可用性 | 典型一致性 |
|---------|---------|----------|---------|
| **银行核心** | < 200ms | 99.99% | 强一致性 |
| **电商交易** | < 500ms | 99.9% | 最终一致性 |
| **社交应用** | < 1s | 99.9% | 最终一致性 |
| **IoT** | < 5s | 99% | 最终一致性 |
| **游戏** | < 100ms | 99.9% | 强一致性 |

## 4. 性能设计与优化

### 4.1 性能优化的基本原则

| 原则 | 描述 |
|------|------|
| **测量先行** | 先测量，再优化，避免过早优化 |
| **热点优先** | 优化热点，不要优化非热点 |
| **性价比优先** | 优先优化投入产出比高的部分 |
| **分层优化** | 从前端到后端到数据库分层优化 |

### 4.2 性能优化的层次

| 层次 | 优化手段 |
|------|---------|
| **前端** | 缓存、压缩、CDN、懒加载 |
| **网络** | HTTP/2、连接池、压缩 |
| **应用** | 多线程、异步、缓存、连接池 |
| **数据** | 索引、分库分表、读写分离、缓存 |
| **基础设施** | 扩容、CDN、负载均衡 |

### 4.3 缓存策略

| 缓存类型 | 描述 | 适用场景 |
|---------|------|---------|
| **本地缓存** | 进程内缓存 | 不变数据、高频访问 |
| **分布式缓存** | Redis/Memcached | 共享数据、跨进程 |
| **CDN** | 内容分发网络 | 静态资源 |
| **浏览器缓存** | 浏览器本地缓存 | 不变资源 |

### 4.4 异步处理策略

| 策略 | 描述 | 适用场景 |
|------|------|---------|
| **消息队列** | 异步消息处理 | 异步任务、解耦 |
| **定时任务** | 定时批量处理 | 统计报表、数据同步 |
| **多线程** | 并行处理 | 耗时计算 |
| **响应式** | 非阻塞响应 | 高并发 |

## 5. 可用性设计与保障

### 5.1 可用性设计原则

| 原则 | 描述 |
|------|------|
| **消除单点** | 每个组件都有备份 |
| **冗余设计** | 关键组件多副本部署 |
| **故障隔离** | 故障不扩散 |
| **优雅降级** | 部分功能故障时整体可用 |

### 5.2 高可用架构模式

| 模式 | 描述 | 适用场景 |
|------|------|---------|
| **主备** | 一主一备，备机冷备 | 低成本高可用 |
| **主从** | 一主多从，读写分离 | 读多写少 |
| **集群** | 多节点集群，无单点 | 高可用 |
| **多活** | 多机房多活 | 异地容灾 |

### 5.3 故障处理策略

| 策略 | 描述 | 适用场景 |
|------|------|---------|
| **熔断** | 故障时快速失败 | 下游服务故障 |
| **降级** | 非核心功能降级 | 资源不足 |
| **限流** | 限制请求速率 | 流量突增 |
| **隔离** | 故障隔离 | 故障扩散 |

## 6. 可观测性设计

### 6.1 可观测性的 3 个支柱

| 支柱 | 描述 | 工具 |
|------|------|------|
| **日志（Logs）** | 离散的事件记录 | ELK、Loki |
| **指标（Metrics）** | 聚合的数值统计 | Prometheus、InfluxDB |
| **追踪（Traces）** | 请求的完整链路 | Jaeger、Zipkin |

### 6.2 可观测性设计原则

| 原则 | 描述 |
|------|------|
| **业务埋点** | 埋点反映业务语义 |
| **链路追踪** | 完整链路可追踪 |
| **关键指标** | 有明确的业务指标 |
| **告警规则** | 有明确的告警阈值 |
| **仪表盘** | 有业务仪表盘 |

### 6.3 关键业务指标

| 指标类型 | 指标示例 | 说明 |
|---------|---------|------|
| **业务量** | 日订单量、DAU | 业务规模 |
| **转化率** | 下单转化率、支付转化率 | 业务效率 |
| **响应时间** | 接口 P99、页面加载时间 | 用户体验 |
| **错误率** | 接口错误率、JS 错误率 | 稳定性 |
| **可用率** | 系统可用率 | 稳定性 |

## 7. 可恢复性设计

### 7.1 可恢复性设计原则

| 原则 | 描述 |
|------|------|
| **数据备份** | 定期备份，备份可恢复 |
| **故障转移** | 故障时自动或手动转移 |
| **数据恢复** | 有明确的 RTO/RPO |
| **演练** | 定期演练，恢复流程熟练 |

### 7.2 备份策略

| 备份类型 | 频率 | 保留时间 | RPO |
|---------|------|---------|-----|
| **实时备份** | 实时 | 7 天 | RPO≈0 |
| **日备份** | 每日 | 30 天 | RPO≈1天 |
| **周备份** | 每周 | 90 天 | RPO≈7天 |
| **月备份** | 每月 | 1 年 | RPO≈30天 |

### 7.3 故障恢复流程

| 步骤 | 描述 | 责任人 |
|------|------|-------|
| **发现** | 监控/用户发现故障 | 运维/用户 |
| **确认** | 确认故障范围和影响 | 运维 |
| **止损** | 快速止血（降级/限流）| 研发/运维 |
| **定位** | 定位故障根因 | 研发 |
| **修复** | 修复故障 | 研发 |
| **验证** | 验证修复效果 | 研发/测试 |
| **复盘** | 复盘故障原因和教训 | 全员 |

## 8. 运行时需求与业务复杂度的取舍

### 8.1 取舍原则

| 原则 | 描述 |
|------|------|
| **业务优先** | 业务需求优先，非功能需求其次 |
| **性价比** | 非功能需求的投入要匹配业务价值 |
| **分场景** | 不同场景可有不同的非功能需求 |
| **可演进** | 非功能需求可以随业务发展演进 |

### 8.2 取舍矩阵

| 业务复杂度 | 性能要求 | 可用性要求 | 推荐架构 |
|-----------|---------|-----------|---------|
| **低** | 低 | 中 | 单体 + 本地缓存 |
| **中** | 中 | 高 | 分层 + 分布式缓存 |
| **高** | 高 | 高 | 分布式 + 读写分离 |
| **极高** | 极高 | 极高 | 微服务 + 多活 |
