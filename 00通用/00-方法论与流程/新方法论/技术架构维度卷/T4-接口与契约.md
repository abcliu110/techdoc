# T4 接口与契约

> **架构维度 4**：业务系统的对外接口设计——API 稳定性、版本兼容、协议设计。

---

## 1. 维度目标

**在 T4，分析者要回答以下问题：**

- 业务系统的**对外接口**有哪些？
- 接口的**契约**是什么？
- 接口如何保证**向后兼容**？
- 接口如何**版本管理**？
- 接口的**协议设计**是否合理？
- 接口的**变更管理**如何进行？

---

## 2. 接口的类型

### 2.1 接口的分类

| 接口类型 | 描述 | 示例 |
|---------|------|------|
| **同步 API** | 请求-响应模式 | REST API、gRPC |
| **异步消息** | 消息队列模式 | MQ、Event Bus |
| **文件传输** | 批量数据交换 | FTP、SFTP、OSS |
| **数据库共享** | 通过数据库共享数据 | 共享表 |
| **RPC** | 远程过程调用 | Dubbo、Feign |

### 2.2 接口的设计原则

| 原则 | 描述 |
|------|------|
| **接口契约清晰** | 输入、输出、错误码明确 |
| **接口语义稳定** | 同一接口的语义不变 |
| **接口向后兼容** | 新版本兼容旧版本 |
| **接口幂等** | 重复调用结果一致 |
| **接口可观测** | 调用可追踪、可监控 |
| **接口安全** | 鉴权、授权、审计 |

## 3. REST API 设计

### 3.1 REST 约束

| 约束 | 描述 |
|------|------|
| **客户端-服务器** | 客户端和服务器分离 |
| **无状态** | 服务器不保存客户端状态 |
| **可缓存** | 响应可被缓存 |
| **分层系统** | 系统可分层 |
| **统一接口** | 资源通过 URI 标识 |

### 3.2 资源设计

| 操作 | HTTP 方法 | 描述 |
|------|----------|------|
| **创建** | POST | 创建资源 |
| **读取** | GET | 读取资源 |
| **更新全量** | PUT | 更新全量资源 |
| **更新部分** | PATCH | 更新部分资源 |
| **删除** | DELETE | 删除资源 |

### 3.3 API 设计规范

| 规范 | 描述 |
|------|------|
| **URI 命名** | 用名词，不用动词 |
| **路径层次** | 不要超过 3 层 |
| **版本管理** | URL 或 Header 中包含版本 |
| **状态码** | 用标准 HTTP 状态码 |
| **错误格式** | 统一错误响应格式 |
| **分页** | 大结果集需要分页 |

## 4. 接口契约

### 4.1 契约的定义

**接口契约 = 接口的输入 + 输出 + 错误 + 语义**

| 元素 | 描述 |
|------|------|
| **输入** | 请求参数、参数类型、参数约束 |
| **输出** | 响应格式、响应字段、响应类型 |
| **错误** | 错误码、错误信息、错误处理 |
| **语义** | 接口的业务含义、调用前提 |

### 4.2 契约文档

| 字段 | 描述 |
|------|------|
| **接口名称** | 接口的命名 |
| **接口路径** | 接口的 URL |
| **接口方法** | HTTP 方法 |
| **接口描述** | 接口的业务含义 |
| **请求参数** | 参数列表及约束 |
| **响应格式** | 成功响应格式 |
| **错误码** | 错误码列表 |
| **调用示例** | 典型调用示例 |

### 4.3 契约的版本管理

#### 版本策略

| 策略 | 描述 | 适用场景 |
|------|------|---------|
| **URL 路径版本** | `/api/v1/orders` | 简单直观，但改动较大 |
| **Header 版本** | `API-Version: v1` | 干净，但需要客户端配合 |
| **Query 参数版本** | `/api/orders?version=1` | 不推荐，污染 URL |

#### 向后兼容变更

| 变更类型 | 是否兼容 | 说明 |
|---------|---------|------|
| 新增字段 | 兼容 | 旧客户端忽略新字段 |
| 新增可选参数 | 兼容 | 旧客户端不传新参数 |
| 新增接口 | 兼容 | 完全新增 |
| 修改字段名 | 不兼容 | 旧客户端依赖旧名称 |
| 删除字段 | 不兼容 | 旧客户端依赖旧字段 |
| 修改字段类型 | 不兼容 | 旧客户端依赖旧类型 |
| 修改约束 | 不兼容 | 旧客户端可能违反新约束 |

## 7. 接口的反模式

### 反模式 1：接口与实现耦合
- **表现：** 接口暴露了内部实现细节
- **后果：** 内部变化导致接口变化
- **修正：** 接口与实现分离，接口稳定

### 反模式 2：接口过细
- **表现：** 接口粒度太细，调用方需要调用大量接口
- **后果：** 网络开销大、性能差
- **修正：** 按业务场景封装接口

### 反模式 3：接口过粗
- **表现：** 一个接口处理太多业务逻辑
- **后果：** 难以复用、难以演进
- **修正：** 按业务边界拆分接口

### 反模式 4：接口契约不清晰
- **表现：** 接口没有文档，或者文档与实现不一致
- **后果：** 调用方难以使用
- **修正：** 契约文档化，契约测试

### 反模式 5：接口不兼容变更
- **表现：** 频繁破坏向后兼容
- **后果：** 调用方频繁升级
- **修正：** 版本管理，向后兼容
