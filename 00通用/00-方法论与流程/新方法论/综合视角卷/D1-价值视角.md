# D1 价值视角

> **综合视角 1**：从业务价值的视角评估业务——业务值多少？改造收益多少？ROI 如何？

---

## 1. 视角目标

**在 D1，分析者要回答以下问题：**

- 业务的**当前价值**是什么？
- 业务的**改造成本**是多少？
- 业务的**改造收益**是多少？
- 改造的 **ROI** 是多少？
- **何时**应该投入资源？

---

## 2. 价值的 5 个维度

### 维度 1：业务规模价值
**含义：** 业务本身的规模大小。

| 指标 | 描述 |
|------|------|
| **用户规模** | 活跃用户数 |
| **交易规模** | 日/月/年交易量 |
| **营收规模** | 业务产生的营收 |
| **数据规模** | 业务产生的数据量 |

### 维度 2：业务战略价值
**含义：** 业务在组织战略中的位置。

| 指标 | 描述 |
|------|------|
| **战略地位** | 核心业务 vs 辅助业务 |
| **战略阶段** | 投入期 vs 收获期 vs 退出期 |
| **战略协同** | 与其他业务的协同价值 |
| **战略差异化** | 与竞争对手的差异化程度 |

### 维度 3：业务运营价值
**含义：** 业务在日常运营中的重要性。

| 指标 | 描述 |
|------|------|
| **运营频次** | 每日/每周运营动作次数 |
| **运营影响** | 运营动作的影响范围 |
| **运营依赖** | 对运营人员的依赖程度 |
| **运营风险** | 运营错误的影响 |

### 维度 4：业务技术价值
**含义：** 业务对技术体系的支撑价值。

| 指标 | 描述 |
|------|------|
| **技术复用** | 其他业务对本业务的复用程度 |
| **技术示范** | 对其他业务的示范价值 |
| **技术风险** | 业务的技术风险大小 |
| **技术债价值** | 业务的技术债偿还价值 |

### 维度 5：业务生态价值
**含义：** 业务在生态系统中的价值。

| 指标 | 描述 |
|------|------|
| **合作伙伴** | 依赖或被依赖的合作伙伴 |
| **行业地位** | 在行业中的地位 |
| **社会价值** | 对社会的贡献 |
| **合规价值** | 对合规要求的满足程度 |

## 3. 价值的评估方法

### 3.1 业务规模评估

| 规模等级 | 用户规模 | 交易规模 |
|---------|---------|---------|
| **超大规模** | > 1000 万 | > 100 亿/年 |
| **大规模** | 100 万-1000 万 | 10 亿-100 亿/年 |
| **中规模** | 10 万-100 万 | 1 亿-10 亿/年 |
| **小规模** | 1 万-10 万 | 1000 万-1 亿/年 |
| **微规模** | < 1 万 | < 1000 万/年 |

### 3.2 业务战略评估

| 战略定位 | 描述 | 资源投入建议 |
|---------|------|------------|
| **核心战略业务** | 未来 3-5 年的核心增长点 | 高投入 |
| **重要业务** | 当前营收的重要来源 | 中高投入 |
| **常规业务** | 稳定运营的业务 | 中等投入 |
| **边缘业务** | 非核心、可退出的业务 | 低投入或退出 |
| **试点业务** | 探索性业务 | 控制投入 |

### 3.3 业务价值评分

按 5 个维度分别评分（1-10 分），加权求和：

```
业务价值总分 = 业务规模价值 × 0.3 + 战略价值 × 0.3 + 运营价值 × 0.15 + 技术价值 × 0.15 + 生态价值 × 0.1
```

## 4. 改造成本与收益评估

### 4.1 改造成本评估

| 成本类型 | 描述 | 评估方法 |
|---------|------|---------|
| **开发成本** | 代码改造 | 人天估算 |
| **测试成本** | 测试验证 | 测试用例数 × 单个用例成本 |
| **数据迁移成本** | 数据迁移 | 数据量 × 单条迁移成本 |
| **运维成本** | 部署、监控 | 部署次数 × 单次部署成本 |
| **风险成本** | 改造失败的影响 | 业务影响估算 |
| **机会成本** | 改造期间放弃的业务 | 业务价值 × 影响时间 |

### 4.2 改造收益评估

| 收益类型 | 描述 | 评估方法 |
|---------|------|---------|
| **直接收益** | 成本节约、效率提升 | 节约金额 / 提升比例 |
| **间接收益** | 用户体验提升、品牌提升 | 用户满意度调查 |
| **战略收益** | 战略目标推进 | 战略目标达成度 |
| **风险降低** | 减少事故、合规风险 | 事故率降低比例 |
| **能力提升** | 团队能力、系统能力 | 能力提升描述 |

### 4.3 ROI 计算

```
ROI = (改造总收益 - 改造总成本) / 改造总成本 × 100%
```

### 4.4 投资回报期

```
投资回报期 = 改造总成本 / 年均收益
```

## 5. 价值视角的决策原则

### 5.1 价值/成本比原则

| 价值/成本比 | 决策 |
|------------|------|
| **> 5** | 必须改造，资源优先 |
| **3-5** | 建议改造，资源次优先 |
| **1-3** | 可以改造，资源按需 |
| **< 1** | 不建议改造 |

### 5.2 战略优先级原则

即使 ROI 不高，如果是**核心战略业务**，也应该投入资源。

### 5.3 风险权衡原则

如果**不改造的风险**很大，即使 ROI 不高，也应该改造。

## 7. 价值视角的反模式

### 反模式 1：只看规模不看战略
- **表现：** 大规模业务优先，小规模业务靠后
- **后果：** 战略业务被忽视
- **修正：** 规模与战略平衡

### 反模式 2：只看直接收益不看间接收益
- **表现：** 只算能直接变现的收益
- **后果：** 战略价值被忽视
- **修正：** 综合考虑直接和间接收益

### 反模式 3：只看收益不看成本
- **表现：** 决策只基于收益
- **后果：** 改造预算失控
- **修正：** 必须计算完整成本

### 反模式 4：只看短期不看长期
- **表现：** 只算当前周期的回报
- **后果：** 长期价值被低估
- **修正：** 必须计算长期价值

## 8. 价值视角与业务/架构维度的对应

| 价值维度 | 对应的业务层 | 对应的架构维度 |
|---------|------------|--------------|
| 业务规模价值 | L1（业务建模层）| T5（运行时特性）|
| 业务战略价值 | L4（业务演化层）| T1（架构形态）|
| 业务运营价值 | L3（业务流程层）| T2（模块化）|
| 业务技术价值 | L2（业务规则层）| T6（技术债务）|
| 业务生态价值 | L5（业务因果层）| T4（接口与契约）|
