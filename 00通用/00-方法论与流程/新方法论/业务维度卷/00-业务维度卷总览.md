# 业务维度卷

> 从 L1 到 L5 共 5 个分析层次，完整覆盖业务分析的全部深度。
>
> 本卷是**分析操作手册**——在元理论卷的 5 个根本性问题（Q1-Q5）的基础上，给出每个层次的具体分析方法、评价标准和典型案例。
>
> 适用场景：接手遗留系统时的完整分析、设计新业务时的建模参照、评审业务方案时的标准参照。

---

## 写作背景与前置假设

### 本卷的定位
- **元理论卷**回答"**为什么**要这样分析"（5 个根本性问题）
- **本卷**回答"**怎么**分析"（L1-L5 的操作方法）
- **技术架构维度卷**回答"**技术实现**如何映射业务"（T1-T6 的架构原理）
- **综合视角卷**回答"**综合应用**时如何融合三个视角"

### 本卷的前置假设
1. 分析对象是**业务信息系统**（有明确主体、目标、规则、协作、时序、视角）
2. 分析目标是**理解业务**（而非单纯优化系统）
3. 分析者是**有业务背景的人**（能理解业务语义，不只是技术实现）

---

## L1-L5 的层次关系

```
L1 业务建模层
  │  回答：业务由哪些核心概念构成？业务如何运作？
  │  输入：Q1（业务是什么）→ 6要素稳定结构
  │  包含：业务对象分析（静态）+ 业务逻辑分析（动态）
  ↓
L2 业务规则层
  │  回答：业务必须遵守什么规则？
  │  输入：Q3（复杂度来源）→ 规则维度
  ↓
L3 业务流程层
  │  回答：业务如何执行？
  │  输入：Q3（复杂度来源）→ 流程维度
  ↓
L4 业务演化层
  │  回答：业务是如何变成现在这样的？
  │  输入：Q2（业务为何如此）→ 三类成分
  ↓
L5 业务因果层
  │  回答：业务决策背后的业务原因是什么？
  │  输入：Q2（业务为何如此）→ 三类成分 + 历史
```

---

## L1-L5 与元理论卷的对应关系

| 分析层 | 对应的根本性问题 | 核心概念 |
|-------|----------------|---------|
| **L1 业务建模层** | Q1 | 主体、目标、规则、协作、时序、视角 |
| **L2 业务规则层** | Q3（规则维度） + Q4（完整性/一致性） | 显性规则、隐性规则、规则依赖、规则冲突 |
| **L3 业务流程层** | Q3（流程维度） + Q4（一致性/可观测性） | 主流程、变体流、补偿流、对账流 |
| **L4 业务演化层** | Q2 + Q5 | 历史包袱、三类成分、驱动力、临界点 |
| **L5 业务因果层** | Q2 | 业务动因、组织塑形、历史路径依赖 |
