## 0. 已冻结前提

### 0.1 理论四句

1. 归纳的产品是骨架，不是清单
2. 冲突是高价值信号，必须升级
3. 无分型，不出方案
4. 一页压不出来 = 归纳未完成

### 0.2 拍板四项

| # | 议题 | 结论 |
|---|------|------|
| 1 | 核心抽象 | 触及对象身份/生命周期、主关系（含 2 跳+）、不变式、一致性边界、对外能力语义 → 算动核心抽象；只改实现/可靠性/局部策略 → 不算 |
| 2 | 无 DEC 有意设计 | 须同时满足：长期稳定路径 + 可说明当时约束/代价 + 未明显突破原假设；且只能标“推断有意设计” |
| 3 | 一页小样上限 | 维持 5/5/3/2/1；小样是压测工具，正式报告可更长，但必须能压回一页 |
| 4 | 文档形态 | L0 理论核 / L1a 进化执行 / L1b 评估重构执行 / L2 方法卡与样例 |

### 0.3 分层原则

- **L0 求锋**：只放判断主轴与硬法则
- **L1 求硬**：只放可门禁的执行链与产物
- **L2 求全**：方法细则、评分细表、样例、培训材料
- 禁止把 L2 完整性写成 L0/L1 废稿条件

## 6. 跨文档接口（必须写清，否则分层失败）

### 6.1 输入输出

```text
DA0-DA8 / V0-V7
        │
        ▼
      L0 强归纳（每次分析后可先出骨架/小样）
        │
        ├─ 不改核心抽象 ──► L1a 进化 ──► EVO-* ──► 安全修改实施
        │
        └─ 必改核心抽象 ──► L1b 评估重构 ──► REV/ESS/TGT/MIG ──► 安全修改实施
                              │
                              └─ 需要时复用/回喂 EVO-D/E
```

### 6.2 编号归属

| 编号 | 归属 | 谁允许首次产出 |
|------|------|----------------|
| 骨架字段（对象/不变式/…） | L0 产物形态 | L0/L1a/L1b 均可，但形状服从 L0 |
| EVO-D/T/E/U | L1a | 仅 L1a |
| REV/ESS/TGT/MIG/RST/DES-U | L1b | 仅 L1b；禁止从 EVO 直接导出 TGT |
| 方法卡编号（可选 METH-*） | L2 | 不进正式业务结论编号体系 |

### 6.3 复用规则（短版，两边同文）

- EVO-D → 可作 L1b 输入，不改编号含义
- ESS → 可作 L1a 阶段2 输入，须再对 DA 一致性校验
- EVO-E → 可辅助 MIG，须补 L1b 要求的取舍与迁移完整度
- 禁止 L1a 产出 TGT/MIG 主结论
