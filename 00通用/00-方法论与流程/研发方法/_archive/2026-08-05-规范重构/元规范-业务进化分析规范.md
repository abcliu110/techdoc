# 元规范-业务进化分析规范

> **层级**：L1a 业务进化执行规范  
> **定位**：在不改动核心抽象的前提下，把 DA0-DA8 / V0-V7 转换为有证据、可兼容、可验证、可回滚的业务进化结论  
> **读者**：Writer / Reviewer / Fixer / Referee 与人工验收者  
> **上位约束**：`00-强归纳理论核.md`（L0）  
> **配套方法**：`12-方法卡-兼容五查与影子验证.md`（L2，按需加载，不构成默认废稿条件）  
> **版本**：v2.2 | **日期**：2026-08-05

## 0. 一页纸入口

### 0.1 何时使用

使用本规范的前提是：目标可以在既有核心抽象内完成，主要工作属于缺陷修复、可靠性增强、局部能力扩展或兼容性演进。

以下任一成立时，不得继续用本规范直接产出方案，转入《元规范-业务系统设计评估与重构规范》：

- 改变核心对象的身份或生命周期；
- 改变对象间主关系，尤其是 2 跳以上的路由、归属或依赖；
- 改变关键不变式；
- 改变一起成功、失败、过期或回溯的一致性边界；
- 改变业务能力的对外语义。

只改变实现手段、可靠性机制或局部策略，不视为改动核心抽象。

### 0.2 输入、输出与禁止事项

| 类别 | 内容 |
|---|---|
| 必需输入 | L0 理论核、DA0-DA8、DA8 收敛结论 |
| 增强输入 | V0-V7、DEC 卡、SOP-08/09 评审意见、既有 EVO/ESS 产物 |
| 输出 | `EVO-D-*` 缺陷、`EVO-T-*` 相关提炼、`EVO-E-*` 进化方案、`EVO-U-*` 未决项 |
| 禁止 | 无证据归纳、未分型出方案、把修复和重构混写、由本规范直接产出 `TGT-*` 或 `MIG-*` 主结论、直接给出代码级实施 |

### 0.3 最短执行链

```text
前置门禁
  -> 缺陷识别与分型（EVO-D）
  -> 按问题信号做相关提炼（EVO-T）
  -> 候选方案、五查、验证与回滚（EVO-E）
  -> 独立 V-EVO
```

**七项发布门禁**：证据可解析、缺陷已分型、修复/演进/不做不混写、兼容五查完整、不确定项默认有依赖、方案可验证或降级为观察项、V-EVO 独立完成。

## 1. 定位与硬边界

本规范只管“现有架构内该修什么、怎样安全演进”。它不负责重新定义业务本质、目标架构或核心边界，也不产出代码。

| 边界 | 硬要求 | 违反后的处理 |
|---|---|---|
| 事实边界 | 每条结论引用 `{DAx §y}`、`{E-xxx:行号}`、`{U-xxx}` 或等价可解析证据 | 结论作废；新事实先回填上游 |
| 分型边界 | 先按 L0 分型，再决定保护、修复、演进或不做 | 未分型不得进入方案阶段 |
| 架构边界 | 不改变 L0 定义的核心抽象 | 命中则升级 L1b |
| 兼容边界 | 数据、接口、消息、定时任务、配置逐项检查 | 缺查不得发布 |
| 实施边界 | 只产出候选方案、影响、验证和回滚要求 | 代码实施转安全修改规范 |
| 通用边界 | 机制换领域后仍成立 | 领域细节进入执行报告或样例 |

## 3. 核心原则

### 3.1 事实锚定

- 每条 `EVO-D/T/E` 都必须有可解析来源；方案必须回指其目标缺陷或机会。
- 新发现但上游未记录的事实，先回填 DA 产物或登记为 `EVO-U-*`，再决定是否使用。
- 经验、通用最佳实践和外部案例只能作为候选启发，不能冒充项目事实。

### 3.2 缺陷分型

先使用 L0 的四对象分型，再映射到行动：

| L0 分型 | L1a 行动 |
|---|---|
| 不变式 | 保护；方案必须证明不会破坏 |
| 有意设计 | 已确认则保留并记录触发条件；无 DEC 仅可标“推断有意设计” |
| 可靠性缺陷 | 在既有核心抽象内修复 |
| 错误抽象 | 停止在 L1a 出方案，升级 L1b |

能力缺口不是独立的架构结论。先判断它是未交付、可靠性问题，还是核心抽象无法承载；分别对应补齐、修复或升级 L1b。

同一问题含多种成分时必须拆项。禁止用一个 `EVO-E-*` 同时包装可靠性修复与核心模型重画。

### 3.3 兼容契约

每个 `EVO-E-*` 至少完成五查；“没有发现”不等于“没有依赖”，未知默认按有依赖处理。

| 维度 | 主文最低要求 | 满足判定（V-EVO 按此检查） |
|---|---|---|
| 数据 | 列出受影响表/字段/枚举和历史数据处理结论 | 已明确历史数据的回填/迁移/失效结论，或登记 `EVO-U-*`（不得以"未知"当"无影响"） |
| 接口 | 列出受影响契约及已知调用方 | 已列出调用方范围，或显式声明"无法穷举并已登记"，未以"未知"当"无依赖" |
| 消息 | 列出 Topic/事件及已知消费者 | 已列出消费者及重试/死信语义，重复消费影响已判定 |
| 定时任务 | 列出任务及任务间依赖 | 已确认调度/补偿任务是否受影响，任务间依赖已说明 |
| 配置 | 列出参数、开关、模板和差异化配置 | 已确认作用域与回滚值，多租户/环境差异已列出 |

需要量化索引、迁移量、不可控调用方、重试、幂等、并发或灰度时，按信号加载 L2 方法卡；L2 深表不要求对无关维度机械填满。

### 3.4 可验证性与回滚

- 每个方案必须定义可观察的基线、目标指标、成功标准、失败标准与停止/回滚条件。
- 按风险选择影子模式、A/B 对比、功能开关或现有等价机制；不强制为低风险变更引入新基础设施。
- 无法形成可信验证的方案降级为观察项，进入 `EVO-U-*`，不得标为可实施结论。
- 涉及数据、契约或消息演进时必须给出兼容期与前向修复/回滚路径；若物理回滚不安全，必须明确只能前向修复。

## 4. 三阶段执行

### 4.1 阶段 1：缺陷识别 -> `EVO-D-*`

| 项 | 要求 |
|---|---|
| 输入 | DA8 风险与未决项、DA4 规则缺口、DA7 决策代价、V0-V7 问题 |
| 动作 | 核对证据 -> 拆分问题 -> L0 分型 -> P0-P3 严重度 -> 去重与冲突升级 |
| 输出字段 | 编号、问题陈述、证据、影响、分型及理由、严重度、处理方向、未知项 |
| 阶段门禁 | 每项有证据和分型理由；冲突未仅并列；P0/P1 有处理方向，允许“不做/待确认” |

严重度：P0 为业务阻断或数据损坏；P1 为能力缺失或显著可靠性/兼容风险；P2 为可持续运行但代价高；P3 为体验或整洁性问题。严重度不替代分型。

阶段末给出可独立阅读的"缺陷面结论"：主要缺陷、分型分布、哪些可直接修复、哪些升级 L1b——一句话面，不复述表格。

### 4.2 阶段 2：相关提炼 -> `EVO-T-*`

只提炼对当前缺陷、兼容判断或方案选择有决策价值的结构；按信号解压，不默认全开方法库。

| 项 | 要求 |
|---|---|
| 输入 | 相关 DA2-DA7、阶段 1 缺陷、可复用 ESS-* |
| 动作 | 从事实上升到对象、关系、规则/不变式、边界、能力和演化轴；冲突必须升级为结构判断 |
| 输出字段 | 编号、提炼结论、决策用途、来源追溯、证据、置信状态 |
| 阶段门禁 | 可逆、可区分、稳定、最小、可决策；2 跳以上关键关系已覆盖；无外部知识冒充事实；每项 `EVO-T-*` 必须标注所支撑的 `EVO-D-*`/`EVO-E-*` 决策，无法标注用途的提炼按 L0 律 4 降为附录 |

当继续提炼不再改变分型、兼容判断或方案选择时停止。正式报告可以展开，但必须能压回 L0 最小骨架。

### 4.3 阶段 3：扩展优化 -> `EVO-E-*`

| 项 | 要求 |
|---|---|
| 输入 | 已通过阶段门禁的 `EVO-D-*` 与相关 `EVO-T-*` |
| 动作 | 明确目标 -> 形成候选（含“不做”）-> 比较收益/成本/风险 -> 五查 -> 验证设计 -> 兼容与回滚 |
| 输出字段 | 编号、目标缺陷/机会、候选及取舍、五查结果、验证指标与阈值、迁移/回滚、影响范围、推荐结论 |
| 阶段门禁 | 不改核心抽象；修复与演进未混写；五查完整；可验证或已降级；高风险项有兼容与回滚路径 |

候选数量服从真实决策空间，不机械凑数；但推荐实施前必须保留”不做”基线，并解释触发条件与机会成本。

阶段末给出可独立阅读的”方案面结论”：推荐哪些、缓做哪些、升级 L1b 哪些、当前最大不确定项——一句话面，不复述表格。

## 5. 产物规范

### 5.1 报告结构

| 章节 | 内容 | 编号 |
|---|---|---|
| §0 核心结论 | 范围、关键缺陷、核心结构、推荐路径、主要风险；每个判断须能在 §1-§4 找到来源，不堆编号 | 不另编号 |
| §1 缺陷清单 | 阶段 1 产物 | `EVO-D-*` |
| §2 相关提炼 | 阶段 2 产物 | `EVO-T-*` |
| §3 进化方案 | 阶段 3 产物 | `EVO-E-*` |
| §4 未决项 | 缺证据、不可验证、需人工决策 | `EVO-U-*` |

### 5.2 编号与复用

- 编号在单份报告内唯一且稳定；修订不得悄悄改变既有编号含义。
- `EVO-D-*` 可作为 L1b 输入；`ESS-*` 可作为阶段 2 输入，但须重新核对 DA；`EVO-E-*` 只可辅助 `MIG-*`，不得替代迁移主结论。
- L1a 不得首次产出 `REV-*`、`ESS-*`、`TGT-*`、`MIG-*` 或 `RST-*`。

### 5.3 执行痕迹

- 报告开头记录输入文件、版本/适用范围、门禁结果与未加载材料。
- 证据引用使用 `{来源:位置}`，可由人工或工具定位。
- 报告末尾给出“本规范要求 -> 实际位置 -> 状态”的字段对照表。
- 假设、推断、未知和已确认事实必须显式区分。

## 6. 独立验证（V-EVO）

由未参与生成的独立角色执行。Writer 不得以自检替代 V-EVO。

| 检查项 | P1 判定 |
|---|---|
| 路径正确性 | 已触及核心抽象仍留在 L1a |
| 事实真实性 | `EVO-D/T/E` 关键结论无可解析证据 |
| 分型正确性 | 未分型、分型与行动矛盾，或修复/重构混写 |
| 兼容完整性 | 五查缺项，或以“未知”推断“无依赖” |
| 可验证性 | 推荐方案无指标、成功/失败标准或停止条件，且未降级 |
| 回滚完整性 | 高风险演进无兼容期、回滚或前向修复路径 |
| 人读结论 | §0 缺可回指判断、与后文矛盾，或含无来源断言 |
| 执行痕迹 | 缺加载记录、门禁记录或字段对照表 |

P2：非关键证据粒度不足、观察项描述不完整、L2 方法深度不足但不影响当前结论。P3：表达、排版和低风险可读性问题。

V-EVO 输出必须包含问题编号、级别、证据、文档位置和修正动作。最多两轮：初评 -> 修正 -> 复审；P0/P1 全部关闭即止，P2/P3 记录在案。

## 8. 路径升级条件

执行任一阶段时，只要发现以下信号，就停止产出新的 `EVO-E-*`，保留现有证据并升级 L1b：

1. 可靠性修复无法在不改变对象身份、生命周期或主关系的情况下完成；
2. 多个缺陷反复指向同一错误抽象或错误边界；
3. 兼容五查显示需要跨代数据模型、接口语义或消息语义重映射；
4. 候选方案的核心差异已不是局部策略，而是业务地图和能力边界；
5. “推断有意设计”的原始约束已被突破，需要重新评估设计是否成立。

升级时携带 `EVO-D-*`、`EVO-T-*`、五查结果和未决项作为 L1b 输入，不改原编号含义。禁止从 EVO 直接推出目标设计。
