# 元规范-业务系统设计评估与重构规范

> **层级**：L1b 设计评估与重构执行规范  
> **定位**：判断既有设计是否仍成立，并在必须改变核心抽象时产出有证据、有取舍、可兼容、可验证的目标设计与迁移路径  
> **读者**：Writer / Reviewer / Fixer / Referee 与人工验收者  
> **上位约束**：`00-强归纳理论核.md`（L0）  
> **配套方法**：`10-方法卡-业务解压与归纳.md`、`11-方法卡-设计评分与重新选型.md`、`12-方法卡-兼容五查与影子验证.md`（L2，按需加载）  
> **版本**：v2.1 | **日期**：2026-08-05

---

## 0. 一页纸入口

### 0.1 何时使用

以下任一成立时使用本规范：

- 需要判断现有设计是否合理、原始假设是否仍成立；
- 多个缺陷反复指向同一错误抽象或错误边界；
- 目标必须改变核心对象身份/生命周期、主关系、关键不变式、一致性边界或对外能力语义；
- 需要产出目标业务模型、目标架构、重新选型结论或分阶段迁移路径。

若问题可以在不改变上述核心抽象的情况下通过可靠性修复、局部策略或兼容演进解决，转用《元规范-业务进化分析规范》（L1a）。

### 0.2 输入、输出与禁止事项

| 类别 | 内容 |
|---|---|
| 必需输入 | L0、DA0-DA8、DA8 收敛结论、核心设计意图证据 |
| 增强输入 | V0-V7、DEC 卡、EVO-D/T/E、已批准 ADR、运行与历史约束 |
| 输出 | `REV-*` 设计评估、`ESS-*` 业务本质、`TGT-*` 目标设计、必要时 `RST-*` 重新选型、`MIG-*` 迁移路径、`DES-U-*` 未决项 |
| 禁止 | 无证据评价、跳过现状直接画目标、把技术偏好写成业务本质、只有目标没有迁移、把重构写成一次性替换、直接产出代码 |

### 0.3 最短执行链

```text
前置门禁
  -> 现状意图与五维评估（REV）
  -> 业务本质与最小骨架（ESS）
  -> 目标设计与必要的重新选型（TGT / RST）
  -> 分阶段兼容迁移（MIG）
  -> 独立 V-DES
```

**七项发布门禁**：证据与意图可追溯、核心对象完成五维评估、ESS 可压成 L0 骨架、TGT 有候选/代价/触发条件、MIG 每阶段可兼容/验证/回退、§0 与阶段总结可人读且不注水、V-DES 独立完成。

## 1. 定位与硬边界

本规范管“是否需要重画业务地图、目标应如何映射、怎样安全迁移”。它不把任何新架构当默认答案，也不负责代码实施。

| 边界 | 硬要求 | 违反后的处理 |
|---|---|---|
| 事实边界 | `REV/ESS/TGT/MIG` 均回指 DA、DEC、EVO 或等价证据 | 无证据结论作废；新事实先回填上游 |
| 意图边界 | 先解释设计为何形成及约束是否变化，再评价优劣 | 不得用当前偏好审判历史选择 |
| 本质边界 | ESS 剥离技术实现，但保留业务语义、约束与代价 | 技术名词替换不等于本质提炼 |
| 目标边界 | 目标设计必须由 REV + ESS 推导，且记录候选与取舍 | 禁止凭想象生成理想态 |
| 迁移边界 | 每个目标差距有分阶段兼容、验证和回滚/前向修复 | 无 MIG 的 TGT 不得进入实施 |
| 实施边界 | 只产出设计与迁移契约，不直接改代码 | 实施转安全修改规范 |

### 2.2 门禁记录

生成正式报告前逐项记录“通过 / 不通过 / 未知 + 证据位置”：

- [ ] DA0-DA8 完整，DA8 已收敛或明确保留未决项；

- [ ] 核心设计选择有 DEC/ADR，或已标记为“推断意图”并给出证据与置信度；
- [ ] 任务已按 L0 核心抽象定义判定为 L1b，而非可由 L1a 解决；
- [ ] 关键未知项已登记 `DES-U-*`，未被假设填平。

前三项任一不通过时，只能输出证据缺口与补查计划，不得生成正式 TGT/MIG。禁止以“DEC 数量达到某固定值”代替核心决策覆盖度。

## 3. 核心原则

### 3.1 事实锚定

- 每条 `REV/ESS/TGT/MIG` 结论必须有来源；TGT 必须回指其 REV 与 ESS，MIG 必须回指目标差距。
- 新发现的事实先回填 DA 或登记 `DES-U-*`；外部案例只作候选启发。
- 证据、推断、假设和未知必须显式区分。

### 3.2 现状第一

评估前先回答：当时要解决什么、受什么约束、选择牺牲了什么、哪些假设后来发生变化。

有 DEC/ADR 时按原记录解释；无记录时只有同时具备稳定路径、可解释的约束/代价、原假设未明显突破，才可标“推断有意设计”。推断不能升级成已确认事实。

### 3.3 五维评估

| 维度 | 核心问题 |
|---|---|
| 职责分配 | 变化原因相同的职责是否聚合，不同变化原因是否被混合 |
| 抽象层次 | 业务判断是否被技术细节、数据表示或部署选择绑架 |
| 关注点分离 | 业务、策略、配置、基础设施的依赖方向是否清晰 |
| 一致性 | 同一概念、状态、规则在不同实现中是否同义且受同一不变式约束 |
| 演进能力 | 高频变化是否需要反复修改核心路径，关键选择是否可渐进替换 |

每个纳入范围的核心评估对象都给出 1-5 分、证据、理由和置信度。分数用于暴露判断，不替代文字结论；详细评分锚点和组合判定按需加载 L2 方法卡。

### 3.4 本质与实现分离

ESS 的目标是产出 L0 最小骨架：对象、关系、不变式、边界、能力、演化轴与分型。技术实现可以作为约束或现状映射保留，但不得冒充业务本质。

提炼必须遵守 L0：先造形后编目、L1 事实 -> L2 结构 -> L3 判断、冲突必须升级、按决策相关性终压。需要具体解压方法时加载 `10-方法卡-业务解压与归纳.md`。

### 3.5 目标有取舍

每个 TGT/RST 必须说明：候选、选择理由、放弃理由、收益、代价、适用约束、失效触发条件和与现状的差距。禁止“最佳实践”自动胜出，也禁止为形式机械凑候选。

### 3.6 迁移与回滚

无迁移路径的目标设计是重写主张，不是重构方案。每个迁移阶段必须有兼容边界、输入输出、验证标准、停止条件，以及物理回滚或前向修复路径。

## 4. 四阶段执行

### 4.1 阶段 1：设计评估 -> `REV-*`

| 项 | 要求 |
|---|---|
| 输入 | DA0-DA8、设计意图、V/EVO 补充证据 |
| 动作 | 追溯意图 -> 选择核心评估对象 -> 五维评分 -> 识别退化路径与冲突 -> 给出保留/修复/重构判断 |
| 输出字段 | 编号、对象与范围、原意图、约束变化、五维评分、证据、判断、置信度、建议方向 |
| 阶段门禁 | 核心对象五维覆盖；评分有证据与文字理由；确认意图与推断意图分开；冲突已升级为结构判断 |

阶段末给出可独立阅读的“设计评估总结”：系统总体怎样、哪些设计仍成立、哪些已退化、根因是什么。总结不堆编号、不复述表格，长度服从判断完整度。

### 4.2 阶段 2：业务本质 -> `ESS-*`

| 项 | 要求 |
|---|---|
| 输入 | DA2-DA7、阶段 1 REV、相关 EVO-T |
| 动作 | 按信号解压 -> 提炼对象/关系/不变式/边界/能力/演化轴 -> 区分本质、实现选择和历史妥协 -> 反证与终压 |
| 输出字段 | 编号、骨架类型、业务陈述、现状实现映射、稳定/变化属性、证据、反证、置信度 |
| 阶段门禁 | 可逆、可区分、稳定、最小、可决策；关键 2 跳以上关系覆盖；技术偏好未写成本质；可压成 L0 一页骨架 |

阶段末给出“业务本质总结”：系统真正解决什么、稳定层与变化层是什么、边界为何这样划分。总结必须与 ESS 明细和证据一致。

### 4.3 阶段 3：目标设计 -> `TGT-*` / `RST-*`

| 项 | 要求 |
|---|---|
| 输入 | 已通过门禁的 REV + ESS；当前约束与运行基线 |
| 动作 | 定义目标不变量与边界 -> 形成候选 -> 比较取舍 -> 设计目标模型/架构 -> 必要时重新选型 -> 建立现状差距 |
| 输出字段 | 编号、目标对象、目标描述、来源 REV/ESS、候选与取舍、代价、约束、触发条件、差距、决策状态 |
| 阶段门禁 | 每项可由 REV+ESS 推导；不变量先于技术；候选与放弃理由真实；代价和失效条件明确；RST 有必要性证据 |

只有现有技术/架构选择无法承载目标业务语义或演化轴时才产出 `RST-*`。在旧技术上可渐进实现且代价可接受时，不得为“现代化”重新选型。

阶段末给出“目标设计总结”：目标形态、最关键变化、为何更好、主动接受什么代价、哪些内容明确不改。

### 4.4 阶段 4：迁移路径 -> `MIG-*`

| 项 | 要求 |
|---|---|
| 输入 | TGT/RST、REV 差距、五类存量契约、运行与发布约束 |
| 动作 | 按可验证边界拆阶段 -> 定义依赖和关键路径 -> 设计兼容/数据迁移/验证 -> 定义停止、回滚或前向修复 -> 评估风险 |
| 输出字段 | 编号、目标、前置依赖、输入、输出、影响范围、兼容策略、验证指标/阈值、停止条件、回滚/前向修复、风险与责任 |
| 阶段门禁 | 每阶段可独立验证；五查覆盖；依赖明确；失败不会落入不可解释中间态；数据变化有对账和修复方向 |

兼容五查和影子/A-B/开关细节按风险加载 `12-方法卡-兼容五查与影子验证.md`。不是所有阶段都能物理回滚；不能回滚时必须证明前向修复和补偿路径可执行。

阶段末给出“迁移路径总结”：先后顺序、关键依赖、最大风险、不可逆点和停止策略。

## 5. 产物规范

### 5.1 报告结构

| 章节 | 内容 | 编号 |
|---|---|---|
| §0 核心结论 | 人读的总体判断 | 不另编号 |
| §1 设计评估 | 阶段 1 产物 | `REV-*` |
| §2 业务本质 | 阶段 2 产物 | `ESS-*` |
| §3 目标设计 | 阶段 3 产物 | `TGT-*` / `RST-*` |
| §4 迁移路径 | 阶段 4 产物 | `MIG-*` |
| §5 未决项 | 缺证据、不可验证、需人工批准 | `DES-U-*` |

### 5.2 §0 核心结论

§0 必须位于明细之前，并完整回答：

1. 一句话本质：系统的核心结构或核心矛盾；
2. 现状判断：哪里仍合理、哪里已退化；
3. 根因判断：哪些原假设、边界或抽象不再成立；
4. 行动优先级：必须做、应该做、可以做、不要做；
5. 一句话方向：目标和迁移的总方向。

§0 不堆证据编号，但每个判断必须能在 §1-§4 找到来源。缺项、与后文矛盾或出现无来源断言，V-DES 判 P1。

### 5.3 编号与复用

- `REV/ESS/TGT/RST/MIG/DES-U` 在报告内唯一稳定，不得在修订中悄悄改义。
- `EVO-D-*` 可作为 REV 输入；`EVO-E-*` 可辅助 MIG，但须补齐 L1b 的目标取舍和迁移完整度。
- ESS 可供 L1a 阶段 2 复用，但使用方必须重新核对 DA 一致性。
- 只有 L1b 允许首次产出 TGT/MIG/RST 主结论；方法卡不得产出业务结论编号。

### 5.4 执行痕迹

- 报告开头记录输入、版本/适用范围、门禁结果、未加载材料；
- 全程使用可解析 `{来源:位置}` 引用；
- 报告末尾给出“规范字段 -> 实际位置 -> 状态”对照表；
- 决策状态标明提议、待批准或已批准，禁止把提议写成既定 ADR。

## 6. 独立验证（V-DES）

V-DES 由未参与生成的独立角色执行，Writer 自检不能替代独立验证。

| 检查项 | P1 判定 |
|---|---|
| 路径正确性 | 明明可由 L1a 修复却无理由升级重构，或触及核心抽象仍未走 L1b |
| 事实与意图 | 关键 REV 无证据，或把推断意图写成已确认事实 |
| 五维评估 | 核心对象缺维度、评分无理由，或分数与结论明显矛盾 |
| ESS 质量 | 技术实现冒充本质、不能形成 L0 骨架、关键冲突未升级 |
| TGT/RST 推导 | 目标无法回指 REV+ESS，缺真实取舍/代价/触发条件，或无必要性重新选型 |
| MIG 完整性 | 任一关键阶段缺兼容、验证、停止、回滚/前向修复或数据处置 |
| 人读结论 | §0 缺五项、与明细矛盾；四阶段任一缺少高密度总结 |
| 执行痕迹 | 缺加载/门禁记录、证据不可定位或缺字段对照表 |

P2：非关键对象评分粒度不足、次要候选比较不完整、L2 方法深度不足但不改变主结论。P3：表达、排版和低风险可读性问题。

V-DES 输出问题编号、级别、证据、位置和修正动作。最多两轮：初评 -> 修正 -> 复审；P0/P1 全关闭即止，P2/P3 记录在案。

## 7. 与其他层的关系

```text
DA0-DA8 / V0-V7
        -> L0 强归纳与路径判断
        -> L1b REV / ESS / TGT / RST / MIG / DES-U
        -> 安全修改实施规范
        -> 实施级测试、灰度与迁移验证
```

| 规范或产物 | 关系 |
|---|---|
| `00-强归纳理论核.md` | 上位：解压、骨架、分型、核心抽象与完成定义 |
| DA0-DA8 / V0-V7 | 上游事实基线 |
| 业务进化分析规范（L1a） | 平级出口；EVO 可输入或回喂，但不得替代 L1b 编号 |
| `10/11/12` 方法卡 | L2：按信号提供方法，不构成默认废稿条件 |
| 既有系统安全修改代码 AI 执行规范 | 实施层：承接已批准的 TGT/MIG，负责代码级兼容、测试与发布 |

## 8. 与 L1a 的复用和降级规则

- `EVO-D -> REV`：保留 EVO 编号和来源，新增设计维度与意图判断；
- `ESS -> EVO-T`：L1a 使用时重验 DA 一致性，不改 ESS 原义；
- `EVO-E -> MIG`：只能作为候选步骤，必须补目标差距、依赖、兼容、验证与回滚；
- `REV` 发现只是可靠性或局部策略问题时，可降级回 L1a，不必完成 TGT/MIG；
- 禁止由 EVO 直接导出 TGT，禁止由方法卡直接导出业务目标。
