# 开源应用壳网址索引与选型分析

> 整理日期：2026-07-18  
> 范围：GitHub、Gitee 上可用于企业后台、低代码平台、数据应用、项目协作、知识空间和开发者平台的开源应用壳。  
> 说明：Star、维护状态、许可证和商业版边界会变化。正式选型前必须核对目标版本的 `LICENSE`、依赖许可证、发行说明和商用条款。

## 1. 什么是应用壳

应用壳是多个业务页面共同运行的公共外层和上下文管理结构，通常包含：

```text
登录与用户会话
租户、组织、工作空间或应用切换
顶部栏、侧边栏、菜单、路由和面包屑
标签页、最近访问、收藏和全局搜索
权限控制、主题、国际化、通知和个人设置
列表、详情、表单等业务页面的公共容器
```

需要区分以下概念：

| 概念 | 主要作用 | 是否等于应用壳 |
|---|---|---|
| UI 组件库 | 提供按钮、表格、表单、弹窗等零件 | 否 |
| Admin 模板 | 提供导航、布局和示例页面 | 属于前端应用壳，但通常不含后端业务模型 |
| 页面设计器 | 拖拽和配置页面 | 否，属于设计态工具 |
| 页面运行时 | 根据 Schema 渲染业务页面 | 只覆盖应用壳的一部分 |
| 完整平台 | 应用壳、业务模型、权限、流程、发布和运维 | 是，且范围大于应用壳 |

## 2. 分类模型

| 类型 | 核心导航模型 | 典型使用场景 |
|---|---|---|
| 通用后台模板壳 | 菜单 -> 路由 -> 页面 | 管理后台、平台控制台 |
| Headless 资源应用壳 | Resource -> List/Create/Edit/Show | CRUD、数据管理应用 |
| 全栈企业业务壳 | 应用/模块 -> 业务对象 -> 视图 -> 记录 | ERP、CRM、OA、企业业务系统 |
| 低代码运行与构建壳 | 应用 -> 页面/对象 -> 画布/区块 -> 发布 | 低代码平台、内部工具 |
| 数据应用壳 | 空间 -> 数据库 -> 表 -> 视图 -> 记录 | 多维表格、内容和数据管理 |
| 项目任务壳 | 空间 -> 项目 -> 视图 -> 任务 | 研发、项目和任务管理 |
| 知识空间壳 | 工作空间 -> 页面树 -> 内容画布 | 知识库、文档和门户 |
| 服务队列壳 | 工作台 -> 队列 -> 工单 -> 上下文 | 客服、ITSM、运营处理台 |
| 开发者资源壳 | 组织 -> 项目 -> 代码/问题/构建/部署 | DevOps、云资源管理 |

- 比纯 Admin 模板更接近应用框架。

### 12.2 自研企业低代码平台的组合建议

不建议把一个开源项目的所有层次整体照搬。更稳妥的组合是：

```text
全局平台壳：Vue Vben Admin / Ant Design Pro
资源和 CRUD 抽象：Refine / React Admin
业务对象运行时：Frappe / Odoo / NocoBase
角色工作台：ERPNext / Zammad / Plane
数据多视图：Teable / NocoDB / Baserow
设计器工作台：Appsmith / Retool 思路 / Power Apps 思路
企业权限与租户：RuoYi-Vue-Pro / JeecgBoot
```

建议的统一层级：

```text
全局层
├─ 租户/工作空间/环境切换
├─ 应用切换器
├─ 全局搜索或命令面板
├─ 通知、帮助和用户入口
└─ 最近访问与收藏

应用层
├─ 应用首页或角色工作台
├─ 业务对象和功能模块
├─ 流程、报表和集成
└─ 应用设置

页面层
├─ 列表、看板、日历和图表视图
├─ 记录详情和相关数据
├─ 页面级动作
└─ 筛选、保存视图和导出

设计态
├─ 对象树或页面树
├─ 组件/区块物料
├─ 中央画布
├─ 属性、数据、规则和权限
└─ 预览、版本和发布
```

## 13. 评估清单

选型或吸收应用壳前，应逐项验证：

```text
[ ] 全局层、应用层和页面层是否边界清楚？
[ ] 用户能否判断当前租户、应用、对象和页面上下文？
[ ] 菜单权限、工作台权限和数据权限是否分离？
[ ] 是否支持最近访问、收藏、搜索或命令面板？
[ ] 列表到详情是否必须整页跳转？是否支持抽屉或分栏？
[ ] 多任务是标签页、浏览器页签还是上下文返回？
[ ] 响应式策略是重排、隐藏还是独立移动运行时？
[ ] 设计态与运行态是否分离？普通用户是否会看到构建工具？
[ ] 主题和品牌能力是否只换颜色，还是覆盖组件 Token 和布局？
[ ] 插件、模块和页面扩展是否具有稳定注册协议？
[ ] 是否支持应用版本、发布、回滚和审计？
[ ] 开源许可证是否允许目标部署和商业模式？
```

## 14. 证据边界

- 本文是网址索引和结构性选型分析，不代表所有项目均已完成安装和登录态实测。
- Frappe、NocoBase、金蝶和部分低代码产品已有本地知识库证据；其他项目主要依据公开仓库、README、官方 Demo 和公开产品结构整理。
- “设计质量高”不等于“适合直接采用”。企业业务平台还必须验证权限、租户、审计、版本、升级、许可证和维护成本。
- 仓库公开不等于许可宽松；AGPL、GPL、BSL、自定义许可、Sustainable Core License 和商业插件必须单独审查。
