# 12-方法卡-兼容五查与影子验证

> **层级**：L2 方法卡  
> **用途**：为统一 L1 路径 A/B 的兼容评估与可验证性设计补充操作深度  
> **加载方式**：按风险信号加载；不得把本卡全部细项机械升级为所有任务的废稿门禁  
> **来源**：统一 L1 五查与验证细则；当前接口服从统一 L1  
> **版本**：v1.1 | **日期**：2026-08-06

---

## 1. 使用原则

1. 先满足 L1 主门禁，再按真实风险选择本卡深度。
2. “无影响”必须有检索范围或事实依据；无法确认时按有依赖处理。
3. 方法服务于验证，不为凑表引入项目原本不存在的基础设施。
4. 阈值必须来自项目基线、SLO、历史分布或批准标准；本卡示例数值不是默认验收值。

## 2. 兼容五查深度

### 2.1 数据

| 深度 | 检查内容 | 输出示例 |
|---|---|---|
| L1 表字段 | 受影响表、字段、枚举和值域 | N 张表、M 个字段 |
| L2 索引约束 | 唯一约束、索引、外键、校验约束 | N 个约束需保留/调整 |
| L3 历史数据 | 存量规模、异常分布、清洗与迁移 | N 条历史数据，M 条需处理 |
| L4 双轨兼容 | 双写、回填、读路径、版本字段 | 旧读/新读并行边界 |
| L5 一致性验证 | 全量/增量校验、对账、容差 | 校验范围与差异处置 |

L1 主文最低到 L3。即使不迁移，也要说明历史数据为什么不受影响。

### 2.2 接口

| 深度 | 检查内容 | 输出示例 |
|---|---|---|
| L1 契约 | 受影响接口、入参、出参、错误码 | N 个接口 |

| L3 版本 | 直接兼容、双版本、适配层、弃用期 | v1/v2 并行期限 |
| L4 切换 | 灰度范围、回退条件、消费者迁移 | 分批切换计划 |

L1 主文最低到 L2。无法列全调用方时必须登记未知及补查动作。

### 2.3 消息

| 深度 | 检查内容 | 输出示例 |
|---|---|---|
| L1 主题契约 | Topic/事件、Schema、Key、顺序语义 | N 个 Topic |
| L2 消费者 | 消费者、可控性、版本、积压 | M 个不可控消费者 |
| L3 投递语义 | 重试、死信、重复、乱序、回放 | 当前与目标策略 |
| L4 幂等兼容 | 幂等键、去重窗口、双发布/双消费 | 新旧消费者并行边界 |

L1 主文最低到 L2。格式变化不能只检查生产者。

### 2.4 定时任务

| 深度 | 检查内容 | 输出示例 |

| L1 调度 | 任务、频率、分片、启停方式 | N 个任务 |

## 3. 验证方式选择

| 变更信号 | 优先考虑 | 关键限制 |
|---|---|---|
| 计算或接口结果变化 | 影子比对 | 新路径不得产生不可逆副作用 |
| 状态或数据模型变化 | 影子读/双写校验 + 切换开关 | 明确真源、对账与修复方向 |
| 用户体验或性能策略 | A/B 对比 | 分组稳定、样本量与观察周期足够 |
| 新能力或高风险路径 | 功能开关/分批灰度 | 默认态、审计、回退与清理责任明确 |
| 消息契约变化 | 新旧消费者并行或双发布 | 防重复、副作用隔离、回放可控 |
| 低风险局部修复 | 特征化测试、回放、对账或项目现有验证 | 不为形式引入新平台 |

选择顺序：先问“要观察哪种行为差异”，再选机制。影子、A/B 和开关可以组合，但必须说明每种机制解决什么风险。

## 4. 影子模式

### 4.1 适用条件

- 新旧实现可接收等价输入；
- 新实现的副作用可禁止、隔离或写入独立空间；
- 输出能够归一化并比较；
- 差异可追溯到请求、对象或批次。

### 4.2 最低设计字段

| 字段 | 要求 |
|---|---|
| 流量来源 | 在线复制、历史回放或抽样 |
| 隔离方式 | 不落地、独立库/表/Topic，或幂等可清理写入 |
| 比对规则 | 忽略字段、排序、时间容差、金额/计量精度 |
| 观察指标 | 覆盖量、差异率、差异类型、资源开销 |
| 停止条件 | 数据污染、资源超限、差异超阈值 |
| 处置 | 暂停、定位、修复、重新回放 |

不得让影子路径共享会改变老实现结果的可变状态。涉及真实外部调用、支付、库存或通知时，默认禁止影子副作用。

---

## 5. A/B 对比

### 5.1 适用条件

- 指标是用户或业务结果，不只是实现正确性；
- 分组不会破坏用户、租户、订单或会话的一致性；
- 能控制同期活动、渠道、版本等主要干扰因素；
- 有足够样本和观察周期。

### 5.2 最低设计字段

分流键、实验单位、样本量依据、主指标、护栏指标、观察周期、显著性/业务阈值、提前停止规则、实验污染检查。

`p < 0.05` 不是通用成功条件。统计门槛、最小可检测效应和业务价值必须共同定义；低流量场景可改用时段回放、配对样本或人工审查。

---

## 6. 功能开关与灰度

### 6.1 最低设计字段

| 字段 | 要求 |
|---|---|
| 默认态 | 未配置、配置中心不可用时的行为 |
| 作用域 | 用户、租户、门店、区域、版本或请求 |
| 变更控制 | 权限、审计、审批、热更新能力 |
| 灰度批次 | 每批范围、观察时长、晋级条件 |
| 回退 | 手动/自动条件及回退后数据处置 |
| 清理 | 负责人、到期时间、删除开关与旧路径的条件 |

开关只能切换可兼容的路径，不能替代数据迁移、契约协商或幂等设计。自动回退只在信号可靠且回退本身安全时使用。

## 7. 成功、失败与停止条件模板

| 项 | 内容 |
|---|---|
| 基线 | 当前版本、时间窗口、流量和数据范围 |
| 成功标准 | 业务正确性 + 技术护栏 + 最小观察量 |
| 失败标准 | 明确不可接受的差异、错误或退化 |
| 停止条件 | 立即暂停验证/灰度的安全阈值 |
| 回退条件 | 何时切回；切回后如何处理新产生的数据 |
| 前向修复 | 无法物理回滚时的修复、补偿与对账路径 |
| 证据保留 | 指标、差异样本、日志摘要、审批和结论 |

示例阈值只能来自当前系统证据：历史错误率、延迟分位、财务零容差、允许的展示时间偏差等。禁止复制固定百分比作为默认标准。

---

## 8. 常见失效模式

- 只写“可灰度”，没有分组、指标、阈值和回退；
- 影子路径仍发送通知、扣减库存或调用支付；
- A/B 分组跨越必须一致的订单或租户边界；
- 双写没有指定真源，差异后不知道修哪边；
- 功能开关永久存在，没有清理条件；
- 只查接口定义，不查调用方；只查 Topic，不查消费者；
- 以“未检索到”直接下结论“无依赖”；
- 回滚只描述代码版本，不处理新版本已经写入的数据。

L1 报告只需引用本卡的实际使用结果，不复制整张方法卡。建议记录：

```text

实际检查：范围、证据、未知项

```
