## 0. 一句话

创造性归纳不是“多想一点”，而是**用 5 个强制认知动作，逼 AI 在最可能续写的均值答案之外跳跃**；跳跃后用“反证 + 换领域检测 + 禁技术变体”兜住，不许停在泛化建议上。

## 2. 创造力强制五步（对“业务轨”和“架构轨”各跑完整一轮）

> 每一轮输出都必须落在输入契约上，且【步骤 2 的类比必须做结构差异验证、步骤 5 后必须得出胜者与败者】。五步不全 = 本轮作废。

### 步骤 1 · 缺席清单（期望违例 + 重新框定）
列出这个系统**刻意不做什么、把什么排除在边界外**——不是“没找到”，而是看得见的**设计缺席**（如：成本域刻意为差异报表不给“责任/原因”，核算域不承载“责任闭环”）。
> 判据：找到一个真实可引用的缺席，且能说明“缺席本身造成了什么业务后果/绕行”。

### 步骤 2 · 远方类比 ×3（结构类比，强制带差异验证）
对当前惊讶 S，指定 **3 个不同领域**的结构类比（不是同义改写）。每个必须回答：
- **哪里像**（结构同构点）；
- **哪里不像**（这点不同揭示了什么新约束/新视角）；
- 至少 1 个类比必须**改变**你对该机制的因果看法。
> 不验证差异的类比 = 作文，不算数。

### 步骤 3 · 反事实支柱（反事实）
回答：“如果这个设计从第一天就不存在，这个系统会被迫长成什么样子？”
> 目的是暴露被隐式依赖的设计承诺——它被迫在别处手工补哪些事。

### 步骤 4 · 角色视角切换（重新框定）
对同一事实，分别用 **3 个冲突视角**各写一种读法（示例：财务总监 / 实施顾问 / 十年后维护者 或 接线员 / 运维 / 挑战者）。至少一个视角必须与常规读法冲突。

### 步骤 5 · 为败者辩护 + 竞争到极限（假设反转 + 因果回路/博弈）
把当前最强的竞争解释挑出来，**攻击胜者、给败者找活路**；然后让候选在“同场景下产生不同预测”上对撞，写出各自的冒险预测与否证条件。
> 如果所有候选最终预测完全相同 → 它们不算竞争，回到步骤 2 换类比重跳。

## 3. 双轨提炼模板（业务轨 + 架构轨）

> 业务轨与架构轨不是两个任务，是**同一条链**：业务轨的骨架是架构轨的输入。先业务、后架构，不许跳过。

### 3.1 业务轨（提炼归纳总结）
对每个惊讶 S 输出：

```text
S  惊讶事实（锚定证据，文件:行号）
M0 当前解释
Δ  解释缺口（S 为什么不能被 M0 自然解释）
H  候选解释（必须含一个由 §2 五步逼出来的“非均值”候选）
P  冒险预测（实施前可观察、可能为错、能区分 H 与其他候选）
F  否证条件（什么最小事实会削弱/否证 H）

提炼骨架：核心对象 / 关键关系(2跳+) / 不变式 / 边界 / 能力 / 演化轴
总结判据：一页压得回来吗？压不回 = 未完成。
```

### 3.2 架构轨（归纳总结，禁止“换实现”冒充）
对同一个业务骨架，输出**架构证据**，而不是“改成 XX 技术”：

```text
形态证据 ：这段代码/表/接口的“形状”（单字段压多轴？if-else 形态？隐式状态？）
职责矛盾 ：形状承担了什么业务职责、两者为何冲突
正交轴识别：哪些业务维度被压缩进同一载体（如“确认时点×确认状态”压进一个字段）
边界错放 ：哪些能力共用依赖但一致性边界不对齐
承重墙    ：动住哪根会全塌（= 主干不变式落在的载体）
架构提炼  ：真正的问题是“轴分离 / 边界对齐 / 显式化承诺”，而不是“换成状态机/微服务”
```

> **架构轨红线**：候选没有回答“角色/决定/承诺/结果/激励/一致性边界怎么变”，只换了存储、中间件、线程、状态机、微服务 = 判“技术变体”，本轮作废（对齐 L1 共同门禁 CG7 与路径豁免）。

## 4. 反机械验收（任一“否” → 停止，补证或重写）

1. 核心洞察是否从 §2 五步逼出，而不是标题改写？（是创造力→还是复述）
2. 是否做了**缺席清单 + 结构差异验证**，且至少一个类比改变了因果看法？
3. 是否存在 ≥2 个**因果结构不同、同场景预测不同**的候选，而非同义改写？
4. 冒险预测是否实施前可观察、可能为错、能区分候选（非“方案成功后指标变好”的自我证明）？
5. 是否给了 F（否证条件）并**执行或登记为未知**，而不是“初步支持”提前称胜？
6. **换领域检测**：核心结论换成订单/库存/会员/支付后还成立吗？成立 = 泛化 = 判复述，重写。
7. 架构轨结论是否改变了业务机制/一致性边界，而不是“换实现”？
8. 是否写明了胜者依据 + 最强反方 + 否证结果，而不是只展示胜出答案？

## 5. 正反范例（同一输入，两种质量）

### 5.1 输入 S（真实证据，K3Cloud 核销）
**S1**：特殊核销校验基于**行数**（允许 1对1、1对0、2对0 且必需一正一负），而非金额。（证据 `FinMatch.cs:171-196`）

### 5.2 反例（均值答案——宁可判作废）
- “H2=历史遗留 / H3=风险控制”，预测靠“找 TODO 注释”“看普通核销有没有同样限制”——看似合理，但**没换个因果轴**；
- 进化候选“把 70 层 if-else 重构为状态机”——**技术变体冒充业务进化**；
- 演进方向“显式区分双重语义 / 双层校验”——**换任何 ERP 都成立 = 泛化 = 复述**。

### 5.3 正例（创造力强制后；候选态，待验证，不提前称胜）
**H9「几何配对 = 可重放性」**：行数与符号约束既不是金额/关系/风控，而是保证**每笔核销在行粒度可逆、可重放、结构自明**——核销是暂估→财务这条**凭证重放缝上的接榫**。
- “1对0/2对0（正负）”：正数暂估被负数暂估冲掉 = 发票在暂估侧已被预冲、账面无需新增财务行（零新增自动勾稽）；符号约束表达“哪条冲哪条”的**冲销瞬间**，不许跨业务自由抵消。
- **与 H1-H3 的因果轴差异**：它们在问“为什么要限”，H9 问“限制保证了核销**之后**的什么性质”，预测 H1-H3 未覆盖的现象——撤销/红冲粒度 = **配对组**而非金额或单行。
- **P9**：自动核销后“未核销金额”必须能逐行指回暂估行；“2对0”核销被撤销时须**整组（正+负）一起废**，不允许只红一行。
- **F9**：核销保存时未核销字段直接重算、无配对 ID、红冲允许任意单行 → H9 削弱。
- **架构轨派生**：行数与符号约束 = “配对关系”被压进**操作参数**而非数据模型 → 架构痛点是真问题不是“重构成状态机”，是“把配对关系显式建模 + 保证可重放”。

## 6. 禁用与降级

- 禁用：请您更有创意 / 请您深入思考（空指令）；只换名称、只加字段、只罗列视角（非解释增量）；把某个技术偏好写成业务本质；外部案例冒充项目事实。
- 降级：五步跑满仍产不出非均值候选 → 允许保留“当前解释胜出”，但必须写清：跑了几轮、换了哪些类比、为什么均值解释解释力最强（有证据），不得用“填完流程”冒充完成。
- 与本卡冲突时：机制性判断服从 L0 §10.5 强制术语表；正式产物编号与门禁服从 L1。
