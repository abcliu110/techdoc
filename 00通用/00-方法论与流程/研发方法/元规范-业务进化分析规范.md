## 1. 使用边界

满足以下条件时执行本 Profile：

- 已有 DA0-DA8 或等价的既有系统事实基线；
- 当前业务地图总体成立，目标是在核心抽象内修复、增强或演进；
- L0 §7.1 的核心抽象判据 `K1-K5` 均明确不改变。

出现 `K1-K5` 任一变化、多个问题指向同一错误业务模型，或必须重新定义目标业务机制时，按统一 L1 §4.6 申请转路径 B。切换必须记录路径纪元、新增证据或经确认的原判定纠错、累计次数；同一任务第二次切换先交 Referee 或人工责任人裁决。路径 A 可以创造性地改进控制、策略、反馈和局部协作，但不得借“创新”暗中首次产出 `ESS/BIZ/TGT/MIG`。

缺少事实基线时，只能输出补证计划和创造性问题，不得输出正式 `EVO-T/E`。外部案例、行业常识和类比可以提出假设，不能补造项目事实。

## 2. 路径 A 创造性执行链

```text
EVO-D 决策问题
  -> 理解循环（CA0-CA5）
     -> CA0 划定生成样本、保留样本与当前解释 M0
     -> CA1 建立业务活模型，捕捉“本不该如此”的惊讶事实 S
     -> CA2 用业务结果/义务/风险重新框定问题
     -> CA3 执行认知跳跃，生成多个候选解释
     -> CA4 让候选解释竞争并形成冒险预测与 P/F
     -> CA5 形成可竞争的 EVO-T 候选，并保留解释剩余
     -> 独立反证后转正为已验证 EVO-T
  -> 重设计循环（CA6-CA8）
     -> CA6 以已验证 EVO-T 为输入，生成不同业务机制的 EVO-E 候选
     -> CA7 用反事实、博弈和失败预演攻击候选
     -> CA8 用保留样本或最小实验收敛
  -> V-EVO 独立验证
```
CA3 与 CA4 是迭代回路（对齐统一 L1 v1.7：先跳跃生成解释，后竞争与冒险预测）；不得把 CA4 当作 CA3 的机械补记。轮次预算和停止条件服从 L0 §6，默认最多 3 轮；预算耗尽仍不能区分时只保留 `CA-*` 与补证计划。CA5 后的独立反证必须先把候选转正为 `EVO-T`，CA6 才能以它为输入；不得用路径 B 的 `ESS` 替代路径 A 的 `EVO-T`。

### 2.1 先找惊讶，不先找方案

每个声称“有洞察”的核心结论必须先写出一条**溯因链**：

```text
S  惊讶事实：观察到什么反常、冲突、缺席、绕行或业务失败？
M0 当前解释：按现有理解，本来应该发生什么？
Δ 解释缺口：S 为什么不能由 M0 自然解释？
H  候选解释：如果 H 成立，S 为什么反而变得可预期？
P  冒险预测：H 还预测什么尚未用于产生 H、且可能被证明为错的现象？
F  推翻条件：什么最小事实会削弱或否证 H？
```

没有 `S-M0-Δ` 的内容通常只是摘要；没有可能失败的 `P/F`，通常只是不可证伪的漂亮解释。惊讶必须锚定项目事实或明确标为待验证现象，不能为了显得有创造性而虚构。

### 2.2 竞争解释必须竞争因果

至少保留当前解释和一个实质竞争解释。二者必须在对象身份、责任/权威、因果机制、边界、不变量、价值结果或演化轴之一不同，并对同一场景给出不同预测。

以下不算竞争：同义改写、不同技术实现、抽象层级不同但预测完全相同、只写“方案好/方案差”。答案确实唯一时，用排他证据关闭搜索空间，不能只写“没有想到其他解释”。

### 2.3 跳跃必须产生解释增量

按事实信号调用 `10-方法卡-业务解压与归纳.md`：反事实、期望违例、跨事实组合、重新框定、结构类比、假设考古，以及因果回路/博弈分析。

一次跳跃只有满足以下任一项才算有效：

- 同时解释了此前分散的正常、异常或历史事实；
- 暴露了新的隐性关系、规则、边界、失败场景或取证问题；
- 改变了缺陷分型、兼容判断、候选机制或验证优先级；
- 证明当前简单解释已经足够，并有证据排除更复杂解释。

只换名称、只增加字段、只罗列视角，均不算解释增量。

### 2.4 进化候选必须改变业务机制

`EVO-E-*` 先写清当前与目标业务机制：谁在什么信息下决定或承诺什么，谁执行，谁承担结果和补救责任，结果怎样反馈。随后才讨论系统实现。

路径 A 可以改变局部策略、控制点、反馈、责任衔接和例外治理，但必须保持核心抽象。候选还要检查：

- 哪个角色获益、付出成本或失去裁量权；
- 指标是否可能被优化而真实结果变差；
- 重复、套利、规避或信息隐瞒能否让参与者“合法地做坏结果”；
- 延迟反馈是否放大积压、误判或人工补救；
- 局部优化是否把成本或风险转嫁给下游、客服、运营或用户。

命中上述机制且需要改变核心对象、义务或能力语义时，停止路径 A 并升级路径 B。

## 3. 正式产物接口

| 探索结果 | 正式归宿 | 转正条件 |
|---|---|---|
| `CA-*` 洞察假设 | `EVO-T-*` 或未知项 | 通过溯因链、竞争预测、项目证据和保留样本/等价验证 |
| 局部业务机制候选 | `EVO-E-*` | 不改核心抽象；因果链、激励/博弈、兼容、验证和回退成立 |
| 发现错误抽象或目标业务机制变化 | 路径 B 输入 | 保留 `CA/EVO-D/T`，升级后首次产出 `ESS/BIZ/TGT/MIG` |

已有 `EVO-D/T/E/U` 编号和报告无需改号。`CA-*` 是可淘汰探索痕迹，不要求进入所有正式报告，但核心结论必须保留胜出依据、最强反方和否证结果。

## 4. 反机械验收

任一问题回答“否”，不得宣告完成：

1. 核心洞察是否有真实 `S-M0-Δ-H-P-F`，而不是从标题直接改写？
2. 把领域名词替换成“对象、用户、系统”后，结论是否变成适用于任何系统的空话？若是，失败。
3. 最强竞争解释是否会在至少一个相同场景产生不同预测？
4. 冒险预测是否可能在实施前被观察为错，而不是方案成功后的自我证明？
5. `EVO-T` 是否比原解释多解释事实或少使用假设？
6. `EVO-E` 是否改变业务因果机制，而不只是更换技术实现？
7. 是否检查了受损角色、指标博弈、反馈延迟和风险外溢？
8. 若最终没有新洞察，是否有证据证明当前解释胜出，而不是因为填完流程就停止？
9. CA3/CA4 是否按迭代回路执行（先跳跃生成解释、后竞争与冒险预测），并未把 CA4 当作 CA3 的机械补记？
10. 路径 A 的本质候选是否在理解循环（CA5）独立反证后才转正 `EVO-T`，而不是提前称胜出？
11. 快速通道是否遵守封口（对齐统一 L1 v1.7）：仅缺陷修复/可靠性/局部策略可入，只能产出 `EVO-D` 与未编号的修复、验证和回退方向，**不得首次产出 EVO-T/EVO-E/ESS/BIZ**，且须检查至少一个最小反例；涉及正式进化候选、本质/重设计或核心抽象判断者一律不得走通道？
12. CA3/CA4 是否记录预算、实际轮次和停止理由，且没有把预算耗尽伪装成胜出？
13. 升级是否引用 `K1-K5`、新增证据或经确认的原判定纠错、路径纪元；第二次切换是否已停止自动执行并取得裁决？

Reviewer 对正式或高影响结论必须按统一 L1 §7.1 逐项验证 `CG1-CG8`，包括独立提出一个反方解释和最小合法反例。Writer 的自我反驳不能替代 V-EVO。快速通道路由由 Reviewer 可否决；需要正式 `EVO-E` 时必须退出快速通道，补走理解循环与 A3。

快速通道报告只保留路径理由、`EVO-D`、最小反例、直接修复方向、验证和回退；`EVO-T/E` 章节显式标记“不适用”，不得为了套模板生成空洞提炼或假方案。

## 5. AI 直接执行指令

```text
不要先给方案。先从 DA/V/DEC 中选择一个会改变决策的惊讶事实 S，
写出当前解释 M0 及其解释缺口 Δ；提出至少一个因果结构不同的 H，
为 M0/H 写出同一场景下不同且可能失败的预测 P，再选择信息增益最高的证据。
胜出的解释才能进入 EVO-T。随后保持核心抽象，至少探索一个非直接修补的
业务机制候选，并检查角色激励、指标博弈、反馈延迟、风险外溢、兼容、验证和回退。
证据不足时保留 CA/未知项；命中 K1-K5 时按路径纪元规则升级路径 B，不得在路径 A 偷做重构。
```
