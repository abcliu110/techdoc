## 0. 一页纸入口

### 0.1 何时使用

本文只用于**既有业务系统**。使用前必须先通过文档 20 建立现状事实；正式、高风险或核心抽象变更还必须通过文档 21 对关键结论做独立反证。

以下任务进入本文：

- 判断当前设计是否仍然成立；
- 修复缺陷、增强可靠性或扩展局部能力；
- 在兼容历史行为的前提下演进既有系统；
- 改变核心抽象、目标业务模型、系统边界或架构映射；
- 为上述变化形成可验证、可回退的迁移路径。

以下任务不进入本文：

- 没有既有实现的从零设计：直接进入 22A；
- 只定位一个明确故障且不需要形成演进决策：进入排障规范；
- 已批准方案的代码实施：进入既有系统安全修改规范；
- 未建立 DA0-DA8 事实基线，却直接评价或重画目标系统。

### 0.2 路径判定

先按 L0 §7.1 的唯一核心抽象判据 `K1-K5` 判断，再选择路径。下表只是路由摘要，不构成第二套定义：

| 判定 | 路径 | 主要输出 |
|---|---|---|
| `K1-K5` 均不改变，且不需要重评原设计 | 路径 A：核心抽象内进化 | `EVO-D/T/E/U` |
| 需要评价原设计，或 `K1-K5` 任一项必须改变 | 路径 B：设计评估与重构 | `REV/ESS/BIZ/TGT/RST/MIG/DES-U` |
| 当前证据无法判断 | 暂不出正式方案 | 路径未知项与补证计划 |

只改变存储、中间件、线程模型、可靠性机制或局部策略，默认属于路径 A；但若这些变化实际命中 `K1-K5` 任一项，必须升级路径 B。

**不算动核心抽象（对齐 L0 §7.1，默认仍走在路径 A；不得因"看起来大"强行升级 B）**：
- 仅改实现手段（存储、中间件、线程模型等），业务语义不变；
- 仅补可靠性（超时、重试、幂等、监控）；
- 仅调局部策略参数，且不改变对外能力语义与不变式。
这三类豁免若实际改变业务语义、责任或一致性边界，则升级路径 B。

路径不是一次性标签，但切换必须服从 L0 §7.2 的路径纪元和防循环规则。路径 A 发现承重墙时可升级路径 B；路径 B 证明问题只是局部缺陷时可降级路径 A。只有改变 `K1-K5` 判断的新证据，或经 Reviewer/Referee 定位并确认的原判定错误，才能触发切换；同一任务第二次切换必须暂停正式产物并交 Referee 或人工责任人裁决。已形成的证据、编号和切换历史继续复用，不重新包装事实或清零计数。

### 0.3 输入、输出与禁止事项

| 类别 | 内容 |
|---|---|
| 必需输入 | L0、DA0-DA8、DA8 收敛结论、适用范围与证据索引 |
| 条件必需 | 路径 B 必须有核心设计意图证据；正式、高风险任务和路径 B 必须有 V0-V7 或明确的证据不足结论 |
| 增强输入 | DEC/ADR、运行基线、历史约束、既有 EVO/ESS、SOP-08/09 评审意见 |
| 路径 A 输出 | `EVO-D-*`、`EVO-T-*`、`EVO-E-*`、`EVO-U-*` |
| 探索中间产物 | `CA-*` 创造性分析记录；可被削弱、否证或丢弃，不是正式业务事实 |
| 路径 B 输出 | `REV-*`、`ESS-*`、`BIZ-*`、`TGT-*`、必要时 `RST-*`、`MIG-*`、`DES-U-*` |
| 禁止 | 无证据判断、未分型出方案、把局部修复和核心重构混写、把技术偏好写成业务本质、只有目标没有迁移、直接产出代码 |

### 0.4 最短执行链

```text
DA0-DA8 / V0-V7
  -> L0 骨架与初步分型
  -> 路径判定
     -> 快速通道：仅 EVO-D + 未编号修复/验证/回退方向
     -> A：EVO-D
        -> 理解循环 CA0-CA5 -> 独立反证 -> 已验证 EVO-T
        -> 重设计循环 CA6-CA8 -> EVO-E -> V-EVO
     -> B：REV
        -> 理解循环 CA0-CA5 -> 独立反证 -> 已验证 ESS
        -> 重设计循环 CA6-CA8 -> BIZ
        -> 22A 目标系统设计 TGT -> MIG -> V-DES
  -> 已批准结论
  -> 安全修改实施
```

最短链只省略说明，不省略类型和门禁：正式 `EVO-T/ESS` 必须出自理解循环并独立验证，正式 `EVO-E/BIZ` 必须出自重设计循环；快速通道不得借本图越权生成这些产物。

## 1. 共同边界

| 边界 | 硬要求 | 违反后的处理 |
|---|---|---|
| 事实边界 | 每条关键结论引用 DA、V、DEC、EVO 或等价可解析证据 | 结论作废；新事实先回填上游或登记未知项 |
| 意图边界 | 先解释设计为何形成及原约束是否变化，再评价优劣 | 不得用当前偏好审判历史选择 |
| 分型边界 | 先按 L0 分型和核心抽象判据选路径 | 未分型不得进入推荐方案 |
| 本质边界 | 业务本质剥离技术实现，但保留业务语义、约束和代价 | 技术名词替换不等于本质提炼 |
| 创造边界 | 探索空间允许反事实、类比和大胆假设，正式结论必须经竞争解释、反证和区分性验证 | 不得因暂时无证据禁止假设，也不得把假设冒充事实 |
| 目标边界 | 目标业务机制由 `REV+ESS` 推导，目标系统设计由选定 `BIZ` 推导 | 禁止从缺陷或最佳实践直接跳到技术理想态 |
| 兼容边界 | 数据、接口、消息、定时任务、配置逐项检查 | 缺查不得发布正式建议 |
| 迁移边界 | 核心重构必须分阶段兼容、验证和回退或前向修复 | 无 `MIG-*` 的 `TGT-*` 不得进入实施 |
| 实施边界 | 本文只产出决策与迁移契约 | 代码实施转安全修改规范 |

已被调用方、历史数据、配置、任务、消息或对外契约依赖的合法可观察行为，默认是兼容候选。已确认的越权、跨租户访问、注入、凭据泄露或财务完整性错误不是必须保留的兼容基线，但修复仍需评估调用方、数据处置和回退影响。

## 3. 共同原则

### 3.1 事实、推断和决策分层

- 新发现但上游未记录的事实，先回填 DA，或登记为 `EVO-U-*` / `DES-U-*`。
- 经验、类比和外部案例只能生成候选，不能冒充项目事实。
- 事实、交叉验证结论、经验判断、推断、假设、未知和决策必须显式区分。
- 推荐方案必须回指目标缺陷、设计退化或业务机会；没有来源的方案不得进入主结论。

### 3.2 设计意图与四对象分型

先使用 L0 四对象分型：

| L0 分型 | 默认行动 |
|---|---|
| 业务不变式 | 保护；任何方案都要证明不会破坏 |
| 有意设计 | 保留，直到原约束、代价或触发条件失效 |
| 可靠性缺陷 | 优先路径 A，在既有核心抽象内修复 |
| 错误抽象 / 建模反模式 | 路径 B，评估重构 |

无 DEC/ADR 时，只有同时具备长期稳定路径、可解释的当时约束与代价、原假设未明显被突破，才可标“推断有意设计”。推断不能升级成已确认事实。

能力缺口不是独立分型。先判断它是未交付、可靠性问题，还是核心抽象无法承载，再分别选择补齐、路径 A 或路径 B。

### 3.3 创造性探索与工程收敛

本文负责把创造性从口号变成受检过程。创造性不是要求答案新奇，而是面对当前模型解释不了的事实，提出让该事实变得可预期的新解释，再用冒险预测区分解释；胜出的解释才能产生业务本质和业务机制候选。

#### 3.3.1 三个空间必须隔离

| 空间 | 允许内容 | 进入下一空间的条件 |
|---|---|---|
| 事实空间 | DA/V/DEC、运行样本和已确认业务事实 | 能定位来源，事实/推断/未知已分层 |
| 探索空间 | `CA-*` 竞争解释、反事实、类比、新抽象和业务进化机会 | 给出不同预测、反例和验证问题；允许暂无支持证据 |
| 决策空间 | `EVO/ESS/BIZ/TGT/MIG` 等受检结论 | 已通过区分性验证、适用门禁和责任人决策 |

禁止用事实门禁封死探索空间，也禁止把探索项越级写进决策空间。`CA-*` 可以大胆、失败和被删除；删除时保留否证原因，避免后续重复提出已失败假设。

#### 3.3.2 两个创造性循环（理解循环与重设计循环）

经理解循环确认仍属于路径 B 的任务，必须继续完成重设计循环；若证明问题只是局部缺陷、可靠性或实现手段，必须按 §5.8 正式降级路径 A，才可停止路径 B 的重设计循环。路径 A 遇到 P0/P1、高影响未知、多个合理解释、跨对象/时间/边界冲突，或命中 L0 §10.5 定义的**反复修补信号**时，也必须执行适用循环；答案唯一、局部、低风险且可逆的问题可以精简，但要给出"为什么不需要结构性探索"的证据。

**理解循环（CA0-CA5）**：从事实到验证后的本质。顺序是：建立 `M0` → 装配活模型找惊讶 → 重构问题 → **认知跳跃生成竞争解释** → 比较解释并形成冒险预测 → 反证收敛 → 产出**已验证的** `EVO-T/ESS`。该循环的阶段不依赖 `BIZ`，也不预设业务要重设计。

| 阶段 | AI 必须执行的认知动作 | 最小结果 |
|---|---|---|
| CA0 归纳对象 | 建立当前解释 `M0`、生成样本和保留样本；区分事实、推断、假设和未知 | 可推演的证据语料、验证样本和基线解释 |
| CA1 活模型与惊讶 | 装配"角色—决定/承诺—动作/交换—结果—反馈/恢复"，寻找 `M0` 不能自然解释的冲突、例外、绕行、缺席和技术成功但业务失败 | `S-M0-Δ` 惊讶账本与活模型 |
| CA2 问题重构 | 删除表、接口、页面和组件名，用业务结果、义务、风险或控制点重写问题 | 表面问题与重构问题 |
| CA3 认知跳跃 | 执行反事实、期望违例、跨事实组合、重新框定、结构类比、假设反转或因果回路/博弈分析，切换业务视角，生成多个候选解释 | `CA-*` 各候选解释（允许大胆、未验证） |
| CA4 竞争与冒险预测 | 让 CA3 生成的解释相互竞争：至少保留两个因果结构和预测不同的解释，比较各自比 `M0` 多解释什么；为 `H1...Hn` 各自形成实施前可观察、可能为错的冒险预测 | `H1...Hn`、解释增量、冒险预测、最强反方；答案唯一时提供排他证据 |
| CA5 本质候选 | 寻找能用更少假设解释更多正常、异常和历史现象的对象、关系、不变式、边界、能力和演化轴；保留尚不能解释的剩余事实 | 候选 `EVO-T/ESS` 与解释剩余 |

CA3 与 CA4 是迭代回路：新跳跃催生新解释，新解释的竞争失败又触发新跳跃；不得把 CA4 当作 CA3 的机械补记。没有 CA3 有质量的跳跃产物，CA4 就会退化成"凑两个直觉再补视角"。

CA3/CA4 的轮次预算、停止条件和预算耗尽处理统一服从 L0 §6。报告必须记录计划轮数、实际轮数和停止理由；达到预算仍不能区分时只能保留 `CA-*`、未知项和补证计划，不得因时间耗尽把候选转正。任何扩轮都需要 Referee 或人工责任人批准，不能由 Writer 自行把“再想一轮”变成无限回归。

理解循环在 CA5 之后必须**独立反证收敛**（用保留样本/最小实验/区分性验证淘汰、削弱或转正），只有通过这一验证的本质候选才能转正为正式 `EVO-T/ESS`。转正后 CA3-CA5 的竞争痕迹必须保留，不得只展示胜出解释。

**重设计循环（CA6-CA8）**：以理解循环已经验证的业务结构为输入——路径 A 使用 `EVO-T`，路径 B 使用 `ESS`；不得借用未验证候选。该循环按路径分别产出 `EVO-E` 或 `BIZ`，不在本循环内悄悄改变已验证的 `EVO-T/ESS`；若新证据、失败预测或候选推演暴露本质矛盾，必须回到理解循环重新竞争和验证。

| 阶段 | AI 必须执行的认知动作 | 最小结果 |
|---|---|---|
| CA6 业务重设计 | 路径 A 以已验证 `EVO-T`、路径 B 以已验证 `ESS` 为输入；保持不变量，改变责任、决策点、控制点、反馈、协作、激励或例外机制，挑战目标指标是否替代真实结果 | 路径 A 的 `EVO-E` 或路径 B 的 `BIZ` 候选 |
| CA7 反事实与预演失败 | 用角色变化、延迟、重复、套利/规避、十倍规模、历史回放和依赖失效挑战候选 | 最小反例、博弈路径、二阶影响和失效条件 |
| CA8 区分验证与收敛 | 优先取得能改变假设排序的证据，用保留样本或最小实验淘汰、削弱或转正 | 条件化结论、未知项与下一验证 |

**两循环边界**：`EVO-T`（路径 A）或 `ESS`（路径 B）是理解循环的正式产出，也是各自重设计循环的合法输入；它们必须在理解侧验证完成，重设计侧不得借用尚未验证的本质。理解循环若证明原路径 B 问题只是局部缺陷或已能完全由 `M0` 解释，必须记录证据并按 §5.8 降级路径 A；只有完成降级后，才可停止路径 B 的重设计循环。

认知跳跃的具体操作、信号选择、保留样本、收敛十问和业务机制变换，执行 `10-方法卡-业务解压与归纳.md`。22A §1A 使用同一 CA 语言承接正向目标系统设计；稳定性候选通过 22B 展开。

**平凡任务快速通道（封口）**：仅当证据唯一、答案唯一、可逆、局部、无多解释歧义，且不涉及资金/库存/权限/跨作用域等高风险时，允许以**一行理由**声明"不需要结构性探索"并跳过两循环。**该通道不得首次产出 `EVO-T/EVO-E/ESS/BIZ/TGT/MIG`——凡涉及业务本质提炼、正式进化候选、业务机制重设计或核心抽象判断者一律不得进入快速通道**；通道只能产出 `EVO-D` 及其未编号的直接修复、验证和回退方向。若需要形成正式 `EVO-E`，必须退出快速通道，至少取得通过门禁的相关 `EVO-T` 后执行 A3。快速通道仍须检查**一个最小反例**并写明"什么事实会使其失效"，不得只写一句理由；"答案唯一"不得由 Writer 自判为唯一出口，Reviewer 有权否决该路由并强制补走理解循环。凡命中 P0/P1、多解、跨约束冲突或反复修补信号者不得走此通道。

快速通道的最小报告只包含路径理由、`EVO-D`、最小反例、直接修复方向、验证与回退；路径 A 报告的 §2“相关提炼”和 §3“进化方案”必须显式标为“不适用—快速通道未产正式 `EVO-T/E`”，不能伪造空产物补齐模板。V-EVO 对此类报告只验证路由资格、事实证据、反例、兼容、验证和回退，不得因缺少本就禁止生成的 `EVO-T/E` 判失败。

#### 3.3.3 溯因链：阻止机械填表

每个核心洞察使用以下最小推理结构：

```text
S  惊讶事实：实际观察到什么反常、冲突、缺席、绕行或业务失败
M0 当前解释：按现有理解，本来预期什么
Δ 解释缺口：为什么 S 不能由 M0 自然解释
H  候选解释：H 成立时，S 为什么变得可预期
P  冒险预测：H 还预测什么未参与生成 H、可在实施前观察且可能为错的现象
F  推翻条件：哪个最小事实会削弱、缩小或否证 H
```

`P` 不得是“采用方案后指标会改善”这种自我证明，也不得只是重述 `S`。它必须在竞争解释之间产生不同结果，且验证结果无论支持谁都可能改变结论。没有 `S-M0-Δ` 的候选是摘要或自由联想；没有 `P/F` 的候选不得转正为核心洞察。

用“解释增量”比较 `H` 与 `M0`：新增解释了哪些事实/例外、减少了哪些特殊假设、产生了哪些新预测、又引入了多少新概念和无法解释的剩余。更复杂的新抽象若没有更大解释增量，不得胜出。

#### 3.3.4 创造性最低成立条件

一次合格的核心业务提炼或重设计必须同时满足：

1. `CG1` **有惊讶锚点**：明确 `S-M0-Δ`，不是从任务标题或方法名称直接生成结论；
2. `CG2` **不是复述**：删除技术标识后仍成立，并解释至少一个输入未直接写出的关系或现象；
3. `CG3` **存在竞争**：至少比较一个因果结构和预测实质不同的解释，或用排他证据证明答案唯一；
4. `CG4` **具有解释增量**：比 `M0` 多解释事实、少使用补丁假设，且新增概念成本合理；
5. `CG5` **能够生成和冒险**：推出一个实施前可观察、可能为错、能区分解释的新预测；
6. `CG6` **能够被推翻**：写出最小反例、失效条件或区分性验证；
7. `CG7` **能够重设计业务并保持机制韧性**：候选先说明角色、责任、决定、真实结果、激励和反馈怎样变化，再谈系统承载；同时检查代理指标、套利/规避、反馈时滞和风险外溢；
8. `CG8` **安全收敛**：事实、假设和决策未混写，兼容、安全、验证和回退门禁没有降低。

`CG1-CG8` 是 L0 完成定义在 L1 的执行展开，不是另一套创造性理论：L0“溯因”对应 `CG1-CG2`，“解释增量”对应 `CG4`，“竞争”对应 `CG3`，“冒险与可证伪”对应 `CG5-CG6`，“机制韧性”对应 `CG7` 的机制检查；L0 基础五关和工程门禁由 `CG8` 承接。若映射出现冲突，先修改 L0，再同步本节和 §7.1，禁止两套门禁分别判定。

只完成字段覆盖、只提出一个直觉、多个候选只是同义改写、用外部案例代替项目事实，均视为创造性门禁不通过。充分探索后收敛到现有简单方案是允许的，但必须保留排除其他解释和机制的理由。`CG7` 在仅形成理解中间产物时标记“待后续循环”，不能据此宣告整个进化/重构任务完成；正式 `EVO-E/BIZ` 必须通过它。

### 3.4 兼容五查

每个推荐的 `EVO-E-*` 和每个 `MIG-*` 阶段至少完成：

| 维度 | 最低要求 | 通过判定 |
|---|---|---|
| 数据 | 受影响表/字段/枚举、历史数据和权威源 | 已给出保留、回填、迁移或失效结论；未知未被写成无影响 |
| 接口 | 契约、版本和已知调用方 | 已列范围或登记无法穷举；未把未知写成无依赖 |
| 消息 | Topic/事件、生产者、消费者和失败语义 | 重复、乱序、重试、死信及兼容窗口已有结论 |
| 定时任务 | 任务、调度、补偿和任务间依赖 | 已说明受影响任务、先后关系和恢复方式 |
| 配置 | 参数、开关、模板和作用域 | 已说明环境/租户差异、回退值和生命周期 |

需要量化迁移量、不可控调用方、影子流量、A/B、灰度或数据对账时，按风险加载 `12-方法卡-兼容五查与影子验证.md`，不为无关维度机械填深表。

### 3.5 验证与回退

- 每个推荐方案定义基线、目标指标、成功标准、失败标准和停止条件。
- 按风险选择静态证明、测试、影子、A/B、功能开关、灰度或现有等价机制。
- 无法形成可信验证的方案降级为未知或观察项，不得标为可实施结论。
- 涉及数据、契约或消息演进时，必须给出兼容期与回退或前向修复路径。
- 无法物理回滚时，明确不可逆点、补偿、对账和前向修复责任。

## 4. 路径 A：核心抽象内进化

### 4.1 适用边界

路径 A 只管“现有业务地图仍成立时，该修什么、怎样安全演进”。它不得重新定义核心业务本质、目标业务机制、目标架构或核心边界，也不得首次产出 `BIZ-*`、`TGT-*`、`RST-*`、`MIG-*`。

### 4.2 A1 缺陷识别 -> `EVO-D-*`

| 项 | 要求 |
|---|---|
| 输入 | DA8 风险与未决项、DA4 规则缺口、DA7 决策代价、V0-V7 问题 |
| 动作 | 核对证据 -> 拆分问题 -> L0 分型 -> P0-P3 严重度 -> 去重与冲突升级 |
| 输出字段 | 编号、问题、证据、影响、分型及理由、严重度、处理方向、未知项 |
| 门禁 | 每项有证据和分型理由；冲突未仅并列；P0/P1 有处理方向，允许“不做/待确认” |

严重度只表达业务影响，不替代分型：P0 为业务阻断或数据损坏；P1 为能力缺失或显著可靠性/兼容风险；P2 为可以运行但代价高；P3 为体验或整洁性问题。

### 4.3 A2 相关提炼 -> `EVO-T-*`

只提炼会改变当前缺陷、兼容判断或方案选择的结构，不默认全开方法库。

| 项 | 要求 |
|---|---|
| 输入 | 相关 DA2-DA7、`EVO-D-*`、可复用 `ESS-*`、适用的生成/保留样本 |
| 动作 | 装配相关业务活模型；记录 `S-M0-Δ`；从事实上升到对象、关系、规则/不变式、边界、能力和演化轴；按信号执行认知跳跃；高影响判断形成竞争解释并用保留样本收敛 |
| 输出字段 | 编号、`S-M0-Δ-H-P-F`、提炼结论、解释增量和解释剩余、最强竞争解释、决策用途、来源、证据、置信状态 |
| 门禁 | L0 基础五关通过；高影响项同时通过创造性五关；冒险预测可在实施前区分解释；关键 2 跳以上关系已覆盖；每项标注其支撑的 `EVO-D/E`；未把 `CA-*` 假设直接转正 |

无法说明决策用途的提炼降为附录。无法产生新预测的候选通常是事实摘要，不得冒充洞察。继续取证已不改变竞争解释排序、分型、兼容判断或方案选择时停止；正式报告必须能压回 L0 最小骨架。

### 4.4 A3 进化候选 -> `EVO-E-*`

| 项 | 要求 |
|---|---|
| 输入 | 已通过门禁的 `EVO-D-*` 与相关 `EVO-T-*` |
| 动作 | 明确真实业务结果 -> 保持核心抽象与不变量 -> 用业务机制变换形成候选（含不做）-> 比较因果机制、激励、指标博弈、反馈延迟、收益/成本/风险和二阶影响 -> 五查 -> 最小实验/验证 -> 兼容与回退 |
| 输出字段 | 编号、目标缺陷/机会、当前与目标业务机制、候选及实质差异、改善结果的因果链、不同预测、受益/受损角色、激励与可博弈性、反馈延迟/外部性、五查、指标与阈值、迁移/回退、影响范围、推荐状态 |
| 门禁 | 不改核心抽象；至少保留不做基线；多个候选不是同一机制的技术变体；指标不能替代真实结果；博弈和外溢风险已检查或有不适用证据；修复与演进未混写；五查完整；可验证或已降级；高风险项有回退/前向修复 |

候选数量服从真实决策空间，不机械凑数；高影响问题除“不做”外，至少探索一个非直接修补的机制候选，若不成立则记录淘汰证据。只有技术实现不同、业务责任和因果机制相同的方案属于一个候选。稳定性问题按需调用 22B，22B 产生的机制候选仍须回到本路径完成兼容和验证收敛。

阶段末给出“方案面结论”：推荐、缓做、不做、升级路径 B 的项目及成立条件。

|---|---|---|
| §0 核心结论 | 范围、关键缺陷、核心结构、推荐路径、主要风险 | 不另编号 |
| §1 缺陷清单 | A1 | `EVO-D-*` |
| §2 相关提炼 | A2 | `EVO-T-*` |

| §4 未决项 | 缺证据、不可验证、需人工决定 | `EVO-U-*` |

### 4.6 升级路径 B

出现任一信号时，停止新增 `EVO-E-*`，保留证据并重跑 L0 §7.1 `K1-K5`。下列只是触发重判的证据信号，不是另一套核心抽象定义；重判命中任一 `K` 才升级：

1. 修复无法在不改变对象身份、生命周期或主关系的情况下完成；
2. 多个缺陷反复指向同一错误抽象或错误边界；
3. 兼容五查显示需要跨代数据、接口或消息语义重映射；
4. 候选差异已是业务地图、能力语义或一致性边界变化；
5. 推断有意设计的原约束已被突破。

升级时携带 `EVO-D/T`、`CA-*` 探索痕迹、五查和未知项，并更新路径纪元、切换次数、命中的 `K` 与新增证据。`EVO-E-*` 只能作为后续候选，不得直接升级为 `BIZ-*`、`TGT-*` 或 `MIG-*`。若这是同一任务的第二次切换，先执行 L0 §7.2 裁决，不得继续自动推进。

## 5. 路径 B：设计评估与核心重构

### 5.1 适用边界

路径 B 管“设计是否仍成立、业务地图是否必须重画、目标应如何映射、怎样安全迁移”。它不把任何新架构设为默认答案，也不负责代码实施。

### 5.2 B1 设计评估 -> `REV-*`

评估前先回答：当时要解决什么、受什么约束、主动牺牲了什么、哪些假设后来变化。

| 维度 | 核心问题 |
|---|---|
| 职责分配 | 变化原因相同的职责是否聚合，不同变化原因是否混合 |
| 抽象层次 | 业务判断是否被技术细节、数据表示或部署选择绑架 |
| 关注点分离 | 业务、策略、配置、基础设施的依赖方向是否清晰 |
| 一致性 | 同一概念、状态和规则是否同义并受同一不变式约束 |
| 演进能力 | 高频变化是否反复修改核心路径，关键选择能否渐进替换 |

| 项 | 要求 |
|---|---|
| 输入 | DA0-DA8、设计意图、V/EVO 补充证据 |
| 动作 | 追溯意图 -> 选择核心对象 -> 五维评估 -> 识别退化与冲突 -> 保留/修复/重构判断 |
| 输出字段 | 编号、对象与范围、原意图、约束变化、五维判断、证据、结论、置信度、方向 |
| 门禁 | 核心对象五维覆盖；判断有证据与理由；确认/推断意图分开；冲突已升级 |

每个核心对象可使用 1-5 分暴露判断，但分数不能替代文字结论。评分锚点和重新选型细节按需加载 `11-方法卡-设计评分与重新选型.md`。

阶段末给出“设计评估总结”：仍成立的设计、已经退化的设计、根因、最大不确定项和路径判断。

### 5.3 B2 业务本质 -> `ESS-*`

| 项 | 要求 |
|---|---|
| 输入 | DA2-DA7、`REV-*`、相关 `EVO-T-*`、生成样本与保留样本 |
| 动作 | 执行**理解循环 CA0-CA5**：建立 `M0` -> 装配业务活模型和 `S-M0-Δ` -> 认知跳跃生成竞争解释（CA3）-> 竞争与冒险预测（CA4）-> 本质候选（CA5）-> 用反证与保留样本**独立验证后转正**为 `ESS` |
| 输出字段 | 编号、骨架类型、`S-M0-Δ-H-P-F`、业务陈述、解释覆盖与解释剩余、现状映射、稳定/变化属性、最强竞争解释、保留样本结果、证据、置信度 |
| 门禁 | L0 基础五关和创造性五关全部通过；关键 2 跳以上关系覆盖；技术偏好未冒充本质；外部类比未冒充事实；可压回 L0 骨架 |

阶段末给出“业务本质总结”：系统为谁解决什么、通过什么业务机制产生结果、稳定层与变化层是什么、边界为什么这样划分、它比最强竞争解释多解释了什么、什么事实会推翻该理解。

### 5.4 B3 创造性业务重设计 -> `BIZ-*`

`ESS-*` 回答“当前业务本质是什么”，`BIZ-*` 回答“目标业务应怎样更好地履约、控制风险或创造价值”。这一阶段只设计业务机制，不选择数据库、中间件、部署形态或代码模式。

| 项 | 要求 |
|---|---|
| 输入 | 已通过门禁的 `REV+ESS`、业务目标、不可突破的不变量、现实约束、适用 `CA-*` |
| 动作 | 执行 CA6-CA8：核对真实结果与代理指标 -> 保留价值与不变量 -> 改变角色责任、决策/控制点、义务、反馈、协作、激励或例外机制 -> 形成因果机制不同的候选 -> 推演博弈、反馈回路和二阶影响 -> 用最小实验、反事实和责任人判断收敛 |
| 输出字段 | 编号、来源 `REV/ESS/CA`、服务对象与真实目标结果、代理指标及偏离风险、当前机制及代价、目标机制主链、改变的角色/权利/义务/控制点/边界、改善结果的因果链、不同预测、受益/受损角色、激励与可博弈性、反馈延迟和外部性、最小实验、指标/停止条件、兼容前提、失效条件、决策状态 |
| 门禁 | 至少保留不做基线、一个最小机制改进和一个结构性候选，或给出某层不成立的证据；候选差异是业务因果机制而非技术选型；业务目标有责任人和来源；代理指标不能冒充目标；博弈、反馈和外部性已检查；可验证、可证伪、可兼容或已降级 |

优先使用 `10-方法卡-业务解压与归纳.md` 的责任重配、控制点迁移、隐性显式化、闭环反馈、稳定/变化分离、协作方式反转、例外正规化和价值/风险重配。算子只产生候选，不预设更高变化层级更好。

阶段末给出“业务重设计总结”：明确推荐、备选和不做；每项如何改善业务结果、谁受益、谁付出代价、最可能失败在哪里、用什么最小证据决定是否继续。未经业务责任人批准的 `BIZ-*` 只能标“提议/待验证”，不得伪装成既定需求。

### 5.5 B4 目标系统设计 -> `TGT-*` / `RST-*`

目标系统的完整设计以 22A 为唯一总纲；涉及可靠性目标、故障治理、数据收敛、容灾或事故响应时，同时执行 22B。本文只负责把已选定的业务机制转换为设计任务和受检决策，不复制 22A/22B 的完整设计维度。

| 项 | 要求 |
|---|---|
| 输入 | 已通过门禁的 `REV+ESS`、已批准或待批准的 `BIZ-*`、当前约束、运行基线和 22A 设计产物 |
| 动作 | 将 `BIZ` 的角色、决定、义务、控制和反馈映射为 22A 设计任务 -> 定义目标不变量与边界 -> 展开系统候选 -> 比较取舍 -> 必要时重新选型 -> 建立现状差距 |
| 输出字段 | 编号、目标对象、来源 `REV/ESS/BIZ`、所承载的业务机制、目标描述、系统候选与取舍、代价、约束、失效触发、差距、22A/22B 产物位置、决策状态 |
| 门禁 | 每项可由 `REV+ESS+BIZ` 推导；若业务机制明确不变则显式记录；22A 适用门禁通过；不变量先于技术；候选与放弃理由真实；代价和失效条件明确 |

只有现有技术或架构无法承载目标业务语义和演化轴时才产出 `RST-*`。可渐进实现且代价可接受时，不得为了现代化重新选型。

“待批准”的 `BIZ-*` 只能生成提议态 `TGT-*` 以暴露承载代价；`BIZ-*` 未批准时，`TGT-*` 不得标为已批准或进入实施。业务机制不变声明也必须由相应业务责任人确认。

阶段末给出“目标系统设计总结”：系统如何承载 `BIZ`、关键变化、为何更好、主动接受的代价、明确不改的部分和待批准决策。若两个系统候选承载同一业务机制，应作为同一 `BIZ` 下的技术取舍比较，不得冒充业务创新。

### 5.6 B5 迁移路径 -> `MIG-*`

22A 规定目标设计必须考虑兼容和可迁移性；本文的 `MIG-*` 是**针对特定既有系统迁移的唯一决策真源**。

| 项 | 要求 |
|---|---|
| 输入 | `TGT/RST`、`REV` 差距、五类存量契约、运行与发布约束 |
| 动作 | 按可验证边界拆阶段 -> 定义依赖和关键路径 -> 设计兼容/数据迁移/验证 -> 定义停止与回退/前向修复 -> 评估风险 |
| 输出字段 | 编号、目标、依赖、输入、输出、影响范围、兼容策略、指标/阈值、停止条件、回退/前向修复、风险与责任 |
| 门禁 | 每阶段可独立验证；五查覆盖；依赖明确；失败不落入不可解释中间态；数据变化有对账和修复方向 |

阶段末给出“迁移路径总结”：先后顺序、关键依赖、最大风险、不可逆点、停止策略和责任人。

### 5.7 路径 B 报告

| 章节 | 内容 | 编号 |
|---|---|---|
| §0 核心结论 | 本质、现状、根因、行动优先级、目标与迁移方向 | 不另编号 |
| §1 设计评估 | B1 | `REV-*` |
| §2 业务本质 | B2 | `ESS-*` |
| §3 目标业务机制 | B3 | `BIZ-*` |
| §4 目标系统设计 | B4，并引用 22A/22B 正文 | `TGT-*` / `RST-*` |
| §5 迁移路径 | B5 | `MIG-*` |
| §6 未决项 | 缺证据、不可验证、待批准 | `DES-U-*` |

§0 必须回答：一句话本质、现状判断、根因判断、目标业务机制、行动优先级和系统/迁移总方向。每个判断必须能在 §1-§5 找到来源。

### 5.8 降级路径 A

`REV-*` 证明问题只属于可靠性缺陷、局部策略或实现手段时，可以申请降级路径 A，不必继续生成 `ESS/BIZ/TGT/MIG`。降级不是 Writer 的自由出口，必须同时满足：

1. 依据当前事实基线重跑 L0 §7.1，`K1-K5` 五项均明确“不改变”；
2. 写明推翻原路径 B 判定的**新增/新验证证据**，或由 Reviewer/Referee 确认的原推理、范围、引用错误；同一证据不得在没有纠错记录时同时保留为升级理由；
3. 未参与原路径判定的 Reviewer 独立确认 `REV-*`、`K1-K5` 和反方解释；
4. 更新路径纪元、累计切换次数和锁定/重开条件；若这是第二次及后续切换，先由 Referee 或人工责任人裁决。

保留 `REV-*`、证据和完整切换历史作为路径判定依据，后续 `EVO-*` 引用它，不重复改写事实。任一条件缺失时保持路径 B 或标记路径证据不足，不得通过降级提前结束重设计循环。

## 6. 编号、复用与执行痕迹

### 6.1 编号归属

| 编号 | 首次产出位置 | 复用规则 |
|---|---|---|
| `CA-*` | 路径 A/B 探索空间或 22A | 仅作可淘汰的探索痕迹，不得冒充事实、正式业务结论或批准决策 |
| `EVO-D/T/E/U` | 路径 A | 可输入路径 B，原编号和含义不变 |
| `REV/ESS/BIZ/TGT/RST/MIG/DES-U` | 路径 B | 路径 A 只能按 §6.2 作为证据或受检复用来源；目标态语义不得直接成为 A 的正式结论，且不得由 A 首次产出 |
| L0 骨架字段 | L0/L1 | 形状和完成定义服从 L0 |
| 方法卡中间产物 | L2 | 不得直接冒充正式业务结论 |

`BIZ-*` 是 v1.1 新增的目标业务机制接口。既有报告中的 `TGT-*` 不要求追溯改号；后续实质修订时，应补 `BIZ-*`，或明确记录“业务机制不变，TGT 仅改变系统承载”。

### 6.2 跨路径复用

- `EVO-D -> REV`：保留原编号，补设计意图和结构判断；
- `REV -> 路径 A 证据`：只能作为原设计判断的证据输入，不能直接成为 `EVO-T/E` 结论；按当前事实基线重新分型并执行适用的理解循环；
- `ESS -> EVO-T`：先重验 DA 一致性，再逐项执行 `K1-K5` 投影，写明复用的对象/关系/不变式/边界/能力在**当前核心抽象内**怎样保持不变；由独立 Reviewer 复核后，才能转为新的 `EVO-T`。若 `ESS` 依赖目标态、已重构对象或任一 `K` 变化，只能留在路径 B，禁止截取措辞后降格复用；
- `CA -> EVO-T/ESS/BIZ`：只能在通过反证、区分预测和适用证据门禁后转正；未转正的 `CA` 保持假设状态；
- `ESS -> BIZ`：先确定保护的不变量和目标结果，再生成目标业务机制；禁止从单个缺陷直接跳到 `BIZ`；
- `BIZ -> TGT`：`TGT` 只映射已经选择的业务机制；若 `BIZ` 未批准，`TGT` 必须保持提议状态；
- `EVO-E -> MIG`：只能作为候选步骤，必须补目标差距、依赖、兼容、验证和回退；
- 禁止由 `EVO-*` 直接导出 `BIZ/TGT/MIG`；
- 禁止由方法卡直接导出业务目标或批准决策。

### 6.3 执行痕迹

- 报告开头记录输入文件、版本、适用范围、路径判定、创造性循环适用性、门禁结果和未加载材料；
- 每次路径切换记录路径纪元、事实基线、`K1-K5` 变化、新增证据、累计次数、Reviewer/Referee 决定和路径重开条件；
- 证据引用使用 `{来源:位置}` 或等价可解析格式；
- 报告末尾给出“规范要求 -> 实际位置 -> 状态”对照表；
- 决策状态标明提议、待批准或已批准；
- 核心结论保留最强竞争解释、区分预测和否证痕迹；不得只展示胜出答案；
- 修订不得悄悄改变稳定编号的既有含义。

## 7. 独立验证

### 7.1 共同要求

V-EVO 和 V-DES 均由未参与生成的独立角色执行。Writer 自检不能替代独立验证。

共同 P1 条件：

| 检查项 | P1 判定 |
|---|---|
| 路径正确性 | 改核心抽象仍走 A，或局部缺陷无理由升级 B；同一证据触发反向切换；第二次切换无 Referee/人工裁决；路径 A 未经 `K1-K5` 投影复用目标态 `ESS` |
| 事实真实性 | 关键结论无可解析证据，把推断/假设写成事实 |
| 分型正确性 | 未分型、分型与行动矛盾，或修复与重构混写 |
| 创造真实性 | 无 `S-M0-Δ`；核心结论只是复述/改名；只有一个直觉；竞争解释预测相同；类比未做结构差异验证 |
| 证伪真实性 | 冒险预测只是重述或方案实施后的自我证明；用生成假设的同一证据冒充保留样本；没有最小反例或失效条件 |
| 机制韧性 | `BIZ/EVO-E` 只优化代理指标；未检查适用的激励博弈、反馈延迟或风险外溢；受损角色被隐藏 |
| 业务/系统分层 | 从 `ESS` 或缺陷直接跳到技术 `TGT`，没有 `BIZ` 或“业务机制不变”声明 |
| 兼容完整性 | 五查缺项，或以未知推断无依赖 |
| 可验证性 | 推荐无指标、通过/失败标准或停止条件且未降级 |
| 回退完整性 | 高风险变化无兼容期、回退或前向修复 |
| 人读结论 | §0 无来源、与明细矛盾或不能独立说明判断 |
| 执行痕迹 | 缺输入、路径、门禁、证据或字段对照记录 |

每个核心洞察还必须由独立 Reviewer 逐条完成 `CG1-CG8` 映射，不能只引用 Writer 的自检勾选：

| 门禁 | Reviewer 必须执行的独立动作 | 最小证据 | 失败处理 |
|---|---|---|---|
| `CG1` 惊讶锚点 | 回到原始事实确认 `S`，并核对 `M0` 是否真的预期相反结果 | 事实位置、预期与实际差异 | 洞察退回摘要/假设 |
| `CG2` 不是复述 | 删除领域与技术标识，检查结论是否仍是任意系统都适用的空话 | 删除标识后的表述与区分事实 | 判创造真实性 P1 |
| `CG3` 存在竞争 | 独立提出一个因果结构不同的反方解释，或复核排他证据 | 反方解释、不同预测或唯一性证据 | 不得转正本质 |
| `CG4` 解释增量 | 核算新增解释事实、减少的补丁假设、剩余事实和概念成本 | `M0/H` 对照 | 保留为候选或淘汰 |
| `CG5` 生成和冒险 | 检查预测是否在实施前可观察、可能为错且能区分解释 | 冻结的 `P` 与观察窗口 | 判证伪真实性 P1 |
| `CG6` 能够被推翻 | Reviewer **独立提出并验证至少一个最小合法反例**，确认命中后会削弱、缩小或否证结论 | 独立反例、`F`、验证结果或计划 | 无真实推翻路径即 P1 |
| `CG7` 重设计业务与机制韧性 | 对 `EVO-E/BIZ` 检查角色、责任、决定、真实结果、激励和反馈是否改变，排除纯技术变体，并攻击代理指标、套利/规避、反馈时滞和风险外溢 | 机制差异、不同预测与博弈/外溢反例 | 不得形成正式 `EVO-E/BIZ` |
| `CG8` 安全收敛 | 独立核对事实/探索/决策分层及兼容、安全、验证、停止和回退 | 门禁位置与未决项 | 不得进入批准或实施 |

任一适用 `CG` 未独立验证即属于 P1，不能用“Reviewer 抽查”降级。理解中间产物的 `CG7` 可以暂记“待重设计循环”，但任务不得因此宣告完成；快速通道不产生核心洞察，按 §3.3.2 的专用最小报告验证。

验证问题必须包含编号、级别、证据、文档位置和修正动作。修正后重跑原反证与受影响门禁；不得删除失败案例、放宽标准或改写事实制造通过。

### 7.2 V-EVO 专项

- `EVO-D/T/E` 的问题、提炼和方案能够互相追溯；
- 高影响 `EVO-T/E` 留有 `S-M0-Δ-H-P-F`、解释增量、实质竞争解释和收敛证据；
- 方案没有改变核心抽象；
- 多个候选不是同一业务机制的技术变体，非直接修补候选被采用或有证据淘汰；代理指标、激励博弈、反馈延迟和风险外溢已检查；
- “不做”基线和机会成本真实；
- 观察项没有冒充可实施结论；
- P0/P1 缺陷有处理方向，风险接受有权责和期限。

### 7.3 V-DES 专项

- 核心对象五维评估有证据，确认意图与推断意图分开；
- `ESS-*` 能形成 L0 骨架，关键冲突已经升级，并通过 L0 创造性五关；
- 核心本质结论具有 `S-M0-Δ-H-P-F`，与最强竞争解释存在冒险预测，保留样本或等价区分性验证真实执行；
- `BIZ-*` 先于系统方案说明目标角色、责任、决定、结果、激励和反馈，且有因果链、代理指标风险、可博弈性、反馈/外部性、二阶影响、最小实验和失效条件；
- `TGT/RST` 可回指 `REV+ESS+BIZ`（或业务机制不变声明），并通过 22A/22B 的适用门禁；
- 每个关键 `MIG-*` 阶段有依赖、兼容、验证、停止和回退/前向修复；
- 目标设计没有把提议写成已批准 ADR。

### 7.4 方法能力迁移压测（能力基准）

本节校准“这套规范能否驱动创造性分析”，不替代具体项目的 V-EVO/V-DES。本基准是**可重复执行的评分基准**，不是一次性原则。首次采用本规范，或实质修改 AI、Prompt、L0/L1/L2 创造性方法后，必须全项执行；后续至少按轮换周期复测一次。

**测试集管理**：
- 维护**隐藏测试集**：至少 3 个领域 × 每领域 1 个未见变体，随轮换周期轮换（换领域/角色/失败机制），使同一 AI 不能靠记忆某套答案通过；
- **材料隔离**：生成样本与保留样本/反证包分置，由未参与生成、作答和评分的保管者持有反证包；首轮作答前，AI 与评估者只能获取生成样本；
- **分阶段揭示**：AI 提交并冻结首轮 `H/P/F` 后，保管者才向 AI 与评估者同时揭示保留样本/反证包，禁止事后改写原预测；
- **独立双评分**：至少两名未参与生成和作答的评估者在讨论前分别评分；每个 2 分必须同时引用被测输出位置和保留样本/反证证据。任一项分差 ≥1 时交 Referee 按量表裁决并保留原分、理由和裁决，不能用协商平均分制造通过；
- **无标准创意答案**：反证包只保存隐藏事实、最小业务契约和已知违规捷径，不保存唯一候选名或唯一抽象；结构不同但同样可证伪、能解释事实的答案按量表评分，不能因未命中预想措辞而扣分；
- **生成与结论分离**：只给被测 AI 事实语料、现实约束和本规范，不给样例结论、候选名或期望抽象。

**评分量表与通过阈值**（每项 0-2 分，未做 0 / 部分 1 / 达成 2）：

每个有效测试包必须让以下 7 项都可观察：至少包含能触发实质溯因/竞争的惊讶事实、可形成不同业务机制的现实约束，以及会检验证据更新和机制韧性的隐藏反证。某项因题目设计无法评分时，该测试包无效，必须更换，不能记“不适用”后降低分母。

| 能力项 | 达成（2 分）标准 |
|---|---|
| 溯因 | 产出真实 `S-M0-Δ-H-P-F`，惊讶锚定项目事实，不是从标题改写 |
| 竞争 | 至少两个因果结构、预测不同的解释；被否决者有留档 |
| 解释增量 | 比 `M0` 多解释事实、少补丁假设，新增概念成本透明 |
| 冒险与可证伪 | 冒险预测实施前可观察、可能为错、能区分解释，非自我证明 |
| 机制生成 | 从已验证 `EVO-T/ESS` 形成不做基线、最小机制改进和至少一个因果机制不同的结构性候选，或给出某层不成立的证据；不得用技术变体冒充业务重设计 |
| 机制韧性 | 识别代理指标、激励博弈/套利、反馈时滞、风险外溢的适用项 |
| 证据更新 | 揭示保留样本后，对照已冻结的 `P/F` 比较信息增量，并按证据比例保持、增强、缩小、削弱或否证解释；保留更新链且不事后改写预测。固守反例或无条件迎合、盲目改口均为 0 分 |

没有“输出位置 + 隐藏证据 + 判分理由”三项证据的 2 分无效，最高只能记 1 分。Referee 只能解释量表和证据，不能降低 2 分标准或追加标准答案。

**通过阈值（非补偿式）**：共 7 项、满分 14 分，**7 项必须全部达到 2 分，总分必须为 14 分**，才记为“能力达成”。任一项为 1 只表示该能力“部分出现”，仍记为**能力未达成**；任一项为 0 同样失败。总分只用于校验记录，不允许用机制生成、证据更新或其他强项补偿溯因、竞争、解释增量、冒险与可证伪等弱项。“弱归纳但能生成方案”与“会改口但不会按冻结预测更新证据”都必须失败。

**多领域连续通过要求**：单领域通过不算达标。首次采用或实质修改后，必须在作答前冻结至少 **3 个不同领域**及顺序，并让全部领域分别取得 14 分；任一领域失败即本轮整体未达成，禁止事后只挑两个通过领域报告。例行轮换复测至少预先指定 2 个不同领域并连续通过，任一失败即重新开始连续计数。跨领域时更换领域、角色或失败机制，禁止用复述公开样例证明。

**记录要求**：每次压测记录 AI 冻结的首选解释与 `P/F`、揭示保留样本后的实际更新（保持/增强/缩小/削弱/否证）及逐项证据、是否出现固守或盲目迎合、未达成项及归因（触发信号不足？门禁不严？Prompt 缺失？）。压测失败时，应修正触发信号、认知动作或否证门禁——**不得靠增加表格字段制造通过**。

首次采用或实质修改后，对预先冻结的全部领域执行完整 7 项评分；之后按轮换周期复测，防止记忆或挑选结果通过。

`91-样例-权益恢复/创造性归纳与业务重设计压测.md` 是公开回归夹具，只能验证方法契约和输出形状。AI 已见其答案时，必须更换领域、角色或失败机制再测，不能用复述样例证明创造能力。压测失败时，应修正触发信号、认知动作或否证门禁，不得靠增加表格字段制造通过。

## 8. 与其他文档的关系

```text
文档 20 / 21
  -> L0 + L2：事实解压、活模型、创造性归纳、骨架与分型
  -> 本文：路径 A 或路径 B 的决策治理
     -> ESS：当前业务本质
     -> BIZ：目标业务机制
     -> 22A：目标业务系统完整设计（TGT）
        -> 22B：稳定性专项
  -> 已批准方案
  -> 安全修改实施规范
```

| 文档 | 唯一职责 |
|---|---|
| 文档 20 / 21 | 既有系统事实重建与独立反证 |
| L0 / L2 | 强归纳双循环、业务活模型、认知跳跃、假设竞争、业务机制变换、分型与路径判据 |
| 本文 | 既有系统创造性理解、提炼、业务重设计，以及进化/重构的决策、兼容、验证和迁移治理 |
| 路径 A Profile | 旧任务、旧链接和旧 Prompt 的可执行兼容入口；公共规则与产物语义仍服从本文 |
| 22A | 目标业务系统正向完整设计 |
| 22B | 目标系统的稳定性与可靠性专项设计 |
| 90/91 方法样例 | 解释方法、执行回归和跨领域压测；不是项目事实、规则真源或可复制业务答案 |
| 安全修改规范 | 经批准方案的代码、配置、数据和发布实施 |
