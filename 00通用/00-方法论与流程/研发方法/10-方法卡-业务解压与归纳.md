# 10-方法卡-业务解压、创造性归纳与重设计

> **层级**：L2 方法卡  
> **用途**：为统一 L1 的路径 A `EVO-T/E`、路径 B `ESS/BIZ` 提供业务解压、洞察生成、假设竞争和业务机制重设计方法  
> **上位约束**：`00-强归纳理论核.md`；本卡不得改写 L0 四律、骨架和完成定义  
> **正向接口**：22A §1A `CA0-CA8`；本文与其使用同一创造性分析语言  
> **压测样例**：`91-样例-权益恢复/创造性归纳与业务重设计压测.md`  
> **版本**：v1.3 | **日期**：2026-08-06

## 1. 使用方式

先识别压缩信号，再选方法。恢复性归纳负责还原已经存在的业务语义；生成性归纳负责提出竞争解释和新预测；业务重设计负责在不编造目标的前提下改变业务机制。三者不得混成一次“填表”。

```text
事实信号 -> 当前解释 M0 -> 惊讶事实 S 与解释缺口 Δ
        -> 选择解压卡 -> 装配活模型
        -> 溯因与创造性跳跃 -> 竞争假设 -> 冒险预测 -> 区分性验证
        -> L0 骨架 / ESS -> 业务机制候选 BIZ -> 目标系统设计
```

每次使用记录：触发信号、输入证据、所用方法、形成的骨架字段、反证结果和决策影响。

以下任务必须执行完整的**理解循环与重设计循环**：路径 B 的业务本质与业务重设计、正式或高影响结论、存在多个合理解释，或命中 L0 §10.5 的反复修补信号。答案明确且可逆的局部缺陷可以精简，但必须写明为什么不存在需要区分的结构性解释。

## 2. 信号到方法

| 信号 | 首选方法 | 主要产物 |
|---|---|---|
| 同名不同义、技术名掩盖业务含义 | 概念净化 | 对象、能力、语义边界 |
| 对象通过中介间接影响、归属不清 | 关系还原 | 主关系、2 跳以上隐性契约 |
| 分支/校验/异常散落 | 规则抽象 | 不变式、策略、例外 |
| 步骤很多但目的不明 | 流程抽象 | 业务阶段、状态转换、补偿点 |
| 多套实现名称不同但目的相同 | 多实现归一 | 共同能力、变化点、冲突 |
| 配置、枚举和条件持续膨胀 | 策略识别 | 演化轴、策略边界 |
| 创建/过期/重试/结算时点混乱 | 时间维度分析 | 生命周期、时效不变式 |
| 失败路径决定数据与补偿 | 异常归类 | 失败语义、恢复边界 |
| 一起创建/修改/失败的范围不清 | 一致性边界分析 | 边界、不变式 |
| 模块边界与业务变化不同步 | 业务边界划分 | 能力边界、依赖方向 |
| 系统对外价值被接口清单淹没 | 能力图谱 | 业务能力与服务对象 |
| 单个事实都合理但组合后出现断点 | 跨事实组合 | 隐性契约、时间断点、跨边界矛盾 |
| 活模型遇到异常、延迟或角色变化无法推演 | 反事实 | 缺失规则、恢复机制、失效条件 |
| 同类系统通常具备但当前材料未出现 | 期望违例 | 待验证的缺席能力或历史假设 |
| 第一反应已经是表、接口、组件或架构方案 | 重新框定 | 业务承诺、决策、义务、风险或控制点 |
| 历史设计反复增加例外 | 假设考古与反转 | 原假设、突破证据、演化轴 |
| 存在结构相似的成熟领域 | 结构类比 | 可迁移机制、差异和验证问题 |
| 高影响问题存在多个解释 | 竞争假设 | 不同预测、区分性验证、信息增益 |
| 已知本质但现有履约方式不再合适 | 业务机制变换 | `BIZ-*` 候选及最小实验 |
| 实际行为偏离当前模型本应产生的结果 | 惊讶驱动溯因 | `S-M0-Δ-H-P-F` 与解释增量 |
| 局部指标改善但用户/业务结果恶化 | 因果回路与博弈 | 代理指标失真、激励错配、反馈和外部性 |

## 3. 表示解压

### 3.1 概念净化

1. 收集同一词在代码、表、接口、配置和流程中的定义；
2. 区分业务身份、数据表示、技术载体和历史别名；
3. 对同名不同义拆分，对异名同义合并；
4. 给出业务定义、反例、生命周期和证据；
5. 冲突无法消解时升级为“语义分裂”，不得强行统一。

### 3.2 时间维度分析

检查创建、生效、执行、过期、关闭、重试、补偿、归档的业务时间与系统时间。输出时间事件、时效规则、允许乱序、过期后的权利义务和恢复策略。

### 3.3 能力图谱

从“谁为了什么结果使用系统”出发定义能力，而不是从 Controller、菜单或接口命名能力。能力至少包含服务对象、触发、业务结果、关键约束和实现映射。

---

## 4. 层级解压

### 4.1 规则抽象

将散落条件归成：资格规则、计算规则、状态转换、不变式、策略和例外。先找不允许被破坏的结果，再判断条件是业务规则还是技术保护。

### 4.2 策略识别

当同一目标存在多种可替换做法，且选择随租户、场景、规模或时间变化时，将其识别为策略。稳定不变的约束不是策略，不能为了扩展性全部配置化。

### 4.3 异常归类

按业务语义区分：拒绝、可重试失败、需补偿失败、部分成功、人工介入和不可恢复失败。异常类型必须影响调用方决策，否则只是技术分类。

---

## 5. 语境解压

### 5.1 关系还原

从直接引用扩展到业务路径：A 经 B 影响 C、谁拥有谁、谁决定谁、谁必须与谁一致。对 2 跳以上关系记录路径、传播规则、断裂后果和证据。

### 5.2 流程抽象

把方法调用序列压成业务阶段：触发、校验、决策、执行、确认、失败恢复。每阶段写清输入、业务结果、状态变化、不变式和补偿，不保留无决策价值的技术步骤。

### 5.3 边界与一致性

用“一起变化、一起成功/失败、一起过期、一起回溯”判断边界。数据库事务、服务部署或包结构只是证据，不能自动等同业务边界。

### 5.4 多实现归一

1. 对齐共同业务目的；
2. 分离共同不变式与实现差异；
3. 判断差异是策略、渠道约束、历史妥协还是语义冲突；
4. 只统一真实共性，保留有意义差异；
5. 冲突必须升级为语义分裂、边界错误或原假设失效等判断。

| 归属、路由、依赖与传播路径 | 关系 |

## 7. 创造性洞察生成

### 7.1 先建立归纳对象和保留样本

创造性不是脱离对象自由联想。执行 `CA0` 时先建立证据语料，并在提出核心假设前划出至少一组**未用于生成该假设**的保留样本：

- 正常主路径：系统如何兑现业务结果；
- 边界或失败路径：重复、延迟、部分成功、取消、人工补救；
- 变体：渠道、组织、客户、地区、版本或多实现差异；
- 历史样本：旧数据、旧契约、原设计决策和已废弃路径。

按任务适用性选取，不机械凑齐。没有可用保留样本时，必须设计一个未来可观察的新场景或最小实验，并把结论保持为假设；不得用生成假设时已经挑中的同一条证据冒充独立验证。

### 7.2 装配业务活模型

用一句可推演的主链描述当前理解：

```text
谁为了什么结果
  -> 在什么触发和信息下作出什么决定或承诺
  -> 对什么对象执行什么动作或交换
  -> 谁获得什么结果、承担什么义务或风险
  -> 失败如何恢复，结果怎样反馈到下一次决定
```

把事实、推断、假设和未知分别标记。若模型只能写成接口调用序列或表关系，尚未形成业务活模型，不得进入创造性推演。

### 7.3 惊讶驱动的溯因跳跃

创造性归纳从当前解释失败的地方开始，而不是从“请创新”开始：

```text
S  惊讶事实：反常、冲突、缺席、绕行或业务失败
M0 当前解释及其本来预测
Δ  S 与 M0 的解释缺口
H  让 S 变得可预期的候选解释
P  H 独有、实施前可观察且可能失败的冒险预测
F  削弱或否证 H 的最小事实
```

操作顺序：先固定 `S/M0/Δ`，再生成 `H`；否则 AI 容易先想一个漂亮概念，再挑事实为它背书。比较候选时记录**解释增量**：相对 `M0` 新解释了什么、减少了哪些补丁假设、产生了什么新预测、引入了多少新概念、仍剩哪些事实无法解释。

合格的 `P` 必须满足：竞争解释给出不同结果；无需先实施推荐方案即可观察；结果为反方时会改变结论。`P=S`、泛化常识、“方案上线后会更好”和无法失败的预测均不合格。

### 7.4 七种认知跳跃

方法用于产生候选，不直接产生事实结论。按信号选择，路径 B 至少使用一种“事实内部重组”方法和一种“改变观察条件”方法；没有产生新候选也要保留淘汰理由。

| 方法 | 怎么做 | 合格候选 | 防失真要求 |
|---|---|---|---|
| 反事实 | 每次只改变一个关键条件，如角色、顺序、延迟、规模、依赖或失败方式；保持其他不变量，沿活模型推演 | 暴露缺失规则、恢复边界或不同预测 | 不把虚构场景写成已经发生的事实 |
| 期望违例 | 先写明“为什么按业务承诺或同类结构应该存在”，再查当前材料是否出现 | “该有而未见”的能力、控制或反馈假设 | 未找到证据只能标“待验证缺席”，不能直接判缺陷 |
| 跨事实组合 | 选取分属不同对象、阶段、文件、时间或边界的事实，做 AND/先后/互斥/守恒组合 | 任一单项都未直接写出的隐性契约、断点或冲突 | 必须给出完整组合链和断裂后果 |
| 重新框定 | 删除表、字段、接口、组件名，连续追问“它代表谁的什么决定、承诺、义务、风险或结果” | 能改变问题边界或候选空间的业务表述 | 只换高级名词、没有新预测，不算重构 |
| 结构类比 | 映射源领域与当前业务的角色、关系、不变量、状态和失败机制，再列结构差异 | 可迁移的业务机制和待验证空缺 | 概念同名不算同构；必须写明不能迁移什么 |
| 假设考古与反转 | 从稳定路径和历史决定还原“当时必须成立什么”，再令规模、渠道、时效、组织或风险条件反转 | 原设计假设的失效点、演化轴或新机制候选 | 不能用今天的偏好倒推历史错误 |
| 因果回路与博弈 | 画出“角色行动 -> 指标/收益 -> 反馈延迟 -> 下一步行动 -> 最终结果”，尝试让参与者在规则内优化自身利益 | 代理指标失真、激励错配、正/负反馈、风险外溢和套利路径 | 不凭道德判断猜动机；必须说明角色可见信息、可选行动和收益/代价 |

### 7.5 换眼镜，不换形容词

当第一种描述只能复述材料时，至少选择两个能产生不同预测的视角重看同一活模型：

| 视角 | 追问 |
|---|---|
| 结果与价值 | 用户真正需要完成什么，什么结果值得付出成本？ |
| 角色与激励 | 谁受益、谁付款、谁承担风险、谁有权决定、谁被迫补救？ |
| 权利与义务 | 谁应在什么条件和期限内向谁交付什么，用什么证明完成？ |
| 身份与生命周期 | 哪些状态其实代表不同对象或不同阶段？对象何时产生、转移、失效？ |
| 决策与信息 | 谁在什么信息下做决定；信息晚到、错误或不完整会怎样？ |
| 控制与反馈 | 错误最早能在哪里被阻止；结果何时被谁看见并改变后续行为？ |
| 边界与权威 | 哪些事实必须一起一致；冲突时谁有最终解释权？ |
| 时间与演化 | 延迟、回放、规则版本、十倍规模或组织变化时，哪个假设先失效？ |
| 指标与博弈 | 当前指标是不是目标的代理；角色能否改善指标却伤害真实结果？ |

两个视角若只产生同义描述，说明没有真正换眼镜，应更换视角或收敛为“当前证据下解释唯一”。

### 7.6 `CA-*` 探索记录

`CA-*` 是可丢弃的探索痕迹，不是正式业务结论。最小记录如下：

```markdown
### CA-<编号>：<洞察主题>

- 触发信号与归纳对象：
- S 惊讶事实 / M0 当前解释 / Δ 解释缺口：
- 使用的认知跳跃/视角：
- 候选解释：
- 相对 M0 的解释增量与仍未解释的事实：
- 支持证据与反证：
- 区分于竞争解释的冒险预测：
- 保留样本或最小实验：
- 什么结果会推翻它：
- 决策用途：
- 状态：待验证 / 增强 / 削弱 / 否证 / 转正
```

没有新预测、可证伪条件或决策用途的候选，不得转入 `EVO-T/ESS/BIZ`。

## 8. 竞争假设与证据收敛

### 8.1 什么叫真正竞争

高影响问题至少提出两个在以下任一方面不同的解释：核心对象身份、因果机制、责任/权威、边界、不变量、价值结果或演化轴。每个解释必须对至少一个相同场景给出不同预测；“代码不好”“设计不优雅”“应该抽象”不是竞争假设。

答案确实唯一时，不强行凑数，但必须给出能够排除其他合理解释的证据，而不是写“未想到其他方案”。

#### 8.1.1 解释竞争预算与停止

一次 `CA3 -> CA4` 算一轮。轮次预算与停止语义以 L0 §6 为准，默认最多 3 轮；本卡只提供生成和比较方法，不得自行放宽预算。每轮记录新增因果结构、新增区分预测、被淘汰解释和下一项区分证据。已具备可验证竞争时进入独立反证；非平凡任务至少两轮且使用不同认知动作后，Reviewer 仍确认没有新增结构或预测，才可按当前空间饱和收敛；预算耗尽仍无法区分时保留未知与补证计划，禁止用“暂时最像”冒充胜出。扩轮必须记录 Referee 或人工批准及新的停止点。

### 8.2 收敛十问

| 检验 | 必须回答 |
|---|---|
| 惊讶锚点 | `S` 为什么违背 `M0` 的预期；若没有违背，为什么需要新解释？ |
| 证据可逆 | 能否回指事实，是否把经验或缺席证据当事实？ |
| 解释压缩 | 是否用更少假设解释更多正常、异常和历史现象？ |
| 解释增量 | 相对 `M0` 新解释什么、仍解释不了什么，新增概念成本是否值得？ |
| 冒险预测 | 与最强竞争解释在哪个实施前场景下结果不同，且预测可能为错？ |
| 保留样本 | 未参与生成的样本是否符合预测；不符合如何降级？ |
| 生成能力 | 能否推出材料未直接写出的规则、场景或验证问题？ |
| 最小反例 | 哪个最小合法事实足以推翻或缩小适用范围？ |
| 机制韧性 | 角色能否博弈指标、利用规则或把风险外溢给别人；延迟反馈会不会反转结果？ |
| 决策价值 | 它是否改变保护、修复、演进、重绘、兼容或迁移判断？ |

不能通过保留样本或区分性验证的候选不得悄悄删除反证，应标为“削弱、否证或未知”。正确但显然的解释可以胜出；新奇程度不参与排序。

### 8.3 下一步取证按信息增益选择

优先寻找能够让两个领先解释产生不同结论的证据。只增加背景细节、无论结果如何都不改变分型或方案排序的取证延后。若一次验证同时支持所有假设，它通常不是区分性验证。

## 9. 创造性业务重设计

### 9.1 先改业务机制，再映射系统

三个产物不得混写：

```text
ESS：当前业务本质是什么，哪些不变量和边界必须保留
BIZ：为了更好地产生业务结果，目标角色、责任、决定、承诺、控制和反馈怎样协作
TGT：用什么系统、数据、交互和技术机制承载已经选定的 BIZ
```

若第一版候选已经出现数据库、MQ、微服务、缓存或框架名，先删除技术名词重写。删掉后无法说明谁的行为、结果或风险发生了什么变化，说明它只是技术改造，不是业务重设计。

### 9.2 先发现业务机会，不只修已知缺陷

业务机会通常藏在现有系统没有正式拥有的结果和代价中。优先寻找：

- 用户、客服或运营长期手工补回系统没有兑现的结果；
- 某角色承担结果和风险，却没有信息、决定权或补救入口；
- 系统已经产生高价值信息，但没有反馈给能够改变结果的人；
- 局部指标持续改善，最终履约、客户结果或总成本反而恶化；
- 高频“例外”其实是稳定存在的业务模式或未被服务的场景；
- 等待、重复确认、跨边界搬运和风险转嫁没有创造业务价值；
- 现有能力重新组合后，可以服务邻近角色或消除一次交接，但当前边界把它们隔开；
- 规则、组织或规模变化使原业务承诺仍有价值，而现有履约机制已经失效。

机会信号只生成候选。它必须回到真实业务结果、责任人、受益/受损角色、证据和最小实验；“行业都这样做”或“技术已经具备”不能独立创建业务目标。

### 9.3 业务机制变换算子

保持已确认不变量和安全底线，每次有意识地改变一个机制，再观察因果链：

| 变换 | 创造性追问 |
|---|---|
| 目标/指标重构 | 当前 KPI 是真实结果还是代理；能否在 KPI 变好时让真实结果变差？应怎样绑定结果护栏？ |
| 责任重配 | 决策权、执行责任、结果责任和补救责任是否落在不同角色，能否重新对齐？ |
| 控制点迁移 | 判断、校验或风险阻断能否移到更早、更局部、更接近权威事实的位置？ |
| 隐性显式化 | 隐含在人工、字段或异常分支里的义务、版本、期限、策略或例外能否成为一等业务概念？ |
| 闭环反馈 | 发送/执行能否变成“承诺—履约—回执—核对—补救”的闭环？ |
| 激励对齐 | 谁能从规则漏洞、信息差或责任转嫁中获益；能否让正确结果也是参与者更合理的选择？ |
| 反馈时滞缩短 | 哪个结果反馈太晚导致过量行动、积压或误判；能否更早给出可行动信号？ |
| 稳定与变化分离 | 哪些不变量应保持稳定，哪些渠道、规则或组织差异应成为受约束变体？ |
| 协作方式反转 | 推送/拉取、中心决定/本地自治、事前审批/事后监督的另一种组合是否更符合责任和风险？ |
| 例外正规化 | 高频人工绕行是否其实是合法业务模式，应建模而不是继续当异常？ |
| 价值与风险重配 | 能否减少无价值等待、重复确认或风险转嫁，同时保持责任可追溯？ |
| 能力重组与边界重画 | 已有能力能否组合成新的业务结果；哪些责任应吸收、拆出或交给更合适的角色？ |

变换算子只负责产生候选。是否采用取决于事实、价值、兼容、成本、风险和可验证性。

### 9.4 候选光谱与实质差异

按问题实际空间考虑：不做、直接修复、机制治理、能力提炼、控制点迁移、业务机制进化、核心抽象变化。核心重设计至少保留“不做/现状”基线、一个最小机制改进和一个因果机制不同的结构性候选；若某层不成立，写清淘汰理由，不机械凑齐全部层级。

两个候选只有技术实现不同而业务角色、责任、决定、结果和反馈完全相同，属于同一个 `BIZ-*` 下的不同 `TGT-*`，不得伪装成两个业务候选。

### 9.5 `BIZ-*` 最小语义

```markdown
### BIZ-<编号>：<目标业务机制>

- 来源问题与 `REV/ESS/CA`：
- 服务对象、真实目标结果与价值：
- 当前代理指标、指标失真和结果护栏：
- 必须保持的不变量：
- 当前业务机制及主要代价：
- 目标机制：触发 -> 决定/承诺 -> 行动/交换 -> 结果 -> 反馈/恢复
- 改变的角色、责任、权利、义务、控制点或边界：
- 为什么能改善结果的因果链：
- 与其他候选不同的预测：
- 各角色可见信息、可选行动、收益/代价与可博弈路径：
- 反馈回路、时滞、外部性、受损角色和二阶影响：
- 最小实验、指标、停止条件和失效条件：
- 兼容/迁移前提：
- 状态：探索 / 待验证 / 提议 / 待批准 / 已批准 / 已否证
```

`BIZ-*` 可以大胆。状态为“待批准”的候选可以进入提议态 `TGT-*`，用于比较系统承载代价；只有业务责任人认可目标、项目证据支持因果链且最小实验或区分性验证成立后，`BIZ/TGT` 才能升级为已批准决策或实施输入。无法验证的候选保留为机会或未知，不得包装成需求。

## 10. 反证与停止

使用 L0 五关：

- 可逆：能否回到事实；
- 区分：能否区分本系统与泛化常识；
- 稳定：换一组等价证据是否仍成立；
- 最小：删除后是否损失关键结构；
- 可决策：是否改变后续行动。

继续阅读材料已不改变骨架、分型或路径判断时停止。正式报告可以展开，但必须能压回 L0 一页骨架。

## 11. 失真模式

- 把 Redis、MQ、微服务、表结构直接写成业务本质；
- 从单条代码事实跳到目标架构；
- 只列概念、规则和问题，不形成主结构；
- 将所有变化都解释成策略，将所有实体都解释成聚合；
- 冲突并列记录但不升级判断；
- 用领域样例替代证据；
- 为覆盖方法清单制造无决策价值的产物。
- 把同义改写伪装成竞争解释，或为了“有创意”机械凑候选数量；
- 没有惊讶事实和基线解释就直接发明新抽象，或用任务标题冒充 `S-M0-Δ`；
- 把重述输入、方案上线后的目标指标或永远正确的常识写成“冒险预测”；
- 先选方案再倒推业务本质，只保留支持首选方案的证据；
- 把外部类比的成熟能力直接判成当前系统缺陷；
- 用生成假设的同一条样本冒充保留样本验证；
- `ESS` 后直接跳到技术方案，没有形成目标业务机制 `BIZ`；
- 只描述收益，不写受损角色、二阶影响、失效条件和最小实验。
- 优化代理指标却不验证真实结果，忽略参与者套利、反馈时滞和成本/风险外溢。

## 12. 与 L1 的接口

L1 报告只引用实际使用的方法与结果，不复制本卡。`CA-*` 是探索痕迹，可被否证和丢弃；正式业务结论仍使用统一 L1 的 `EVO-T/E`、`ESS-*`、`BIZ-*` 等编号、证据和门禁。

路径 A 使用**理解循环**发现隐性结构，再用**重设计循环**形成局部业务机制候选，但不得借“创造性”偷改 L0 `K1-K5`。路径 B 必须完成竞争解释、保留样本或等价区分性验证，并先形成 `BIZ-*`，再由 22A 映射为 `TGT-*`。
