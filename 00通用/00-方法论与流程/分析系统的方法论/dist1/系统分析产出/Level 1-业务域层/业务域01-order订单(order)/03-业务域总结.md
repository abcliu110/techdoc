# 03-业务域总结

## 1. 跨上下文一致性分析

### 1.1 状态机一致性

| 上下文 | 状态定义 | 一致性 |
|--------|----------|--------|
| order-订单创建 | 待结账(10)→已结账(20)→已退款(30) | ✅ 一致 |
| order-订单支付 | 支付完成触发状态变更 | ✅ 一致 |
| order-订单退款 | 已结账→已退款(30) | ✅ 一致 |
| order-反结账 | 已结账→待结账(10) | ✅ 一致 |
| order-订单查询 | 全状态可查 | ✅ 一致 |

### 1.2 规则一致性

| 规则 | 上下文A | 上下文B | 是否冲突 |
|------|---------|---------|----------|
| 订单状态校验 | order-订单支付 | order-订单退款 | ✅ 无冲突 |
| 支付序号生成 | order-订单支付 | order-反结账 | ✅ 无冲突 |

### 1.3 术语一致性

| 术语 | order内含义 | 统一方案 |
|------|-------------|----------|
| billNo | 账单编号 | 统一使用 |
| orderNo | 订单号 | 统一使用 |
| payId | 支付记录ID | 统一使用 |

## 2. 跨上下文的对象关系

| 对象 | 上下文 | 关系描述 |
|------|--------|----------|
| OrderMasterDO | order-订单创建/支付/退款/反结账 | 聚合根，所有上下文共享 |
| OrderPay | order-订单支付/反结账 | 支付记录，支付和反结账共享 |
| OrderSaleDO | order-订单支付 | 销售汇总，支付计算使用 |

## 3. 业务域内模式识别

| 模式名称 | 描述 | 涉及上下文 |
|----------|------|-----------|
| 聚合根模式 | OrderMasterDO作为订单聚合根 | 所有上下文 |
| 状态机模式 | 订单状态按状态机流转 | 订单创建/支付/退款/反结账 |
| 优惠分摊模式 | 按比例分摊整单优惠到明细 | 订单创建/支付 |
| 逆向操作模式 | cancelPay作为pay的逆向补偿 | 订单支付/反结账 |

| 问题 | 影响 | 建议处理方式 |
|------|------|-------------|
| 反结账次数限制未明确 | 可能无限反结账 | 外部化配置限制 |
| 多次支付合并逻辑 | 多次付需要明确合并规则 | 补充DCF流程 |
