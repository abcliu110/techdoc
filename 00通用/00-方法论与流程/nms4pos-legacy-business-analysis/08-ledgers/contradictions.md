## 2. 矛盾详情

### 2.1 CT001: 打印服务职责不清

**描述**：CLAUDE.md 明确描述打印服务在 pos10printer，但 pos3boot-biz 中存在部分打印相关代码。

**来源证据**：
- CLAUDE.md：打印服务独立为 pos10printer
- CLAUDE.md 矛盾记录 C001

**解释假设**：
1. pos3boot 中的代码是历史遗留，未清理
2. pos3boot 负责打印触发，实际打印在 pos10printer 执行
3. 存在职责迁移过程中的过渡代码

**验证步骤**：
```bash
# 1. 检查 pos3boot 中的打印代码是否被调用
grep -r "printer" nms4cloud-pos3boot-biz/src/main/java/ --include="*.java" | head -20

# 2. 检查调用方
git log --oneline -10 --all -- "**/pos3boot/**/print/**"
```

**影响**：
- 系统维护困难
- 可能导致打印功能异常
- 职责不清影响代码理解

**解决建议**：
1. 确认 pos3boot 中的打印代码是否仍在使用
2. 如果废弃，制定迁移计划
3. 如果需要保留，明确职责边界

### 2.2 CT002: 优惠叠加规则不一致

**描述**：不同文档对优惠叠加顺序描述不一致。

**来源证据**：
- SLICE-001：可能按整单→菜品→会员→优惠券顺序
- business-rules.md：明确按整单→菜品→会员→优惠券顺序

**差异点**：
- 文档描述基本一致，但细节可能有差异
- 需要产品确认实际优先级

**验证步骤**：
```java
// 检查 CalcOrderService 中的优惠计算逻辑
public CalcOrderVO calc(long mid, long lid, boolean throwEx, boolean force) {
    // 1. 计算应付总额
    // 2. 应用整单优惠
    // 3. 应用菜品优惠
    // 4. 应用会员优惠
    // 5. 应用优惠券
}
```

**影响**：
- 优惠金额计算不准确
- 可能导致财务损失
- 影响会员权益

**解决建议**：
1. 产品确认优惠叠加规则
2. 代码实现与规则文档对齐
3. 增加优惠叠加的测试用例

### 2.3 CT003: 离线能力描述与实现差距

**描述**：文档描述离线模式是"差异化关键能力"，但代码分析显示实现相对简单。

**来源证据**：
- 能力地图：离线模式是差异化能力
- SLICE-008：sync_queue 机制较简单

**差异点**：
- 文档强调离线能力的重要性
- 但实现主要依赖 sync_queue，没有复杂的冲突解决

**解释**：
1. 离线能力的重要性可能体现在业务场景，而非技术复杂度
2. 简单实现可能是设计选择（可靠性优先）
3. 更复杂的离线能力可能需要更大投入

**影响**：
- 对离线能力的期望可能过高
- 极端场景（长时离线、大量数据）可能有问题

**解决建议**：
1. 明确离线能力的业务边界
2. 测试极端场景
3. 评估是否需要增强
