## 2. 系统上下文

### 2.1 系统定位

nms4pos 是餐饮行业 POS 收银系统的完整技术栈，包含：
- **后端**：Java/Spring Boot 微服务（8个核心模块）
- **前端**：React/Taro 多端应用（POS桌面端、商家移动端、顾客小程序）

### 2.2 模块架构

```
nms4pos 后端模块
├── pos1starter      # 基础组件和公共代码
├── pos2plugin       # 核心业务逻辑（收银、点餐、结账）、CalcOrderService、DwdBillOpsService
├── pos3boot         # 业务编排（CloseMpScHandler 负责结账流程编排）、启动引导
├── pos4cloud        # 云端服务接口
├── pos5sync         # 数据同步（Canal + Kafka）
├── pos6monitor      # 监控和运维
├── pos9cash         # 收银客户端
└── pos10printer     # 打印服务
```

**源码验证说明**：
- `CalcOrderService` 定义在 pos2plugin，但实际由 pos3boot 的 `CloseMpScHandler` 调用
- `CloseMpScHandler.runInner()` 有 80 个 callees，包含完整的结账业务流程（锁、计算、支付、积分、优惠券、打印等）

### 2.3 外部系统依赖

| 系统 | 角色 | 交换内容 |
|------|------|----------|
| nms4cloud | 上游平台 | 会员、订单、支付、菜品基础数据 |
| MySQL | 数据存储 | 业务数据持久化 |
| Redis | 缓存 | Session、分布式锁 |
| Nacos | 配置中心 | 应用配置、服务发现 |
| RocketMQ | 消息队列 | 异步消息、事件驱动 |
| Canal | 数据同步 | Binlog 解析和转发 |

### 2.4 源码验证成果

使用 code-review-graph 知识图谱对关键结论进行源码验证：

| 验证对象 | 源码位置 | 验证结果 | 影响结论 |

| CloseMpScHandler | pos3boot-biz/service/local/ | ✅ 80个callees，结账编排核心 | C002 修正 |

1. pos3boot 的 `CloseMpScHandler.runInner()` 是结账业务编排的核心，调用了 `CalcOrderService.calc()`

3. 业务逻辑并非完全集中在 pos2plugin，pos3boot 承担了重要的编排职责

## 4. 核心业务切片

### 4.1 切片评分与优先级

| 切片 | 业务关键性 | 风险影响 | 变化强度 | 证据缺口 | 总分 | 优先级 |
|------|-----------|----------|----------|----------|------|--------|
| SLICE-001 点餐→结账 | 5 | 5 | 4 | 2 | 16 | P0 |
| SLICE-008 断网离线收银 | 4 | 5 | 5 | 4 | 18 | P0 |
| SLICE-010 云端数据同步 | 5 | 4 | 4 | 3 | 16 | P0 |

### 4.2 SLICE-001: 点餐→结账完整流程

**分析范围**：从开台到结账的完整业务链路

**关键发现**：
- 开台 → 点餐 → 结账的状态转换已定义
- 金额计算通过 CalcOrderService 集中处理
- 支付流程支持多种支付方式

**核心调用链路**：
```
开台 → DwdBillService.createBill()
    ↓
点餐 → DwdFoodService.addDish() × N
    ↓
结账 → CalcOrderService.calc()
    ↓
支付 → DwdPayService.createPay()
    ↓
打印 → PrnPrintJobService.print()
```

### 4.3 SLICE-008: 断网离线收银

**分析范围**：门店断网后的收银能力和数据同步

**关键发现**：
- 离线模式支持现金和会员卡支付
- 通过 sync_queue 本地存储离线操作
- 网络恢复后自动同步到云端
- 冲突解决以云端时间戳为准

**核心机制**：
```
断网检测 → 切换离线模式
    ↓
离线收银 → 写入 sync_queue (status=0)
    ↓
网络恢复 → 读取 sync_queue 同步
    ↓
冲突处理 → 云端时间戳优先
```

### 4.4 SLICE-010: 云端数据同步

**分析范围**：门店与云端之间的增量数据同步

**关键发现**：
- 使用 Canal 解析 MySQL binlog
- 通过 Kafka 实现异步传输
- 增量同步服务（IncrementalSyncDataService）处理落地

**同步表范围**：
- 菜品相关：pt_dish, pt_dish_flavor, pt_set_meal 等
- 桌台相关：pt_tbl, pt_tbl_area 等
- 基础数据：其他字典表

### 5.1 核心业务对象

| 对象 | 说明 | 关键字段 | 状态机 |
|------|------|----------|--------|
| DwdBill | 账单 | lid, mid, sid, order_no, status | ✅ |
| DwdFood | 菜品明细 | lid, bill_id, dish_id, num, price | ✅ |
| DwdPay | 支付明细 | lid, bill_id, pay_type, amount | ✅ |

| SyncQueue | 同步队列 | lid, tbl_name, opt_type, sync_status | ✅ |

### 5.2 状态机定义

**账单状态机**：
```
开台(status=0) → 结账(status=1) → 完成(status=2)
                      ↓
                 反结账(status=0)
```

**菜品明细状态机**：
```
待下单(status=0) → 已下单(status=1) → 已上菜(status=2)
                        ↓
                   退菜(恢复状态)
```
