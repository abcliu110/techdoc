# nms4pos 遗留系统业务分析报告（快速摸底版）

## 执行摘要

本报告基于《10B-方法论-遗留系统业务分析》对 `nms4pos` 项目体系进行快速摸底分析（B0-B3 阶段），建立了业务上下文、能力地图和候选切片清单，为后续深度分析奠定基础。

### 核心发现

1. **系统定位清晰**：`nms4pos` 是餐饮行业 POS 收银系统的完整技术栈，包含后端（Java/Spring Boot 微服务）和前端（React/Taro 多端应用）

2. **模块结构合理**：8 个核心模块按职责分离，其中 `pos2plugin` 承载核心收银业务，`pos4cloud` 负责云端服务，`pos5sync` 处理数据同步

3. **差异化能力**：离线收银模式是系统的重要差异化特性，但证据覆盖不足

4. **依赖关系复杂**：与 `nms4cloud` 主平台存在深度耦合，通过 Feign 接口调用 CRM、订单、支付等服务

### 推荐切片

| 优先级 | 切片 | 理由 |
|--------|------|------|
| P0 | SLICE-001 点餐→结账完整流程 | 核心业务，变更风险高 |
| P0 | SLICE-008 断网离线收银 | 差异化能力，证据不足 |
| P0 | SLICE-010 云端数据同步 | 门店与云端协同基础 |

## 2. 系统上下文

### 2.1 系统边界

```
nms4cloud 主平台（上游）
    ├── CRM 会员服务
    ├── 订单服务
    ├── 支付服务
    └── 微信服务
          ↓ Feign
    nms4pos 体系（核心）
    ├── 前端：nms4pos-ui
    └── 后端：8 个微服务模块
          ↓ 数据上报
    相关项目：pos11report, pos8book, pos11lowcode
```

### 2.2 核心角色

| 角色 | 价值结果 | 使用入口 |
|------|----------|----------|
| 收银员 | 快速完成点餐、结账 | POS 桌面端 |
| 门店管理员 | 菜品/桌台/员工/报表管理 | 商家后台 Web |
| 厨师 | KDS 菜品制作 | KDS 显示端 |
| 顾客 | 自助点餐、扫码支付 | 微信小程序 |
| 外卖平台 | 外卖订单处理 | 美团/饿了么对接 |
| 总部运营 | 多门店管理、数据分析 | 商家后台 Web |

### 2.3 外部系统依赖

| 系统 | 角色 | 交换内容 |
|------|------|----------|
| nms4cloud | 上游平台 | 会员、订单、支付、菜品基础数据 |
| MySQL | 数据存储 | 业务数据持久化 |
| Redis | 缓存 | Session、分布式锁 |
| Nacos | 配置中心 | 应用配置、服务发现 |
| RocketMQ | 消息队列 | 异步消息、事件驱动 |
| ClickHouse | OLAP | 报表数据聚合 |
| 美团/饿了么 | 外卖平台 | 订单同步 |

### 3.1 能力域概览

| 能力域 | 核心能力数 | 重要性 |
|--------|-----------|--------|
| 收银核心域 | 4 | 核心 |

| 数据同步域 | 3 | 核心 |
| 运营分析域 | 3 | 支撑 |
| 系统域 | 3 | 支撑 |

### 3.2 核心能力卡

#### CAP-001 开台管理
- **业务结果**：创建或关联账单，为后续点餐提供上下文
- **使用角色**：收银员、服务员
- **核心对象**：桌台(pt_tbl)、账单(dwd_bill)

#### CAP-002 点餐管理
- **业务结果**：向账单添加菜品明细
- **使用角色**：收银员、服务员、顾客
- **核心对象**：菜品(pt_dish)、菜品明细(dwd_food)

#### CAP-003 结账管理
- **业务结果**：完成账单支付
- **使用角色**：收银员
- **核心对象**：账单(dwd_bill)、支付明细(dwd_pay)

#### CAP-004 会员识别与优惠
- **业务结果**：识别会员身份，应用优惠
- **使用角色**：收银员、顾客
- **核心对象**：会员(biz_member)

#### CAP-005 云端数据同步
- **业务结果**：保持门店与云端数据一致
- **使用角色**：系统自动
- **核心对象**：同步状态、Canal 事件
