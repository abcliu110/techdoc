# Level 1 骨架完整性检查脚本

## 🎯 设计目标

这些脚本是为 **AI Agent 自动执行**而设计的，不是为人工手动运行设计的。

AI 会在以下时机自动调用这些脚本：

1. **G1 门禁** - Level 1 完成后，进入 G2 之前
2. **G2 启动前置** - 确保 Level 1 基础完整
3. **G6 验收** - 最终交付前全面检查

## 📋 脚本清单

- `check-level1-skeleton.ps1` - Windows PowerShell 版本
- `check-level1-skeleton.sh` - Linux/macOS Bash 版本

这两个脚本功能完全一致，根据运行平台自动选择。

## 退出码定义

| 退出码 | 含义 | 说明 |
|-------|------|------|
| **0** | ✅ 检查通过 | 所有业务域骨架齐全且含实质内容，可继续 G2 |
| **2** | ❌ 骨架缺失 | Level 1 目录存在但骨架文件缺失或被误删 |
| **3** | ❌ Level 2 孤立 | Level 2 任务所属业务域未在 Level 0 清单或无 Level 1 骨架 |
| **4** | ❌ 清单不一致 | 业务域清单与 Level 1 目录不一致（漏建、错号、错名） |
| **5** | ❌ 内容空洞 | Level 1 文件存在但内容全为模板占位符（G1 未完成） |

## 使用方法

### ⚠️ 重要提示

**这些脚本由 AI Agent 自动执行，人工通常无需手动运行。**

如果你是人类用户且需要手动验证，可以参考以下命令：

### Windows (PowerShell)

```powershell
# 在项目根目录运行
.\check-level1-skeleton.ps1

# 指定自定义路径
.\check-level1-skeleton.ps1 -RootPath "D:\项目\系统分析产出"

# 检查退出码
.\check-level1-skeleton.ps1
if ($LASTEXITCODE -ne 0) {
    Write-Host "检查失败，退出码: $LASTEXITCODE"
}
```

### Linux/macOS (Bash)

```bash
# 添加执行权限（首次运行）
chmod +x check-level1-skeleton.sh

# 在项目根目录运行
./check-level1-skeleton.sh

# 指定自定义路径
./check-level1-skeleton.sh "项目路径/系统分析产出"

# 检查退出码
./check-level1-skeleton.sh
if [ $? -ne 0 ]; then
    echo "检查失败，退出码: $?"
fi
```

## 检查内容

脚本会执行以下 5 个步骤：

### 1. 解析业务域清单
- 读取 `Level 0/02-模块分级.md`
- 提取所有业务域定义（格式：`业务域NN-名称(domain)`）
- 验证业务域清单存在且格式正确

### 2. 校验业务域编号
- 编号连续性（01, 02, 03...）
- 编号不重复
- 编号与目录名一致

### 3. 校验 Level 1 骨架
检查每个业务域的三份必需文件：
- `01-业务域概览.md`
- `02-上下文清单.md`
- `03-业务域总结.md`

验证项：
- 文件存在且非空
- 文件顶部包含 `<!-- skeleton: do not delete -->` 标记
- 文件内容**不是**纯模板占位符（不能只有"待补充""待分析""-""TODO"等）

### 4. 校验 Level 2 任务归属
- 检查 `Level 2/` 下所有上下文目录
- 验证每个上下文在某个业务域的 `02-上下文清单.md` 中被引用
- 确保没有"孤立"的 Level 2 任务

### 5. 最终汇总
- 统计业务域数量
- 统计 Level 1 目录和文件数量
- 确认所有文件含实质内容

## 占位符检测规则

脚本会将以下内容视为**无实质内容的占位符**：

- 空行
- 单独的 `-`
- `待补充`
- `待分析`
- `TODO`
- `[...]`（空括号）
- 纯标题行（`###` 等）

**如果文件只包含上述内容，会返回退出码 5。**

## 常见问题

### Q1: 为什么需要 skeleton 标记？
**A**: 标记用于区分"故意清空的占位文件"和"尚未创建的文件"，防止误删导致检查失败。

### Q2: 什么是"实质内容"？
**A**: 除了模板占位符之外的分析文本，例如：
- 业务域描述
- 上下文列表
- 业务规则
- 流程说明
- 任何具体的业务语义信息

### Q3: 脚本报错"清单不一致"怎么办？
**A**: 检查以下情况：
1. Level 0 业务域清单与 Level 1 目录名是否完全匹配
2. 业务域编号是否连续（01, 02, 03...）
3. 是否有重复编号
4. 是否有业务域在清单中但目录未创建

### Q4: 退出码 5（内容空洞）如何修复？
**A**: 进入对应的 Level 1 文件，填写实际分析内容：
- `01-业务域概览.md` - 补充业务域职责、边界、依赖
- `02-上下文清单.md` - 列出所有上下文及其核心职责
- `03-业务域总结.md` - 总结业务域关键特性和演化方向

### Q5: Level 2 孤立（退出码 3）怎么办？
**A**: 
1. 检查 Level 2 上下文名称是否在某个业务域的 `02-上下文清单.md` 中
2. 如果上下文确实属于某个业务域，在清单中添加它
3. 如果上下文不应存在，删除 Level 2 目录

## 集成到工作流

### 在 SOP 中的位置

```markdown
## Phase 1: G1 门禁检查点

1. 业务域骨架已预创建 ✅
2. 所有业务域概览已填写 ✅
3. 所有上下文清单已补全 ✅
4. **运行骨架检查脚本**：
   ```powershell
   .\check-level1-skeleton.ps1
   # 退出码: 0 ✅
   ```
5. 通过门禁 → 进入 G2

## Phase 2: G2 启动前置

在开始任何 Level 2 分析前，必须运行：
```powershell
.\check-level1-skeleton.ps1
if ($LASTEXITCODE -ne 0) {
    Write-Host "❌ Level 1 基础不完整，禁止进入 Level 2"
    exit $LASTEXITCODE
}
```
```

### CI/CD 集成

```yaml
# .github/workflows/check-analysis.yml
name: 检查分析产出完整性

on: [push, pull_request]

jobs:
  check-level1:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: 检查 Level 1 骨架
        run: |
          chmod +x check-level1-skeleton.sh
          ./check-level1-skeleton.sh
        working-directory: 系统分析产出
```
