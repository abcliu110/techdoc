## 速查卡3：七要素快速判定

```text
遇到一个业务事实，问自己：

它的本质是什么？
├─ 是"谁"？          → 主体
├─ 是"想做什么"？    → 目标
├─ 是"必须遵守"？    → 规则
├─ 是"如何配合"？    → 协作
├─ 是"何时/多久"？   → 时序
├─ 是"被操作的对象"？→ 资源
└─ 是"传递的数据"？  → 信息

⚠️ 每个事实只能归一类！如果能归入两类，说明判断错误。
```

**互斥边界检查表**：
- [ ] 不是技术实现（Handler/数据库约束不是业务要素）
- [ ] 不是实现手段（录入/计算不是目标，是手段）
- [ ] 不是结果（"已完成"是状态，不是目标）

## 速查卡4：对象分类决策树（30秒判定）

```text
发现一个类/表/接口？

有业务身份？
├─ 否 → 是请求/响应？
│      ├─ 是 → 命令/结果
│      └─ 否 → 是框架类？
│             ├─ 是 → 技术组件
│             └─ 否 → 值对象候选
└─ 是 → 有生命周期？
       ├─ 否 → 值对象候选
       └─ 是 → 状态变化有业务意义？
              ├─ 否 → 技术对象
              └─ 是 → 能独立存在？
                     ├─ 否 → 实体成员
                     └─ 是 → 是聚合对外入口？
                            ├─ 否 → 实体
                            └─ 是 → 聚合根候选（需验证5条件）

聚合根5条件（必须全满足）：
1. ✓ 对外唯一身份入口
2. ✓ 控制内部对象生命周期
3. ✓ 维护聚合不变式
4. ✓ 事务边界
5. ✓ 发布领域事件（可选但强烈建议）
```

## 速查卡5：规则依赖类型速查

| 依赖类型 | 识别特征 | 代码证据 | 处理方式 |
|---------|---------|---------|---------|
| **强依赖** | A必须先于B | B用到A的计算结果 | 执行顺序：A→B |
| **弱依赖** | A和B都要，顺序无关 | 两个独立的if判断 | 并行执行 |
| **互斥** | A和B不能同时生效 | if-else或覆盖赋值 | 冲突解决规则 |
| **条件依赖** | 某条件下A依赖B | if(condition) { 用到B } | 条件判断+依赖 |

**规则冲突解决策略**：
- 优先级法：高优先级覆盖低优先级
- 互斥矩阵法：列出两两互斥关系
- 规则分层法：特殊层覆盖通用层

## 速查卡6：证据分级5秒判断

| 层级 | 定义 | 判断标准 | 可用性 |
|------|------|---------|--------|
| **L1 直接事实** | 可定位的代码/数据 | 有文件名+行号 | 可直接采用 |
| **L2 代码推断** | 由代码推出的结论 | 有完整调用链 | 可采用，需跨路径验证 |
| **L3 业务语义** | 对代码的业务解释 | 代码+文档/访谈 | 可采用，需标注来源 |
| **L4 业务推断** | 未被确认的假设 | 只有单一推理 | 待确认，不可作结论 |
| **L5 未知** | 证据不足或冲突 | 无法确认 | 必须标记，不得补写 |

⚠️ **禁止**：把L4/L5伪装成L1/L2

## 速查卡8：评分公式速算

### 扩展性评分（目标≥60）
```text
总分 = (规则×30% + 概念×25% + 流程×25% + 集成×20%) × 20
单项 = (5 - 改动率×5) × 对应权重
改动率 = 新增功能改动行数 / 总代码行数
```

### 质量评分（目标≥80）
```text
质量分 = (概念×20% + 规则×30% + 流程×20% + 术语×15% + 依赖×15%) × 100
概念完整率 = 已建模 / 候选对象
规则完整率 = 已提取 / 代码分支
```

## 速查卡13：紧急故障处理

### 场景1：分析中断恢复

```text
1. 读取检查点.md，获取最后位置
2. 读取索引.md，确认已完成项
3. 运行门禁脚本，验证状态一致性
4. 从中断点继续，不重复已完成工作
```

### 场景2：门禁不通过

```text
1. 查看脚本退出码
2. 根据退出码定位问题
3. 修复后重新运行脚本
4. 退出码=0后才能继续
```

### 场景3：评分不达标

```text
1. 查看各维度分项得分
2. 识别最低分维度
3. 针对性改进
4. 重新评分直到达标
```

## 速查卡15：理论适用性快速判断

### 3秒判断：适合用本理论吗？

```text
问题1：有源代码或可访问的数据库吗？
问题2：系统仍在运行，可观察行为吗？
问题3：业务有规则可循（非纯创意）吗？

3个问题都是"是" → 适用本理论
任意一个"否" → 需要调整或不适用
```
