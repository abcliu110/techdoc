## 概念组织要求（通用原则，不预设领域分组）

概念必须**按业务语义的自然分组**呈现，禁止平铺罗列；分组名称由当前分析领域的业务语义决定（AI 自行定义并说明分组依据），SOP 不预设任何领域分组（如"设备""配置""流程"等仅作示例，是否适用由领域决定）。

示例（仅演示分组形式，非规定分组）：
```
## 概念分组（按领域业务语义，示例）
### 组1：{本领域的核心业务对象}
### 组2：{本领域的配置/规则对象}
### 组3：{本领域的技术支撑概念}
```

## 跨阶段概念追溯机制（DA8 收敛时强制）

DA2 概念字典必须覆盖后续 DA 阶段（DA3 关系、DA4 规则、DA5 数据）将引用的全部核心概念：

1. 完成 DA3/DA4 后，**反向检查**（反查）其使用的每个对象/关系/规则（如 OR-*、REL-*、BR-* 涉及的概念）是否都能在 DA2 中找到定义；
2. 未定义的概念 → **回填** DA2 补定义，或登记 U-* 说明为何未定义；
3. DA8 收敛时输出**"概念覆盖追溯表"**（DA3/DA4 引用概念 × DA2 定义状态），存在未定义引用则 DA8 不通过。

**追溯链定义**：原始目标 → DQ → 业务切片 → 概念（DA2）→ 关系/规则（DA3/DA4）→ 实现（DA7）→ 证据（E-*）→ 结论（C-*）。任何结论必须能沿此链追溯到证据；任何被引用的概念必须能反查到 DA2 定义。
