### 2.3 当前产物的具体缺陷

#### 缺陷 1：技术转述，非业务叙事

**反面案例**（当前产物）：
```
| 步骤 | 操作 | 代码位置 |
| 1 | 创建订单 | OrderMasterService |
| 2 | 添加商品 | OrderMasterDO |
```

删除类名后只剩"创建订单 → 添加商品"，没有任何业务含义。

**正面案例**（新版 SOP §9.4.2）：
```
收银员小王在中午12点为3号桌4位客人开单。
→ 系统先根据桌台类型找到对应的价目表（堂食价/外卖价）。
→ 顾客点了宫保鸡丁（微辣）+米饭2份，系统检查库存后添加到订单。
→ 应用会员折扣（8折）+ 满减优惠（满100减20），生成最终应付金额。
→ 收银员确认支付，系统发布订单事件，后厨打印机自动出单。
→ 如果后厨打印机离线，系统切换到备用打印机并通知收银员。
```

删除类名后，上述叙事仍完整表达业务过程。

#### 缺陷 3：关系分析缺失

**当前产物**：无 DA3 关系分析文档

**新版 SOP 要求**（§9.5.4 DA3 模板）：

必须回答：
1. **业务对象识别**：订单/商品/会员/打印机等是什么业务对象
2. **直接关系**（1-hop）：订单 → 商品（订单包含商品）
3. **间接关系**（3-hop）：订单 → 出品部门 → 打印队列 → 打印机
4. **为什么要经过中间对象**：
   - 简化配置：只需为每个部门配置一个队列，而不是为每道菜单独配置打印机
   - 自然分组：同一部门的菜自动合打一张单
   - 故障转移：队列层可以配主/备打印机

**新版 §9.5.4a 合格范例**：
```
菜品 → 出品部门（菜品归属哪个部门制作）
  → 打印队列（部门关联哪个队列出单）
  → 打印机（队列选择哪台健康打印机）

如果直接关联（菜品→打印机）：
- 新增/更换打印机需修改所有关联菜品配置
- 无法按部门合单
- 打印机故障时无备机可切
```
