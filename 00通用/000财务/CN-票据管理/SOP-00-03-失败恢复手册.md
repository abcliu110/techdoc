## 七、并发场景处理

### 7.1 票据操作并发

| 场景 | 风险 | 处理机制 | 用户感知 |
|---|---|---|---|
| 用户A和B同时背书同一票据 | 重复背书 | 悲观锁检查状态 | B收到"票据状态已变更"提示 |
| 用户A托收时B同时修改票据 | 数据不一致 | 事务隔离 | B收到"票据已被修改"提示 |
| 定时任务更新状态时用户操作 | 状态冲突 | 乐观锁版本控制 | 操作失败，提示重试 |

### 7.2 资金操作并发

| 场景 | 风险 | 处理机制 | 用户感知 |
|---|---|---|---|
| 多用户同时付款同一票据 | 超额付款 | 余额检查+锁 | B收到"余额不足"提示 |
| 付款和托收同时执行 | 金额重复处理 | 事务隔离 | 提示冲突 |

## 九、升级路径

### 9.1 问题升级标准

| 级别 | 场景 | 升级到 |
|---|---|---|
| 一线处理 | 权限不足、数据录入错误、配置缺失 | 票据会计组长 |
| 二线处理 | 并发锁、金额不一致、凭证生成失败 | 财务主管 |
| 三线处理 | 数据损坏、状态异常、银行接口问题 | DBA/运维/银行 |
| 四线处理 | 代码缺陷、系统异常 | 开发团队 |

### 9.2 升级触发条件

- 同一问题超过3次未能解决
- 涉及资金损失或信用风险
- 引发其他模块异常
- 影响财务报表准确性
- 银行接口持续失败

## 十、常用恢复命令参考

### 10.1 SQL恢复参考

```sql
-- 检查应收票据金额一致性
SELECT FBillID, FBillNo, FAmount, FCashedAmount,
       FAmount - FCashedAmount AS UnCashedAmt
FROM CN_RECEIVEBILL
WHERE FBillID = @BillID

-- 检查应付票据金额一致性
SELECT FBillID, FBillNo, FAmount, FPayedAmount,
       FAmount - FPayedAmount AS UnPayedAmt
FROM CN_PAYBILL
WHERE FBillID = @BillID

-- 清理脏背书数据
DELETE FROM CN_BILLENDORSERECORD
WHERE FBillID NOT IN (SELECT FBillID FROM CN_RECEIVEBILL)

-- 检查票据与AR关联一致性
SELECT r.FBillID, r.FBillNo, r.FAmount,
       r.FCashedAmount,
       (SELECT SUM(FWriteOffAmt) FROM AR_WRITEOFFRECORD
        WHERE FSourceBillID = r.FBillID) AS WriteOffAmt
FROM CN_RECEIVEBILL r
WHERE r.FBillID = @BillID

-- 检查票据状态
SELECT FBillID, FBillNo, FBillStatus, FDueDate
FROM CN_RECEIVEBILL
WHERE FDueDate <= GETDATE()
  AND FBillStatus NOT IN (2, 3, 4, 5)  -- 非到期/已兑现/拒付/作废
```

## 十一、快速故障排查流程

### 11.1 票据登记问题排查

```
1. 检查票据号码是否已存在
      ↓ 是 → 修改票据号码
      ↓ 否 → 继续
2. 检查关联AR/AP单是否已审核
      ↓ 否 → 先审核关联单据
      ↓ 是 → 继续
3. 检查票据金额是否≤关联单未核销金额
      ↓ 否 → 调整金额或关联多个单据
      ↓ 是 → 继续
4. 检查到期日是否有效
      ↓ 否 → 修改到期日
      ↓ 是 → 联系技术支持
```

### 11.2 票据背书问题排查

```
1. 检查票据状态是否为开立或背书中
      ↓ 否 → 检查票据状态
      ↓ 是 → 继续
2. 检查票据是否已到期
      ↓ 是 → 提示到期不可背书，需托收
      ↓ 否 → 继续
3. 检查商业承兑背书次数
      ↓ ≥3次 → 该票据不可再背书
      ↓ <3次 → 继续
4. 检查被背书人是否有效
      ↓ 否 → 选择有效供应商
      ↓ 是 → 联系技术支持
```

### 11.3 票据到期问题排查

```
1. 检查票据状态是否为到期
      ↓ 否 → 检查状态变更规则
      ↓ 是 → 继续
2. 应收票据：检查托收银行
      应付票据：检查银行账户余额
3. 检查关联AR/AP核销状态
      ↓ 不一致 → 同步核销状态
      ↓ 一致 → 联系技术支持
```
