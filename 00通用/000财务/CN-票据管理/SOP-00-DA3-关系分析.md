## 一、对象分析（10对象）

### 1.1 核心业务对象

| 对象ID | 对象名称 | 类/表 | 职责 |

| OBJ-01 | 应收票据 | CN_RECEIVEBILL | 记录企业收到的票据信息 |

## 二、关系分析（13关系）

| REL-07 | 应收票据 | 凭证 | 1:N 生成 | 收票、兑现生成凭证 |
| REL-08 | 应付票据 | 凭证 | 1:N 生成 | 开票、付款生成凭证 |
| REL-09 | 应收票据 | 客户 | N:1 出票人 | 客户开出票据 |
| REL-10 | 应付票据 | 供应商 | N:1 收款人 | 供应商收取票据 |
| REL-11 | 应收票据 | 核销记录 | 1:N 核销 | 票据与AR核销 |
| REL-12 | 应付票据 | 核销记录 | 1:N 核销 | 票据与AP核销 |
| REL-13 | 应收票据 | 应付票据 | N:N 背书转让 | 应收票据背书后成为对方应付 |

## 三、查询路径分析（10路径）

### 3.1 核心查询路径

| 路径ID | 路径名称 | 路径描述 | 性能要求 |
|---|---|---|---|
| PATH-01 | 票据余额查询 | CN_RECEIVEBILL → 按客户/状态 → SUM(FAmount) | <2s |
| PATH-02 | 票据到期提醒 | CN_RECEIVEBILL → FDueDate ≤ 当前+7天 → 状态≠已兑现 | <1s |
| PATH-03 | 票据核销追溯 | CN_RECEIVEBILL → WRITEOFFRECORD → AR_RECEIVABLE | <3s |
| PATH-04 | 背书历史追溯 | CN_RECEIVEBILL → CN_ENDORSERECORD → 供应商 | <2s |
| PATH-05 | 票据凭证追溯 | CN_RECEIVEBILL → GL_VOUCHER → GL_VOUCHERENTRY | <3s |
| PATH-06 | 应付票据余额 | CN_PAYBILL → 按供应商/状态 → SUM(FAmount) | <2s |
| PATH-07 | 票据银行流水 | CB_BANKACCOUNT → 票据收付记录 → 日期范围 | <3s |
| PATH-08 | 应收单票据关联 | AR_RECEIVABLE → CN_RECEIVEBILL → 未核销金额 | <2s |
| PATH-09 | 应付单票据关联 | AP_PAYABLE → CN_PAYBILL → 未核销金额 | <2s |
| PATH-10 | 票据状态变更 | CN_RECEIVEBILL → 历史状态 → 时间轴 | <1s |

## 四、DA3结论

### 4.1 产出汇总

| 产出 | 数量 |
|---|---|
| 核心对象 | 10个（OBJ-01至OBJ-10） |
| 关系 | 13条（REL-01至REL-13） |
| 查询路径 | 10条（PATH-01至PATH-10） |

### 4.2 关键关系洞察

| 洞察 | 说明 |
|---|---|
| CN↔AP/AR核心关联 | 票据是AP/AR核销的支付工具，票据金额可部分或全部核销 |
| CN↔GL凭证映射 | 票据收票、开票、兑现、付款均生成GL凭证 |
| CN↔CB银行账户 | 票据资金通过银行账户流转 |
| 背书关系特殊 | 应收票据背书后可能成为其他企业的应收票据或应付票据 |
