# 00-十分钟读懂AP应付管理 — K3Cloud AP应付管理模块

## 快速理解指南

### 一句话概括

AP应付管理模块是金蝶云星空的"账房先生"——记录企业欠了谁多少钱，帮助财务人员完成从采购/费用发生到付款的全流程管理。

---

## 核心概念（3个必须懂）

### 1. 应付单据：欠条

想象你从供应商那里进货，货物到了但发票还没来，这时财务会做一笔"暂估"——先把账记上"欠供应商一笔钱"。等发票来了，再做"财务"确认。这两个状态的切换就是**核算类型**。

### 2. 核销：销账

欠了钱怎么还？财务术语叫"核销"。核销就是告诉系统"这笔债已经清了"。核销时会生成凭证，更新未核销金额。特殊核销有限制规则（1对1、1对0、2对0），保证账目清晰。

### 3. 钩稽：建立关系

暂估和财务两笔账需要"挂钩"——这就是钩稽关系。钩稽后系统知道哪笔暂估对应哪笔财务，核销才能正确执行。

---

## 核心流程（3步走）

### 第一步：采购入库 → 产生暂估

```
供应商发货 → 仓库入库 → 审核入库单 → 生成暂估凭证
                                    ↓
                          AP_PAYABLE.FSetAccountType = 暂估(2)
```

### 第二步：发票到达 → 财务确认

```
供应商发票 → 应付会计录入 → 审核发票 → 判断财务核算类型
                                         ↓
                               AP_PAYABLE.FSetAccountType = 财务(3)
                               钩稽关系建立（暂估 ←→ 财务）
```

### 第三步：付款核销 → 债务清零

```
选择单据 → 行数校验(1:1/1:0/2:0) → 金额计算 → 执行核销
                                         ↓
                              AP_WRITEOFFRECORD生成
                              未核销金额更新
                              核销凭证生成
```

## 核心场景（3分钟理解）

### 场景1：采购发票核销

小王采购了一批电脑，仓库先入库了（产生暂估应付），一个月后发票到了，小李（应付会计）录入发票、审核、自动核销。

### 场景2：费用报销

员工张三出差回来报销差旅费，小李审核后核销。

### 场景3：反核销

如果核销错了怎么办？财务主管老赵有"反清理"权限，可以反核销——系统会生成补偿凭证恢复原状态。

## 常见问题（1分钟QA）

**Q：为什么要区分暂估和财务？**
A：采购有"货到票未到"的时差。暂估反映权责发生，财务反映发票校验完成，符合会计准则。

**Q：为什么核销要限制行数？**
A：保证核销对应关系的可追溯性。1:1是一一对应，1:0是全额核销，2:0支持折扣/折让场景。

**Q：反核销为什么要生成补偿凭证？**
A：因为原凭证已经过账到账簿了，不能简单删除，必须用补偿凭证冲销。

**Q：CG和FY有什么不同？**
A：CG是采购业务，FY是费用报销。两者在税务处理、成本确认、会计科目上不同，所以核算逻辑分开。

**Q：什么是内部核销？**
A：集团内部不同组织之间的应收应付互相抵消，生成内部抵消凭证。
