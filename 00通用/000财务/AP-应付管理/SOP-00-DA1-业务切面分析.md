## 二、业务分类

### 2.1 应付单据管理

| 业务类别 | 说明 | 核心单据 |
|---|---|---|
| 采购应付(CG) | 采购业务产生的应付账款 | 采购应付单 |
| 费用应付(FY) | 费用报销产生的应付账款 | 费用应付单 |
| 其他应付 | 其他业务产生的应付账款 | 其他应付单 |
| 合同应付 | 合同约定的应付账款 | 合同应付单 |

### 2.2 核销匹配业务

| 业务类别 | 说明 | 核心操作 |
|---|---|---|
| 普通核销 | 按金额自动匹配 | FinMatch (method=72) |
| 特殊核销 | 行数限制的核销 | FinMatch (method=73) |
| 钩稽确认 | 暂估→财务确认 | Verify() |
| 钩稽返回 | 财务→暂估退回 | HookReturn() |
| 内部核销 | 组织间应收应付核销 | InnerClear |

### 2.3 凭证生成业务

| 业务类别 | 说明 | 触发时机 |
|---|---|---|
| 暂估凭证 | 入库时生成暂估凭证 | 保存/审核时 |
| 发票校验凭证 | 发票到达后校验 | 审核时 |
| 核销凭证 | 核销时生成 | 核销完成 |
| 付款凭证 | 付款时生成 | 付款完成 |

### 2.4 报表分析业务

| 业务类别 | 说明 | 核心报表 |
|---|---|---|
| 应付余额分析 | 未付款余额统计 | PayableOpenDetail |
| 账龄分析 | 逾期账款分析 | AgingAnalysis |
| 到期债务分析 | 到期应付分析 | MaturedDebt |
| 供应商汇总 | 供应商维度汇总 | APSumReport |

## 三、核心用例（UC）

### UC-01：采购发票处理

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AP-01 |
| 用例名称 | 采购发票审核与核销 |
| 参与者 | 采购员、应付会计 |
| 前置条件 | 采购入库单已审核，供应商发票已录入 |
| 主流程 | 1.采购员录入采购发票<br>2.应付会计审核发票<br>3.系统判断核算类型（暂估/财务）<br>4.触发凭证生成<br>5.进行钩稽确认<br>6.执行核销匹配 |
| 成功结果 | 发票已审核，已核销，应付余额更新 |
| 失败场景 | 核算类型判断失败、核销行数不匹配 |

### UC-02：费用报销处理

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AP-02 |
| 用例名称 | 费用报销审核与核销 |
| 参与者 | 员工、应付会计 |
| 前置条件 | 费用单据已录入 |
| 主流程 | 1.员工提交费用报销<br>2.应付会计审核<br>3.系统判断核算类型（FY逻辑）<br>4.触发凭证生成<br>5.执行核销 |
| 成功结果 | 费用已审核，已核销 |
| 失败场景 | FY逻辑判断失败 |

### UC-03：核销匹配操作

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AP-03 |
| 用例名称 | 暂估与财务单据核销 |
| 参与者 | 应付会计、财务主管 |
| 前置条件 | 存在暂估应付单和财务应付单 |
| 主流程 | 1.打开核销界面<br>2.选择暂估单和财务单<br>3.系统校验行数限制(method=73)<br>4.计算未核销金额<br>5.执行核销<br>6.生成核销凭证<br>7.更新未核销金额 |
| 成功结果 | 单据已核销，未核销金额更新 |
| 失败场景 | 行数不匹配、金额不一致 |

### UC-04：反核销操作

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AP-04 |
| 用例名称 | 核销反操作 |
| 参与者 | 财务主管 |
| 前置条件 | 存在已核销单据 |
| 主流程 | 1.打开核销记录<br>2.点击反核销<br>3.系统返回UnVerifyResultAction<br>4.检查"反清理"权限<br>5.执行反核销<br>6.可能需要补偿凭证 |
| 成功结果 | 核销已撤销，单据恢复 |
| 失败场景 | 权限不足、存在下级依赖 |

### UC-05：内部核销

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AP-05 |
| 用例名称 | 组织间应收应付核销 |
| 参与者 | 财务主管、账套管理员 |
| 前置条件 | 存在内部应收和内部应付 |
| 主流程 | 1.打开内部核销界面<br>2.选择内部应收和内部应付<br>3.执行内部核销<br>4.生成内部抵消凭证 |
| 成功结果 | 组织间往来清零 |
| 失败场景 | 组织权限不足 |

### UC-06：账龄分析

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AP-06 |
| 用例名称 | 应付账款账龄分析 |
| 参与者 | 财务主管、管理层 |
| 前置条件 | 存在未付款应付单据 |
| 主流程 | 1.打开账龄分析报表<br>2.设置账龄区间(0-30/31-60/61-90/90+)<br>3.按供应商/组织汇总<br>4.展示逾期明细 |
| 成功结果 | 账龄分析报表生成 |
| 失败场景 | 数据不完整 |

## 四、业务规则（BR）

| 编号 | 规则描述 | 约束级别 | 证据 |
|---|---|---|---|
| BR-AP-001 | 应付单必须审核后才能核销 | MUST | FinMatch.cs核销前状态校验 |
| BR-AP-002 | 特殊核销行数限制：1:1, 1:0, 2:0(正负) | MUST | FinMatch.cs:171-196 |
| BR-AP-003 | CG和FY业务类型采用不同的核算逻辑 | MUST | PayableEdit.cs:643-715 |
| BR-AP-004 | 核销金额不得超过双方未核销金额 | MUST | MatchServiceHelper.cs |
| BR-AP-005 | 反核销需要"反清理"权限 | MUST | InnerClearRecordEdit.cs:54-67 |
| BR-AP-006 | 凭证生成依赖BizVchMakeScheme模板 | MUST | VoucherGenerateServiceHelper.cs |
| BR-AP-007 | 核销后需更新未核销金额 | MUST | MatchServiceHelper.cs |
| BR-AP-008 | 钩稽确认后才能进行核销 | MUST | VerificationServiceHelper.cs |
| BR-AP-009 | 内部核销只在同体系组织间进行 | MUST | InnerClearRecordEdit.cs |
| BR-AP-010 | 账龄基于未核销金额和到期日期计算 | MUST | AgingAnalysis.cs |

## 六、触发时机图

```
业务事件                      系统响应
─────────────────────────────────────────────────────
采购入库单审核      ────▶    生成暂估凭证（CG逻辑）
      │                      ↓
      │              更新AP_PAYABLE.FSetAccountType=暂估
      │
采购发票审核        ────▶    判断核算类型（CG/FY）
      │                      ↓
      │              生成发票校验凭证
      │                      ↓
      │              更新AP_PAYABLE.FSetAccountType=财务
      │
钩稽确认            ────▶    暂估→财务钩稽关系建立
      │                      ↓
      │              记录Verification关系
      │
核销匹配            ────▶    校验行数限制
      │                      ↓
      │              计算未核销金额
      │                      ↓
      │              创建AP_WRITEOFFRECORD
      │                      ↓
      │              生成核销凭证
      │                      ↓
      │              更新FWRITTENOFFSTATUS
      │
付款                ────▶    关联付款记录
      │                      ↓
      │              更新FRelateHadPayAmount
```
