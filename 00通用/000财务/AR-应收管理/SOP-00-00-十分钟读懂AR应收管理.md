# 00-十分钟读懂AR应收管理 — K3Cloud AR应收管理模块

## 快速理解指南

### 一句话概括

AR应收管理模块是金蝶云星空的"收账管家"——记录客户欠了企业多少钱，帮助财务人员完成从销售出库到收款核销的全流程管理。

---

## 核心概念（3个必须懂）

### 1. 应收单据：借条

想象企业向客户销售了货物，货物先出库但发票还没开给客户，这时财务会做一笔"暂收"——先把账记上"客户欠我一笔钱"。等发票开了，再做"财务"确认。这两个状态的切换就是**核算类型**。

### 2. 核销：销账

客户付款后怎么销账？财务术语叫"核销"。核销就是告诉系统"这笔债已经清了"。核销时会生成凭证，更新未核销金额。特殊核销有限制规则（1对1、1对0、2对0），保证账目清晰。

### 3. 钩稽：建立关系

暂收和财务两笔账需要"挂钩"——这就是钩稽关系。钩稽后系统知道哪笔暂收对应哪笔财务，核销才能正确执行。

---

## 核心流程（3步走）

### 第一步：销售出库 → 产生暂收

```
销售订单 → 仓库出库 → 审核出库单 → 生成暂收应收单
                                       ↓
                            AR_RECEIVABLE.FSetAccountType = 暂收(2)
```

### 第二步：发票开具 → 财务确认

```
开具发票 → 应收会计录入 → 审核发票 → 判断财务核算类型
                                          ↓
                                AR_RECEIVABLE.FSetAccountType = 财务(3)
                                钩稽关系建立（暂收 ←→ 财务）
```

### 第三步：收款核销 → 债权清零

```
客户付款 → 选择单据 → 行数校验(1:1/1:0/2:0) → 金额计算 → 执行核销
                                              ↓
                                 AR_WRITEOFFRECORD生成
                                 未核销金额更新
                                 核销凭证生成
```

## 关键数字（5个必记）

| 数字 | 含义 | 为什么重要 |
|---|---|---|
| 暂收=2，财务=3 | 核算类型的枚举值 | 区分出库阶段和开票阶段 |
| method=72 | 普通核销 | 自动金额匹配，无行数限制 |
| method=73 | 特殊核销 | 行数限制1:1/1:0/2:0 |
| 70+层嵌套 | SetAccountType的复杂度 | SA和其他业务核算逻辑不同，难以维护 |
| 10个DQ闭环 | 核心问题的答案 | 理解系统设计的关键 |

## 核心场景（3分钟理解）

### 场景1：销售应收核销

小王向客户销售了一批电脑，仓库先出库了（产生暂收应收），一个月后开具发票，小李（应收会计）录入发票、审核、自动核销。

### 场景2：客户对账认领

客户打了一笔钱，应收会计在BillRecReport中查看该客户的所有应收单据，系统自动匹配合适的单据进行认领。

### 场景3：反核销

如果核销错了怎么办？财务主管老赵有"反清理"权限，可以反核销——系统会生成补偿凭证恢复原状态。

## 常见问题（1分钟QA）

**Q：为什么要区分暂收和财务？**
A：销售有"货先出、票后开"的时差。暂收反映权责发生，财务反映发票开具完成，符合会计准则。

**Q：为什么核销要限制行数？**
A：保证核销对应关系的可追溯性。1:1是一一对应，1:0是全额核销，2:0支持折扣/折让场景。

**Q：反核销为什么要生成补偿凭证？**
A：因为原凭证已经过账到账簿了，不能简单删除，必须用补偿凭证冲销。

**Q：SA销售和其他业务有什么不同？**
A：SA销售涉及出库→暂收→发票→校验的完整链路，其他业务直接计入应收，两者在税务处理、收入确认、会计科目上不同。

**Q：什么是收付款认领？**
A：AR独有的客户对账与自动匹配机制，按客户维度自动匹配应收单据和收款记录，认领后更新未核销金额。

**Q：什么是内部应收核销？**
A：集团内部不同组织之间的应收应付互相抵消，生成内部抵消凭证（类似AP内部核销）。
