## 二、业务分类

### 2.1 应收单据管理

| 业务类别 | 说明 | 核心单据 |
|---|---|---|
| 销售应收(SA) | 销售业务产生的应收账款 | 销售应收单 |
| 其他应收 | 其他业务产生的应收账款 | 其他应收单 |
| 预收账款 | 预收客户款项 | 预收账款单 |
| 合同应收 | 合同约定的应收账款 | 合同应收单 |

### 2.2 核销匹配业务

| 业务类别 | 说明 | 核心操作 |
|---|---|---|---|
| 普通核销 | 按金额自动匹配 | FinMatch (method=72) |
| 特殊核销 | 行数限制的核销 | FinMatch (method=73) |
| 钩稽确认 | 应收单据关联确认 | Verify() |
| 内部核销 | 组织间应收应付核销 | InnerClear |
| 收付款认领 | 客户对账自动匹配 | BillRecReport |

### 2.3 凭证生成业务

| 业务类别 | 说明 | 触发时机 |
|---|---|---|---|
| 暂收凭证 | 出库时生成暂收凭证 | 保存/审核时 |
| 发票校验凭证 | 发票到达后校验 | 审核时 |
| 核销凭证 | 核销时生成 | 核销完成 |
| 收款凭证 | 收款时生成 | 收款完成 |

### 2.4 报表分析业务

| 业务类别 | 说明 | 核心报表 |
|---|---|---|
| 应收余额分析 | 未收款余额统计 | ReceivableBillBalRpt |
| 账龄分析 | 逾期账款分析 | ReceivableBillReport |
| 到期债权分析 | 到期应收分析 | ReceivableAgingReport |
| 客户汇总 | 客户维度汇总 | ReceivableSumReport |

## 三、核心用例（UC）

### UC-01：销售应收处理

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AR-01 |
| 用例名称 | 销售应收审核与核销 |
| 参与者 | 销售员、应收会计 |
| 前置条件 | 销售出库单已审核，客户发票已录入 |
| 主流程 | 1.销售员录入销售发票<br>2.应收会计审核发票<br>3.系统判断核算类型（暂收/财务）<br>4.触发凭证生成<br>5.进行钩稽确认<br>6.执行核销匹配 |
| 成功结果 | 应收单已审核，已核销，应收余额更新 |
| 失败场景 | 核算类型判断失败、核销行数不匹配 |

### UC-02：收付款认领

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AR-02 |
| 用例名称 | 客户对账与自动匹配 |
| 参与者 | 应收会计、出纳 |
| 前置条件 | 存在未核销应收单和收款记录 |
| 主流程 | 1.打开收付款认领界面<br>2.选择客户和收款记录<br>3.系统自动匹配应收单<br>4.确认认领金额<br>5.执行认领<br>6.更新未核销金额 |
| 成功结果 | 收款已认领，应收余额更新 |
| 失败场景 | 金额不匹配、客户不一致 |

### UC-03：预收账款处理

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AR-03 |
| 用例名称 | 预收款录入与核销 |
| 参与者 | 销售员、应收会计 |
| 前置条件 | 客户预付了款项 |
| 主流程 | 1.录入预收账款单<br>2.审核预收单<br>3.生成预收凭证<br>4.销售发生时执行核销<br>5.核销后更新余额 |
| 成功结果 | 预收已核销 |
| 失败场景 | 核销金额超限 |

### UC-04：反核销操作

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AR-04 |
| 用例名称 | 核销反操作 |
| 参与者 | 财务主管 |
| 前置条件 | 存在已核销单据 |
| 主流程 | 1.打开核销记录<br>2.点击反核销<br>3.系统返回UnVerifyResultAction<br>4.检查"反清理"权限<br>5.执行反核销<br>6.可能需要补偿凭证 |
| 成功结果 | 核销已撤销，单据恢复 |
| 失败场景 | 权限不足、存在下级依赖 |

### UC-05：内部应收核销

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AR-05 |
| 用例名称 | 组织间应收应付核销 |
| 参与者 | 财务主管、账套管理员 |
| 前置条件 | 存在内部应收和内部应付 |
| 主流程 | 1.打开内部核销界面<br>2.选择内部应收和内部应付<br>3.执行内部核销<br>4.生成内部抵消凭证 |
| 成功结果 | 组织间往来清零 |
| 失败场景 | 组织权限不足 |

### UC-06：账龄分析

| 字段 | 内容 |
|---|---|
| 用例ID | UC-AR-06 |
| 用例名称 | 应收账款账龄分析 |
| 参与者 | 财务主管、管理层 |
| 前置条件 | 存在未收款应收单据 |
| 主流程 | 1.打开账龄分析报表<br>2.设置账龄区间(0-30/31-60/61-90/90+)<br>3.按客户/组织汇总<br>4.展示逾期明细 |
| 成功结果 | 账龄分析报表生成 |
| 失败场景 | 数据不完整 |

## 四、业务规则（BR）

| 编号 | 规则描述 | 约束级别 | 证据 |
|---|---|---|---|
| BR-AR-001 | 应收单必须审核后才能核销 | MUST | FinMatch.cs核销前状态校验 |
| BR-AR-002 | 特殊核销行数限制：1:1, 1:0, 2:0(正负) | MUST | ARFinMatch.cs行数限制 |
| BR-AR-003 | SA销售业务采用SA核算逻辑 | MUST | ARReceivableEdit.cs核算判断 |
| BR-AR-004 | 核销金额不得超过双方未核销金额 | MUST | MatchServiceHelper.cs |
| BR-AR-005 | 反核销需要"反清理"权限 | MUST | InnerClearRecordEdit.cs权限校验 |
| BR-AR-006 | 凭证生成依赖BizVchMakeScheme模板 | MUST | VoucherGenerateServiceHelper.cs |
| BR-AR-007 | 核销后需更新未核销金额 | MUST | MatchServiceHelper.cs |
| BR-AR-008 | 钩稽确认后才能进行核销 | MUST | VerificationServiceHelper.cs |
| BR-AR-009 | 内部核销只在同体系组织间进行 | MUST | InnerClearRecordEdit.cs |
| BR-AR-010 | 账龄基于未核销金额和到期日期计算 | MUST | ReceivableBillReport.cs |

## 六、触发时机图

```
业务事件                      系统响应
─────────────────────────────────────────────────────
销售出库单审核      ────▶    生成暂收凭证（SA逻辑）
      │                      ↓
      │              更新AR_RECEIVABLE.FSetAccountType=暂收
      │
销售发票审核        ────▶    判断核算类型（SA）
      │                      ↓
      │              生成发票校验凭证
      │                      ↓
      │              更新AR_RECEIVABLE.FSetAccountType=财务
      │
收款单审核          ────▶    触发收款凭证生成
      │                      ↓
      │              收付款认领界面可选
      │
核销匹配            ────▶    校验行数限制
      │                      ↓
      │              计算未核销金额
      │                      ↓
      │              创建AR_WRITEOFFRECORD
      │                      ↓
      │              生成核销凭证
      │                      ↓
      │              更新FWRITTENOFFSTATUS
      │
内部核销            ────▶    AR内部应收与AP内部应付抵消
      │                      ↓
      │              生成内部抵消凭证
```
