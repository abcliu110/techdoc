## 一、核销业务失败场景

### 1.1 普通核销失败

| 失败代码 | 失败描述 | 根因 | 自动恢复 | 人工介入 |
|---|---|---|---|---|
| AR-E101 | 核销金额超限 | 核销金额>任一方未核销金额 | 无 | 减少核销金额，重新执行 |
| AR-E102 | 行数不匹配 | 特殊核销（method=73）行数组合不合规 | 无 | 按1:1/1:0/2:0调整单据行 |
| AR-E103 | 单据未审核 | 尝试核销未审核的单据 | 无 | 先审核单据 |
| AR-E104 | 客户不一致 | 尝试跨客户核销 | 无 | 更换为同客户单据 |
| AR-E105 | 组织不一致 | 尝试跨组织核销 | 无 | 更换为同组织单据 |
| AR-E106 | 币别不一致 | 尝试跨币别核销 | 无 | 更换为同币别单据 |
| AR-E107 | 未核销金额为负 | 核销后金额计算错误 | 无 | 检查数据一致性，联系DBA |

### 1.2 特殊核销失败

| 失败代码 | 失败描述 | 根因 | 自动恢复 | 人工介入 |
|---|---|---|---|---|
| AR-E110 | 2:0组合缺少负数 | method=73的2:0组合需要一正一负 | 无 | 调整分录，确保有正负金额 |
| AR-E111 | 2:0组合金额不一致 | 正负金额合计不相等 | 无 | 调整分录金额 |
| AR-E112 | 多行对多行 | method=73不允许多行对多行 | 无 | 改用method=72普通核销 |

## 九、并发场景处理

### 9.1 核销并发

| 场景 | 风险 | 处理机制 | 用户感知 |
|---|---|---|---|
| 用户A和B同时核销同一单据 | 核销金额超出未核销金额 | FUnWriteOffAmt使用乐观锁/悲观锁 | B收到"单据状态已变更"提示 |
| 用户A核销时B同时修改单据 | 数据不一致 | 事务隔离，并发检测 | B收到"单据已被修改"提示 |

### 9.2 凭证生成并发

| 场景 | 风险 | 处理机制 | 用户感知 |
|---|---|---|---|
| 多张单据同时审核 | 凭证号可能重复 | 数据库序列+失败重试 | 无感知 |
| 同一单据多次审核 | 重复生成凭证 | 幂等性检查，已有凭证不重复生成 | 无感知 |

### 9.3 认领并发（AR独有）

| 场景 | 风险 | 处理机制 | 用户感知 |
|---|---|---|---|
| 用户A和B同时认领同一客户 | 认领金额超出 | FUnWriteOffAmt锁控制 | B收到"单据状态已变更"提示 |
| 认领和核销同时执行 | 金额重复处理 | 事务隔离 | 提示冲突 |

## 十一、升级路径

### 11.1 问题升级标准

| 级别 | 场景 | 升级到 |
|---|---|---|
| 一线处理 | 权限不足、数据录入错误、配置缺失 | 应收会计组长 |
| 二线处理 | 并发锁、金额不一致、凭证生成失败 | 财务主管 |
| 三线处理 | 数据损坏、死锁、期间异常 | DBA/运维 |
| 四线处理 | 代码缺陷、系统异常 | 开发团队 |

### 11.2 升级触发条件

- 同一问题超过3次未能解决
- 涉及数据一致性问题超过30分钟未解决
- 引发其他模块异常
- 影响财务报表准确性
- 用户情绪激动或业务影响扩大

## 十二、常用恢复命令参考

### 12.1 SQL恢复参考

```sql
-- 检查应收单未核销金额一致性
SELECT FBillID, FBillNo, FReceivableAmt, FUnWriteOffAmt,
       FReceivableAmt - ISNULL((SELECT SUM(FWriteOffAmt)
       FROM AR_WRITEOFFRECORD
       WHERE FSourceBillID = FBillID AND FStatus = 0), 0) AS CalcUnWriteOff
FROM AR_RECEIVABLE
WHERE FBillID = @BillID

-- 清理脏映射数据
DELETE FROM BAS_BusinessVoucher
WHERE FSourceBillID NOT IN (SELECT FBillID FROM AR_RECEIVABLE)

-- 检查核销记录完整性
SELECT wr.FWriteOffRecordID, wr.FSourceBillID, wr.FTargetBillID
FROM AR_WRITEOFFRECORD wr
WHERE NOT EXISTS (SELECT 1 FROM AR_RECEIVABLE WHERE FBillID = wr.FSourceBillID)
   OR NOT EXISTS (SELECT 1 FROM AR_RECEIVABLE WHERE FBillID = wr.FTargetBillID)

-- 检查认领后未核销单据
SELECT FBillID, FBillNo, FCustomerID, FUnWriteOffAmt
FROM AR_RECEIVABLE
WHERE FUnWriteOffAmt > 0
ORDER BY FCustomerID, FDueDate
```

## 十三、快速故障排查流程

### 13.1 核销问题排查

```
1. 检查单据状态（是否已审核）
      ↓ 是 → 继续
      ↓ 否 → 先审核单据
2. 检查核销方法（method=72还是73）
      ↓ method=73 → 检查行数组合
      ↓ method=72 → 检查金额
3. 检查客户/组织/币别是否一致
      ↓ 不一致 → 更换为一致单据
      ↓ 一致 → 检查未核销金额
4. 检查未核销金额是否充足
      ↓ 不足 → 减少核销金额
      ↓ 充足 → 联系技术支持
```

### 13.2 凭证问题排查

```
1. 检查凭证模板是否配置
      ↓ 未配置 → 配置BizVchMakeScheme
      ↓ 已配置 → 检查科目映射
2. 检查科目映射是否完整
      ↓ 未映射 → 配置科目映射
      ↓ 已映射 → 检查汇率配置
3. 检查汇率是否有效
      ↓ 无效 → 配置汇率
      ↓ 有效 → 检查Floating窗口状态
4. 检查凭证是否已生成（查询BAS_BusinessVoucher）
      ↓ 已生成 → 检查凭证内容
      ↓ 未生成 → 手动重试生成
```

### 13.3 认领问题排查（AR独有）

```
1. 检查客户是否存在未核销应收单
      ↓ 无 → 检查应收单录入
      ↓ 有 → 继续
2. 检查认领金额是否超出
      ↓ 超出 → 减少认领金额
      ↓ 未超出 → 检查自动匹配
3. 检查自动匹配算法执行情况
      ↓ 超时 → 分批处理
      ↓ 正常 → 联系技术支持
```
