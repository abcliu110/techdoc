# 92-样例-账类系统业务机制分析（Writer-Reviewer 完整闭环）

> **层级**：L2 方法样例（公开回归夹具）
> **用途**：展示"元规范(L1) + 强归纳(L0) + 源码证据 + Writer/Reviewer 双角色竞争-证伪"完整落地；检验方法契约与输出形状，**不是**项目事实或可复制业务答案。
> **上位约束**：`00-强归纳理论核.md`(L0 v1.6)、`元规范-既有业务系统评估、进化与重构规范.md`(L1 v1.7)、`10-方法卡-业务解压与归纳.md`(L2)
> **领域样本**：金蝶 K3Cloud 供应链负库存开关机制
> **重要声明**：AI 若已见过本样例答案，用于压测时必须更换领域/角色/失败机制再测（防记忆通过）；本样例保留了"被修正、被削弱、未转正"的诚实痕迹，作为方法契约基线。

---

## 0. 一页流程（样本的"形状"）

```text
定义(对象/路径/事实边界)
 -> 业务活模型装配(角色-决定-动作-结果-反馈)
 -> 惊讶驱动溯因(S-M0-Δ-H)
 -> 认知跳跃(≥2 种算子) + 竞争解释(因果结构不同)
 -> 划保留样本 + 冻结 P/F(不等验证后改写)
 -> 压回 L0 一页骨架 + 分型(保护/修复/演进/重绘,不混写)
 -> 独立 Reviewer 反证(CG1-CG8 + 最小反例 + 独立 H'')
 -> 证据更新(保持/增强/缩小/削弱/否证,不固守不前、不盲目迎合)
 -> 补证计划 + 状态落定(转正/增强待补证/削弱/否证)
```

| 项 | 记录 |

| 决策问题 | 它的业务本质为何；它是缺陷还是有意的设计；系统应如何承载 |

## 2. Writer 侧流程（严格规程）

### 2.1 业务活模型
```text
服务对象与结果：制造/贸易仓储执行——不断料、不压货地兑现出库/领料，且账实可查。
角色-决定-动作-结果-反馈：
  计划    提出领料/发货需求
  仓管    在"库存不足?"下决定先走货还是先停；系统提示"允许负库存?"
  单据岗  补录/冲销单据(把账补平)
  财务    月末关账,要求负库存被处置
  系统守卫 过账引擎+CheckInvMinusService 裁决"允许→放行/禁止→拦截"
状态/义务：库存余量(可暂时为负)；补单义务；关账收敛义务。
失败恢复/反馈：负→补单/蓝冲→关账盘点调平→反馈"剩余可领量"。
```

### 2.2 溯因链与分型
```text
S  成熟 ERP 把"允许负库存"做成仓库级布尔开关。
M0 账类守恒 → 负库存是违规,不该有"合法负库存"。
Δ  为何成熟产品主动提供"合法突破守恒"的一等参数?
H  不是"允许破坏",是"允许时间错位":实物先动、单据后补是常态,守恒破坏只是同期短时,靠补单+期盘收敛。
分型(先分型再给方案): 有意设计(受控豁免)→保护; 缺时长监控→可靠性缺陷(修复)。
```

### 2.3 认知跳跃（≥2 算子，本轮用 3 种）
| 算子 | 推演 | 产出 |
|---|---|---|
| 反事实 | 移除开关→频繁停线,或仓管被迫先补单→文书库存(错位从"负"翻成"虚正") | 开关真实作用是"选哪种账实错位" |
| 因果回路与博弈 | 负库存保生产→月底调平→部门博弈；"负库存存续时长"=流程健康信号 | 监控对象=时长/及时率,非有无 |
| 结构类比 | 同类 ERP 亦有等价参数 | 支持"有意设计"而非缺陷 |

### 2.4 竞争 / 保留样本 / 冻结 P/F
- 竞争：`H(时间错位)` vs `H'(历史缺陷)`。
- 保留样本(交 Reviewer 独立核验)：CheckInvMinusService 的"一正一负即使允许也拦"；开关粒度(仓库/物料?)；关账/盘点对负库存的处置要求。
- 冻结：P1(允许组负库存平均存续时长显著低于禁止组改写账实偏差)、P2(强监管物料负库存发生率更低)；F(跨月大量无处置的常住负库存→削弱 H)。
- 轮次预算：默认 3 轮；本轮已形成可区分预测，停止并进入独立反证。

### 2.5 一页骨架压测
核心对象≤5：库存行/出库领料单/补单(蓝冲)/能力开关/负库存检查；不变式≤5：最终守恒/短期可突破/允许负≠任意负/期末须处置/可重建；隐性关系≤3：负库存时长↔补单及时↔关账责任(2跳)、开关粒度↔监管强度；演化轴≤2：时长监控化、开关细粒度化。

## 3. Reviewer 独立反证记录（关键）

| 环节 | 结论 |
|---|---|
| 事实核验 | `FALLOWMINUSQTY` 全源码仅 4 处、全指向 `T_BD_STOCK`(L615/L803/L999/L1216/L394)；**无物料级开关**；默认 "0" opt-in；序列号强制禁负(L394-397) |
| 受控性 | allowMinus 只降为 errType=1(可忽略)+交互确认表单；锁量冲突**无条件硬拦**(L447-452)、一正一负默认硬拦(L409-427)；"允许负≠允许任意负"在代码层成立 |
| 修正1(推翻我的P2) | 无"物料级+仓库级双层开关"→ P2 前提失真，须删/改为"序列号强制禁负的不对称结构" |
| 修正2(降级我的H) | "守恒靠补单+期盘收敛"是行为期望，非产品保证——关账可勾选"忽略负库存检查"(`tbIgnoreMinus`)→ 跨期容忍是显式产品路径 |
| 新竞争 H'' | 开关可能是"转化松弛变量"(放行超卖/超投,降单据转化阻抗)，与时间错位因果不同；动机无法从代码证实 |
| 最小反例 F'-2 | 允许负+关账忽略→同一物料连续≥2期常驻为负且无补单/盘盈 → 命中 H 推翻条件(产品原生可达,经验风险) |
| CG1-CG8 | CG1✓ CG3✓ CG6✓；CG2/CG4/CG7/CG8 质疑(缺行为证据/动机不可证实/时长无现成口径/表述降级) |
| 最终判定 | **增强·待补证**(保留分型；非转正、非否证) |

## 4. 证据更新与诚实记录

- **保持**：分型"有意设计(受控豁免)+缺时长监控=可靠性缺陷"。
- **增强**：受控架构证据(分层/交互/多路硬拦/关账专项)。
- **缩小**：P1 处理组侧可测、对照组基线昂贵；删 P2。
- **削弱**："期末收敛"是期望非承诺(降级表述)。
- **未改口项**：F'-2 命中即触发推翻条件(与冻结 P 一致,未事后放宽)。
- **补证清单**(若引擎转正)：①开关心智动因访谈/H''区分；②负库存行生命周期数据(T_STK_INVENTORYLOG 时间戳+INVMINUSCHECKRESULT 期快照)；③禁止组盘点物理量基线；④强监管与普通物料发生率对比。

## 5. 可复用操作清单（把本次流程压成五步模板）

1. **定义**：对象/决策问题/路径判定(K1-K5)/事实边界 — 未定路径不出方案。
2. **活模型**：角色-决定-动作-结果-反馈主链；画不出主链=还没立项。
3. **溯因+跳跃**：先固定 S-M0-Δ 再给 H；≥2 种认知跳跃；竞争解释须预测不同。
4. **冻结与分型**：划保留样本；P/F 冻结不改写；按四对象分型(保护/修复/演进/重绘)。
5. **独立反证+证据更新**：用**未参与生成**的角色/子代理核验(CG1-CG8+最小反例)；按结果保持/增强/缩小/削弱/否证——固守反例与盲目迎合均不合格。

## 6. 本样例固化的"方法契约基线"

- 一条洞察要"转正"须同时通过：源码可回溯 + 行为证据 + 可区分 H'' + 最小反例可达成 + 表述不把行为期望写成定律。
- "分型"先于"方案"：本例中同一现象，分型决定并修正了方案方向(保护+补监控)。
- Writer 与 Reviewer 分角色是必要而非可选：Reviewer 独立核验才暴露了"P2 前提失真"与"守恒收敛被降级"两处 Writer 盲点。
