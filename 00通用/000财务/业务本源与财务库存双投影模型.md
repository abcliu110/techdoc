# 业务本源与财务/库存双投影模型

> 文档编号：24-方法论
> 主题：回答"业务系统的所有概念是否都应对应财务系统的概念"，给出"一个本源、两个投影"的统一建模结论
> 配套：与 `23-方法论-财务思维与库存思维在SaaS系统的应用与分析.md` 配套阅读（本文为其中 §14 的独立展开）
> 更新日期：2026-08-06

---

## 1. 要回答的问题

> 业务系统里的所有概念，是不是都可以、也应该对应到财务系统的概念？

**结论：理论上"可以对应"（可投影），实践上"不应归并"（不可取代）。**
财务是所有业务事件的经济投影，但不是本源，也不是唯一合法的建模视角。

这个结论可以概括成一句话模型：**一个本源，两个投影。**

---

## 2. 核心模型：一个本源，两个投影

```
                业务主模型（领域/事件，真相源）
                订单、菜品、状态机、券、履约
                       │ 事件驱动
        ┌──────────────┴──────────────┐
   库存视图（资源投影）            财务视图（经济投影）
   可用/锁定/在途、批次/效期        收入/成本/应收、递延/账龄
   不变量：数量守恒、账实一致        不变量：借贷平衡、期间不错配
                               │ 同一事件 ID + 对账
                               └──────── 关联
```

- **本源（业务主模型）**：记录"发生了什么"——订单、状态、明细、履约、券的核销。它是发生与状态的归属地。
- **库存视图**：对"资源存量与占用"的投影，保证"够不够、能不能承诺"。
- **财务视图**：对"价值与权责"的投影，保证"值多少、归哪期、账平不平"。
- **关联方式**：三个视图各自守恒，靠**事件 ID + 对账**互相对平，**禁止做成一张表/一套模型**。

---

## 3. 为什么"可以对应"（投影方向成立）

复式记账从设计上就是**完备的经济刻画系统**：

- 一张资产负债表 + 一张损益表，理论上能收纳企业一切与经济相关的业务——收入、成本、资产、负债、权益、存货、积分负债、递延收入、固定资产，财务都有科目；
- 价值是**闭环守恒**的：库存有成本，交货有毛利，发券有让渡，拉新有费用——任何业务动作最终都能折算成"现金/资产/负债/权益"四个桶的移动。

因此，**财务视图永远能作为对账兜底层，从业务事件推导出来**。这就是 ERP"一切沉淀到财务"的思想根基。

---

## 4. 为什么"不应归并"（四条理由）

### 4.1 时序不同
- 库存/下单世界：秒级、高并发、面向承诺——锁定、抢占、释放、防超卖，要当前瞬间"能不能卖"；
- 财务世界：低频、事后、面向期间——记账、结转、关账、对账。
- 用记账去抢库存，性能与语义全错。

### 4.2 大量概念在财务无处安放
口味、时刻表、排队顺序、评价、路由、权限等没有"价值/权责"语义。财务科目是**分类汇总视图**，不是状态载体——把业务状态机（如订单：初始→已结→已撤）塞进会计结构是灾难。

### 4.3 资源视图是正确操作的前提
防超卖靠"可用量 ± 锁定量"的**数量守恒**，不靠现金守恒。配额、席位数、API 次数同理，它们属于数量世界。

### 4.4 方向反了：账是投影，不是本源
先有业务事件（订单、发货、结账），才有经济投影（收入、成本、应收）。把账当成系统骨架，等于把"发生"降级为"记账"，系统会腐化成"为了能入账而设计"。

---

## 5. 判断尺：一个概念该对齐哪个视图

| 概念它有没有…… | 决定 |
|---|---|
| 数量/可用性/占用 语义 | → 向库存领域对齐（存量 + 占用/释放成对） |
| 价值/权责/期间/平衡 语义 | → 向财务领域对齐（账户 + 前后值 + 只可冲正） |
| 两者都有 | → 交界区，拆两层模型、事件串联、定期对账 |
| 两者都没有（纯运营/体验/平台属性） | → 留在业务主模型，不对齐任何领域 |

---

## 6. 交界区（两个视图都必须建模的地方）

| 业务概念 | 对齐库存层（表现/履约） | 对齐财务层（价值/真相） |
|---|---|---|
| 订单 | 明细履行量：sku/数量/锁定/扣减 | 订单头价值：应收/折扣/税费/实收 |
| 发货/货权转移 | 在库→在途→签收 | 风险报酬转移=收入确认触发点 |
| 退款 | 数量回流：释放/回库 | 冲销收入/红冲包含义务 |
| 余额消费 | 余额池扣减（视角上"出库"） | 资金服务原子记账 + 凭证 |
| 成本 | 批次/计价法决定流出金额 | 结转营业成本、库存资产减少 |

**成本结转（数量 → 金额）和货权转移（履约 → 收入）是两个视图必须握手的地方，也是最容易出错的地方。**

## 7. 印证：本工作区代码

`nms4cloud` 顾客点餐 → 结账业务线恰好是这个格局：

- **业务主模型**：`order_bill` / `order_food` / `order_pay` —— 管发生与状态（订单状态机、明细数量、券核销）；
- **财务投影**：`BalanceDealInterface`（充值/消费/蓝补/红冲/撤销）+ `ScInstFinanceBill` 台账（前后余额 + 本金/赠送分账 + `refflag` 红冲）+ `DealTypeEnum` 六类交易类型；
- **库存投影**：`order_pay.card_balance_before/after`（余额镜像）、券的核销三态（可用→核销→撤销）；
- **事件串联**：`cardConsumeInner` 扣款带凭证与幂等，业务侧只存余额快照，真正的增减由资金服务原子记账。

不需要把这套改造成"一切皆记账"——它已经是教科书式的"本源 + 双投影"。

---

## 8. 一句话收尾

> **财务是完备的"验算器"，不是唯一的"建模器"。**
> 所有业务事件都应能投影到财务（对账兜底），但只有涉及价值/权责/期间的才建模为财务概念，只有涉及资源存量/占用的才建模为库存概念，其余留在业务主模型——一个本源，两个投影，事件串联，对账兜底。
