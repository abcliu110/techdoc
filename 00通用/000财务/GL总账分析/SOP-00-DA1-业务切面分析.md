### 1.2 业务价值
| 价值维度 | 说明 |
|---|---|
| **价值确认** | 将业务事件转化为标准化的财务语言（凭证） |
| **信息聚合** | 按科目、期间、账簿多维度聚合业务发生额 |
| **合规保障** | 借贷平衡、期间控制确保财务数据准确性 |
| **追溯能力** | 业务单据 ↔ 凭证 ↔ 账表双向追溯链 |
| **报告输出** | 为管理层提供决策支持的财务报表 |

## 二、核心角色

| 角色 | 操作 | 接触系统 |
|---|---|---|
| **业务操作员** | 在AP/AR/CN/CB等模块录入业务单据并审核 | 业务子系统 |
| **凭证录入员** | 手工录入/修改/审核/过账GL凭证 | GL总账 |
| **账套管理员** | 管理账簿、科目体系、凭证字、会计期间 | GL总账+基础数据 |
| **财务主管** | 审核凭证、期间结账、报表审批 | GL总账 |
| **审计人员** | 凭证追溯、业务联查、凭证打印 | GL总账（只读） |
| **报表查询用户** | 查询总账/明细账/余额表 | GL报表 |
| **系统管理员** | 权限配置、参数设置 | 全系统 |

## 三、业务分类

### 3.1 凭证生命周期管理
| 业务项 | 触发时机 | 说明 |
|---|---|---|
| 凭证新增 | 手工录入或业务单据审核触发 | 手工录入或系统生成 |
| 凭证修改 | 发现错误时 | 仅限未审核凭证 |
| 凭证删除 | 错误凭证需要作废时 | 仅限未审核凭证 |
| 凭证审核 | 录入完成确认正确 | 状态变更，不可再修改 |
| 凭证反审核 | 审核后发现错误 | 恢复为保存状态 |
| 凭证过账 | 审核后提交过账 | 更新余额表，进入报表 |

### 3.2 业务钩稽
| 业务项 | 触发时机 | 说明 |
|---|---|---|
| 凭证生成 | 业务单据审核通过 | VoucherGenerateService异步生成 |
| 凭证联查 | 从业务单据查看对应凭证 | ViewGlVoucher |
| 单据联查 | 从凭证追溯业务来源 | BAS_BusinessVoucher映射 |
| 多对多钩稽 | 一张单据生成多张凭证或多张单据对应一张凭证 | BAS_BusinessVoucher多记录 |

### 3.3 账簿与科目管理
| 业务项 | 触发时机 | 说明 |
|---|---|---|
| 账簿创建 | 新建组织或账套时 | 凭证归属的财务边界 |
| 科目维护 | 会计制度变更时 | 科目体系+核算维度 |
| 凭证字设置 | 按业务类型分组 | 凭证汇总表按凭证字汇总 |
| 科目体系切换 | 账簿科目体系变更 | 影响新凭证的科目选项 |

### 3.4 会计期间管理
| 业务项 | 触发时机 | 说明 |
|---|---|---|
| 期间打开 | 月初开启新期间 | 允许录入凭证 |
| 期间关闭 | 月末结账 | 禁止新增/修改凭证 |
| 期间反结账 | 发现错误需要调整 | 恢复期间开放状态 |

### 3.5 报表与钻取
| 业务项 | 触发时机 | 说明 |
|---|---|---|
| 总账查询 | 财务人员查看科目汇总 | 按科目+期间聚合 |
| 明细账查询 | 查看科目明细 | 按分录级次展开 |
| 余额表查询 | 查看科目期初/本期/期末 | AccountBalance表 |
| 凭证汇总表 | 按日期/凭证字汇总 | 凭证维度聚合 |
| 报表钻取 | 总账→明细账→凭证 | 依赖方案ID状态机 |
| 钻取会话恢复 | 重新打开浏览器 | 会话状态丢失 |

## 四、核心用例

### UC-1：业务单据审核后自动生成凭证
```
用例编号：UC-1
参与者：业务操作员、GL总账系统
前置条件：业务单据（AP/AR/CN/CB）已保存，且科目映射已配置
基本流程：
  1. 业务操作员点击"审核"按钮
  2. 系统触发VoucherGenerateService
  3. 异步打开Floating窗口（用户不等待）
  4. 后台生成GL_VOUCHER表头
  5. 后台生成GL_VOUCHERENTRY分录
  6. 写入BAS_BusinessVoucher映射
  7. Floating窗口关闭
后置条件：凭证已生成，业务单据与凭证已钩稽
异常处理：
  - 科目映射缺失 → 凭证生成失败，提示用户配置映射
  - 借贷不平衡 → 凭证生成失败，回滚
  - 异步窗口被关闭 → 凭证生成中断，需手动重试
```

### UC-2：从业务单据联查GL凭证
```
用例编号：UC-2
参与者：审计人员、财务主管
前置条件：业务单据与凭证已存在钩稽关系
基本流程：
  1. 用户在业务单据界面点击"联查凭证"
  2. 系统调用ViewGlVoucher
  3. 查询BAS_BusinessVoucher获取关联凭证ID
  4. 查询GL_VOUCHER获取凭证表头
  5. 查询GL_VOUCHERENTRY获取分录明细
  6. 执行两级权限检查（GL子系统权限 → 子系统降级权限）
  7. 返回凭证查看界面
后置条件：用户看到凭证详情
异常处理：
  - 无凭证权限 → 降级到业务子系统权限尝试
  - 无任何权限 → 返回"无权查看"
  - 凭证不存在 → 显示"凭证已被删除"
```

### UC-3：从总账钻取到明细账再到凭证
```
用例编号：UC-3
参与者：报表查询用户、财务主管
前置条件：凭证已审核且已过账
基本流程：
  1. 用户打开总账报表（GL_RPT_GeneralLedger）
  2. 系统从AccountBalance聚合数据
  3. 用户双击某科目单元格（CellDbClick）
  4. 系统检查用户权限（CheckViewDetailRight）
  5. 获取下一报表方案ID（GetNextEntrySchemeId）
  6. 打开明细账报表，传入过滤参数
  7. 用户继续双击某行，钻取到凭证
后置条件：用户到达凭证联查界面
异常处理：
  - 无明细账权限 → 钻取被取消
  - 方案ID为-1（已耗尽） → 钻取终止
  - 用户关闭浏览器 → 方案ID状态丢失，钻取路径断裂
```

### UC-4：凭证审核与反审核
```
用例编号：UC-4
参与者：凭证录入员、财务主管
前置条件：凭证处于"保存"状态
基本流程（审核）：
  1. 用户点击"审核"按钮
  2. 系统验证凭证借贷平衡
  3. 系统验证凭证日期在开放期间内
  4. 系统验证科目存在于当前账簿科目体系
  5. 更新GL_VOUCHER.FDocumentStatus为"已审核"
  6. 凭证进入可过账状态
基本流程（反审核）：
  1. 用户点击"反审核"按钮
  2. 系统验证凭证未过账
  3. 更新GL_VOUCHER.FDocumentStatus为"保存"
  4. 凭证恢复可编辑状态
异常处理：
  - 凭证已过账 → 不可反审核，需先反过账
  - 凭证被其他用户锁定 → 操作被拒绝
```

### UC-5：期间结账
```
用例编号：UC-5
参与者：财务主管
前置条件：当月所有凭证已审核、已过账
基本流程：
  1. 财务主管点击"期间结账"
  2. 系统检查当月所有凭证是否已审核
  3. 系统检查AccountBalance是否完整
  4. 系统检查是否有未钩稽的业务单据
  5. 财务主管确认结账
  6. 系统关闭当月会计期间
后置条件：当月期间禁止新增/修改凭证
异常处理：
  - 有未审核凭证 → 结账被阻止，提示具体单据
  - 有未过账凭证 → 结账被阻止
  - 期间已反结账 → 可重新打开期间
```

## 五、业务规则汇总

| 规则编号 | 规则内容 | 约束级别 | 证据 |
|---|---|---|---|
| BR-GL-001 | 凭证必须借贷平衡（借方合计 = 贷方合计） | MUST | E-SRC: 业务规则 |
| BR-GL-002 | 凭证日期必须在已打开的会计期间内 | MUST | E-SRC: 业务规则 |
| BR-GL-003 | 分录科目必须在当前账簿的科目体系中存在 | MUST | E-SRC: 业务规则 |
| BR-GL-004 | 凭证审核后才能过账 | MUST | E-SRC: 业务规则 |
| BR-GL-005 | 期间结账后不能再新增/修改凭证 | MUST | E-SRC: 业务规则 |
| BR-GL-006 | 凭证联查需要有效权限（GL权限或业务子系统权限） | MUST | E-SRC: ViewGlVoucher.cs:37-50 |
| BR-GL-007 | 报表钻取依赖方案ID顺序状态机 | MUST | E-SRC: ReportFilterCommonFunction.cs |
| BR-GL-008 | 业务单据与凭证为多对多关系 | MUST | E-SRC: ViewGlVoucher.cs |
| BR-GL-009 | 凭证审核后不可直接修改，需先反审核 | MUST | E-SRC: 业务规则 |
| BR-GL-010 | 过账后凭证不可直接删除 | MUST | E-SRC: 业务规则 |
