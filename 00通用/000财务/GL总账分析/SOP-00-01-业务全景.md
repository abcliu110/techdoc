```
┌─────────────────────────────────────────────────────────────────┐

├─────────┬─────────┬─────────┬─────────┬─────────┬───────────────┤

     │         │         │         │         │
     └─────────┴────┬────┴─────────┘
                    │

            ┌───────────────┐
            │   凭证生成    │

                    │
```

**定位**：GL总账是财务域的价值确认枢纽，负责将各业务子系统产生的经济事件统一转化为标准财务凭证。

## 二、核心业务对象全景

### 2.1 凭证（Voucher）— 价值确认原子

| 属性 | 说明 |
|---|---|
| **业务定义** | 记录一笔经济业务的财务确认单元 |
| **物理结构** | GL_VOUCHER（表头）+ GL_VOUCHERENTRY（分录，1-N条） |
| **状态流转** | 保存 → 已审核 → 已过账 |
| **权威源** | GL子系统 |

### 2.2 账簿（AccountBook）— 财务核算边界

| 属性 | 说明 |
|---|---|
| **业务定义** | 一个核算组织的财务核算边界 |
| **组成** | 账簿名称、本位币、科目体系、凭证字集合、期间范围 |
| **隔离性** | 不同账簿数据完全隔离 |
| **权威源** | BD子系统 |

### 2.3 会计科目（Account）— 分类标签

| 属性 | 说明 |
|---|---|
| **业务定义** | 对经济业务进行分类的标签 |
| **编码规则** | 4-2-2-2-...（如1001-银行存款） |
| **辅助核算** | 部门、项目、供应商、客户、自定义维度 |
| **权威源** | BD子系统 |

### 2.4 科目余额（AccountBalance）— 预计算缓存

| 属性 | 说明 |
|---|---|
| **业务定义** | 每个科目在每个期间、每个维度组合下的聚合余额 |
| **用途** | 报表查询直接读取，避免实时聚合 |
| **更新时机** | 凭证过账时同步更新 |
| **权威源** | GL子系统 |

### 2.5 业务凭证映射（BusinessVoucher）— 钩稽桥梁

| 属性 | 说明 |
|---|---|
| **业务定义** | 业务单据与财务凭证的多对多关联 |
| **用途** | 支持业务追溯到财务、财务追溯到业务 |
| **复杂度** | 一单据→多凭证（价税分离）、多单据→一凭证（合并开票） |
| **权威源** | GL子系统 |

## 三、业务角色与职责

| 角色 | 职责 | 核心操作 |
|---|---|---|
| 录入员 | 创建和修改凭证 | 凭证录入、保存 |
| 审核员 | 审核凭证，触发生成 | 凭证审核、联查凭证 |
| 过账员 | 将已审核凭证过账 | 凭证过账 |
| 账套管理员 | 管理账簿、科目、期间 | 账簿配置、科目维护、期间结账 |
| 财务主管 | 监督和复核 | 报表查询、凭证复核 |
| 报表查询员 | 查看和分析报表 | 总账、明细账、余额表查询 |
| 审计人员 | 合规审计 | 历史凭证追溯、报表审计 |

## 四、核心业务能力

### 4.1 凭证生命周期管理

```
录入员                    审核员                   过账员
   │                        │                       │
   ▼                        ▼                       ▼
┌──────┐    保存     ┌──────┐   审核    ┌──────┐   过账    ┌──────┐
│ 保存 │ ──────────▶ │ 待审核 │ ────────▶ │ 已审核 │ ──────────▶ │ 已过账 │
└──────┘             └──────┘           └──────┘            └──────┘
                          │                 │                   │
                          ▼                 ▼                   ▼
                    Floating窗口        凭证生成完成        余额表更新
                    异步生成凭证       业务钩稽建立         报表可查
```

### 4.2 业务钩稽能力

```
AP发票（业务单据）                    GL凭证（财务确认）
       │                                      │
       │  审核                                 │  过账
       ▼                                      ▼
┌─────────────────┐                  ┌─────────────────┐
│ BAS_Business    │◀──────────────▶│ GL_VOUCHER      │
│ VoucherMapping  │    多对多关联    │ + ENTRY         │
└─────────────────┘                  └─────────────────┘
       │                                      │
       ▼                                      ▼
  业务追溯财务                           财务追溯业务
```

### 4.3 报表钻取能力

```
总账报表 ──双击──▶ 明细账报表 ──双击──▶ 凭证列表 ──双击──▶ 单张凭证
  │                                                   │
  │ 返回                                             ▼
  ◀──────────────────────────────────────────── 业务单据
  （方案ID状态机记录钻取路径）
```

## 六、关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 凭证表头分录分离 | GL_VOUCHER + GL_VOUCHERENTRY | 支持1-N灵活分录，按分录钩稽 |
| 多对多业务映射 | BAS_BusinessVoucher独立表 | 支持价税分离和合并开票 |
| 余额表预计算 | AccountBalance独立存储 | 报表查询性能优化 |
| 凭证号业务语义 | {凭证字}-{年份}-{序号} | 满足财务追溯和审计需求 |
| 钻取方案ID | IUserParameterService管理 | 比URL参数更安全 |
| 凭证生成异步 | Floating窗口模式 | 提升业务操作效率 |

## 七、系统边界

| 边界 | 归属 | 说明 |
|---|---|---|
| 业务单据 | AP/AR/INV子系统 | GL不拥有业务单据，只关联财务结果 |
| 资金收付 | CB出纳模块 | GL记录收付款结果，不管理实际资金 |
| 库存核算 | INV存货模块 | GL记录库存价值，不管理库存实物 |
| 税务申报 | 其他系统/手工 | GL不直接生成税务报表 |
