# G0-B 问题基线 — 金蝶 K3Cloud 财务域

| DQ | 问题（业务语义，非接口清单） |
|---|---|
| DQ-BIZ-01 | 财务域的本质是什么：是"记账"（把事实翻成凭证），还是"时间盒上的守恒承诺"？两者预测不同 |
| DQ-FACT-01 | 凭证怎样生成/过账，期间如何守卫？"模板翻译→凭证→过账驱动余额"是否成立 |
| DQ-FACT-02 | 结账"锁期"的真实形态：全量锁 / 局部可写（改期/反结通道）？写入口在哪 |
| DQ-OBLIGATION-01 | 过账/核销的成功、失败、结果未知三态如何界定与收敛 |
| DQ-RISK-01 | 改期/反结/反核销作为"受控补偿通道"的治理边界（审计/留痕强制度） |
| DQ-ACTOR-01 | 会计/审核/出纳/往来/财务负责人/系统管理 各自的决定与责任 |
| DQ-OWNERSHIP-01 | 权威源：科目表/余额写点/期间状态 谁是最终解释者 |
| DQ-MECHANISM-01 | 平台承载：元数据+操作框架（operationNumber/timingPoint/插件）如何承载财务语义 |

**候选解释池（先惊讶后命名，见 DA8 六节）**：
- 记账—对账—披露 = 一条链（语义分组）还是三重视角对同一组事实的三个投影？
- "记账软件"的称谓是否把"期间不可逆承诺"这一本质藏住了（CI 候选）。
