## 30秒结论（最高价值，只看这段也能下手）
1. **它本质不是"记账软件"**：财务域 = **时间盒(期间)上的守恒承诺机**——记录是手段，把一段时间的账目"冻结成不可逆承诺、并约定受控撤销"才是产品。称谓藏住了卖点。
2. **承重墙 = 凭证-余额-期间 三段式 + 元数据/操作框架**：动"期间"=同时伤历史不可变、审计、结账三件事。
3. **最脆弱点 = 结账写入口未定位（U-DA0-5）**：这面"承诺墙"到底能不能真锁死，目前没有人证——是补证与风险的优先项。
4. **唯一受控的洞 = 改期/反结**：它既是救你出错的通道，也是历史被反复改写的入口；治理（权限+留痕+审计强制度）未实证。
5. **该动什么 = 显式承诺生命周期**：把"改期/反结 + 释放"模型化为承诺对象+强度三档（占用/冻结/改期中）+ 释放锚点=结算点，消除"双路径互漏"结构性原因；**怎么动** = 先实测 U-DA0-5 锁死承重墙 → 三阶段迁移（治理 → 释放统一 → 承诺对象显式），全程新锁定才进、可灰度可回退。

## 一、业务分析（它在做什么）
- **一条链三段**：记账（凭证/余额/期间）→ 对账（核销/差异调平）→ 披露（报表/多账簿折算）。这是"做成什么"的总纲，不是模块清单。
- **四大设计决策**（DEC-001~004，全是有意决策）：三段式=可审计+可汇总+历史不可变；元数据零代码=百种单据配置化；锁期可反结=默认防篡改、异常可纠错；核销经"核销单"=合并/部分/差异/审计可表达。
- **权威源**：科目表=账目；过账=余额唯一写点；期间=结账状态。三件事各有唯一解释者，无多重写。

## 二、架构分析（它怎么建）
- **单通道操作**：保存/审核/过账/结账全走操作框架（operationNumber+timingPoint+插件）——财务语义以"插件+元数据"存在，不是大段代码。改业务=改元数据/插件，不动骨架。
- **服务门面分层**：FIN 的 `*ServiceHelper` 是业务门面，复用平台编排——跨模块一致性靠这一层收敛。
- **关键反证**（X-002-1）：`AdjustPeriodServiceHelper` 命名像"能写"，实测**只读查询门面**——"改期"的真实写能力在别处（未定位），别被名字骗。

## 三、业务归纳（它真正是什么）
- **本质 = 时间盒上的守恒承诺机**（非"记账"）：对应 000财务02 DA8 6.1 的 `S-M0-Δ-H-P-F-ΔH-CI`。
  - CI 反直觉："记账软件"称谓恰好藏住真实卖点——它卖的是"冻结时间"，不是"记录事实"。
  - F（可推翻它的最小事实）：一条不经期间检查直写已结余额的路径 → U-DA0-5 正是取证点。
- **换领域通用层**：库存期间关账、会员积分冻结、生产期间结账 = 同一抽象（时间盒承诺）；凭证-余额-期间是财务专属实现。

## 四、架构归纳（哪根是承重墙）
- **承重墙 = 凭证-余额-期间 三段式 + 操作框架**：摘掉"期间"= 历史不可变/审计/结账全塌；回指不变量"期间封闭锁历史"。
- **正交轴被压三表**：多维账页"科目×期间×核算维度×币别"投影成 凭证(明细轴)+余额(聚合轴)+期间状态(时间轴)。
- **J.2 后验**：模式名（"三表投影/账类系统"）是在证据之后命名的，不是先扣帽子。

## 五、业务进化（机制上该动什么）
- **必做底线 = 改期治理**：权限+留痕+审计强制度化 — 唯一"不做会出事"，历史可被反复改写（不做即风险）。
- **机制候选 = 显式承诺生命周期**：改期/反结/释放 + 冻结 → 承诺对象+强度三档(占用/冻结/改期中) + 释放锚点=结算点 — 消除"收款审核 vs 核销"双路径互漏的结构性原因（同 Stock 范例 02 的释放=承诺终态收敛）。**竞争预测** vs 现状：同"SO 部分交付+关单"场景，候选预测"按承诺比例释放"，现状预测"仅关单事件触发"——可区分。
- **最小实验**：改期单+留痕+审计+强度降级 小范围实测，观察"反复改"发生率与责任链清晰度（不推广，先证伪候选）。

## 六、架构进化（怎么安全演化）
- **K1-K5 复核**：K1 承诺对象身份新引入（候选 B）/K2 不变/K3 守恒不变/K4 一致性受治（核心入口）/K5 能力扩展 → 路径 A 起步，K1 决定是否进路径 B。
- **交接包**：BIZ「显式承诺生命周期」+ EVO-D ①改期治理 ②释放锚点统一 ③写入口实测；最大未决 U-DA0-5（结账写入口）。
- **迁移（三阶段可灰度+可回退）**：阶段 1 治理基线（路径 A, 低风险，留痕/审计/串签）→ 阶段 2 释放锚点统一（路径 A 强化, 中风险，新锁定才进、旧不追溯）→ 阶段 3 承诺对象显式建模（候选路径 B, 高风险，须先 U-DA0-5 实测）。
- **推翻路径**：若 U-DA0-5 实测发现"不经期间检查可直写已结余额"的路径 → 承重墙"承诺墙"被绕，BIZ/路径判定重评；K1-K3 也需重检。
