# 失败恢复手册 — K3Cloud Sal销售

## 概述

本手册针对Sal销售模块的常见失败场景，提供系统化的排查和恢复指南。涵盖9个常见问题，分为两大类：**销售异常**和**财务异常**。每个问题包含症状、原因分析、解决步骤和预防措施。

---

## 一、销售异常（5个）

### 问题1：订单无法审核（信用额度不足）

#### 症状
- 订单提交审核时报错："信用额度不足"
- 订单状态停留在"创建"
- 客户信用报告显示可用额度为负数

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 历史应收未回款 | 高 | 客户账期已到期但未付款 |
| 信用占用未释放 | 中 | 退货/取消订单后信用未恢复 |
| 订单金额超出总信用 | 高 | 新订单直接超总信用额度 |

#### 解决步骤
```
1. 查询客户信用占用明细
   └─> 打开客户信用分析报表
       - 查看已占用额度来源
       - 识别未核销的应收单

2. 处理历史应收
   ├─> 如果是未付款：
   │   └─> 联系客户催款
   │       - 发送催款通知
   │       - 安排付款
   │
   └─> 如果是异常占用：
       └─> 手动释放信用占用
           - 联系信用专员
           - 核实占用来源
           - 执行释放（如确认已退货）

3. 审批超额度订单（临时）
   └─> 如果业务紧急：
       - 提交超额度审批
       - 主管特批
       - 执行订单

4. 验证
   └─> 重新审核订单，确认通过
```

#### 预防措施
- 每日监控客户信用报告
- 账期到期前自动提醒
- 超额度订单必须走审批流程

### 问题2：库存锁定不足

#### 症状
- 出库审核时报错："库存不足"
- 但订单已审核通过
- 可用量与订单数量不匹配

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 并发出库 | 高 | 多个订单同时出库，锁定量不足 |
| 锁定已释放 | 中 | 订单被反审核/关闭 |
| 批次限制 | 中 | 特定批号库存不足 |

#### 解决步骤
```
1. 查询库存锁定明细
   └─> SELECT * FROM T_PLN_RESERVELINKENTRY
       WHERE FSOURCEBILLNO = '订单号'
       AND FMATERIALID = '物料ID'

2. 查询可用量
   └─> SELECT FSTOCKQTY, FLOCKQTY, FAVAILQTY
       FROM T_STK_INVENTORY
       WHERE FMATERIALID = '物料ID'
       AND FSTOCKID = '仓库ID'

3. 处理方案
   ├─> 如果是并发占用：
   │   └─> 调整出库顺序
   │       - 优先执行当前订单
   │       - 其他订单排队
   │
   └─> 如果是锁定已释放：
       └─> 重新审核订单
           - 反审核当前出库
           - 重新审核订单（重新锁定）
           - 审核出库

4. 紧急方案（分批出库）
   └─> 如果无法立即解决：
       - 分批出库
       - 先出可用部分
       - 后续到货再补发
```

#### 预防措施
- 订单审核时锁定全部数量
- 监控库存可用量预警
- 批次物料提前规划

### 问题3：退货后应收未红冲

#### 症状
- 退货单已审核
- 但应收单金额未减少
- 客户信用占用未恢复

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 退货审核未完成 | 高 | 退货审核流程卡住 |
| 系统异常 | 中 | 退货→应收联动失败 |
| 应收已核销 | 低 | 应收已收款无法红冲 |

#### 解决步骤
```
1. 检查退货单状态
   └─> SELECT FBILLSTATUS, FAPPROVEDATE
       FROM T_SAL_RETURNSTOCK
       WHERE FBILLNO = '退货单号'

2. 检查应收单状态
   └─> SELECT FBillNo, FAmount, FStatus
       FROM T_AR_RECEIVEBILL
       WHERE FSOURCEBILLNO = '原出库单号'

3. 如果退货已审核但应收未红冲：
   ├─> 手动生成红字应收单
   │   └─> 联系财务执行
   │       - 创建应收红字单
   │       - 关联原应收单
   │       - 审核后核销
   │
   └─> 检查退货→应收联动配置
       └─> 联系IT检查
           - SaleReturnService→ARService链路

4. 验证
   └─> 查询应收单，确认红冲金额已抵消
```

#### 预防措施
- 退货审核后自动触发应收红冲
- 每日检查退货与应收一致性
- 退货流程增加应收校验节点

### 问题4：订单变更失败

#### 症状
- 订单已审核，需要修改物料/数量
- 反审核报错
- 订单状态异常

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 已有出库记录 | 高 | 部分出库后无法减少数量 |
| 应收已核销 | 中 | 应收单已收款无法反审核 |
| 锁定已使用 | 中 | 部分锁定已被消耗 |

#### 解决步骤
```
1. 查询订单执行状态
   └─> SELECT FOUTQTY, FRETURNQTY, FStatus
       FROM T_SAL_ORDERENTRY
       WHERE FID = '订单ID'

2. 根据情况处理
   ├─> 如果只有部分出库：
   │   └─> 只能增加数量，不能减少
   │       - 新增订单行（增行）
   │       - 不能直接减少原数量
   │
   └─> 如果无出库记录：
       └─> 正常反审核→修改→重审
           - 反审核订单
           - 修改分录
           - 重新审核

3. 特殊情况：需取消订单
   ├─> 关闭原订单
   │   └─> 释放锁定
   │       - 关闭订单
   │       - 锁定自动释放
   │
   └─> 创建新订单
       └─> 按正常流程处理

4. 验证
   └─> 检查订单状态和锁定明细
```

#### 预防措施
- 审核前仔细核对订单内容
- 订单变更走审批流程
- 部分出库后禁止减少数量

### 问题5：价格审批流程卡住

#### 症状
- 价格超权限的订单无法提交
- 审批流程停滞
- 业务无法推进

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 审批人离线 | 高 | 主管不在，无法审批 |
| 审批流配置错误 | 中 | 工作流节点配置问题 |
| 权限不足 | 低 | 当前用户无审批权限 |

#### 解决步骤
```
1. 查询审批状态
   └─> 打开订单详情
       - 查看审批历史
       - 定位卡住的节点

2. 联系审批人
   └─> 如果审批人离线：
       - 电话/微信联系
       - 说明业务紧急性
       - 请假期间可指定代理人

3. 临时方案：提升权限
   └─> 如果业务非常紧急：
       - 联系管理员临时提升权限
       - 由更高层级代为审批
       - 事后补办手续

4. 流程配置检查
   └─> 如果是配置问题：
       - 联系IT检查工作流配置
       - 修复后重新发起
```

#### 预防措施
- 审批人外出前设置代理人
- 关键业务配置备选审批人
- 定期检查审批流配置

## 二、财务异常（4个）

### 问题6：应收金额与出库金额不一致

#### 症状
- 应收单金额 ≠ 销售出库金额
- 客户对账发现差异
- 可能存在税率/折扣计算错误

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 税率配置错误 | 高 | 物料税率设置不正确 |
| 折扣未同步 | 中 | 出库后订单折扣变更 |
| 币种汇率问题 | 中 | 多币种销售汇率差异 |

#### 解决步骤
```
1. 对比应收与出库
   └─> SELECT 出库单号, 出库金额, 应收单号, 应收金额
       FROM T_SAL_OUTSTOCK o
       JOIN T_AR_RECEIVEBILL a ON o.FID = a.FSOURCEBILLID
       WHERE ABS(o.FALLAMOUNT - a.FALLAMOUNT) > 0.01

2. 查找差异原因
   ├─> 如果是税率：
   │   └─> 检查物料税率配置
   │       - 核实正确税率
   │       - 如已出库，需调整应收
   │
   └─> 如果是折扣：
       └─> 核实出库时的折扣
           - 检查折扣变更历史
           - 确认责任归属

3. 调整应收（谨慎）
   └─> 如果差异确实存在：
       ├─> 红字冲销原应收
       │   └─> 生成红字应收单
       │
       └─> 生成正确应收
           └─> 按正确金额重新生成

4. 验证
   └─> 重新核对，确保金额一致
```

#### 预防措施
- 出库审核时校验应收金额
- 定期核对出库与应收
- 税率配置纳入检查清单

### 问题7：GL凭证与应收不一致

#### 症状
- GL凭证借贷不平衡
- 或凭证金额与应收不符
- 财务对账发现

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 凭证模板配置错误 | 高 | 收入科目设置错误 |
| 凭证生成事务失败 | 中 | 部分成功部分失败 |
| 退货凭证未生成 | 中 | 退货审核未触发凭证 |

#### 解决步骤
```
1. 对比GL凭证与应收
   └─> 查询凭证分录
       SELECT VOUCHERNO, ACCOUNT, DEBIT, CREDIT
       FROM T_GL_VOUCHERENTRY
       WHERE FSOURCEBILLNO = '出库单号'

2. 检查凭证模板
   ├─> 如果是模板错误：
   │   └─> 修复凭证模板配置
   │       - 核实科目映射
   │       - 联系IT修改
   │
   └─> 如果是金额差异：
       └─> 核对出库金额与凭证金额

3. 生成补充凭证
   └─> 如果凭证缺失：
       - 生成调整凭证
       - 记录调整原因
       - 审计追踪

4. 退货凭证检查
   └─> 如果是退货：
       - 核实退货凭证是否生成
       - 红字凭证应对冲原收入
```

#### 预防措施
- 凭证模板配置纳入变更管理
- 出库审核后验证凭证生成
- 退货审核触发凭证联动

### 问题8：收款核销失败

#### 症状
- 收款单无法核销应收单
- 报错"币种不一致"或"金额不匹配"
- 核销流程卡住

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 币种不一致 | 高 | 收款币种与应收币种不同 |
| 金额不匹配 | 中 | 部分核销金额错误 |
| 应收状态异常 | 低 | 应收已完全核销或已红冲 |

#### 解决步骤
```
1. 查询应收与收款币种
   └─> SELECT FCURRENCYID, F Amount, FSTATUS
       FROM T_AR_RECEIVEBILL
       WHERE FBILLNO = '应收单号'
       │
       SELECT FCURRENCYID, FAMOUNT
       FROM T_AR_RECEIVEBILL
       WHERE FBILLNO = '收款单号'

2. 币种不一致处理
   └─> 收款币种必须与应收一致
       - 原路退回客户
       - 重新按应收币种收款
       - 或配置多币种核销

3. 金额不匹配处理
   └─> 部分核销：
       - 输入正确的核销金额
       - 系统自动处理剩余

4. 应收状态异常
   └─> 如果应收已核销：
       └─> 查询核销记录
           - 已核销无需再处理
           │
       └─> 如果应收已红冲：
           └─> 查询红字应收
               - 红字应收与原应收已对冲
               - 无需额外处理
```

#### 预防措施
- 收款录入时校验币种
- 部分核销场景明确核销金额
- 定期检查应收核销状态

### 问题9：多币种汇率损失

#### 症状
- 应收单金额与实际收款金额有差异
- 汇率波动导致损失
- 客户按不同汇率付款

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 汇率锁定时机 | 高 | 出库时汇率与收款时汇率不同 |
| 汇率配置错误 | 中 | 币种汇率设置不正确 |
| 付款时间延迟 | 高 | 汇率波动造成损失 |

#### 解决步骤
```
1. 分析汇率差异
   └─> 计算差异金额
       差异 = 应收本币金额 - 收款本币金额
       正数：汇兑收益
       负数：汇兑损失

2. 核实汇率配置
   └─> 检查出库时的汇率
       - 当时汇率是否正确
       - 是否有锁定价汇率
       │
       └─> 检查收款时的汇率
           - 实际收款汇率
           - 系统使用的汇率

3. 汇兑损益处理
   └─> 生成汇兑损益凭证
       ├─> 汇兑损失：
       │   └─> 借：财务费用-汇兑损益
       │       贷：应收账款
       │
       └─> 汇兑收益：
           └─> 借：应收账款
               贷：财务费用-汇兑损益

4. 汇率风险管理
   └─> 建议措施：
       - 锁定订单时即锁定汇率
       - 预收款降低汇率风险
       - 及时催收缩短账期
```

#### 预防措施
- 订单审核时锁定汇率
- 预收款降低汇率风险敞口
- 设置汇率波动预警
- 缩短外币应收账期

## 三、数据恢复指南

### 紧急恢复：订单重置

如果单据状态异常，可尝试重置：

```
1. 查询单据状态
   └─> SELECT FID, FBILLNO, FBILLSTATUS, FAPPROVEDATE
       FROM T_SAL_ORDER
       WHERE FBILLNO = '订单号'

2. 根据状态处理
   ├─> 如果是"审核中"卡住：
   │   └─> 重置为"创建"
   │       - 联系管理员执行
   │       - 重新提交审核
   │
   └─> 如果是异常状态：
       └─> 数据修复
           - 导出当前状态
           - 修改状态字段
           - 验证业务逻辑
```

### 谨慎操作：事务回滚

对于最近的错误操作，可尝试事务回滚：

```
1. 确认操作时间
   └─> 从日志中确认错误操作的时间点

2. 评估影响范围
   └─> 检查受影响的订单、出库、应收

3. 执行回滚
   └─> 联系DBA执行
       - 恢复到一个安全的时间点
       - 重放后续正确操作
```
