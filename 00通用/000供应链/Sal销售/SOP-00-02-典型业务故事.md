# 典型业务故事 — K3Cloud Sal销售

## 故事1：销售员小王的一天

### 背景
小王是XYZ公司的销售员，负责华东区域的客户管理。公司使用金蝶K3Cloud系统，销售模块是每天工作的核心。

### 场景
2024年1月15日，普通的一天。

**步骤1：早会接收任务**
- 收到主管分配的商机
- 客户A希望采购电机50台
- 客户B有报价询价需求

**步骤2：处理客户A报价**
- 查看电机产品信息和标准价格
- 创建销售报价单：
  - 客户：客户A
  - 物料：电机50台
  - 单价：500元/台（从价目表获取）
  - 报价金额：25,000元
- 提交审核，主管审批通过
- 报价单有效期：30天

**步骤3：签订订单**
- 客户A确认报价，要求签订订单
- 将报价单转为销售订单
- 订单交期：1月25日
- 提交审核

**步骤4：库存锁定检查**
- 系统自动执行库存锁定
- 检查电机可用量：100台
- 锁定数量：50台
- 可用量从100台降为50台
- 订单审核通过 ✅

**步骤5：发货执行**
- 1月25日，仓库备货完成
- 小王在系统确认发货
- 创建销售出库单：
  - 物料：电机50台
  - 批号：B20240101
  - 仓库：上海仓库
- 审核出库单，过账引擎执行

**步骤6：应收确认**
- 出库审核后，系统自动生成应收单
- 应收金额：25,000元（含税）
- 应收到期日：2月15日（账期30天）

**步骤7：收款核销**
- 2月10日，客户付款到账
- 小王在系统录入收款单
- 收款金额：25,000元
- 执行核销，应收单状态变为"已核销"
- 订单完成 ✅

### 业务规则体现
- BR-Sal-101：价格从价目表获取 ✅
- BR-Sal-201：订单审核时创建锁定 ✅
- BR-Sal-202：出库审核时检查可用量 ✅
- BR-Sal-401：出库审核时生成应收 ✅

## 故事2：信用危机

### 背景
XYZ公司的信用专员小李，负责监控客户信用额度。2024年1月20日，发现一个紧急问题。

### 场景
2024年1月20日，信用预警。

**问题发现**
- 客户B申请新订单100,000元
- 系统显示：客户B信用额度200,000元，已占用180,000元
- 可用额度仅20,000元，新订单需要100,000元
- **信用额度不足！**

**步骤1：查询占用明细**
- 小李打开信用分析报表
- 发现客户B的占用来源：
  - 订单O-2024-0010：占用80,000元（出库50,000，已核销30,000）
  - 订单O-2024-0015：占用50,000元（出库30,000，已核销20,000）
  - 订单O-2024-0020：占用50,000元（未出库）
- 已占用180,000元，实际应收100,000元

**步骤2：分析原因**
- 客户B付款延迟
- 账期30天已到期，但仍未付款
- 信用占用未及时释放

**步骤3：处理措施**
- 联系客户B催款
- 客户B承诺1月25日付款
- 新订单暂缓，等信用恢复

**步骤4：后续跟进**
- 1月25日，客户B付款50,000元
- 核销历史应收
- 信用占用释放50,000元
- 新订单可继续执行

### 业务规则体现
- BR-Sal-301：订单审核时检查信用额度 ✅
- BR-Sal-302：出库审核时增加信用占用 ✅
- BR-Sal-303：收款核销时释放信用占用 ✅
- ⚠️ 教训：信用检查需加强账期逾期提醒

## 故事3：退货处理

### 背景
XYZ公司的销售员小王，收到客户A的退货申请。电机50台中有5台存在质量问题。

### 场景
2024年1月28日，处理退货。

**步骤1：接收退货申请**
- 客户A反馈：电机有异响，要求退货5台
- 小王核实：订单O-2024-0115，批号B20240101
- 确认属于质量问题范围

**步骤2：创建退货单**
- 在系统创建销售退货单：
  - 原出库单：OUT-2024-0115
  - 退货数量：5台
  - 退货原因：质量问题
  - 批号：B20240101
- 提交审核

**步骤3：审核退货**
- 仓库确认实物退回
- 主管审核通过退货单
- 系统执行：
  - 退货入库（负数出库）
  - 应收单红字冲销
  - 信用占用释放

**步骤4：退款处理**
- 生成退款通知：2,500元（5台×500元）
- 财务执行退款
- 收款单红字核销应收

### 业务规则体现
- BR-Sal-404：退货审核时生成红字凭证 ✅
- BR-Sal-303：退货审核时释放信用占用 ✅
- REL-07：出库→退货关系追溯 ✅

## 故事4：价格审批

### 背景
XYZ公司的销售员小王，收到一个大客户的价格谈判请求。需要给予较大折扣。

### 场景
2024年2月1日，价格谈判。

**步骤1：评估折扣需求**
- 客户C希望采购钢材100吨
- 标准价格：5,000元/吨
- 客户期望价：4,500元/吨
- 折扣幅度：10%

**步骤2：检查权限**
- 小王的折扣权限：5%
- 10%折扣超出权限范围
- 需要上级审批

**步骤3：发起审批**
- 创建报价单，折扣10%
- 系统提示：超出权限，需审批
- 提交给销售主管

**步骤4：主管审批**
- 主管评估：
  - 客户C是战略客户
  - 订单金额大，长期合作价值高
  - 同意10%折扣
- 审批通过

**步骤5：转订单执行**
- 报价审核通过
- 客户C确认订单
- 转销售订单执行

### 业务规则体现
- BR-Sal-102：订单折扣不能低于客户最低折扣 ✅
- BR-Sal-103：超出价格权限需上级审批 ✅

## 故事5：分批发货

### 背景
XYZ公司的客户D有一个大订单，但由于库存不足，需要分批发货。

### 场景
2024年2月5日，分批发货。

**步骤1：订单审核**
- 客户D订单：电机200台
- 当前库存：120台
- 可用量不足，但客户坚持下单

**步骤2：创建订单**
- 订单交期：分批
- 第一批：120台，2月10日
- 第二批：80台，2月25日
- 审核订单，锁定库存200台

**步骤3：第一次发货**
- 2月10日，备货120台
- 创建销售出库单：120台
- 审核出库，库存扣减120台
- 生成应收单：120×5,000=600,000元

**步骤4：第二次发货**
- 2月25日，新到货80台
- 创建销售出库单：80台
- 审核出库，库存扣减80台
- 生成应收单：80×5,000=400,000元
- 订单完成

### 业务规则体现
- BR-Sal-201：订单审核时锁定全部数量 ✅
- BR-Sal-202：出库审核时检查可用量 ✅
- REL-04：订单→出库 1:N关系 ✅

## 故事6：跨组织销售

### 背景
XYZ公司有上海总部和北京分部两个组织，需要跨组织向客户销售。

### 场景
2024年2月10日，跨组织销售。

**步骤1：发起跨组织订单**
- 北京分部客户E下单100台电机
- 库存在上海仓库
- 需要跨组织调拨销售

**步骤2：订单审核**
- 订单组织：北京分部
- 库存组织：上海总部
- 审核订单，锁定上海仓库库存

**步骤3：出库处理**
- 上海仓库执行出库
- 创建销售出库单：
  - 货主组织：上海
  - 保管组织：上海
  - 发货仓库：上海仓库
  - 客户：北京分部客户E

**步骤4：内部交易处理**
- 系统生成内部交易凭证
- 上海确认销售收入
- 北京确认内部采购
- 内部往来自动清账

**步骤5：应收处理**
- 应收单挂在北京分部
- 北京分部客户E付款
- 核销应收，内部往来结清

### 业务规则体现
- BR-Sal-501：出库审核生成收入凭证 ✅
- 跨组织销售内部交易处理 ✅

## 六个故事的启示

| 故事 | 核心主题 | 关键教训 |
|---|---|---|
| 故事1 | 日常销售闭环 | 报价→订单→锁定→出库→应收→收款 |
| 故事2 | 信用管理 | 信用额度实时管控，催收及时 |
| 故事3 | 退货处理 | 退货→红冲→退款流程 |
| 故事4 | 价格审批 | 超权限需审批，流程合规 |
| 故事5 | 分批发货 | 锁定全部数量，分批出库 |
| 故事6 | 跨组织销售 | 内部交易自动处理 |

**三个关键教训**：
1. 信用管理是销售风险控制的核心
2. 价格审批流程必须严格执行
3. 跨组织销售需注意内部交易处理
