# 十分钟读懂Purchase采购

> 快速理解K3Cloud采购模块的核心逻辑

## 一句话概括

**采购是配置驱动的子域，核心链路"申请→订单→入库→应付"零代码，靠SVM询报价实现供应商协同。**

---

## 核心发现（3个）

### 1. 配置驱动是最大特点
```
申请 ──ConvertRule──▶ 订单 ──ConvertRule──▶ 收料 ──ConvertRule──▶ 入库
                         │                                    │
                         ▼                                    ▼
                      SVM比价 ◀───报价──┘              库存 + 应付
```

**采购链"申请→订单→收料→入库"四个环节，零转换插件代码，全靠元数据ConvertRule配置驱动。**

### 2. SVM是唯一代码化的采购环节
```
申请 → 询价 → 报价 → 比价 → 订单
         ↑       ↑       ↑
       唯一有代码的采购环节
```

### 3. 入库是核心触发点
```
入库审核 → 库存增加 → 应付生成 → GL凭证
```

## 核心流程

### 标准采购流程
```
采购员 → 创建询价单 → 发送供应商 → 接收报价 → 比价分析 → 选择最优 → 生成订单
                                                                               │
                                                                               ▼
供应商 ─────────────────────────────────────────────────────────────────────▶ 送货
                                                                               │
                                                                               ▼
仓库员 → 收料检验 ──▶ 创建入库单 ──▶ 审核入库 ──▶ 库存增加 ──▶ 应付单生成 ──▶ GL凭证
                                                                               │
                                                                               ▼
                                                                         财务付款
```

---

## 决策点（5个）

| 决策点 | 选项 | 选择 |
|---|---|---|
| 比价策略 | SVM询价 vs 直接采购 | 可配置 |
| 入库成本计价 | 订单单价/协议价/计划价 | 订单单价 |
| 应付生成时机 | 入库审核时/发票确认时 | 入库审核时 |
| 发票校验方式 | 严格匹配/允许差异 | 允许差异 |
| GL凭证生成 | 同步生成/异步生成 | 同步生成 |

---

## 风险项（2个高风险）

| 风险 | 等级 | 应对 |
|---|---|---|
| 巨型类PurchaseService维护困难 | 高 | 重构拆分 |
| 采购链配置驱动，无法从源码学习 | 高 | 文档化配置规则 |

---

## 进化方向

### 短期（路径A优化）
- 拆分巨型类PurchaseService
- 文档化ConvertRule配置规则

### 中期（路径A增强）
- 透明化SVM比价算法
- 标准化发票差异处理

### 长期（路径B重构）
- 将配置转化为代码（可选）
- 引入智能比价算法
