# 失败恢复手册 — K3Cloud Purchase采购

## 一、异常场景速查表

| 异常场景 | 紧急程度 | 影响范围 | 恢复方式 |
|---|---|---|---|
| 入库数量超过订单未执行量 | 🔴 高 | 库存、应付 | 拒绝入库或审批超量 |
| 入库审核后需反审核 | 🟡 中 | 库存、应付、凭证 | 反审核+红冲处理 |
| 应付单已核销后需调整 | 🔴 高 | 财务报表 | 反核销+调整 |
| SVM比价结果异常 | 🟡 中 | 采购决策 | 重新比价 |
| 发票金额与应付差异大 | 🟡 中 | 付款 | 审批确认 |
| 批次物料入库无批号 | 🔴 高 | 库存追溯 | 补录批号 |
| GL凭证生成失败 | 🟡 中 | 财务报表 | 重算凭证 |
| 供应商配额超限 | 🟡 中 | 采购执行 | 调整配额 |

## 二、场景一：入库数量超量

### 2.1 问题描述
仓库员尝试入库的数量超过采购订单未执行数量。

### 2.2 系统行为
```
验证规则：BR-Pur-202 入库数量不能超过订单未执行数量
系统响应：拒绝保存，提示"入库数量超出订单未执行量"
```

### 2.3 恢复步骤

```
步骤1：确认超量原因
├── 原因A：供应商多送货
│   └── 处理：联系采购员，确认是否接受超量
├── 原因B：订单数量错误
│   └── 处理：修改订单数量（需反审核）
└── 原因C：重复入库
    └── 处理：取消本次入库
```

**原因A处理流程**：
```
1. 采购员判断是否接受超量送货
2. 如接受：修改订单数量 → 反审核 → 修改 → 重审 → 入库
3. 如不接受：按订单数量入库，超量部分退供应商
```

**原因B处理流程**：
```
1. 采购员确认订单数量需要修改
2. 反审核订单
3. 修改订单数量
4. 重新审核订单
5. 执行入库
```

## 三、场景二：入库反审核

### 3.1 问题描述
入库单审核后发现错误，需要反审核（红冲）。

### 3.2 影响范围
```
入库审核后触发的操作：
├── 库存增加（需红冲减少）
├── 应付单生成（需红冲）
├── GL凭证生成（需生成红字凭证对冲）
└── 可能触发后续付款（需停止或追回）
```

### 3.3 恢复步骤

```
步骤1：检查后续影响
├── 检查应付单是否已核销
│   └── 如已核销：先反核销，再反审核入库
├── 检查付款是否已执行
│   └── 如已付款：先追回或抵下次付款
└── 检查GL凭证是否已过账
    └── 如已过账：需反过账
```

```
步骤2：反审核入库
├── 在入库单上执行"反审核"
├── 系统自动：
│   ├── 库存红冲（减少库存）
│   ├── 生成应付红字
│   └── 生成GL红字凭证
└── 入库单状态变为"已红冲"
```

```
步骤3：修改或重新入库
├── 如需修改：修改入库单后重新审核
└── 如需取消：保持红冲状态
```

### 3.4 注意事项
```
⚠️ 注意1：入库反审核是永久性操作，不可逆
⚠️ 注意2：如有后续付款，需先处理付款
⚠️ 注意3：红冲产生的凭证需手工核对
```

## 四、场景三：批次物料入库无批号

### 4.1 问题描述
批次管理的物料在入库时未填写批号。

### 4.2 系统行为
```
验证规则：BR-Pur-203 批次管理物料入库时必须生成批号
系统响应：拒绝保存，提示"批次物料必须填写批号"
```

### 4.3 恢复步骤

```
步骤1：确认批号来源
├── 来源A：供应商提供批号
│   └── 获取供应商提供的批号
├── 来源B：系统自动生成
│   └── 使用批次规则自动生成
└── 来源C：自定义批号
    └── 按企业内部规则编制批号
```

```
步骤2：补录批号
├── 在入库单分录填写批号
├── 填写生产日期（如适用）
├── 填写效期（如适用）
└── 重新提交审核
```

### 4.4 预防措施
```
建议：启用批次自动生成规则
├── 按供应商+日期自动生成
├── 按物料+批次流水号自动生成
└── 避免手工填写错误
```

## 五、场景四：发票金额差异大

### 5.1 问题描述
供应商开具的发票金额与应付单金额差异较大。

### 5.2 系统行为
```
验证规则：BR-Pur-304 发票金额与应付金额差异需审批
系统响应：
├── 差异≤容差：自动匹配
└── 差异>容差：进入审批流程
```

### 5.3 恢复步骤

```
步骤1：确认差异原因
├── 原因A：供应商开票错误
│   └── 联系供应商重开发票
├── 原因B：税率变更
│   └── 确认新旧税率差异处理方式
├── 原因C：价格调整
│   └── 确认价格调整依据
└── 原因D：数量差异
    └── 核对实际送货数量
```

```
步骤2：根据原因处理

原因A处理（重开发票）：
1. 联系供应商退回错误发票
2. 供应商重新开具正确发票
3. 收到新发票后重新校验

原因B/C/D处理（需审批）：
1. 采购员填写差异说明
2. 提交差异审批流程
3. 审批通过后确认发票
4. 如需调整应付金额，执行调整
```

## 六、场景五：应付单已核销后需调整

### 6.1 问题描述
应付单已完成核销（付款），后发现金额需要调整。

### 6.2 影响范围
```
核销后调整的影响：
├── 如多付：需追回多付金额或抵下次付款
├── 如少付：需补付差额
└── 如错误付款：需全额追回
```

### 6.3 恢复步骤

```
步骤1：停止当前付款
├── 检查付款单状态
├── 如付款未审核：取消付款单
└── 如付款已审核：申请付款退回
```

```
步骤2：反核销应付单
├── 反核销操作
├── 应付单状态恢复为"未核销"
└── 调整应付金额
```

```
步骤3：重新处理
├── 重新发起付款
└── 执行核销
```

### 6.4 特殊情况处理

**情况A：已付款给供应商，无法追回**
```
处理方式：
1. 与供应商协商抵账
2. 在下次付款时扣除
3. 或作为预付款处理
```

**情况B：涉及GL凭证调整**
```
处理方式：
1. 生成调整凭证
2. 冲销原错误凭证
3. 补录正确凭证
4. 调整财务报表
```

## 七、场景六：GL凭证生成失败

### 7.1 问题描述
入库审核时GL凭证生成失败。

### 7.2 可能原因
```
├── 原因A：账簿未设置
│   └── 组织未启用GL模块或账簿未设置
├── 原因B：科目未映射
│   └── 库存科目或应付科目未设置映射
├── 原因C：核算维度缺失
│   └── 凭证缺少必要的核算维度
└── 原因D：金额为零
    └── 入库金额为零时不生成凭证
```

### 7.3 恢复步骤

```
原因A处理：
1. 检查组织GL账簿配置
2. 启用GL模块
3. 设置账簿
4. 重新审核入库（系统会重新生成凭证）

原因B处理：
1. 检查科目映射配置
2. 设置采购成本科目映射
3. 设置应付科目映射
4. 重新生成凭证

原因C处理：
1. 检查核算维度设置
2. 补全必要的核算维度
3. 重新生成凭证

原因D处理：
1. 确认是否为金额零单据
2. 如需生成凭证，调整金额
3. 如不需要，可忽略
```

## 八、通用恢复原则

### 8.1 操作顺序原则
```
恢复操作应遵循逆操作顺序：
入库审核 → 应付生成 → GL凭证
   ↑            ↑           ↑
反审核 ←    反核销   ←   凭证冲销
```

### 8.2 数据一致性检查
```
恢复完成后必须检查：
├── 库存台账与实际库存一致
├── 应付余额与供应商对账一致
├── GL凭证与财务报表一致
└── 所有单据状态正确
```

### 8.3 审批追溯
```
重要操作需保留审批记录：
├── 记录操作原因
├── 记录审批人
├── 记录审批时间
└── 保存相关附件
```

### 8.4 通知相关方
```
恢复操作后需通知：
├── 采购员：订单/入库变更
├── 仓库员：库存变更
├── 财务：应付/付款变更
└── 供应商：如有影响
```
