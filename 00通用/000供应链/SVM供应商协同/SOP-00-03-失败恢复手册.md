## 二、场景一：无供应商响应

### 2.1 问题描述

发起询价后，截止日期到，所有供应商都未响应报价。

### 2.2 系统行为

```
正常行为：询价发送 → 供应商响应 → 报价收集
实际行为：询价发送 → 无响应 → 询价关闭
结果：无法进行比价，采购流程中断
```

### 2.3 影响范围

```
├── 采购计划延迟
├── 需重新发起询价
├── 或改为紧急直采
└── 影响生产/销售计划
```

### 2.4 恢复步骤

```
步骤1：分析无响应原因
├── 原因A：询价条件太苛刻
│   └── 价格太低/交期太短/数量太少
├── 原因B：供应商无货或无产能
│   └── 供应商反馈
└── 原因C：通知未送达
    └── 检查邮件/系统通知

步骤2：根据原因处理

原因A处理（条件问题）：
1. 调整询价条件
2. 适当提高价格预算
3. 放宽交期要求
4. 重新发起询价

原因B处理（供应商问题）：
1. 更换/增加供应商
2. 寻找备选供应商
3. 扩大供应商范围

原因C处理（通知问题）：
1. 确认供应商联系方式
2. 重新发送询价通知
3. 电话/邮件确认

步骤3：后续监控
├── 监控供应商响应率
├── 优化询价条件设置
└── 维护供应商活跃度
```

## 三、场景二：仅一个供应商报价

### 3.1 问题描述

询价截止后，只有1个供应商报价，无法进行有效比价。

### 3.2 系统行为

```
验证规则：BR-SVM-301 比价需要至少2个有效报价
系统响应：提示"报价数量不足，无法执行比价"
```

### 3.3 恢复步骤

```
步骤1：确认情况
├── 检查是否有其他供应商临时报价
├── 确认截止日期是否正确
└── 评估当前报价的有效性

步骤2：选择处理方式

方式A：重新询价
1. 通知其他供应商
2. 延长截止日期
3. 重新收集报价

方式B：转为综合评估
1. 只有一个报价时转为综合评估
2. 对比历史价格和市场价
3. 采购主管审批决策

方式C：直采审批
1. 跳过比价，直接采购
2. 需上级审批
3. 记录原因为"单一来源"

步骤3：记录决策
├── 记录处理方式
├── 记录决策依据
└── 保存相关附件
```

## 四、场景三：比价后供应商拒单

### 4.1 问题描述

比价完成后，选择的最优供应商拒绝按报价成交。

### 4.2 系统行为

```
正常行为：比价完成 → 选择最优 → 生成订单
异常情况：比价完成 → 最优拒单 → 无法转单
结果：需重新选择或重新询价
```

### 4.3 恢复步骤

```
步骤1：确认拒单原因
├── 原因A：原材料涨价
│   └── 供应商要求调整价格
├── 原因B：无货可供
│   └── 库存/产能不足
└── 原因C：报价错误
    └── 供应商操作失误

步骤2：根据原因处理

原因A处理（价格问题）：
1. 评估涨价合理性
2. 谈判或接受涨价
3. 或选择第二名供应商

原因B处理（供货问题）：
1. 选择第二名供应商
2. 或寻找新供应商
3. 或调整交期

原因C处理（错误问题）：
1. 要求供应商履约
2. 或接受调整
3. 或更换供应商

步骤3：执行次优选择
1. 选择比价第二名供应商
2. 按其报价生成订单
3. 记录原因为"最优拒单"

步骤4：事后处理
├── 记录最优供应商拒单
├── 评估供应商信用
├── 调整供应商评估体系
└── 避免后续类似问题
```

## 五、场景四：报价超出预算

### 5.1 问题描述

供应商报价超出预算价格，无法按原预算执行。

### 5.2 系统行为

```
正常情况：报价 ≤ 预算
异常情况：所有报价 > 预算
结果：需上级审批或重新询价
```

### 5.3 恢复步骤

```
步骤1：确认超预算情况
├── 确认预算金额是否正确
├── 确认报价金额是否正确
└── 计算超幅比例

步骤2：根据超幅程度处理

超幅 < 10%：
1. 评估是否可以接受
2. 采购主管审批
3. 记录超预算原因

超幅 10%-30%：
1. 重新询价
2. 或扩大供应商范围
3. 或调整预算后审批

超幅 > 30%：
1. 需高层审批
2. 分析原因
3. 重新评估采购必要性

步骤3：调整与审批
├── 发起预算调整申请
├── 获得审批后执行
└── 记录超预算原因
```

## 六、场景五：询价截止后报价

### 6.1 问题描述

供应商在询价截止日期之后才提交报价。

### 6.2 系统行为

```
验证规则：BR-SVM-201 报价必须在截止日期前提交
系统响应：拒绝接受逾期报价
```

### 6.3 恢复步骤

```
步骤1：确认逾期情况
├── 确认截止日期设置
├── 确认逾期时长
└── 评估逾期原因

步骤2：处理方式

方式A：拒绝逾期报价
1. 告知供应商截止日期已过
2. 要求参与下次询价
3. 记录拒绝原因

方式B：特批接受（紧急情况）
1. 采购主管审批特批
2. 记录特批原因
3. 接受报价继续比价
4. 后续优化截止日期设置

步骤3：预防措施
├── 提前通知供应商截止日期
├── 设置截止前提醒
└── 合理设置截止时间
```

## 七、场景六：转单失败

### 7.1 问题描述

比价完成后，生成采购订单时转单失败。

### 7.2 系统行为

```
正常行为：比价完成 → 生成订单 → 转单成功
异常情况：比价完成 → 生成订单 → 转单失败
结果：订单未生成，需手动处理
```

### 7.3 恢复步骤

```
步骤1：确认失败原因
├── 检查比价单状态
├── 检查目标订单是否有冲突
└── 检查数据完整性

步骤2：常见失败原因及处理

原因A：订单号冲突
处理：检查已有订单号，手动指定新单号

原因B：供应商信息不完整
处理：补充供应商信息后重试

原因C：物料信息不匹配
处理：确认物料数据正确性

原因D：系统异常
处理：记录错误日志，技术支持排查

步骤3：手动生成订单
1. 手动创建采购订单
2. 复制比价单信息
3. 确认订单信息
4. 审核订单

步骤4：数据修复
├── 关联比价单据
├── 更新比价单状态
└── 记录转单异常
```

## 八、场景七：供应商资质异常

### 8.1 问题描述

参与报价的供应商存在资质问题，如资质过期、信誉不良等。

### 8.2 系统行为

```
正常行为：供应商资质审核 → 报价 → 比价
异常情况：资质异常 → 报价 → 比价
结果：合规风险，需取消成交结果
```

### 8.3 恢复步骤

```
⚠️ 这是严重合规问题，需立即处理

步骤1：确认资质异常
├── 检查供应商资质证明
├── 确认资质有效期
├── 评估资质影响

步骤2：紧急处理
├── 暂停比价结果确认
├── 取消该供应商资格
├── 通知相关方

步骤3：重新决策
├── 排除异常供应商
├── 重新评估剩余报价
├── 选择新的最优供应商

步骤4：后续处理
├── 更新供应商资质档案
├── 加强资质审核
├── 建立预警机制
```

## 九、通用恢复原则

### 9.1 合规性优先

```
恢复操作必须保证：
├── 询价过程透明可追溯
├── 比价结果公正合理
├── 订单执行合规有效
└── 决策记录完整保存
```

### 9.2 记录追溯

```
重要操作需保留记录：
├── 记录异常原因
├── 记录处理方式
├── 记录审批人
├── 记录审批时间
└── 保存相关证据
```

### 9.3 监控告警

```
必须监控的异常：
├── 供应商响应率过低
├── 比价后拒单
├── 转单失败
├── 资质异常
└── 报价超预算
```

### 9.4 通知相关方

```
恢复操作后需通知：
├── 采购员：询价/比价异常
├── 采购主管：需审批事项
├── 供应商：报价状态变更
└── 财务：超预算审批
```
