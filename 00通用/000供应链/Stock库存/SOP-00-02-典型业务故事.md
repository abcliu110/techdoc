# 典型业务故事 — K3Cloud Stock库存

## 故事1：仓库管理员小张的一天

### 背景
小张在XYZ制造公司工作，负责上海仓库的日常管理。公司使用金蝶K3Cloud系统，库存模块是每天工作的核心。

### 场景
2024年1月15日，普通的一天。

**步骤1：早会接收任务**
- 物控专员发来MRP运算结果
- 今日需处理：
  - 采购入库：螺丝M10×5000件
  - 生产领料：钢板×200件（工单WO-2024-0088）
  - 销售发货：成品电机×50台（订单SO-2024-0120）

**步骤2：处理采购入库**
- 供应商送货到仓库
- 小张在系统查看PO-2024-0156（已到货待入库）
- 核对实物与单据一致后，创建采购入库单：
  - 物料：螺丝M10
  - 数量：5000件
  - 批号：B20240115（系统自动按日期生成）
  - 有效期：2025-01-15（1年）
  - 仓库：上海仓库
- 审核入库单，过账引擎执行MERGE
- 现存量：5000件，可用量：5000件 ✅

**步骤3：处理生产领料**
- 收到工单WO-2024-0088的领料申请
- 系统检查可用量：
  - 钢板当前现存量：800件
  - 锁定量：200件（另一工单预留）
  - 可用量：600件 > 200件需求 ✅
- 创建领料单，审核后过账
- 现存量：600件（-200），锁定量：200件不变
- 预留量释放，工单继续执行

**步骤4：处理销售发货**
- 客户要求今日发货50台电机
- 系统检查可用量：
  - 电机现存量：80台
  - 无锁定（订单刚下）
  - 可用量：80台 > 50台需求 ✅
- FEFO策略：按批次效期先进先出
  - 批次B20240101（效期2025-12-31）优先出库
- 创建销售出库单，审核后过账
- 现存量：30台（-50），锁定量释放

**步骤5：下班前盘点**
- 抽查几个关键物料
- 账实核对一致
- 生成今日库存日报

### 业务规则体现
- BR-ST-201：出库量不超过可用量 ✅
- BR-ST-204：批次管理物料批号必填 ✅
- BR-ST-102：按FEFO效期先进先出 ✅

## 故事2：物控专员小李的可用量保卫战

### 背景
小李是XYZ公司的物控专员，负责MRP运算和物料可用量分析。年前订单暴增，可用量管理成为重中之重。

### 场景
2024年1月20日，发现一个紧急问题。

**问题发现**
- 销售反映订单SO-2024-0150无法承诺
- 系统显示电机可用量：0台
- 但库存台账显示现存量：50台
- "钱还在，货怎么没了？"

**步骤1：追查锁定量**
- 小李打开锁定期明细报表
- 发现问题：
  - 工单WO-2024-0070（已完成）锁定量未释放
  - 工单WO-2024-0075（已取消）锁定量未释放
  - **僵尸锁定**：50台电机被锁住，但订单已经结束
- 锁定量：50台 = 现存量：50台
- 可用量：0台 ❌

**步骤2：紧急处理**
- 联系生产计划员确认工单状态
- WO-2024-0070：已完成，确认释放锁定
- WO-2024-0075：已取消，确认释放锁定
- 小李手动执行锁定释放
- 可用量恢复：50台 ✅

**步骤3：根因分析**
- 检查为何订单关闭未触发自动解锁
- 发现：系统配置中"订单关闭触发自动解锁"开关未启用
- 提工单给IT部门开启该功能

**步骤4：预防措施**
- 开启锁定自动释放配置
- 设置锁定超时预警（锁定期>7天未释放自动提醒）
- 每日检查锁定期明细报表

### 业务规则体现
- BR-ST-402：锁定释放必须与订单状态一致 ⚠️（规则存在但配置缺失）
- ⚠️ 反证#2：订单关闭后锁定未自动释放

### 异常场景：锁定超时
- 设置锁定超时规则：锁定超过30天未释放，系统自动预警
- 物控专员收到提醒后需确认是否继续保留

## 故事3：财务小王的库存成本核算

### 背景
小王是XYZ公司的财务会计，负责库存成本核算和GL凭证审核。库存模块与GL的联动是她的核心关注点。

### 场景
2024年1月31日，月末盘点。

**步骤1：审核库存凭证**
- 打开GL凭证列表，过滤库存模块生成的凭证
- 审核今日入库凭证：
  - 借：原材料-螺丝M10 5000元
  - 贷：材料采购 5000元
- 审核今日出库凭证：
  - 借：生产成本 10000元
  - 贷：原材料-钢板 10000元
- 凭证借贷平衡 ✅

**步骤2：核对库存日记账**
- 打开库存明细账
- 核对今日出入库记录与GL凭证一致
- 螺丝入库5000元 ✅
- 钢板出库10000元 ✅

**步骤3：期末关账检查**
- 检查是否有未审核的库存单据
- 发现2张领料单未审核
- 联系仓库管理员尽快审核

**步骤4：执行期末关账**
- 所有单据审核完毕后
- 执行库存期末关账
- 系统生成期末库存快照
- 触发GL期末关账协同

**步骤5：生成期末报表**
- 期末库存台账
- 库存成本汇总表
- 库存账龄分析（呆滞物料识别）

### 业务规则体现
- BR-ST-205：审核后生成GL凭证 ✅
- BR-ST-302：期末关账后不能修改历史数据 ✅
- BR-ST-301：库存守恒律（入库=出库+当前库存）✅

## 故事4：批次效期管理危机

### 背景
XYZ公司生产食品添加剂，有效期管理是合规要求。2024年1月25日，发现一批物料即将过期。

### 场景
2024年1月25日，系统预警。

**步骤1：效期预警**
- 早上打开系统，看到效期预警报告
- 发现问题批次：
  - 添加剂A（批号B20230101）
  - 生产日期：2023-01-01
  - 有效期：1年
  - 状态：**已过期25天！**
  - 当前库存：100kg

**步骤2：紧急处理**
- 联系销售部门确认这批物料的去向
- 销售反馈：客户订单SO-2024-0180需要50kg添加剂A
- 紧急会议决定：已过期物料不能销售，全部报废处理

**步骤3：生成调整单**
- 创建库存调整单（报废类型）
- 调整数量：-100kg
- 调整原因：批次过期报废
- 审核后过账
- 现存量：0kg（100kg报废）

**步骤4：根因分析**
- 为什么过期25天才发现？
- 检查发现：效期预警只检查30天内，未检查已过期批次
- 批次过期后未自动从可用量中排除

**步骤5：改进措施**
- 修改效期预警规则：提前60天预警 + 过期即冻结
- 设置批次过期自动处理流程：
  - 过期 → 冻结（禁止出库）→ 生成报废建议 → 手动确认处理
- 建立效期管理台账，定期巡检

### 业务规则体现
- BR-ST-102：批次有效期约束 ⚠️（过期禁止出库规则存在，但未自动执行）
- ⚠️ 反证#1：批次过期后未及时处理导致表面负库存风险

### 异常场景：表面负库存
- 如果不及时报废，过期批次的100kg会被当作正常库存
- 出库时可能"透支"——看似有货，实际已过期
- 这就是"表面负库存"：数量为正，但价值为负

## 故事5：跨组织调拨的复杂场景

### 背景
XYZ公司有上海总部和北京分部两个组织，需要跨组织调拨物料。

### 场景
2024年1月28日，北京分部缺货。

**步骤1：发起调拨申请**
- 北京分部物控专员发起调拨申请
- 物料：电机50台（批号B20240101）
- 从：上海仓库 → 北京仓库
- 数量：50台

**步骤2：组织A出库**
- 上海仓库审核调拨出库单
- 过账引擎执行：
  - 上海仓库现存量 -50台
  - 生成调拨出库凭证

**步骤3：组织B入库**
- 北京仓库收到实物后
- 审核调拨入库单
- 过账引擎执行：
  - 北京仓库现存量 +50台
  - 生成调拨入库凭证

**步骤4：内部交易处理**
- 系统生成GL内部交易凭证
- 借：内部往来-北京分部 25000元
- 贷：内部往来-上海总部 25000元
- 两边财务核对，内部交易平衡 ✅

**步骤5：追溯查询**
- 调拨完成后，可以追溯：
  - 调拨申请单号
  - 上海出库记录
  - 北京入库记录
  - 内部交易凭证
  - 全链路完整 ✅

### 业务规则体现
- BR-ST-301：库存守恒（总库存不变）✅
- GL内部交易：跨组织调拨必须生成内部往来凭证 ✅

## 故事6：盘点发现账实差异

### 背景
XYZ公司每季度进行一次全面盘点。2024年1月15日季度盘点。

### 场景
2024年1月15日，季度盘点日。

**步骤1：制定盘点计划**
- 审计人员制定盘点计划
- 范围：上海仓库全部物料
- 方式：全盘
- 时间：1月15日-1月17日

**步骤2：实地盘点**
- 仓库管理员小张带领团队实地盘点
- 每个库位逐一清点
- 记录实盘数量

**步骤3：账实核对**
- 盘点完成后，系统生成差异清单
- 发现差异：
  - 螺丝M10：账面1000件，实盘980件，**差异-20件**
  - 钢板：账面500件，实盘500件，**一致 ✅**

**步骤4：差异分析**
- 小张回忆：1月10日领料200件，但只发了180件
- 记录差异原因：领料少发未补录

**步骤5：生成调整单**
- 确认差异原因后
- 生成盘点损溢单
- 审核后过账：
  - 螺丝M10现存量 -20件
  - 写入库存日记账

**步骤6：追溯原账目**
- ⚠️ 理想情况：应追溯到1月10日的领料单
- 实际系统：仅记录调整后的日记账，未关联原单据

**步骤7：改进建议**
- 建议增加盘点差异追溯功能
- 调整单应记录原单据编号
- 建立差异原因分类统计

### 业务规则体现
- BR-ST-401：对账差异必须查明原因 ✅
- ⚠️ 反证#3：盘点差异处理后未追溯原账目变更

## 六个故事的启示

| 故事 | 核心主题 | 关键教训 |
|---|---|---|
| 故事1 | 日常出入库 | 五量模型是库存的核心 |
| 故事2 | 锁定管理 | 订单关闭必须触发解锁 |
| 故事3 | 财务联动 | 库存与GL必须同步 |
| 故事4 | 批次效期 | 过期必须自动冻结 |
| 故事5 | 跨组织调拨 | 总库存守恒，内部交易平衡 |
| 故事6 | 盘点差异 | 调整必须追溯原单据 |

**三个反证教训**：
1. ⚠️ 锁定未释放 → 开启自动解锁配置
2. ⚠️ 批次过期未处理 → 增加过期冻结流程
3. ⚠️ 盘点差异未追溯 → 增加溯源字段
