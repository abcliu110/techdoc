# 失败恢复手册 — K3Cloud Stock库存

## 概述

本手册针对Stock库存模块的常见失败场景，提供系统化的排查和恢复指南。涵盖9个常见问题，分为两大类：**账务异常**和**流程异常**。每个问题包含症状、原因分析、解决步骤和预防措施。

---

## 一、账务异常（5个）

### 问题1：负库存（现存量<0）

#### 症状
- 库存台账显示某物料现存量为负数
- 出库单审核时报错："库存不足"
- 财务发现成本异常（负数量×单价=负成本）

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| BR-ST-101被绕过 | 高 | 弱控模式下直接修改数据 |
| 批次过期未处理 | 中 | 反证#1：过期批次仍参与出库计算 |
| 并发操作冲突 | 中 | MERGE操作未加锁导致竞态条件 |
| 单据红冲操作失误 | 低 | 红冲出库数量录错 |

#### 解决步骤
```
1. 查询负库存日志（StockCheckNegative）
   └─> 找到产生负库存的时间和操作

2. 确定负库存原因
   ├─> 如果是批次过期：
   │   └─> 执行批次报废调整单
   │       - 新增调整单（报废类型）
   │       - 审核后过账
   │       - 现存量恢复为0或正数
   │
   ├─> 如果是操作失误：
   │   └─> 执行红字回冲
   │       - 新增红字出库单（负数量）
   │       - 审核后过账还原
   │
   └─> 如果是并发问题：
       └─> 联系IT排查MERGE锁机制

3. 验证恢复
   └─> 查询库存台账，确认现存量≥0
```

#### 预防措施
- 开启负库存强控（强烈推荐）
- 批次效期预警提前至60天
- 过期批次自动冻结（禁止出库）

### 问题2：可用量计算错误

#### 症状
- 可用量与公式计算不符
- AvailQty ≠ StockQty - LockQty - ReserveQty
- 出库审核时报错，但库存台账看起来正常

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 五量不在同一事务 | 中 | ⚠️ U-02未验证：五量更新可能分开执行 |
| 历史数据损坏 | 低 | 数据库异常导致字段值错误 |
| 批次状态未同步 | 低 | 过期批次未冻结但被计入可用 |

#### 解决步骤
```
1. 诊断五量关系
   └─> 查询库存台账
       SELECT FORGID, FMATERIALID, FSTOCKQTY, FLOCKQTY, FRESERVEQTY, FAVAILQTY
       FROM T_STK_INVENTORY
       WHERE FAVAILQTY <> (FSTOCKQTY - FLOCKQTY - FRESERVEQTY)

2. 如果发现不一致：
   ├─> 计算正确值
   │   correct_avail = StockQty - LockQty - ReserveQty
   │
   └─> 执行五量修复（谨慎！）
       - 创建调整单
       - 调整FSTOCKQTY至正确值
       - 或调整FLOCKQTY/FRESERVEQTY
       - 审核后过账

3. 验证
   └─> 重新查询，确保公式一致
```

#### 预防措施
- 每日巡检五量一致性报表
- 确保五量更新在同一事务中执行（需验证U-02）

### 问题3：锁定量异常（僵尸锁定）

#### 症状
- 某物料锁定量>0，但对应订单已关闭/取消
- 可用量虚减，影响销售承诺
- 锁定期明细报表显示"占用"状态但无来源单据

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 订单关闭未触发解锁 | 高 | ⚠️ 反证#2：AutoReleaseOnClose未执行 |
| 出库单部分执行 | 中 | 订单部分出库，部分锁定未释放 |
| 数据迁移异常 | 低 | 旧系统迁移时锁定数据带入 |

#### 解决步骤
```
1. 查询僵尸锁定期
   └─> SELECT * FROM T_STK_STOCKLOCK
       WHERE FLOCKSTATUS = 1  -- 占用状态
       AND NOT EXISTS (
           SELECT 1 FROM T_SAL_ORDER WHERE FSALORDERID = FSOURCEBILLID AND FDOCUMENTSTATUS = 'C'  -- 已关闭
       )

2. 确认锁定来源
   ├─> 如果订单已关闭：
   │   └─> 执行手动释放
   │       - 联系物控专员确认
   │       - 在锁定期明细中手动释放
   │
   └─> 如果订单已完成：
       └─> 检查是否有未关联的出库单

3. 释放锁定
   └─> StockLockBLL.ReleaseLock(lockId)

4. 验证
   └─> 重新查询可用量，确认增加
```

#### 预防措施
- 开启"订单关闭触发自动解锁"配置（关键！）
- 设置锁定超时预警（>7天提醒）
- 每日检查锁定期明细报表

### 问题4：库存日记账不连续

#### 症状
- 库存明细账出现断层
- 某物料某日无记录，但前后日期有记录
- 无法追溯完整的库存变动链

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 过账引擎异常 | 中 | MERGE失败但业务单据已审核 |
| 日记账写入失败 | 中 | 事务回滚但业务表已更新 |
| 数据清理误操作 | 低 | 历史日记账被错误删除 |

#### 解决步骤
```
1. 确认问题范围
   └─> 查询T_STK_STOCKTRANS是否有缺失记录
       - 检查时间序列连续性
       - 对比T_STK_INSTOCK/OUTSTOCK的审核时间

2. 如果是过账失败：
   ├─> 检查单据的FPOSTSTATUS状态
   │
   └─> 重新执行过账
       - 反审核单据
       - 重新审核
       - 触发过账引擎

3. 如果是日记账丢失：
   ├─> 从单据反推日记账内容
   │   - 入库单：+QTY
   │   - 出库单：-QTY
   │
   └─> 手工补录日记账（谨慎！）
       - 联系IT执行
       - 记录补录原因
       - 生成审计日志
```

#### 预防措施
- 过账操作纳入事务管理
- 日记账表禁止DELETE权限
- 定期核对日记账与单据数量

### 问题5：期末关账后发现跨期单据

#### 症状
- 期末关账已完成
- 但发现某张单据日期在历史期间
- BR-ST-302被违反

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 关账前检查不严 | 高 | 检查脚本未执行 |
| 单据日期录入错误 | 中 | 用户录错日期 |
| 数据导入异常 | 低 | 批量导入时日期格式错误 |

#### 解决步骤
```
1. 查询跨期单据
   └─> SELECT * FROM T_STK_INSTOCK
       WHERE FBILLDATE < (SELECT FCLOSEDATE FROM T_STK_CLOSEPERIOD WHERE FORGID = xxx)
       AND FCLOSEDATE IS NOT NULL

2. 处理方式
   ├─> 如果是日期错误：
   │   └─> 需要反关账后修改
   │       - 联系账套管理员
   │       - 执行反关账
   │       - 修改单据日期
   │       - 重新审核过账
   │       - 重新关账
   │
   └─> 如果是特殊情况：
       └─> 记录差异，审计追踪
           - 在单据备注说明原因
           - 生成审计日志
           - 不修改（维持账实一致）
```

#### 预防措施
- 期末关账前强制执行未审核单据检查
- 单据日期字段增加校验（不能早于启用日期）
- 批量导入时增加日期格式验证

## 二、流程异常（4个）

### 问题6：批次效期混乱

#### 症状
- 批号重复或缺失
- 有效期与批号不匹配
- FEFO分配时无法正确排序

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 批号生成规则混乱 | 高 | 不同仓库使用不同规则 |
| 批次数据迁移错误 | 中 | 旧系统批号格式不兼容 |
| 用户手动录入错误 | 中 | 批号/效期录入错误 |

#### 解决步骤
```
1. 查询批号异常
   ├─> 重复批号：
   │   └─> SELECT FBATCHNO, COUNT(*) FROM T_STK_INVENTORY GROUP BY FBATCHNO HAVING COUNT(*) > 1
   │
   └─> 缺失批号（应批次但无批号）：
       └─> 查询批次管理物料但FBATCHNO为空

2. 修正批号
   ├─> 如果是重复：
   │   └─> 合并或拆分库存行
   │       - 联系仓库确认实际批次归属
   │       - 调整库存行数据
   │
   └─> 如果是缺失：
       └─> 补录批号
           - 根据入库单/供应商信息追溯
           - 补录批号和效期
           - 审核确认

3. 规范批号规则
   └─> 在系统配置中统一批号生成规则
       - 格式：供应商代码+日期+流水号
       - 例：SUP001-20240115-001
```

#### 预防措施
- 批号生成规则标准化
- 批次管理物料强制批号必填
- 批次效期预警提前60天

### 问题7：盘点差异未处理

#### 症状
- 盘点已完成但差异未确认
- 盘点单状态显示"盘点中"
- 盘点损溢单未生成

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 盘点流程未完成 | 高 | 盘点确认步骤遗漏 |
| 盘点损溢单未审核 | 中 | 审核流程卡住 |
| ⚠️ 盘点追溯缺陷 | 中 | 反证#3：调整未关联原单据 |

#### 解决步骤
```
1. 检查盘点单状态
   └─> SELECT * FROM T_STK_STOCKCHECK
       WHERE FSTATUS <> 'C'  -- 未完成

2. 完成盘点流程
   ├─> 确认盘点
   │   └─> StockCheckService.Confirm(billId)
   │
   └─> 生成损溢单
       └─> 盘点损溢单自动生成或手动创建

3. 审核损溢单
   └─> OutstockService.Audit(billId)  -- 报损
       InstockService.Audit(billId)    -- 报溢

4. 追溯原账目
   ⚠️ 注意：当前系统可能无法追溯原单据
   └─> 手动记录：
       - 差异原因
       - 可能的原单据
       - 审计备注
```

#### 预防措施
- 完善盘点流程检查清单
- 增加调整单与原单据的关联字段（系统改进）
- 盘点结果纳入绩效考核

### 问题8：GL凭证与库存不一致

#### 症状
- 库存台账数量正常
- 但GL凭证借贷不平衡
- 或GL凭证金额与库存成本不符

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 凭证模板配置错误 | 高 | 入库/出库使用错误科目 |
| 成本核算异常 | 中 | 单价计算错误 |
| 凭证生成事务失败 | 中 | 部分成功部分失败 |

#### 解决步骤
```
1. 对比库存与GL
   └─> 查询库存成本 vs GL凭证金额
       SELECT t1.FMATERIALID, t1.FTOTALCOST, t2.FGLAMOUNT
       FROM (
           SELECT FMATERIALID, SUM(FQTY * FPRICE) AS FTOTALCOST
           FROM T_STK_INSTOCKENTRY
           WHERE FBILLDATE BETWEEN '2024-01-01' AND '2024-01-31'
           GROUP BY FMATERIALID
       ) t1
       JOIN (
           SELECT FEXPENSEITEMID, SUM(FDEBIT - FCREDIT) AS FGLAMOUNT
           FROM T_GL_VOUCHERENTRY
           WHERE FACCOUNTID = 物料科目ID
           AND FDATE BETWEEN '2024-01-01' AND '2024-01-31'
           GROUP BY FEXPENSEITEMID
       ) t2 ON t1.FMATERIALID = t2.FEXPENSEITEMID

2. 如果不一致：
   ├─> 检查凭证模板配置
   │   └─> 修复凭证模板
   │
   └─> 生成调账凭证
       └─> 如果历史凭证无法修改
           - 生成调整凭证
           - 记录差异原因

3. 修复后验证
   └─> 重新核对，确保一致
```

#### 预防措施
- 凭证模板配置纳入变更管理
- 每日核对库存凭证与GL
- 成本核算使用标准成本法

### 问题9：组织间调拨账务混乱

#### 症状
- 调拨出库和入库数量不一致
- 两边GL内部往来不平账
- 组织A减少但组织B未增加

#### 原因分析
| 原因 | 可能性 | 典型场景 |
|---|---|---|
| 部分过账失败 | 高 | 调拨入库未审核 |
| 跨组织事务异常 | 中 | 组织A成功但组织B失败 |
| 内部交易配置错误 | 低 | 两组织科目映射不一致 |

#### 解决步骤
```
1. 查询调拨单状态
   └─> 检查调拨出库和入库单的状态
       - 出库是否已审核？
       - 入库是否已审核？
       - 是否有未关联的调拨单？

2. 处理不完整的调拨
   ├─> 如果只有出库：
   │   └─> 需要反审核出库
   │       - 查询原因
   │       - 确认是否取消调拨
   │       - 或补录入库单
   │
   └─> 如果出库和入库都有：
       └─> 检查内部交易凭证
           - 是否都已生成？
           - 是否借贷平衡？

3. 账务调整（谨慎！）
   ├─> 反关账（如需要）
   │   └─> StockPeriodCloseBLL.ReverseClose
   │
   └─> 手工调整
       - 联系IT执行
       - 记录调整原因
       - 生成审计日志
```

#### 预防措施
- 调拨流程设为必须两步审核（出库+入库）
- 内部交易配置标准化
- 定期核对两组织的内部往来余额

## 三、数据恢复指南

### 紧急恢复：库存快照

如果数据库出现严重问题，可使用期末快照恢复：

```
1. 查找最近的快照
   └─> SELECT * FROM T_STK_INVENTORY_SNAPSHOT
       WHERE FSNAPSHOTDATE = (
           SELECT MAX(FSNAPSHOTDATE) FROM T_STK_INVENTORY_SNAPSHOT
           WHERE FORGID = xxx
       )

2. 评估恢复范围
   ├─> 如果是单表损坏：
   │   └─> 从快照恢复单表
   │
   └─> 如果是多表问题：
       └─> 需要全量恢复
           - 停止应用
           - 恢复快照
           - 重放快照后的日记账
           - 恢复当前状态
```

### 谨慎操作：事务回滚

对于最近的错误操作，可尝试事务回滚：

```
1. 确认操作时间
   └─> 从日志中确认错误操作的时间点

2. 评估影响范围
   └─> 检查受影响的库存行、单据、日记账

3. 执行回滚
   └─> 联系DBA执行Point-In-Time恢复
       - 恢复到一个安全的时间点
       - 重放后续正确操作
```
