## 一、交互流程概述

Stock库存模块的交互流程以**过账引擎（PostingEngine）**为核心，构建4个关键时序图、12个核心API、7个服务类。与GL/CB等财务账类相比，Stock的交互复杂度更高——需要处理多维度库存行（15维）、批次效期、FEFO分配、锁定释放等特有逻辑。

## 三、核心API（12个）

### 库存查询类（3个）

| API | 类 | 方法签名 | 说明 |
|---|---|---|---|
| API-01 | InventoryQueryBLL | QueryInventory(orgId, stockId, materialId, batchNo) | 按维度查询库存 |
| API-02 | InventoryQueryBLL | QueryAvailQty(orgId, materialId) | 查询可用量 |
| API-03 | StockReportBLL | QueryStockJournal(billDate, orgId) | 查询库存日记账 |

### 入库操作类（2个）

| API | 类 | 方法签名 | 说明 |
|---|---|---|---|
| API-04 | InstockService | Save(instockEntity) | 保存入库单 |
| API-05 | InstockService | Audit(billId) | 审核入库单 → 触发过账 |

### 出库操作类（2个）

| API | 类 | 方法签名 | 说明 |
|---|---|---|---|
| API-06 | OutstockService | Save(outstockEntity) | 保存出库单 |
| API-07 | OutstockService | Audit(billId) | 审核出库单 → 触发过账 + BR-ST-201校验 |

### 锁定管理类（2个）

| API | 类 | 方法签名 | 说明 |
|---|---|---|---|
| API-08 | StockLockBLL | CreateLock(sourceBillId, qty) | 创建锁定期 |
| API-09 | StockLockBLL | ReleaseLock(lockId) | 释放锁定期 |

### 盘点调整类（2个）

| API | 类 | 方法签名 | 说明 |
|---|---|---|---|
| API-10 | StockCheckService | Confirm(billId) | 确认盘点单 → 生成损溢单 |
| API-11 | StockAdjustService | Audit(billId) | 审核调整单 → 过账调整 |

### 期末关账类（1个）

| API | 类 | 方法签名 | 说明 |
|---|---|---|---|
| API-12 | StockPeriodCloseBLL | ClosePeriod(orgId, periodId) | 期末关账 |

## 四、服务类（7个）

### 服务类1：OperationController（过账引擎核心）

| 属性 | 内容 |
|---|---|
| 命名空间 | Kingdee.K3.SCM.Stock.App.Core |
| 核心职责 | 库存过账的统一入口，协调各策略子类 |
| 关键方法 | InstockPosting/OutstockPosting/AdjustPosting/TransferPosting |
| 原子操作 | MERGE（库存行合并更新） |
| 策略模式 | 7个子类处理不同单据类型 |

### 服务类2：InstockService（入库服务）

| 属性 | 内容 |
|---|---|
| 核心职责 | 采购入库/生产入库的保存和审核 |
| 关键方法 | Save/Submit/Audit |
| 依赖服务 | OperationController |

### 服务类3：OutstockService（出库服务）

| 属性 | 内容 |
|---|---|
| 核心职责 | 销售出库/领料的保存和审核 |
| 关键方法 | Save/Submit/Audit |
| 前置校验 | CheckAvailQty（BR-ST-201） |
| 依赖服务 | StockLockBLL/OperationController |

### 服务类4：StockLockBLL（锁定管理）

| 属性 | 内容 |
|---|---|
| 核心职责 | SO/MO锁定的创建和释放 |
| 关键方法 | CreateLock/ReleaseLock/QueryLock |
| ⚠️ 风险 | 订单关闭未触发ReleaseLock（反证#2） |

### 服务类5：StockCheckService（盘点服务）

| 属性 | 内容 |
|---|---|
| 核心职责 | 盘点计划的执行和确认 |
| 关键方法 | CreatePlan/Execute/Confirm |
| ⚠️ 风险 | 盘点调整未生成完整溯源（反证#3） |

### 服务类6：StockPeriodCloseBLL（期末关账）

| 属性 | 内容 |
|---|---|
| 核心职责 | 库存期末关账和反关账 |
| 关键方法 | ClosePeriod/ReverseClose |
| 协同动作 | 触发GL期末关账协同 |

### 服务类7：InventoryBLL（库存台账）

| 属性 | 内容 |
|---|---|
| 核心职责 | 库存行的读写和MERGE操作 |
| 关键方法 | Query/Merge/CheckNegative |
| 核心逻辑 | 15维唯一定位 + 五量更新 |

## 五、交互流程与账类系统映射

| 交互维度 | GL总账 | CB现金银行 | Stock库存 |
|---|---|---|---|
| 业务入口 | 凭证 | 收付款单 | 入出库单 |
| 过账触发 | 凭证审核 | 收付审核 | 单据审核 |
| 过账引擎 | GL.PostingEngine | CB.PostingEngine | Stock.OperationController |
| 原子操作 | 借贷平衡校验 | 三列差异更新 | MERGE库存行 |
| 日记账 | GL_JOURNAL | CN_BANKJOURNAL | STK_STOCKTRANS |
| GL联动 | 自生成 | 自生成 | 同步生成GL |
| 期末关账 | GL期末结账 | 无需关账 | Stock期末关账 |
