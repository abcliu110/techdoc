## 一、侦察范围

### 1.1 模块定位
Credit信用管理是供应链和财务系统中的辅助子域，负责**客户信用额度管理**和**信用风险控制**。

### 1.2 与周边模块关系
```
┌─────────────────────────────────────────────────────────┐
│                    供应链/财务系统                         │
├──────────┬──────────┬──────────┬──────────┬────────────┤
│   Sal    │  Credit  │   AR     │   Stock  │   其他模块  │
│  销售    │  信用    │  应收    │  库存    │            │
└──────────┴────┬─────┴──────────┴──────────┴────────────┘
                 │
                 ▼
         信用检查与额度控制
```

### 1.3 核心职责
- 客户信用额度授信
- 信用额度占用与释放
- 信用风险控制（交易前检查）
- 信用预警与催收管理

## 六、关键业务流程

### 6.1 销售信用检查流程
```
销售订单创建
    │
    ▼
执行CreditCheck
    │
    ├── 检查客户信用评级
    ├── 检查可用额度
    ├── 检查预警状态
    │
    ▼
┌─────────────────────────┐
│  额度充足？              │
└───────────┬─────────────┘
            │
     ┌──────┴──────┐
     │             │
     ▼             ▼
   是            否
    │             │
    ▼             ▼
  允许下单    拒绝/审批
```

### 6.2 额度占用释放流程
```
销售出库/AR记账
    │
    ▼
更新额度占用
    │
    ├── 增加占用（出库时）
    └── 释放占用（收款时）
    │
    ▼
更新可用额度
```
