## 三、用例规约

### 3.1 UC-Cred-101 授信申请

**参与者**：信用管理员
**前置条件**：客户档案存在、信用管理员已登录
**基本流程**：
```
1. 选择客户
2. 输入授信额度
3. 选择额度类型（临时/永久）
4. 设置有效期（如适用）
5. 提交审批
```
**后置条件**：授信申请进入审批流程
**异常流程**：
- 客户已存在额度：提示额度已存在

### 3.2 UC-Cred-201 交易前检查

**参与者**：系统（自动触发）
**前置条件**：销售订单正在创建
**基本流程**：
```
1. 获取客户ID
2. 查询客户信用额度
3. 查询当前占用额
4. 计算可用额度
5. 计算本次交易需占用额
6. 判断是否允许交易
```
**决策点**：
- 可用额度 >= 交易金额：允许
- 可用额度 < 交易金额：拒绝或需审批

**后置条件**：
- 允许：订单创建成功
- 拒绝：订单创建失败，提示原因

### 3.3 UC-Cred-203 额度占用

**参与者**：系统（自动触发）
**前置条件**：销售出库或AR记账
**基本流程**：
```
1. 获取关联订单的客户
2. 获取订单金额
3. 在额度使用表中新增记录
4. 更新客户可用额度
```
**后置条件**：可用额度减少

### 3.4 UC-Cred-204 额度释放

**参与者**：系统（自动触发）
**前置条件**：收款确认或核销
**基本流程**：
```
1. 获取应收单对应的客户
2. 获取本次核销金额
3. 查找对应的额度占用记录
4. 标记占用记录为已释放
5. 更新客户可用额度
```
**后置条件**：可用额度增加

## 五、业务场景

### 5.1 场景1：新客户授信
```
业务背景：新客户首次合作，需要评估信用
流程：
  1. 销售员提出授信申请
  2. 信用管理员审核客户资质
  3. 风控专员进行信用评级
  4. 信用管理员创建信用额度
  5. 额度生效，客户可下单
```

### 5.2 场景2：销售下单触发信用检查
```
业务背景：销售员为客户创建订单
流程：
  1. 销售员选择客户、物料、数量
  2. 系统自动触发信用检查
  3. 检查客户评级、可用额度、预警状态
  4. 额度充足：允许创建订单
  5. 额度不足：提示并拒绝或提交审批
```

### 5.3 场景3：出库触发额度占用
```
业务背景：销售出库时占用信用额度
流程：
  1. 仓库员执行出库
  2. 系统自动触发额度占用
  3. 创建额度使用记录
  4. 更新客户可用额度
  5. 出库完成
```

### 5.4 场景4：收款触发额度释放
```
业务背景：客户付款，收款员确认收款
流程：
  1. 财务专员确认收款
  2. 系统自动触发额度释放
  3. 标记对应占用记录为已释放
  4. 更新客户可用额度
  5. 额度恢复，客户可继续下单
```

### 5.5 场景5：信用预警触发
```
业务背景：客户信用状况恶化
流程：
  1. 系统定时检查客户信用状态
  2. 发现逾期应收超过阈值
  3. 触发信用预警
  4. 风控专员收到预警通知
  5. 风控专员处理预警（冻结额度/催收）
```
