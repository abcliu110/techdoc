# 业务全景 — K3Cloud Credit信用管理

## 一、业务定位

### 1.1 在供应链中的位置

```
┌─────────────────────────────────────────────────────────────┐
│                      供应链（Supply Chain）                    │
├─────────────┬─────────────┬─────────────┬──────────────────┤
│   销售模块   │   采购模块   │   库存模块   │    财务模块      │
│    (Sal)    │ (Purchase)  │   (Stock)   │  (GL/AP/AR/CB)  │
├─────────────┼─────────────┼─────────────┼──────────────────┤
│   销售订单   │   采购申请   │             │                 │
│      ↓      │      ↓      │             │                 │
│   信用检查   │   SVM询价   │             │                 │
│      ↓      │      ↓      │             │                 │
│   销售出库   │   采购入库   │ ──▶ 库存   │                 │
│      ↓      │      ↓      │             │                 │
│   应收生成   │   应付生成   │             │                 │
│      ↓      │      ↓      │             │                 │
│   收款收回   │   付款付出   │             │                 │
└─────────────┴─────────────┴─────────────┴──────────────────┘
                            ↑
                    Credit信用管理嵌入销售
```

### 1.2 信用管理核心职责

| 职责 | 说明 |
|---|---|
| 信用额度管理 | 为客户设置信用额度，支持动态调整 |
| 信用检查 | 交易前校验客户可用额度 |
| 额度占用 | 出库时占用客户额度 |
| 额度释放 | 收款后释放已占用额度 |
| 额度冻结 | 风控冻结/解冻客户额度 |
| 信用预警 | 逾期/超限/评级下调预警 |

## 二、业务边界

### 2.1 信用管理范围

**包含**：
- 客户信用额度设置与审批
- 销售订单信用检查
- 额度占用与释放管理
- 客户信用评级
- 信用预警与处理
- 额度冻结与解冻

**不包含**：
- 客户档案管理（属于基础数据）
- 销售订单管理（属于Sal模块）
- 应收应付管理（属于AR/AP模块）
- 收款付款管理（属于CB模块）
- GL凭证生成（属于GL模块）

## 三、业务架构

### 3.1 信用管理子域划分

| 子域 | 说明 | 关键特性 |
|---|---|---|
| 额度管理 | 额度创建/调整/冻结 | 审批流程 |
| 信用检查 | 交易前额度校验 | 实时/异步 |
| 额度占用 | 出库时占用额度 | 原子操作 |
| 额度释放 | 收款时释放额度 | FIFO顺序 |
| 评级管理 | 客户信用评级 | 系数影响 |
| 预警管理 | 风险预警触发 | 自动升级 |

### 3.2 核心服务架构

| 服务 | 职责 | 复杂度 |
|---|---|---|
| CreditService | 核心调度（~2,800行） | 高 ⚠️ |
| CreditLimitService | 额度生命周期管理 | 中 |
| CreditCheckService | 信用检查执行 | 中 |
| CreditOccupancyService | 占用/释放执行 | 中 |
| CreditRatingService | 评级管理 | 低 |
| CreditWarningService | 预警管理 | 低 |

---

## 四、业务能力

### 4.1 核心能力

| 能力 | 说明 |
|---|---|
| 额度配置 | 按客户+币种设置信用额度 |
| 实时检查 | 订单创建时实时校验额度 |
| 异步检查 | 后台异步执行复杂检查 |
| 额度占用 | 出库审核时自动占用 |
| 额度释放 | 收款核销时自动释放 |
| 冻结管理 | 手动/自动冻结额度 |
| 预警通知 | 多级预警+自动升级 |
| 评级体系 | 多级信用评级+系数 |

### 4.2 关键业务规则

| 规则 | 约束级别 |
|---|---|
| 同一客户同一币种只能有一个生效额度 | 强 |
| 可用额度 = 总额度 - 已占用 - 已冻结 | 强 |
| 可用额度 >= 订单含税金额 | 强 |
| 冻结客户直接拒绝交易 | 强 |
| 占用操作必须原子完成 | 强 |
| 释放金额不能超过未释放金额 | 强 |

## 五、业务指标

| 指标 | 说明 |
|---|---|
| 额度使用率 | 已占用 / 总额度 |
| 逾期率 | 逾期应收 / 总应收 |
| 预警处理率 | 已处理预警 / 总预警 |
| 超额审批通过率 | 审批通过 / 超额申请 |
| 冻结客户占比 | 冻结客户 / 总客户 |

## 六、业务风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 额度占用与释放时序 | 高 | AR异常导致占用泄漏 |
| 跨模块数据一致性 | 中 | Sal/AR/Credit同步 |
| 信用检查性能 | 中 | 实时检查影响响应 |
| 巨型类维护困难 | 中 | CreditService ~2,800行 |
| 评级主观性 | 低 | 缺乏量化标准 |
| 预警处理延迟 | 中 | 未及时处理升级 |
