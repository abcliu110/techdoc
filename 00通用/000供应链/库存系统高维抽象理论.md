# 库存系统 · 高维抽象理论

> **定位**：库存系统（Inventory/Stock）的底层思想与抽象模型——不依赖具体 ERP 产品。
> **实例锚点**：金蝶 K3Cloud 供应链库存模块（SCM）反编译源码（即时库存/过账引擎/账存/预留锁库）。
> **重要声明**：**库存是"账类系统"**——它与财务共享同一套底层思想（守恒、事件溯源、维度、时间轴）。阅读前建议先读财务理论篇：《财务系统高维抽象理论.md》。本篇将逐章做**对位呼应**，展示"一套思想驱动整个 ERP 模型"。

---

## 0. 一句话总纲

> **库存系统是把"实物移动"翻译成"库存事实"，并沿"事务时间轴"沉淀为守恒、可重算、可追溯的数量账。**

四大不变量（与财务同构）：
1. 实物世界 ↔ 数量世界：**翻译问题**（单据 → 库存行）
2. 数量**守恒**：入=出+余（过账不丢量、不双记）
3. 数量可**重算**：从流水能重建任意时点库存
4. 库存是**多维的**：不发散地记录"什么、在哪、谁的、什么批次、多少"

---

## 1. 守恒的增量系统 —— 过账的本质是"Σ增 = Σ减"

### 抽象定义
库存的守恒律不是"资产=负债"，而是**流量守恒**：
```
库存存量 = 期初 + Σ入库 - Σ出库
```
每个库存单据在过账时被翻译为一个"带符号的增量"（入库 +1 / 出库 -1 / 对冲 0），系统保证"任何有效过账都恰好把一份数量从一个状态转到另一个状态，不超发、不虚增"。

### K3Cloud 实例
- 过账引擎 `OperationController`：`QtyMultiplicator(addQtyOption, updateFlag, chargeOff)` 输出**数量乘数**——正是"把单据翻译成带符号增量"的抽象；
- **负库存校验 6 条规则**（`CheckInvMinusService`）：现存量<锁定量、基本/辅助单位正负不一致、扣锁后方向相反等——这是对守恒与"可出性"的运行时监督；
- 过账后即时库存行 `FBASEQTY += 增量`（`UpdateStockByTmpSqlBuilder` MERGE）。

### 普适启示
> 与财务完全同构：**先定义守恒方程，再写过账，再配验证器**。库存的"负库存检查"=财务的"试算平衡"——都是守恒监督器，只是监控对象从"钱"换成"数量"。自研千万不要"只写扣减不写校验"，事故都会在"负库存"上爆发。

## 2. 事件溯源 × 投影模型 —— 流水、即时库存、账存

### 抽象定义
库存天然分三层（与财务 §2 一一对应）：
- **事件层**：`库存流水` = 每一次移动的不可变记录（来源单据/分录/±数量/操作/时间）；
- **投影层**：`即时库存`(实时存量,按维度组合一行) 与 `账存`(期间收/发/存,用于结账与报表) 两个投影；
- **视图层**：台账、进销存、收发存、结存表。

### K3Cloud 实例
- 事件：`T_STK_INVENTORYLOG`（每笔过账插入流水，含来源表单/分录/操作号/事务号）；
- 投影：`T_STK_INVENTORY`(即时) 与 `T_STK_INVBAL`(账存,`FieldBalTable` 定义期初/收入/发出/期末六量)；
- 可重算：全套 `*BAK` 备份表 + `StockBillDataService` 还原 = 投影重建工具；`T_STK_STKBALRESULT/OCCURLOG` = 投影与事件的**对账日志**。

### 普适启示
> 库存是事件溯源的最佳教材：**流水只追加、余额可重建**。一旦支持"重算库存"千万级别的回滚/反审核才敢做。与财务共用同一套"事件/投影/视图"心智，减少一整套学习成本。

## 3. 多维库存空间 —— 即时库存是"维度组合的唯一行"

### 抽象定义
与财务"科目 × 期间 × 组织"的立方体同构，库存的维度更"物理化"：
```
组织维度: 库存组织 / 货主 / 保管者
物理维度: 仓库 / 仓位 / 物料 / BOM / 委托加工单 / 项目
特性维度: 辅助属性 / 库存状态 / 批次 / 生产日期 / 有效期
计量维度: 基本单位 / 库存单位 / 辅助单位   ← 三套并行
```
**即时库存 = 沿所有维度组合的稀疏唯一行**（`FCOMBINEID` 组合键）。库存报表 = 对这些维的切片/聚合/下钻。

### K3Cloud 实例
- 15 维 + `FCOMBINEID` + 三单位并行 `FBASEQTY/FSECQTY/FQTY`；
- 过账用 `FCOMBINEID` 做**集合匹配**而非逐列比较——维度组合被折叠为一个键，这是性能与正确性的关键设计；
- `T_BD_MATERIALSTOCK`(物料库存属性：批次管理/序列号管理/负库存/效期并入批次) = 维度能力的**开关元数据**。

### 普适启示
> 自研库存第一张表就该是"宽表：维度列 + 组合键 + 多单位数量列"。**维度是元数据可开关的**（是否启用批次/仓位/序列号由物料属性驱动），否则同一套引擎无法同时服务"经销商仓储"与"制药批号"两种场景。这与财务"新增核算维度只改元数据"是同一个道理。

## 4. 多渠道一致性：五量模型 —— "存量是状态，可用量是关系"

### 抽象定义
库存不是单一数字，而是一组**互相关联的量**：
```
现存量(存量状态)   ≥   锁定量(被承诺)  +   可用量(可再承诺)
                     预留量(需求占用)   +   在途量(尚未到达)
```
关键抽象：**锁定量/预留量不是独立维护的字段，而是从"承诺明细"实时聚合出来的关系值**。任何单据承诺或释放，都自动改变聚合结果，从而避免"多个计数器各记各的、最后对不上"。

### K3Cloud 实例
- 即时库存只存 `FBASEQTY/FSECQTY`；锁定量 = 实时 `SUM(T_PLN_RESERVELINKENTRY.FBASEQTY)`（`StockLockService` 的 LEFT JOIN 聚合），可用量 = `现存量 - 锁定量`；
- 预留明细带 `FRESERVETYPE(强预留)`/`保留期/释放日`，支持"到期自动解锁"（`UnLockStockByDateBGService`）。

### 普适启示
> **最值钱的一条**：别给"锁定数"建独立计数器。把"承诺"建模成明细（谁承诺了哪一行库存多少、何时到期），锁定量永远实时聚合。这样：单据反审核、预留释放、到期自动解锁全都自动一致。此模式是库存复杂度的"降维打击"。

## 5. 过账引擎 —— "策略 + 元数据驱动"的通用投影器

### 抽象定义
所有库存单据（入库/出库/调拨/盘点/组装/批次调整）共享**同一套过账逻辑**，差异被抽象为三个参数：
1. **过账点**：保存时过账还是审核时过账（元数据配置 `UpStockPoint_Save=1/Audit=2`）；
2. **数量乘数**：+1/-1/0（入库、出库、对冲）；
3. **操作集合**：保存/审核/取消/反审核/删除/反取消——每个操作是投影器的一个**策略**，保证"任何操作后投影都正确"。

### K3Cloud 实例
- `UpdateStock/` 目录：`OperationController`(抽象基类) + `Save/Audit/Cancel/UnAudit/UnCancel/Delete/UnSupport` 七个策略子类；
- 过账三步：把分录读入**差异临时表**(`T_STK_INVMINUSCHECK`) → 用 `FCOMBINEID` 匹配/分配库存行 → 一条 `MERGE` 原子合并 + 同步写流水；
- `UnSupportOperationController` = 不支持过账的操作兜底（防漏实现）。

### 普适启示
> 自研库存的核心投资收益在**一次过账引擎服务所有单据**。若每张单据自己写扣减逻辑，5 种单据 = 5 套 if-else 五处不一致。抽象三参数（过账点/乘数/操作策略）+ 元数据驱动 = 新增单据零引擎改动。**这也让"反审核/取消"这样高风险操作天然有统一策略，而不是靠特判**。

## 6. 并发安全 —— 集合式增量 + 锁与预占

### 抽象定义
同一库存行的并发扣减是分布式一致性的典型问题。安全的写法必须满足：
- **原子性**：`读余额→改余额→写回` 三段式必然丢量；必须用"数据库原子语句"（如 `MERGE`/`UPDATE ... 加减`）一步完成；
- **串行化**：过账批次彼此隔离（事务号 + 行锁）；同一维度组合的行在并发时不重复创建（预分配/预占）。

### K3Cloud 实例
- 一次过账 = 一个事务一个 `TranId`；用 `MERGE INTO T_STK_INVENTORY` 原子地"存在则累加、不存在则插入"；
- 并发保护：`T_STK_INVUPLOCKIDTABLE`(锁行) ；维度组合先建 `T_STK_PREINVDIMENSION`(预占维度,`FISEFFECTIVED=0`) 避免高并发下"同一组合插入两行"。

### 普适启示
> "在内存里 `balance = balance - qty` 再 UPDATE"是库存系统最常见的并发事故源。**原则：用数据库原子集合并、把并发边界收敛在过账引擎一层**。所有未来会并发扣减的系统（余额、配额、座位、预算）都可套用。

## 7. 事务时间轴 —— 期初、盘点、关账、反关账

### 抽象定义
与财务期间同构，库存也有时间轴状态机：
```
期初建账(库存初始化) → 日常过账 → 盘点调整(盘盈/盘亏) → 期末关账(锁定) → 反关账(重开)
```
"关账"把某时点之前的库存**固化为历史**，之后的过账才允许——它是权限与一致性的边界。

### K3Cloud 实例
- `StockInitService`(期初) → `StockCheck/Count/CycleCountService`(盘点:输入→盘盈`GAIN`→盘亏`LOSS`) → `StockCloseService.InvAccountOnOff/InvAccountOff`；
- 关账流水线（`StockCloseService`）：清批次 → 记轨迹 → 校验开账日期/期初状态/上期已关/期间单据/未审盘点单 → `DoInvCloseOperate` → 删轨迹；
- 账存(`T_STK_INVBAL`)由期初/关账写入，与即时库存(`T_STK_INVENTORY`)分轨，**由关账动作对齐**。

### 普适启示
> 与财务同构的"时间轴 + 固化 + 对账"。**关键决策：要不要"账存与即时库存双轨"？** 若只需要业务实时查询，单表足够；若要做月度结账/审计/报表隔离，就需要"实时投影 + 期间投影"双轨并在关账时对齐。复杂度与需求强相关，别被"别人有两张表"带偏。

## 8. 批量与集合式操作 —— 性能的隐藏杠杆

### 抽象定义
过账的对象是"一批分录"，而非单条。**集合式处理（一条 SQL 合并整批）** 与逐行循环的性能差距可达数量级，且天然原子。
库存/财务的大批量日常（关账、盘点差异、反审核）都必须走集合式路径。

### K3Cloud 实例
- `UpdateStockByTmpSqlBuilder.GetTempToInvSql`：差异表 → 一条 `MERGE` 整体并入即时库存；用 `/*dialect*/` 分支同时支持 SQLServer/Oracle；
- 日报/对账批量临时表（`DailyDataHelper`/`BulkInsertAdapter`）同模式。

### 普适启示
> 设计过账 DTO 时就用"批 + 事务号"，让 SQL 层能一次合并；**不要为了"代码可读"把批量拆成逐行**。并发下这是安全性的来源之一（整批原子）。

## 9. 描述属性 vs 主数据 —— 库存与"基础档案"的耦合

### 抽象定义
库存行上有两类维度：**描述性主数据**（物料、仓库、批次主档，来自基础档案）与**业务因子**（货主/保管者/项目/委托加工单）。正确建模必须区分：
- 主数据决定"可不可能"（该物料是否批次管理、是否允许负库存、用哪个单位）；
- 业务因子决定"现在在哪"（谁持有、在哪个项目订单上）。

### K3Cloud 实例
- `T_BD_MATERIALSTOCK`：批次管理/序列号管理/仓存单位/负库存允许/效期并入批次（`FISEXPPARTOFLOT`）；
- 过账 JOIN 主数据取校验参数；效期字段 `FPRODUCEDATE/FEXPIRYDATE` 若"并入批次"则由批次主档(`T_BD_LOTMASTER`)决定，否则取单据值。

### 普适启示
> 库存引擎只该面向"通用维度"编程，**能力差异一律下沉到主数据配置**。这使同一引擎能服务"食品批次+效期管控"与"电子料无需批次"两种极端的客户，而不用 if(productType) 写死。

## 10. 最小完整库存内核 —— 从抽象到可实现的骨架清单

| # | 内核组件 | 抽象来源 | 必备验证器 |
|---|---|---|---|
| 1 | 维度宽表（组合键 + 三单位数量） | §3 §6 | 组合键唯一约束 |
| 2 | 过账引擎（策略 + 过账点 + 乘数 + MERGE） | §5 §6 §8 | 增量守恒、原子性 |
| 3 | 事件日志（只追加流水 + 重算/备份） | §2 | 重算=现账 |
| 4 | 负库存守卫（守恒监督） | §1 | 六式校验、可出性检查 |
| 5 | 承诺/预留明细(锁定量实时聚合) | §4 | 聚合与现账一致 |
| 6 | 期初/盘点/结账时间轴 | §7 | 账存↔即时 对账结果 |
| 7 | 主数据能力开关（批次/序列号/负库存/单位） | §9 | 能力与单据一致性 |

> **一条公式贯穿全篇**：`正确库存 = 守恒(翻译(实物移动)) 沿 事务时间轴固化，且可重算` —— 与财务公式只差"记账→记数"。

## 附：库存 与 财务 的理论对位表（一套思想、两个实证）

| 抽象 | 财务篇 | 库存篇 |
|---|---|---|
| 守恒律 + 验证器 | 借贷平衡 / 试算平衡 | 数量守恒 / 负库存检查 |
| 事件溯源×投影 | 凭证分录 → 科目余额 → 报表 | 库存流水 → 即时/账存 → 台账 |
| 维度立方体 | 组织×科目×期间×币别×辅助核算 | 组织×仓库×仓位×批次×效期×单位 |
| 时间轴机制 | 启用→初始化→结账→反结账 | 期初→盘点→关账→反关账 |
| 承诺关系 | 往来核销(借项↔贷项配对) | 预留占用(需求↔库存行配对) |
| 翻译层 | 业务单据→凭证模板 | 单据→过账点+数量乘数 |
| 主数据开关 | 科目/账簿/币别配置 | 物料库存属性配置 |

> **结论**：财务与库存不是两个系统，是**同一套"守恒 + 溯源 + 维度 + 时间轴"抽象在"钱"与"数量"两种主题上的两次实例化**。掌握了这套思想，仿写任何"账类"业务系统（库存、往来、预算、配额、积分、仓位）都是"换主题词不改骨架"。
