## 一、核心发现：资金模块与总账模块的双轨并行

K3 Cloud 的账务体系存在两个独立的模块，各自解决不同的问题：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          K3 Cloud 账务体系                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  业务单据（收款单/付款单/现金单/银行单）                                  │
│             │                                    │                           │
│             ├─────────────────────────────────┘                           │
│             │                                                            │
│             ▼                                                            │
│  ┌─────────────────────┐              ┌─────────────────────┐               │
│  │ 现金/银行日记账      │              │ 凭证账簿（GL）       │               │
│  │ T_CN_JOURNALENTRY   │              │ T_GL_VOUCHER        │               │
│  │                     │              │ T_GL_VOUCHERENTRY   │               │
│  │ ━━━━━━━━━━━━━━━━━━━ │              │ ━━━━━━━━━━━━━━━━━━━ │               │
│  │ 视角：钱去哪了      │              │ 视角：借贷是否平衡   │               │
│  │                     │              │                     │               │
│  │ 关键功能：         │              │ 关键功能：         │               │
│  │ ├─ 勾对 FBLEND     │              │ ├─ 凭证生成方案     │               │
│  │ └─ 银行对账        │              │ └─ 复式记账         │               │
│  └──────────┬──────────┘              └──────────┬──────────┘               │
│             │                                    │                          │
│             │         并列关系！                │                          │
│             │                                    │                          │
│             │    业务单据 同时下推生成：        │                          │
│             │    ① CN日记账 + ② GL凭证      │                          │
│             │                                    │                          │
└─────────────┼────────────────────────────────────┼──────────────────────────┘
              │                                    │
              ▼                                    ▼
       ┌─────────────────────┐        ┌─────────────────────┐
       │ T_CN_BLENDDATA      │        │ T_GL_BALANCE       │
       │ 勾对记录表          │        │ 余额表              │
       └─────────────────────┘        └──────────┬──────────┘
                                                  │
                                                  ▼
                                          ┌─────────────────────┐
                                          │ 总账/明细账/报表   │
                                          └─────────────────────┘
```

## 二、业务单据到两个模块的关系

### 2.1 两种不同的生成方式

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    业务单据到财务模块的关系                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  业务单据（收款单/付款单）                                              │
│       │                                                                     │
│       ├──→ 审核时触发 → GL凭证（凭证生成方案配置）                    │
│       │                                                                     │
│       └──→ 审核时触发 → 资金日记账（CN_BANKTRANSCFG配置）             │
│                                                                              │
│  ⚠️ 关键区分：                                                          │
│  • GL凭证：审核时"触发"生成，不是"下推"生成                         │
│  • CN资金日记账：审核时"触发"生成，不是"下推"生成                   │
│  • 两者是并列关系，同时从业务单据审核事件触发                          │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 CN_BANKTRANSCFG 配置的作用

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    CN_BANKTRANSCFG 配置的本质                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  CN_BANKTRANSCFG 定义：哪些业务单据可以生成资金日记账，以及字段映射规则    │
│                                                                              │
│  配置示例：                                                              │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │ FTYPE = 1（银行日记账）                                      │      │
│  │ FBILLFORMID = AR_ReceiveBill（收款单）                        │      │
│  │ FBANKACNTIDKEY = FBANKACNTID（收款单的银行账号字段）           │      │
│  │ FDATEKEY = FDATE（收款单的业务日期字段）                        │      │
│  │ FDEBITAMOUNTKEY = FAMOUNT（收款金额映射到借方）              │      │
│  │ FFLAG = 0（收款=借方）                                         │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.3 为什么需要持久化存储

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    为什么要持久化存储？                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  勾对状态 FBLEND 需要长期保存！                                       │
│                                                                              │
│  如果是临时表：                                                         │
│  ├── 每次查询结束数据就消失                                          │
│  ├── 无法保存"哪些交易已勾对"                                        │
│  └── 无法进行跨月/跨年的银行对账                                      │
│                                                                              │
│  持久化存储：                                                           │
│  ├── FBLEND = '0'（未勾对）                                       │
│  ├── FBLEND = '1'（已勾对）                                       │
│  └── 可以追踪任意时间点的勾对状态                                     │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.3 K3 Cloud 凭证与财务概念的对应关系

│  ┌─────────────────────┬─────────────────────┬─────────────────────────────┐  │

│  ├─────────────────────┼─────────────────────┼─────────────────────────────┤  │
│  │ T_GL_VOUCHER      │ 记账凭证           │ 一张凭证（一个业务事件） │  │

│  ├─────────────────────┼─────────────────────┼─────────────────────────────┤  │

│  ├─────────────────────┼─────────────────────┼─────────────────────────────┤  │

│  │ FPosted            │ 过账状态           │ 0=未过账 1=已过账      │  │
│  ├─────────────────────┼─────────────────────┼─────────────────────────────┤  │
│  │ FAccountID         │ 科目编码           │ 会计科目                │  │
│  ├─────────────────────┼─────────────────────┼─────────────────────────────┤  │
│  │ FDC                │ 借贷方向           │ 1=借 -1=贷            │  │
│  ├─────────────────────┼─────────────────────┼─────────────────────────────┤  │
│  │ FDebit/FCredit     │ 借方/贷方金额     │ 金额字段               │  │
│  └─────────────────────┴─────────────────────┴─────────────────────────────┘  │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.4 凭证的生命周期

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    凭证的生命周期（与手工账完全对应）                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  手工时代：                              K3 Cloud：                       │
│  ━━━━━━━━━━━━━                          ━━━━━━━━━━━━━                     │
│                                                                              │
│  1. 编制凭证                             1. 生成/录入凭证                   │
│     会计手工写借/贷                         自动或手工创建                   │
│     ↓                                       ↓                              │
│  2. 复核                                  2. 审核                           │
│     主管检查借贷平衡                        FCheckerId = 审核人              │
│     ↓                                       ↓                              │
│  3. 过账                                  3. 过账                           │
│     登记到账簿                             FPosted = 1                      │
│     ↓                                       ↓                              │
│  4. 结账                                  4. 结账                           │
│     月末汇总                               期间结账                         │
│                                                                              │
│  对应关系：                                                                │
│  FDocumentStatus = 'C' 等价于 手工凭证已审核                            │
│  FPosted = 1 等价于 手工凭证已过账                                     │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.5 K3 Cloud 凭证的特殊之处

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    K3 Cloud 凭证的独特设计                              │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │

│  3. 多账簿支持                                                          │
│     ┌─────────────────────────────────────────────────────────────────┐    │

## 六、凭证、分录、总账、明细账的概念关系

### 6.1 概念之间的关系

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    凭证体系的概念层次关系                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  一张凭证 = 多条分录                                                       │
│                                                                              │
│  ┌─────────────────────────────────────────────────────────────────┐         │
│  │                    凭证（Voucher）                           │         │
│  │  ┌─────────────────────────────────────────────────────────┐ │         │
│  │  │  分录1：借 银行存款 100万                        │ │         │
│  │  │  分录2：贷 主营业务收入 85.47万                 │ │         │
│  │  │  分录3：贷 应交税费-销项税 14.53万             │ │         │
│  │  └─────────────────────────────────────────────────────────┘ │         │
│  │  日期：2024-01-01                                        │         │
│  │  凭证号：记-001                                           │         │
│  └─────────────────────────────────────────────────────────────────┘         │
│                                                                              │
│  凭证是容器，分录是内容。                                                   │
│  一张凭证可以有多条分录，但借贷必须相等。                                   │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.2 分录与账户的关系

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    分录与账户的关系                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  分录 = 账户的变动记录                                                     │
│                                                                              │
│  每条分录明确：                                                            │
│  ├── 哪个账户（科目）发生变化                                          │
│  ├── 变多了还是变少了（借 or 贷）                                    │
│  └── 变了多少（金额）                                               │
│                                                                              │
│  账户 = 累积的分录                                                       │
│                                                                              │
│  账户"银行存款"：                                                        │
│  ├── 分录1：+100万（收到货款）                                      │
│  ├── 分录2：-50万（支付货款）                                       │
│  └── 当前余额：50万                                                  │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.3 日记账、分类账、总账的关系

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    账簿体系的层次关系                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  ┌─────────────────────────────────────────────────────────────────────┐    │
│  │                        日记账（序时账）                           │    │
│  │  ┌─────────────────────────────────────────────────────────────┐ │    │
│  │  │ 1月1日  凭证#001  银行存款 +100万                        │ │    │
│  │  │ 1月1日  凭证#002  银行存款 -50万                        │ │    │
│  │  │ 1月2日  凭证#003  银行存款 +80万                        │ │    │
│  │  └─────────────────────────────────────────────────────────────┘ │    │

### 6.6 为什么要"过账"？

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    为什么需要"过账"这个操作？                          │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  凭证不过账会怎样？                                                    │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │ 假设：只有凭证，没有过账                                           │      │
│  │                                                                     │      │
│  │ 要生成报表怎么办？                                                 │      │
│  │ → 必须实时计算：从所有凭证分录中，统计每个科目的余额      │      │
│  │ → 10000张凭证 × 每天查询 = 系统崩溃                        │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  过账做了什么？                                                        │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │ 过账 = 把凭证分录的金额，累加到余额表                           │      │
│  │                                                                     │      │
│  │ 凭证分录：借 银行存款 100万                                      │      │
│  │           贷 主营业务收入 100万                                  │      │
│  │                                                                     │      │
│  │ 过账后：                                                            │      │
│  │ T_GL_BALANCE：银行存款 +100万                                    │      │
│  │ T_GL_BALANCE：主营业务收入 +100万                                │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  过账的好处：                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │ 1. 查询报表时不需要重新计算，直接读余额表                  │      │
│  │ 2. 凭证可以"暂存"不发布，不影响报表                      │      │
│  │ 3. 月末结账后，凭证被"锁定"，余额已确定                  │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  类比：                                                                │
│  凭证 = 购物小票                                                       │
│  过账 = 结算后，把金额累加到账户余额                                   │
│  余额表 = 账户余额（每次消费都要更新）                             │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.7 为什么叫"科目余额表"？

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    总账为什么叫"科目余额表"？                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  "总账"这个名字容易误解。实际内容是：                                 │
│                                                                              │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │                    T_GL_BALANCE 结构                             │      │
│  │                                                                     │      │
│  │  FACCOUNTID    │  FPERIOD  │  FDEBIT  │  FCREDIT │  FBALANCE │ │
│  │  ─────────────┼───────────┼──────────┼──────────┼───────────│      │
│  │  1001(银行存款)│  2024-01 │  100万   │  50万    │  50万     │      │
│  │  1002(应收账款)│  2024-01 │  50万    │  30万    │  120万    │      │
│  │  6001(主营业务)│  2024-01 │   0万    │  85.47万 │  85.47万  │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  它实际上记录的是：                                                      │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │  某个科目（FACCOUNTID）                                          │      │
│  │  某个期间（FPERIOD）                                             │      │
│  │  借方累计、贷方累计                                               │      │
│  │  当前余额（FBALANCE）                                             │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  所以叫"科目余额表"比"总账"更准确：                                   │
│  • 每一行 = 一个科目                                                   │
│  • 内容 = 该科目的余额（不是分录）                               │
│  • 目的 = 快速查询任意科目的当前余额                        │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.10 从结构因果分析科目余额表

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    为什么要这样设计？因果分析                          │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  问题1：为什么要分"本位币"和"原币"？                             │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │ 场景：公司做美元业务                                              │      │
│  │                                                                     │      │
│  │ 1月1日：收到美元1000，汇率7.2，收入72,000元人民币        │      │
│  │ 1月15日：收到美元1000，汇率7.3，收入73,000元人民币        │      │
│  │                                                                     │      │
│  │ 如果只有本位币字段：                                               │      │
│  │ → 无法知道当时汇率是多少                                         │      │
│  │ → 无法重新计算历史汇率下的金额                                 │      │
│  │                                                                     │      │
│  │ 分开存储：                                                        │      │
│  │ FBEGINBALANCEFOR = 1000（美元）                              │      │
│  │ FBEGINBALANCE = 7200（人民币）                               │      │
│  │ → 期末可以直接按当前汇率重估                                  │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  问题2：为什么要分"期初"和"发生额"？                             │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │ 期初余额 + 借方发生额 - 贷方发生额 = 期末余额                │      │
│  │                                                                     │      │
│  │ 1月1日：银行存款余额 = 10万（期初）                           │      │
│  │ 1月份：                                                          │      │
│  │   借方发生额 = 5万（收到货款）                               │      │
│  │   贷方发生额 = 3万（支付货款）                               │      │
│  │ 1月31日：余额 = 10 + 5 - 3 = 12万                          │      │
│  │                                                                     │      │
│  │ 分开存储的好处：                                                  │      │
│  │ 1. 可以追溯任一期间的"过程"                                   │      │
│  │ 2. 可以验证数据是否正确（借贷平衡）                          │      │
│  │ 3. 生成账表时可以选择显示哪些列                               │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  问题3：FDETAILID = 0 和 > 0 的区别？                            │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │ FDETAILID = 0：该科目的"总账"余额                            │      │
│  │ FDETAILID > 0：该科目的"明细账"余额                         │      │
│  │                                                                     │      │
│  │ 例子：                                                          │      │
│  │ 科目：应收账款（1002）                                         │      │
│  │                                                                     │      │
│  │ 总账（FDETAILID=0）：                                         │      │
│  │   应收账款 余额 = 50万                                       │      │
│  │                                                                     │      │
│  │ 明细账（FDETAILID>0，按客户核算）：                         │      │
│  │   应收账款-A公司 余额 = 30万（FDETAILID=1）              │      │
│  │   应收账款-B公司 余额 = 20万（FDETAILID=2）              │      │
│  │                                                                     │      │
│  │ 30万 + 20万 = 50万 ✓                                         │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  问题4：为什么要分"期间发生额"和"本年累计"？                │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │ FYTDDEBIT = 从年初到现在的累计借方                           │      │
│  │                                                                     │      │
│  │ 1月末：本年累计借方 = 5万                                     │      │
│  │ 2月末：本年累计借方 = 5 + 8 = 13万                           │      │
│  │ 12月末：本年累计借方 = 全年借方合计                          │      │
│  │                                                                     │      │
│  │ 好处：                                                          │      │
│  │ 1. 年报可以直接取FYTD字段，不用跨期间汇总               │      │
│  │ 2. 查询"年初至今"数据很快                                   │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  问题5：FYEAR + FPERIOD 为什么不直接用日期？                     │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │ 原因：会计期间不一定是自然月                                 │      │
│  │                                                                     │      │
│  │ 情况1：自然月（1-12月）                                       │      │
│  │   2024-01 = 1月1日-1月31日                                 │      │
│  │                                                                     │      │
│  │ 情况2：非自然月（如4月1日-次年3月31日）                  │      │
│  │   FYEAR=2024, FPERIOD=1 = 2024年4月1日                   │      │
│  │   FYEAR=2025, FPERIOD=12 = 2025年3月31日                │      │
│  │                                                                     │      │
│  │ 用年度+期间更灵活，不依赖具体日期！                        │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.11 余额计算公式

│                                                                              │

│  │  下期期初 = 本期期末                                             │      │

│  ├─────────────────┼─────────────────────────────────────────────────┤      │
│  │ 分类账/总账     │ T_GL_BALANCE（科目余额表）                    │      │
│  │                 │ - 来源：凭证过账                               │      │
│  │                 │ - 本质：科目余额的聚合                          │      │
│  ├─────────────────┼─────────────────────────────────────────────────┤      │
│  │ 财务报表        │ 资产负债表、利润表、现金流量表                 │      │
│  │                 │ - 来源：T_GL_BALANCE汇总                      │      │
│  └─────────────────┴─────────────────────────────────────────────────┘      │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.4 关键区别

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    K3凭证 vs 传统记账凭证 的关键区别                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  传统记账凭证：                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │ ① 根据原始凭证手工编制                                           │      │
│  │ ② 编制完成后，直接登记日记账和分类账                          │      │
│  │ ③ 凭证和账簿是分开的实体                                       │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  K3凭证（T_GL_VOUCHER）：                                              │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │ ① 根据业务单据自动/半自动生成                                   │      │
│  │ ② 生成后需要"审核"操作                                        │      │
│  │ ③ 审核后需要"过账"操作                                        │      │
│  │ ④ 过账后才更新T_GL_BALANCE余额                               │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  K3的"审核+过账" = 传统手工的"编制+登记账簿"                     │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.5 K3中的三个状态

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    K3凭证的三种状态                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  状态1：保存（Draft）                                                    │
│  ├── 凭证已保存，但还未完成                                         │
│  └── 类比：传统手工写好草稿                                           │
│            ↓                                                              │
│  状态2：审核（Approved）                                                 │
│  ├── 凭证审核通过，可以过账                                         │
│  └── 类比：传统手工审核凭证                                           │
│            ↓                                                              │
│  状态3：过账（Posted）                                                  │
│  ├── 凭证过账，更新T_GL_BALANCE余额                               │
│  └── 类比：传统手工把凭证登记到账簿                               │
│                                                                              │
│  注意：未过账的凭证不会影响余额表！                               │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.6 总结

**K3凭证的本质 = 传统记账凭证**

区别在于：
1. 编制方式：手工 → 自动/半自动
2. 登记方式：手工抄写 → 过账操作
3. 存在形式：纸质的凭证本 → 数据库中的凭证记录

**K3新增的"资金日记账"是传统手工账中没有的概念，它是为了解决"银行对账"这个出纳视角的问题。**

# 附录二：银行对账与勾对

## 一、三个核心概念

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    银行对账涉及的三方                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  1. 企业交易明细                                                        │
│     ├── 来源：T_CN_JOURNALENTRY（资金日记账）                          │
│     └── 记录：企业自己知道的每一笔收付款                            │
│                                                                              │
│  2. 银行对账单（Bank Statement）                                       │
│     ├── 来源：从银行导入的交易记录                                      │
│     ├── 表格：T_CN_BANKACNTSTATE                                      │
│     └── 记录：银行告诉企业的每一笔收付款                            │
│                                                                              │
│  3. 勾对记录（Reconciliation）                                         │
│     ├── 来源：企业交易与银行对账单的匹配结果                            │
│     ├── 表格：T_CN_BLENDDATA + T_CN_BLENDDATAENTRY                   │
│     └── 记录：哪些业务已经被银行确认                                │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 二、银行对账的数据流

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    银行对账完整数据流                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  1. 业务发生                                                             │
│     客户付款 100万                                                        │
│            ↓                                                              │
│  2. 录入收付款单                                                        │
│     收款单 T_AR_RECEIVEBILL                                               │
│     ├── FCUSTOMERID = A公司                                             │
│     ├── FBANKACNTID = 建设银行账号                                      │
│     ├── FAMOUNT = 100万                                                │
│     └── FSETTLENO = GD20240101001                                       │
│            ↓                                                              │
│  3. 下推生成资金日记账                                                   │
│     T_CN_JOURNALENTRY                                                   │
│     ├── FBANKACNTID = 建设银行账号                                     │
│     ├── FDIRECTION = 1（收款）                                         │
│     └── FBLEND = '0'（未勾对）                                       │
│            ↓                                                              │
│  4. 导入银行对账单                                                      │
│     T_CN_BANKACNTSTATEENTRY                                             │
│     ├── FTRANSDATE = 2024-01-01                                       │
│     ├── FOPPOSITEACCNT = A公司                                          │
│     ├── FDEBITAMOUNT = 100万                                          │
│     └── FSETTLENO = GD20240101001                                       │
│            ↓                                                              │
│  5. 勾对（自动/手工）                                                  │
│     匹配条件：金额相同 + 结算号相同                                    │
│            ↓                                                              │
│     T_CN_BLENDDATAENTRY                                                 │
│     ├── FSRCBILLFORM = CN_JOURNAL                                     │
│     ├── FSRCENTRYID = 资金日记账ID                                     │
│     └── FBLEDAMOUNT = 100万                                            │
│            ↓                                                              │
│     更新：T_CN_JOURNALENTRY.FBLEND = '1'                               │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 三、为什么勾对用交易明细而不是银行日记账汇总

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    勾对对象的选择                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  银行日记账（报表）：                                                   │
│  ├── 包含汇总行（FRowType = 3,4,5 的合计行）                        │
│  ├── 余额是计算出来的，不是原始数据                                    │
│  └── 无法与银行逐笔匹配                                                │
│                                                                              │
│  交易明细（T_CN_JOURNALENTRY）：                                        │
│  ├── 每行都是原始单据记录                                              │
│  ├── 可以和银行对账单逐笔匹配                                          │
│  └── FBLEND字段记录勾对状态                                            │
│                                                                              │
│  勾对逻辑：                                                           │
│  T_CN_JOURNALENTRY.FBLEND = '0'（未勾）↔ 银行对账单              │
│  匹配后：T_CN_JOURNALENTRY.FBLEND = '1'（已勾）                      │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```
