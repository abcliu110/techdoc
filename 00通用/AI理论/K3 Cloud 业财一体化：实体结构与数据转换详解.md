## 一、文档目的与阅读指南

### 1.1 文档目的

本文档详细说明 K3 Cloud 中各业务实体的数据结构，以及信息在实体之间的转换过程。目标是回答：

- **源实体**的哪些字段被读取？
- **目标实体**的哪些字段被写入？
- **数据转换逻辑**是什么（计算、取值、格式转换）？
- **触发时机**是什么（审核时、下推时、过账时）？

```
│  └─────────────────────────────────────────────────────────────────┘      │
```

### 7.1 销售出库单 → 应收单


### A.2 为什么是这些单据？因果分析

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    为什么这些单据可以直接生成凭证？                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  【因果必要条件：必须同时满足以下三个条件】                               │
│                                                                              │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │                                                                 │      │
│  │  条件1：金额已确定                                             │      │
│  │  ─────────────────────────────────────────────────────────────│      │
│  │  只有金额确定的单据才能生成凭证，因为凭证需要借贷平衡：       │      │
│  │  • 借方合计 = 贷方合计                                       │      │
│  │  • 如果金额不确定，无法平衡                                    │      │
│  │                                                                 │      │
│  │  满足条件1的单据：                                            │      │
│  │  • 收款单/付款单（金额=收款/付款金额）                      │      │
│  │  • 应收单/应付单（金额=商品+税额）                          │      │
│  │  • 费用报销单（金额=报销金额）                               │      │
│  │                                                                 │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │                                                                 │      │
│  │  条件2：涉及资金或债权债务变化                               │      │
│  │  ─────────────────────────────────────────────────────────────│      │
│  │  只有涉及资金或债权债务的业务才需要GL凭证：                 │      │
│  │  • 资金变化：银行存款、现金                                   │      │
│  │  • 债权债务：应收账款、应付账款                               │      │
│  │  • 收入成本：主营业务收入、主营业务成本                       │      │
│  │                                                                 │      │
│  │  满足条件2的单据：                                            │      │
│  │  • 收款单：银行存款↑ + 应收账款↓                            │      │
│  │  • 付款单：银行存款↓ + 应付账款↓                            │      │
│  │  • 应收单：应收账款↑ + 收入↑                               │      │
│  │  • 应付单：应付账款↑ + 库存/成本↑                         │      │
│  │                                                                 │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
│  ┌─────────────────────────────────────────────────────────────────┐      │
│  │                                                                 │      │
│  │  条件3：有明确的借贷科目映射                                 │      │
│  │  ─────────────────────────────────────────────────────────────│      │
│  │  每个单据必须有预设的借贷规则：                              │      │
│  │  • 收款单：借银行存款，贷应收账款                           │      │
│  │  • 付款单：借应付账款，贷银行存款                           │      │
│  │  • 应收单：借应收账款，贷收入                               │      │
│  │  • 应付单：借库存/成本，贷应付账款                         │      │
│  │                                                                 │      │
│  │  这些规则通过"凭证生成方案"配置                            │      │
│  │                                                                 │      │
│  └─────────────────────────────────────────────────────────────────┘      │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```
