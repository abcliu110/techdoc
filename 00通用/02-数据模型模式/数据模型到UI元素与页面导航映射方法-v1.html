Model-driven interface reference

从数据的形状，推导界面的表达

本方法从字段、对象、集合、层级、网络、时间、空间、状态和多维事实出发，推导原子控件、复合视图、页面模式与导航体系。它既回答整数为何可能映射为文本框或增减器，也解释同一订单集合为何可以形成表格、看板、日历、甘特、地图、透视表和异常工作台。

01 / 12

核心定义

映射不是“数据库类型与控件一一对应”，而是从一组合法候选中，选择最适合当前任务的 UI 表达。

CANDIDATE

类型给出候选集

整数可映射为数字输入框、增减器、滑块、只读数字或刻度。它只缩小范围，不直接给出唯一答案。

REFINEMENT

约束完成修正

最小值、最大值、步长、是否必填、可编辑性、候选规模和精度，会淘汰不合适的控件。

CONTEXT

任务决定最终选择

精确录入、快速微调、范围感知、筛选、展示和批量编辑是不同任务，即使数据类型相同也应采用不同表达。

映射可能性决策台

选择一种模型形状，比较它可映射的不同 UI。标记“常用起点”不代表固定答案，最终仍由语义、约束与任务决定。

模型类型 / 语义首选 UI其他候选选择条件不适合的情况
Integer
普通整数		数字输入框 输入增减器、滑块、只读数字精确录入用数字框；小范围逐步调整用增减器；强调范围位置用滑块。范围无限或跨度很大时不用滑块；高频键盘录入不宜只用增减按钮。
Integer + step
数量 / 人数		增减器 输入数字输入框存在明确步长、常做 ±1 或小幅调整，且上下界清晰。需要一次输入大数值时，应允许直接键盘输入。
Decimal
小数 / 比率		带精度的数字框 输入滑块、格式化只读值显式展示单位、精度与范围；比例可在 UI 显示百分比但按约定存储。不能忽略四舍五入、单位或小数位规则。
Money
金额值对象		金额输入框 + 币种 输入只读金额、币种选择器金额与币种共同表达；按币种控制精度和格式。不要用普通浮点框，也不要只显示货币符号而丢失币种。
String
短文本		单行文本框 输入只读文本、可复制文本名称、标题、编号等短内容；按长度、格式、唯一性补充校验。固定候选值不应让用户自由输入。
Text
长文本		多行文本域 输入富文本编辑器、Markdown、只读段落纯文本说明用文本域；需要结构、链接、图片时才升级富文本。短字段不要用大文本域；无格式需求不引入富文本。
String + pattern
电话 / 邮箱 / URL		语义输入框 输入掩码输入、组合输入使用对应 input 类型、格式提示和即时校验；电话需考虑国家区号。格式校验不能代替服务端真实性或唯一性验证。
Boolean
即时设置		开关 输入复选框、单选组设置立即生效用开关；表单提交后生效或表示“同意”用复选框。有“未知/未设置”第三态时不能用二态开关。
Enum
少量互斥选项		单选组 / 分段控件 选择下拉框2–5 个高频选项直接展开；选项多或空间紧张时使用下拉。业务状态机不能直接映射为任意可改的下拉框。
Enum[]
多选集合		复选组 选择多选下拉、标签选择器少量选项用复选组；候选多且可搜索时用多选选择器。大量选项全部铺开会造成扫描负担。
Date
自然日		日期选择器 输入文本输入、日历视图生日、业务日期等不含时刻；允许熟练用户键盘录入。不要偷偷附加时区或午夜时间。
DateTime
明确时刻		日期时间选择器 输入只读时间、相对时间编辑时明确时区；展示可用“刚刚”，但应能查看绝对时间。跨时区场景不能只显示模糊的本地时间。
Duration
持续时间		数值 + 单位 输入时分组合输入、滑块统一存储单位；UI 根据业务使用分钟、小时或天。不要把持续时间误建模为某个日期时间。
Foreign Key
单对象引用		可搜索选择器 选择自动补全、对象卡片、详情链接显示业务名称而非 ID；候选大时服务端搜索；选中后可查看摘要。禁止让用户手填数据库主键。
Object[]
子项集合		可编辑明细表 输入重复表单、卡片列表、独立子页面少量同构子项适合明细表；字段多或移动端可用重复卡片。大集合不能一次渲染，也不应塞进单个多选框。
Tree
递归层级		树选择器 选择级联选择、树表、面包屑导航选择路径用级联；浏览结构用树；深层定位需搜索和路径回显。浅且稳定的两级数据不必强行使用复杂树控件。
File / Image
附件引用		上传器 + 文件列表 输入图片预览、拖放区、下载链接展示类型、大小、进度、失败重试和删除权限。文件二进制通常不直接嵌入业务表单字段。
Derived
计算值 / 汇总值		只读数字或指标 输出进度条、趋势、图表能解释口径、来源和更新时间；需要比较时再加视觉编码。派生值不应伪装成可编辑输入框。
没有匹配的映射规则。

复杂数据形状到复合界面图谱

控件只解决一个值如何读写。对象集合、时间、空间、状态、网络、多维事实、规则和权限会形成表格、看板、日历、地图、图表、设计器等复合界面。

L1数据形状原子、对象、集合、树、图、时间、空间、多维
L2操作语义查找、比较、录入、分组、调度、匹配、分析
L3UI 表达控件、表格、卡片、树、图表、地图、画布
L4页面模式列表、详情、主从、工作台、向导、驾驶舱
L5导航体系嵌入、抽屉、跳转、钻取、流程、上下文恢复

同一个 Integer，因为范围、步长和任务不同，可以得到完全不同的 UI。

STEP 1读取类型Integer
STEP 2读取语义商品购买数量
STEP 3读取约束1–99，步长 1
STEP 4识别任务频繁小幅调整
RESULT选择增减器同时允许键盘输入
min / max 范围较小且用户需要感知位置

可以从数字输入框修正为滑块；若仍要求精确值，应同时显示当前数值或保留输入框。

step 固定且调整频繁

可以从数字输入框修正为增减器。按钮只负责快捷调整，输入框仍负责大跨度录入。

readOnly / derived 不允许用户修改

从输入控件修正为格式化文本、状态徽标、指标或进度条，避免制造“可以编辑”的错误暗示。

nullable 存在“未设置”语义

必须保留清空能力。Nullable Boolean 是三态值，不应直接使用只有开/关的二态开关。

高风险字段

金额、库存、权限和业务状态不能只按类型映射；应通过业务命令、校验、确认和审计完成修改。

候选规模变化

3 个选项可用单选组，300 个对象应改用远程搜索选择器；控件必须随数据规模改变。

导航表达可映射的关系优点缺点选择条件
同页嵌入组成关系、少量一对多上下文完整，编辑和比较路径最短。页面会变长；大集合、独立权限和复杂子对象难承载。子对象依赖父对象，数量少，并且共同保存。
模态弹窗短暂选择、简单确认、轻量子编辑不离开当前任务，完成后能立即回填结果。空间有限，深层导航和复杂表单容易形成“弹窗套弹窗”。任务短、可一次完成、不需要 URL 和跨页历史。
侧边抽屉引用对象预览、列表行快速编辑保留原页面可见性，比弹窗容纳更多内容。窄屏体验差；用户容易混淆当前对象和背景对象的保存边界。需要参考背景信息，但目标任务仍相对轻量。
独立详情页引用关系、独立生命周期对象空间、URL、权限、历史和深层操作边界清晰。产生跳转成本；必须恢复来源筛选、页码和滚动位置。对象可独立识别、分享、收藏或执行复杂操作。
主从布局一对多集合、队列到详情连续浏览效率高，选择列表项即可更新详情。需要较宽屏幕；URL、焦点和移动端堆叠策略更复杂。用户需要在同一集合中快速逐条处理或比较。
标签页 / 分区同一主对象的不同投影把概览、明细、历史等稳定分区收纳在同一对象上下文。内容不易被发现；标签过多会退化为隐藏导航。各区域共享同一主对象身份，但信息任务不同。
树 + 节点详情递归层级、自引用关系结构位置和详情可配合呈现，适合管理层级。大树性能、搜索、展开状态和移动端操作复杂。路径和父子关系本身就是用户决策的重要依据。
流程前进 / 下一任务状态迁移、工作流任务把用户导向合法下一步，减少返回队列的重复定位。不能代替自由浏览；自动前进可能让用户失去完成感。任务有明确顺序、合法动作和队列上下文。

六步决策法

把这套步骤用于元数据驱动表单、低代码设计器或人工界面设计，都能得到可解释的映射结论。

01

识别数据形状

原子值、枚举、可空值、对象引用、集合、树、派生值，先确定结构。

02

补齐业务语义

同为字符串，名称、密码、手机号、颜色和代码需要不同控件与行为。

03

读取约束

范围、步长、精度、格式、必填、只读、唯一性和候选规模。

04

明确用户操作

用户是在查看、录入、微调、选择、比较、筛选，还是执行业务命令？

05

确定关系呈现

组成关系优先嵌入，引用关系优先选择与跳转，大集合优先独立列表。

06

验证边界状态

检查空值、错误、加载、无权限、大数据量、移动端和返回上下文。

常见误区

这些机械映射会让界面看似自动生成，实际却丢失业务语义。

整数一律映射成数字框

忽略范围、步长和调整频率，会错过增减器、滑块或只读指标。

字符串一律映射成文本框

枚举、对象引用、电话、密码和颜色虽然可存为字符串，却不是自由文本。

外键直接显示 ID

用户识别的是客户名、商品名和摘要，不是数据库主键。

业务状态映射成下拉框

状态应由合法命令迁移，必须考虑权限、前置条件、并发和审计。

所有关系都嵌入详情页

大集合和独立生命周期对象需要单独页面与过滤上下文。

跳转后丢失来源上下文

从列表进入详情、再进入关联对象时，应保留筛选、页码、滚动和返回目标。
