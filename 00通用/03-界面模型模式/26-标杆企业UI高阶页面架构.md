# 标杆企业 UI 高阶页面架构设计

> 本文档不含子组件（按钮/输入框/表格等），只负责**页面骨架、布局区域、页面跳转路由、信息架构层级**。面向架构师和产品负责人，回答"系统有哪些页面、页面如何分区、页面间如何跳转"。

---

## 一、核心概念

### 1.1 高阶页面架构的三个维度

```
维度 1：信息架构（Information Architecture）
  系统有哪些页面？页面如何分层组织？用户如何找到目标页面？

维度 2：页面布局（Page Layout）
  单个页面内如何分区？哪些区域固定？哪些区域随内容变化？

维度 3：导航路由（Navigation & Routing）
  页面间如何跳转？跳转时保留哪些上下文？返回时恢复什么状态？
```

### 1.2 设计原则

| 原则 | 含义 | 标杆实践 |
|---|---|---|
| **角色入口分离** | 不同角色看到不同的首页和工作台 | SAP Fiori Launchpad 按角色分组；Salesforce App 按角色切换 |
| **层级不超过 3 层** | 从首页到目标页面不超过 3 次点击 | SAP Fiori：Launchpad→目录→应用；Salesforce：App Launcher→对象→记录 |
| **上下文保持** | 页面跳转后返回，筛选/排序/滚动位置不变 | SAP Flexible Column Layout；Salesforce List View 筛选保持 |
| **面包屑可追溯** | 用户随时知道自己在哪、怎么来的 | SAP Fiori 面包屑；Salesforce Record Page 面包屑 |
| **多标签并行** | 高频用户可同时打开多个页面 | SAP Fiori 多 Tab；Ant Design Pro 多标签页 |

## 二、SAP Fiori 高阶页面架构

### 2.1 信息架构

```
SAP Fiori Launchpad（统一入口）
├── 首页（角色定制）
│   ├── 我的应用（小组件）
│   ├── 最近使用
│   ├── 收藏夹
│   └── 通知
├── 应用目录（按业务分组）
│   ├── 销售
│   │   ├── 销售订单 List Report → 销售订单 Object Page
│   │   ├── 交货单 List Report → 交货单 Object Page
│   │   └── 客户 Fact Sheet → 客户 Object Page
│   ├── 采购
│   │   ├── 采购订单 List Report → 采购订单 Object Page
│   │   └── 供应商 Fact Sheet → 供应商 Object Page
│   ├── 财务
│   │   ├── 凭证 List Report → 凭证 Object Page
│   │   └── 科目余额 Overview Page → Drill-down
│   └── 分析
│       ├── 销售 Overview Page → Analytical List Page
│       └── 库存 Overview Page → Analytical List Page
├── 搜索（全局搜索，跨对象）
└── 通知中心
```

### 2.2 页面布局层级

```
┌─────────────────────────────────────────────────────────┐
│ Shell Bar（全局顶栏：搜索/通知/用户/主题）          [固定] │
├──────────┬──────────────────────────────────────────────┤
│          │                                              │
│  左侧    │           页面内容区                          │
│  导航    │     （随路由切换，Layout 由页面类型决定）        │
│  目录    │                                              │
│  [固定]  │                                              │
│          │                                              │
├──────────┴──────────────────────────────────────────────┤
│ （无全局底栏）                                           │
└─────────────────────────────────────────────────────────┘
```

### 2.3 页面类型与布局

| 页面类型 | 布局结构 | 跳转关系 |
|---|---|---|
| **Launchpad 首页** | 小组件网格（可拖拽重排） | 点击小组件→对应应用 |
| **List Report** | 顶栏 + 筛选区 + 表格 + 分页 | 点击行→Object Page |
| **Object Page** | 顶栏 + 对象头部 + 分区锚点导航 + 滚动内容 | 分区内链接→子对象 Object Page |
| **Overview Page** | 顶栏 + 全局筛选 + KPI卡片网格 + 图表 | 点击卡片→Analytical List Page |
| **Analytical List Page** | 顶栏 + 筛选区 + 图表区 + 明细表 | 点击明细行→Object Page |
| **Worklist** | 顶栏 + 任务列表 + 操作区 | 点击任务→Object Page 或内联处理 |
| **Flexible Column** | 左栏列表 + 中栏详情 + 右栏子详情 | 左选中→中更新→中链接→右展开 |

### 2.4 路由与上下文保持

```
Launchpad
  → List Report（URL: /orders?filter=status:'open'）
      → Object Page（URL: /orders/SO00100）
          → 子对象 Object Page（URL: /orders/SO00100/deliveries/DL001）
      ← 返回 List Report（筛选条件 status:'open' 保持）

Flexible Column Layout（三栏同屏）：
  左栏: /orders（列表）
  中栏: /orders/SO00100（详情）
  右栏: /orders/SO00100/payments/PAY001（子详情）
  ← 窄屏退化为单栏，通过返回按钮回到上级
```

### 3.2 页面布局层级

```
┌─────────────────────────────────────────────────────────┐

├──────────┬──────────────────────────────────────────────┤
│ 左侧     │  Breadcrumb（面包屑：当前位置路径）      [固定] │
│ 导航     ├──────────────────────────────────────────────┤
│ 对象     │                                              │
│ 菜单     │           页面内容区                          │

│          │                                              │
│          │                                              │
└──────────┴──────────────────────────────────────────────┘
```

### 3.3 页面类型与布局

| 页面类型 | 布局结构 | 跳转关系 |
|---|---|---|
| **Home Page** | 3列：左组件栏 + 中主内容 + 右组件栏 | 组件链接→对应对象 |
| **App Launcher** | 宫格：应用卡片网格 | 点击应用→对应 App Home |
| **List View** | 顶栏 + 筛选 + 表格/Kanban 切换 | 点击行→Record Page |
| **Record Page** | 3列：左 Highlights + 中详情+Related Lists + 右组件栏 | Related List "View All"→独立 List View；Path→阶段操作 |
| **Dashboard** | 网格：Report Chart 组件布局 | 点击图表→Report |
| **Report** | 顶栏 + 筛选 + 分组表格 | 点击记录行→Record Page |

### 3.4 Record Page 的三列布局（Salesforce 的标志性架构）

```
┌─────────────────────────────────────────────────────┐
│ Breadcrumb: Accounts > Siemens AG            [固定] │
├──────────┬─────────────────────┬───────────────────┤
│          │  Highlights Panel    │                   │
│  左列     │  (对象名+4-6关键字段) │   右列             │
│  (组件)  │  Path(阶段进度)      │  (AI建议/提醒/    │
│          ├─────────────────────┤   组件)            │
│  · 活动  │  中列(主内容)        │                   │
│  · 详情  │  · Detail 字段分区   │  · Einstein 建议  │
│  · 相关  │  · Related List 1   │  · 关键提醒       │
│    列表  │  · Related List 2   │  · 自定义组件     │
│  · 自定义│  · Activity Timeline │                   │
│    组件  │                     │                   │
└──────────┴─────────────────────┴───────────────────┘
  [可拖拽调整列宽和组件位置，按角色/记录类型动态配置]
```

### 3.5 路由与上下文保持

```
App Launcher → Sales App → Accounts List View
  → Account Record Page（URL: /lightning/r/Account/001/view）
      → Related List "View All" → Orders List View（筛选: Account=Siemens）
      ← 返回 Account Record Page（Tab 状态保持）
  → Dashboard → 点击图表 → Report → 点击记录 → Record Page
  ← 返回 Dashboard（筛选保持）

多 Tab 并行：用户可同时打开多个 Record Page，Tab 之间切换不丢状态
```

## 七、页面跳转路由的六种模式

### 7.1 跳转模式清单

| 跳转模式 | 说明 | 适用场景 | 标杆实践 |
|---|---|---|---|
| **全页跳转** | 当前页完全替换为目标页 | 主流程推进 | Ant Design Pro 路由跳转 |
| **多标签打开** | 新 Tab 中打开目标页，当前页保持 | 并行处理多个对象 | 金蝶/Ant Design 多标签 |
| **三栏展开** | 右侧展开子详情，列表和详情都保持 | 对象链路追踪 | SAP Flexible Column Layout |
| **抽屉覆盖** | 右侧抽屉滑出，背景页保持 | 列表内快速编辑 | Ant Design DrawerForm |
| **弹窗确认** | 模态弹窗，背景页阻断 | 高风险确认 | 所有系统通用 |
| **内联展开** | 当前行下方展开详情，不跳转 | 快速预览 | SAP 表格行展开 |

### 7.2 跳转模式的选择规则

```
用户目标是什么？
├── 查看完整详情 → 全页跳转 或 三栏展开
├── 快速预览 → 内联展开
├── 快速编辑少量字段 → 抽屉覆盖
├── 确认高风险操作 → 弹窗确认
├── 追踪对象链路 → 三栏展开
└── 并行处理多对象 → 多标签打开
```

### 7.3 上下文保持规则

| 跳转模式 | 筛选条件 | 排序状态 | 滚动位置 | 选中状态 |
|---|---|---|---|---|
| 全页跳转 → 返回 | 保持 | 保持 | 保持 | 保持 |
| 多标签打开 | 各Tab独立 | 各Tab独立 | 各Tab独立 | 各Tab独立 |
| 三栏展开 | 左栏保持 | 左栏保持 | 左栏保持 | 左栏保持 |
| 抽屉关闭 | 保持 | 保持 | 保持 | 保持 |
| 弹窗关闭 | 保持 | 保持 | 保持 | 保持 |

## 八、信息架构设计模板

### 8.1 从角色推导信息架构

```
步骤 1：列出所有角色
  店长 / 收银员 / 财务 / 客服 / 仓库 / 运营 / 管理员

步骤 2：列出每个角色的核心任务
  店长：看经营概况 → 处理异常 → 审批
  收银员：处理订单 → 收款 → 退款
  财务：对账 → 凭证 → 报表
  客服：处理工单 → 查客户 → 退款审核

步骤 3：为每个角色设计首页
  店长首页：Dashboard（KPI+异常+待办）
  收银员首页：Worklist（待处理订单队列）
  财务首页：Worklist（待对账+待审核凭证）
  客服首页：Worklist（待处理工单队列）

步骤 4：从首页推导导航目录
  店长：首页/销售分析/门店管理/库存监控/异常中心/报表
  收银员：首页/订单管理/退款管理/会员查询

  客服：首页/工单管理/客户360/退款审核

步骤 5：从任务推导页面类型
  "看经营概况" → Dashboard
  "处理异常" → Exception Center
  "审批" → Worklist → Object Page
  "对账" → Reconciliation Workbench
  "查客户" → Customer 360
```

### 8.2 信息架构验证清单

- [ ] 每个角色有专属首页

- [ ] 从首页到任意页面 ≤ 3 次点击
- [ ] 每个页面有面包屑
- [ ] 页面跳转后返回，筛选/排序/滚动保持
- [ ] 高频页面支持多标签并行
- [ ] 列表→详情→返回 闭环通畅
- [ ] 钻取链路（指标→明细→对象）每层可返回
- [ ] 异常页面有明确的"下一步"入口
- [ ] 空状态有引导入口

## 九、布局区域设计规范

### 9.1 固定区域 vs 动态区域

| 区域 | 是否固定 | 说明 |
|---|---|---|
| 全局顶栏 | 固定 | 始终可见，不随页面滚动 |
| 左侧导航 | 固定 | 始终可见，可折叠 |
| 面包屑 | 固定 | 始终可见，不随页面滚动 |
| 页面标题+操作 | 固定 | 始终可见，不随页面滚动 |
| 筛选区 | 半固定 | 可折叠，折叠后不占空间 |
| 内容区 | 动态 | 随页面滚动 |
| 底部命令栏 | 固定 | 始终可见（金蝶特色） |
| 多标签栏 | 固定 | 始终可见 |

### 9.2 页面分区优先级

```
视觉优先级从上到下：
  1. 页面标题 + 主操作（最优先看到）
  2. 对象头部 / 筛选区（第二优先）
  3. 主内容区（核心数据）
  4. 关联列表 / 补充信息
  5. 操作日志 / 审计信息（最后）

空间分配建议：
  标题+操作：8-12%
  筛选/头部：12-18%
  主内容区：50-60%
  关联/补充：15-20%
  日志/审计：5-10%
```

### 9.3 响应式布局退化规则

| 屏幕宽度 | 布局变化 |
|---|---|
| >1280px（宽屏） | 三栏并列（列表+详情+子详情） |
| 1024-1280px（标准） | 两栏并列（列表+详情） |
| 768-1024px（窄屏） | 单栏 + 侧边导航折叠 |
| <768px（移动端） | 单栏 + 底部导航 + 页面跳转替代三栏 |

## 十、总结：高阶页面架构的设计公式

```
高阶页面架构 = 角色入口设计 + 信息架构层级 + 页面布局分区 + 跳转路由模式 + 上下文保持策略

角色入口设计：不同角色不同首页（Dashboard/Worklist）
信息架构层级：Launchpad/App → 目录 → 对象列表 → 对象详情（≤3层）
页面布局分区：顶栏[固定] + 左导航[固定] + 面包屑[固定] + 标题[固定] + 内容区[动态]
跳转路由模式：全页跳转/多标签/三栏展开/抽屉/弹窗/内联（按任务选择）
上下文保持策略：筛选/排序/滚动/选中 在跳转返回后保持

一句话：高阶页面架构不是"画页面"，而是"设计用户在系统中的移动路径和停留状态"。
```
