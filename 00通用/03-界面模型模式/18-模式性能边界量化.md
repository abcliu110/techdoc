# 方向 5：模式性能与大数据量边界量化

> 目标：为 25 个核心模式每个都定义在数据量、网络条件、渲染性能和感知性能上的量化阈值。
> 理论基线：[`13-界面模型深层逻辑与模式体系.md`](13-界面模型深层逻辑与模式体系.md) §10.1（控制回路与反馈延迟）、§6（表单反馈）、§3.4（数据新鲜度）。
> 依赖：[`14a-模式形式化规约.md`](14a-模式形式化规约.md) 的 `invariants.PERF-1`。

## 0. 为什么需要性能边界量化

现有文档只给了定性方向："大数据量用虚拟列表""进度条要可信""关联列表默认分页"。但没有回答多大数据量才需要虚拟滚动、关联列表何时并行加载、进度条何时切换为阶段描述、窄屏如何退化。没有量化阈值，性能优化全靠经验，设计审查无法对照检查。

## 1. 性能维度

每个模式的性能边界从五个维度量化：

| 维度 | 含义 | 关键指标 |
|---|---|---|
| dataVolume | 数据量边界 | 行/条/个数的分级策略 |
| networkProfile | 网络条件边界 | RTT、带宽、超时、重试 |
| renderBudget | 渲染性能预算 | FCP、TTI、DOM节点数、内存 |
| perceivedPerf | 感知性能契约 | 即时/快速/可感知/可容忍/沮丧 |
| degradation | 降级策略 | 触发条件和应对动作 |

### 1.1 数据量分级

| 级别 | 范围 | 策略 |
|---|---|---|
| small | <100 | 全量渲染 |
| medium | 100-1000 | 分页渲染，每页50 |
| large | 1000-10000 | 虚拟滚动 + 按需加载 |
| veryLarge | >10000 | 服务端筛选 + 游标分页 + 虚拟滚动 |

### 1.2 网络条件分级

| 级别 | RTT | 带宽 | 期望 |
|---|---|---|---|
| fast | <50ms | >10Mbps | 即时响应 |
| normal | 50-200ms | 1-10Mbps | 500ms内首屏 |
| slow | 200-1000ms | 0.1-1Mbps | 骨架屏+渐进加载 |
| offline | ∞ | 0 | 离线缓存+队列重试 |

### 1.3 感知性能分级

| 级别 | 延迟 | 用户感受 | 设计要求 |
|---|---|---|---|
| instant | <100ms | 即时 | 无需反馈 |
| fast | <300ms | 快速 | 无需反馈 |
| perceptible | <1s | 轻微延迟 | 局部loading |
| tolerable | <3s | 需要等待 | loading指示器 |
| frustrating | <10s | 需要进度 | 进度条+预计时间 |
| unacceptable | >10s | 无法等待 | 后台任务+异步通知 |

### 1.4 渲染预算

| 指标 | 目标 | 可接受 | 危险 |
|---|---|---|---|
| FP | <1s | <3s | >3s |
| FCP | <1.5s | <4s | >4s |
| TTI | <3s | <5s | >5s |
| DOM节点数 | <1500 | 1500-5000 | >5000 |
| 内存 | <50MB | 50-150MB | >150MB |

## 2. 25 个模式的性能边界

### 2.1 List Report

| 维度 | 阈值 |
|---|---|
| 行数 <100 | 全量渲染，DOM <700 |
| 行数 100-1000 | 分页50/页，DOM <700 |
| 行数 1000-10000 | 虚拟滚动，DOM <200 |
| 行数 >10000 | 服务端筛选+游标分页+虚拟滚动 |
| 筛选防抖 | 300ms |
| 排序 | <1000行客户端排序，>1000行服务端排序 |
| 查询超时 | 10s |
| 重试 | 指数退避，最多3次 |
| 批量选中响应 | <50ms/行 |
| 导出 | 小量即时，大量后台任务+通知 |
| 降级 | 查询>3s切换为后台任务 |

### 2.2 Object Page

| 维度 | 阈值 |
|---|---|
| 关联列表 ≤5 | 并行加载，超时3s |
| 关联列表 5-10 | 主区并行+关联按需，超时5s |
| 关联列表 >10 | Tab切换按需加载，3s/tab |
| 时间线事件 ≤50 | 全量渲染 |
| 时间线事件 50-500 | 分页50条/次 |
| 时间线事件 >500 | 虚拟滚动+日期折叠 |
| 头部加载 | <500ms |
| 首屏（头部+主分区） | <1.5s |
| 完整加载 | <3s |
| 分区切换 | <100ms |
| 关联骨架屏 | 关联未加载时显示 |
| 降级 | 主区>3s未加载→骨架屏+超时重试 |

### 2.3 Master-Detail

| 维度 | 阈值 |
|---|---|
| 主列行数 <500 | 全量+客户端筛选 |
| 主列行数 500-5000 | 分页+虚拟滚动 |
| 主列行数 >5000 | 服务端筛选+虚拟滚动 |
| 选中到详情加载 | <300ms |
| 行高亮切换 | <50ms |
| 键盘导航延迟 | <16ms |
| 窄屏(<768px) | 退化为页面跳转，保留返回上下文 |
| 详情加载>500ms | 详情区骨架屏 |
| 切换选中 | 取消未完成的详情请求（staleDetailGuard） |

### 2.4 Dashboard

| 维度 | 阈值 |
|---|---|
| KPI卡片数 | ≤6（超过认知过载） |
| 图表数据点 <100 | 全量渲染 |
| 图表数据点 100-1000 | 降采样+聚合 |
| 图表数据点 >1000 | 服务端聚合+按需展开 |
| 钻取深度 | ≤4层（超过用户迷失） |
| KPI并行请求 | ≤5 |
| 首个KPI渲染 | <1s |
| 图表渲染 | <500ms/chart |
| 完整可交互 | <3s |
| 数据新鲜度 | 展示最后更新时间，>5分钟标记可能过期 |
| 数据过期 | FRESH-1不变量：必须展示截止时间和来源 |

### 2.5 Worklist

| 维度 | 阈值 |
|---|---|
| 任务数 <50 | 全量渲染 |
| 任务数 50-200 | 分页+按优先级排序 |
| 任务数 >200 | 虚拟滚动+WIP限制+分批领取 |
| WIP限制 | 每人同时处理 ≤5（防止任务停滞） |
| 老化刷新 | 每60s刷新老化时间 |
| 认领响应 | <200ms |
| SLA超时预警 | 提前20%时间预警 |
| 降级 | 任务>200→WIP限制+Pull Next |

### 2.6 Wizard

| 维度 | 阈值 |
|---|---|
| 步骤数 | ≤7（超过认知过载） |
| 每步字段数 | ≤10 |
| 步骤切换 | <200ms |
| 草稿自动保存 | 每30s或字段变更后5s |
| 草稿保存超时 | 3s，失败时保留本地+显著提示 |
| 步骤校验 | <500ms |
| 降级 | 草稿保存失败→本地存储+提示 |

### 2.7 Sectioned Form

| 维度 | 阈值 |
|---|---|
| 总字段数 | ≤40（超过考虑拆为Wizard） |
| 分区数 | 4-6 |
| 每区分段数 | 8-10 |
| 锚点导航响应 | <100ms |
| 字段校验防抖 | 500ms |
| 提交前预检 | <1s |
| 降级 | 字段>40→考虑Wizard或分步保存 |

### 2.8 Timeline

| 维度 | 阈值 |
|---|---|
| 事件 ≤50 | 全量渲染 |
| 事件 50-500 | 分页50条/次 |
| 事件 >500 | 虚拟滚动+日期折叠 |
| 事件渲染 | <16ms/条 |
| 滚动加载 | 触底前200px触发预加载 |
| 降级 | >500条→虚拟滚动 |

### 2.9 Exception Center

| 维度 | 阈值 |
|---|---|
| 异常数 <50 | 全量渲染 |
| 异常 50-500 | 按严重程度分Tab+分页 |
| 异常 >500 | 聚合同类异常+分页 |
| 聚合规则 | 同接口+同错误码+同时间段聚为一条 |
| 新异常推送 | 实时（WebSocket或轮询30s） |
| 高严重异常通知 | assertive aria-live |

### 2.10 Drill-down Report

| 维度 | 阈值 |
|---|---|
| 钻取深度 | ≤4层 |
| 每层数据点 <100 | 全量渲染 |
| 每层 100-1000 | 降采样 |
| 每层 >1000 | 服务端聚合 |
| 下钻响应 | <500ms |
| 返回上级 | <200ms（保留上下文） |
| 明细导出 | 小量即时，大量后台任务 |

### 2.11 Background Task Center

| 维度 | 阈值 |
|---|---|
| 任务耗时 <3s | 前台等待+loading |
| 任务耗时 3-10s | 前台等待+进度条 |
| 任务耗时 >10s | 后台任务+完成通知 |
| 进度条规则 | 有可靠总量→百分比；否则→阶段+已处理数+更新时间 |
| 进度更新频率 | 每1s或每1% |
| 进度回退 | 禁止（PROG-1不变量） |
| 失败重试 | 幂等语义配套（IDEM-1） |
| 通知 | 页面不打开时系统通知 |

### 2.12 Reconciliation Workbench

| 维度 | 阈值 |
|---|---|
| 对账行 <1000 | 全量同屏 |
| 对账行 1000-10000 | 差异行优先+一致行折叠 |
| 对账行 >10000 | 服务端比对+只展示差异 |
| 比对超时 | 30s |
| 差异行高亮 | <16ms/行 |
| 日结校验 | <3s（全部差异已处理或有受控挂账） |

### 2.13 Permission Matrix

| 维度 | 阈值 |
|---|---|
| 角色 × 权限 <500格 | 全量渲染 |
| 500-5000格 | 虚拟滚动+行列冻结 |
| >5000格 | 分组+搜索+虚拟滚动 |
| 单元格切换响应 | <100ms |
| 影响预览计算 | <2s |
| 批量变更 | <3s |

### 2.14 Config Page

| 维度 | 阈值 |
|---|---|
| 配置项 <20 | 单页全量 |
| 配置项 20-50 | 分区+锚点 |
| 配置项 >50 | Wizard或搜索+分组 |
| 影响预览计算 | <2s |
| 模拟运行 | <5s |
| 版本回滚 | <1s |

### 2.15 Customer 360

| 维度 | 阈值 |
|---|---|
| 渠道区块 | ≤5（超过认知过载） |
| 时间线事件 | 同Timeline |
| 标签数 | ≤10展示，更多折叠 |
| 推荐计算 | <1s |
| 身份解析 | <500ms |
| 降级 | 渠道数据未加载→骨架屏+不阻塞主区 |

### 2.16 其余模式的性能要点

| 模式 | 关键性能阈值 |
|---|---|
| Simple Form | 字段≤5，提交<500ms |
| Drawer Form | 打开<200ms，保存<500ms |
| Modal Form | 打开<100ms，确认<500ms |
| Inline Edit | 进入编辑<50ms，保存<300ms |
| Related Lists | 每列表≤5条默认展示，更多跳转独立页 |
| View Management | 视图切换<200ms |
| Audit Log | 同List Report，但只读 |
| Comparison View | 对比对象≤5，同屏对齐 |
| Analytical List Page | 图表+明细同筛选，下钻<500ms |

## 3. 降级策略矩阵

### 3.1 数据量降级

| 触发条件 | 降级动作 | 适用模式 |
|---|---|---|
| 行数>1000 | 虚拟滚动 | List Report, Data Grid, Audit Log |
| 行数>10000 | 服务端筛选+游标分页 | List Report, Worklist |
| 关联>10 | Tab按需加载 | Object Page |
| 事件>500 | 虚拟滚动+日期折叠 | Timeline |
| 异常>500 | 聚合同类+分页 | Exception Center |
| 对账行>10000 | 服务端比对+只展示差异 | Reconciliation |
| 矩阵格>5000 | 分组+搜索+虚拟滚动 | Permission Matrix |

### 3.2 网络降级

| 触发条件 | 降级动作 |
|---|---|
| RTT>500ms | 骨架屏+渐进加载 |
| 查询>3s | 后台任务化+完成通知 |
| 查询>10s | 超时+重试+指数退避 |
| 离线 | 离线队列+重试+冲突检测 |
| 并发请求>5 | 队列+优先级调度 |

### 3.3 设备降级

| 触发条件 | 降级动作 |
|---|---|
| 窄屏(<768px) | Master-Detail退化为跳转；Dashboard单列 |
| 低内存(<100MB) | 卸载不可见DOM+按需重建 |
| 低性能设备 | 减少动画+降采样图表 |
| 触屏设备 | 放大触摸目标(≥44px)+移除hover依赖 |

## 4. 感知性能契约

### 4.1 操作响应契约

| 操作类型 | 目标响应 | 超出时处理 |
|---|---|---|
| 行选中 | <50ms | — |
| 筛选提交 | <300ms | loading spinner |
| 分页切换 | <200ms | 骨架屏 |
| 步骤切换 | <200ms | 局部loading |
| 字段校验 | <500ms（防抖后） | 校验中提示 |
| 详情加载 | <300ms | 骨架屏 |
| 钻取下钻 | <500ms | loading |
| 导出 | 小量即时，大量后台 | 进度+通知 |

### 4.2 进度展示契约（PROG-1不变量细化）

| 任务耗时 | 展示方式 | 要求 |
|---|---|---|
| <100ms | 无需展示 | — |
| 100ms-1s | 局部loading | 不阻塞其他操作 |
| 1-3s | loading spinner+文字 | 说明正在做什么 |
| 3-10s | 进度条（有总量时百分比） | 每1s或1%更新 |
| >10s | 后台任务+完成通知 | 提供取消入口 |
| 无可靠总量 | 阶段+已处理数+更新时间 | 禁止伪精确百分比 |
| 进度回退 | 禁止 | 如必须，说明原因 |

### 4.3 数据新鲜度契约（FRESH-1细化）

| 数据延迟 | 展示方式 |
|---|---|
| <1min | 不标注 |
| 1-5min | 标注"X分钟前更新" |
| 5-30min | 标注+黄色提示"数据可能过期" |
| >30min | 标注+红色提示"数据已过期，建议刷新" |
| 来源不可用 | 标注"数据源不可用"+降级展示 |

## 6. 与其他方向的关系

- **方向 1**：性能契约作为方向 1 规约的 `perfContract` 属性，`PERF-1` 到 `PERF-5` 写入不变量规则库。
- **方向 4**：虚拟滚动的焦点管理需遵循可访问性契约。
- **方向 7**：性能测试作为实证验证的必检项。
- **方向 8**：行业场景（如海量库存台账）的性能要求作为行业约束补充。
