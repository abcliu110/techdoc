# 方向 8：行业不变量到 UI 约束的映射

> 目标：把行业不变量（如借贷必平、库存非负、职责分离）转成可执行的 UI 校验规则，让行业模式从"描述"升级为"约束"。
> 理论基线：[`13-界面模型深层逻辑与模式体系.md`](13-界面模型深层逻辑与模式体系.md) §9.5（商业完整性与职责分离）、§10.4（Saga）、§3.3（能力模型）。
> 与现有文档关系：本文档是 `10-行业业务专用UI模型.md` 的约束化升级。

## 0. 为什么需要行业不变量映射

现有 `10-行业业务专用UI模型.md` 列了行业模式（Inventory Board、Scheduling Board、POS Console、Financial Voucher、Map Operations），但只描述了"是什么"，没有提炼"行业不变量 → UI 约束"的推导规则。

这导致行业模式无法校验、行业差异不透明、跨行业复用困难。行业不变量映射的目标是让每个行业硬约束变成可在 UI 层校验的规则。

## 1. 不变量模型

### 1.1 不变量定义格式

```yaml
invariant:
  id: "INV-FIN-001"
  industry: "财务"
  name: "借贷必平"
  description: "每笔凭证的借方金额合计必须等于贷方金额合计"
  formula: "sum(debit) = sum(credit)"
  severity: "error"  # error=阻止提交; warning=提示不阻止
  regulatoryBasis: "会计法基本等式"
  uiConstraint:
    checkTiming: "onSubmit"
    checkLocation: "Financial Voucher 页面"
    passAction: "允许提交"
    failAction: "阻止提交 + 高亮不平衡行 + 显示差额"
    recoveryAction: "提示用户调整借贷方金额"
```

### 1.2 不变量分类

| 类别 | 不变量类型 | 检查时机 | 阻断级别 |
|---|---|---|---|
| 数值守恒 | 借贷必平、金额守恒 | onSubmit | error |
| 非负约束 | 库存≥0、余额≥0 | onSubmit + onPreview | error |
| 唯一性 | 单据号唯一、编码唯一 | onChange + onSubmit | error |
| 时序约束 | 生效日期≤失效日期 | onSubmit | error |
| 职责分离 | 创建≠审批、制单≠付款 | onAssign + onSubmit | error |
| 数据范围 | 只能操作本数据范围 | onLoad + onAction | error |
| 合规约束 | 删除权、留存期、脱敏 | onExport + onDelete | error |
| 业务规则 | 阈值、额度、SLA | onSubmit | error/warning |

## 2. 财务行业不变量

### 2.1 借贷必平（INV-FIN-001）

- **公式**：`sum(debit) = sum(credit)`
- **实时校验**：每行变更后显示借方合计、贷方合计、差额；差额=0显示✓平衡
- **提交校验**：不平衡时阻止提交+聚焦到第一个不平衡行
- **日结校验**：阻止日结+列出所有不平衡凭证
- **适用模式**：Financial Voucher, Reconciliation Workbench
- **理论依据**：§9.5 商业完整性

### 2.2 凭证不可篡改（INV-FIN-002）

- **公式**：已过账凭证不可直接修改，必须通过红字冲销
- **编辑校验**：草稿状态允许编辑；已过账阻止编辑+提示创建红字冲销
- **删除校验**：已过账阻止删除
- **适用模式**：Financial Voucher, Audit Log

### 2.3 期间状态约束（INV-FIN-003）

- **公式**：已结账期间的凭证不可修改
- **编辑校验**：凭证期间=已结账时阻止编辑+提示需先反结账
- **结账校验**：当期所有凭证已过账才允许结账

### 2.4 币种汇率一致性（INV-FIN-004）

- **公式**：`外币金额 × 汇率 = 本币金额`
- **实时校验**：本币金额自动计算，不可手动覆盖（除非启用允许差异）
- **容差**：±0.01（四舍五入差异）
- **失败处理**：差异超出容差时高亮提示

## 3. 库存行业不变量

### 3.1 可用量非负（INV-INV-001）

- **公式**：`可用量 = 现有量 - 预占量 ≥ 0`
- **提交校验**：出库/预订时检查可用量；不足时阻止出库+显示当前可用量
- **预览校验**：批量出库影响预览中高亮库存不足的行
- **部分允许**：阻止库存不足的行，允许其余行
- **适用模式**：Inventory Board, List Report, Impact Preview

### 3.2 两阶段预占-确认（INV-INV-002）

- **公式**：库存扣减必须经过"预占→确认"两阶段，不允许直接扣减
- **动作校验**：直接扣减被阻止+提示需先预占再确认
- **确认校验**：预占存在且有效才允许确认
- **Saga补偿**：
  - 预占后超时未确认→释放预占
  - 确认后退款→反向增加库存

### 3.3 批次/效期追溯（INV-INV-003）

- **公式**：有批次管理的商品必须记录批次号；有效期管理的商品出库必须遵循FEFO
- **提交校验**：批次管理商品未指定批次号时阻止出库
- **建议排序**：按FEFO（先到期先出）排序建议批次

### 3.4 库存盘点差异闭环（INV-INV-004）

- **公式**：盘点差异必须经过"记录→审批→调整"闭环
- **提交校验**：不允许直接修改库存+提示需通过盘点差异单
- **审批校验**：差异审批通过后才生成库存调整凭证

## 4. 权限与治理行业不变量

### 4.1 职责分离（INV-GOV-001）

- **公式**：`创建者 ≠ 审批者；制单者 ≠ 付款者`
- **分配校验**：审批人=创建人时阻止分配+提示不能自批
- **提交校验**：当前用户=创建人时阻止审批提交
- **配置校验**：高风险操作的创建和审批权限分配给同一角色时警告
- **适用模式**：Permission Matrix, Worklist, Maker-Checker

### 4.2 数据范围控制（INV-GOV-002）

- **公式**：用户只能查看和操作其数据范围内的对象
- **加载校验**：列表查询自动附加数据范围过滤
- **操作校验**：对象不在数据范围时阻止操作+提示无权
- **导出校验**：只导出数据范围内对象

### 4.3 紧急访问限时（INV-GOV-003）

- **公式**：Break-glass 访问必须限时、限范围、强理由、显著标识、事后复核
- **激活校验**：必须填写理由、范围、预计时长
- **激活效果**：显著标识（红色横幅）+通知监督者
- **超时处理**：自动回收权限+生成复核任务
- **事后复核**：操作日志送审

## 5. 合规行业不变量

### 5.1 数据删除权（INV-COM-001）

- **公式**：GDPR删除请求必须在30天内处理；删除后数据不可恢复（除非法律要求留存）
- **请求校验**：创建删除任务+SLA 30天+通知数据主体
- **执行校验**：
  - 法律留存检查（财务凭证留存10年）
  - 关联数据处理（订单中客户信息脱敏而非删除）
  - 备份策略检查
- **失败处理**：存在法律留存要求时改为脱敏处理

### 5.2 敏感数据脱敏（INV-COM-002）

- **公式**：敏感数据展示时必须脱敏
- **展示规则**：
  - 身份证：前6后4，中间*
  - 手机号：前3后4，中间*
  - 银行卡：前4后4，中间*
  - 邮箱：前2后@域名，中间*
- **例外**：有完整查看权限的角色可点击查看，但记录审计
- **导出规则**：默认脱敏导出；完整导出需审批

### 5.3 数据留存期限（INV-COM-003）

- **公式**：不同数据类型留存期限不同
- **留存规则**：
  - 财务凭证：10年，到期归档
  - 操作日志：3年，到期删除
  - 营销数据：1年，到期删除
  - 客户数据：关系存续期+1年，到期脱敏
- **定期检查**：超期未处理生成清理任务

## 6. 不变量校验引擎

### 6.1 校验流程

```
用户操作（编辑/提交/导出/删除）
  ↓
不变量匹配：查找当前页面和操作类型对应的不变量
  ↓
不变量校验：逐条计算 formula
  ↓
结果处理：pass→放行; fail→阻止; warn→提示
  ↓
反馈与恢复：高亮问题+显示差额+提供恢复路径+记录审计
```

### 6.2 校验报告格式

```yaml
invariantReport:
  page: "凭证录入页"
  operation: "onSubmit"
  results:
    - id: "INV-FIN-001"
      name: "借贷必平"
      status: "fail"
      detail: "借方合计 ¥1,280 ≠ 贷方合计 ¥1,250，差额 ¥30"
      severity: "error"
      fixHint: "请检查第3行贷方金额"
    - id: "INV-FIN-004"
      name: "币种汇率一致性"
      status: "pass"
    - id: "INV-FIN-002"
      name: "凭证不可篡改"
      status: "pass"
      note: "凭证为草稿状态，允许编辑"
```

## 7. 行业不变量到模式的映射矩阵

| 不变量 | 主要约束模式 | 约束内容 |
|---|---|---|
| 借贷必平 | Financial Voucher, Reconciliation | 实时合计+阻止不平衡提交+日结门禁 |
| 凭证不可篡改 | Financial Voucher, Audit Log | 已过账阻止编辑+红字冲销路径 |
| 期间状态 | Financial Voucher | 已结账期间阻止编辑 |
| 币种汇率 | Financial Voucher | 自动计算+容差检查 |
| 可用量非负 | Inventory Board, List Report, Impact Preview | 预占检查+阻止超卖 |
| 两阶段预占 | Inventory Board | 禁止直接扣减+预占-确认流程+Saga补偿 |
| 批次效期 | Inventory Board | 批次必填+FEFO排序 |
| 盘点闭环 | Inventory Board | 差异审批+禁止直接改库存 |
| 职责分离 | Permission Matrix, Worklist, Maker-Checker | 禁止自批+角色互斥检测 |
| 数据范围 | 所有列表和详情模式 | 自动过滤+越权阻止 |
| 紧急访问 | Permission Matrix | 限时+强理由+显著标识+事后复核 |
| 删除权 | Customer 360, Audit Log | SLA+留存检查+脱敏替代 |
| 敏感脱敏 | Customer 360, List Report | 展示脱敏+导出审批 |
| 留存期限 | Audit Log | 按类型定期清理+归档 |

## 8. 跨行业不变量冲突检测

不同行业的不变量可能冲突，需要检测：

| 冲突场景 | 不变量A | 不变量B | 冲突 | 解决 |
|---|---|---|---|---|
| 客户删除 vs 财务留存 | 删除权（删除客户数据） | 凭证留存（10年） | 删除客户会破坏凭证完整性 | 脱敏替代删除，保留财务关联 |
| 库存预占 vs 退款即时 | 预占-确认两阶段 | 退款即时到账 | 退款需立即释放库存但预占未确认 | 退款触发预占自动释放补偿 |
| 数据范围 vs 跨店调拨 | 只操作本店数据 | 跨店调拨需查看他店库存 | 调拨时需临时扩展数据范围 | 临时授权+审计记录 |
| 职责分离 vs 紧急访问 | 禁止自批 | Break-glass单人操作 | 紧急时同一人需完成全流程 | 紧急访问豁免+事后强制复核 |

## 9. 与其他方向的关系

- **方向 1**：行业不变量作为规约的 `industryInvariants` 属性，参与不变量校验。
- **方向 3**：行业不变量作为状态机的 `invariant`，参与缺陷检测。
- **方向 6**：Agent-Native 模式自主执行时必须遵守行业不变量护栏。
- **方向 7**：行业不变量映射作为反例检测的约束来源。
