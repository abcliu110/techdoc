# 方向 4：模式可访问性契约层

> 目标：为 25 个核心模式每个都定义 ARIA 语义、键盘交互、屏幕阅读器宣告和颜色独立契约，让可访问性从"事后补丁"变成"模式内置"。
> 理论基线：[`13-界面模型深层逻辑与模式体系.md`](13-界面模型深层逻辑与模式体系.md) §14.3（局部启发式边界）、§14.2（包容性与等价交互）。
> 参考：W3C WAI-ARIA 1.2、ARIA APG、WCAG 2.2。

## 0. 为什么需要可访问性契约

现有文档在 §14.3 提到"可访问性不是事后补丁"，但 **25 个模式没有一个带 ARIA 契约**。这导致组件库实现时可访问性全靠开发者自觉，设计审查时没有可对照的检查清单，自动化测试时无法从模式定义生成测试用例。

可访问性契约的目标是让每个模式拥有与 WAI-ARIA APG 对齐的语义结构、键盘契约和宣告模板。

## 1. 契约的五层结构

```yaml
a11yContract:
  semanticStructure:    # ARIA role 和 landmark
  keyboardContract:     # 按键交互
  screenReader:         # 宣告模板
  colorIndependence:    # 非颜色编码方案
  wcagMapping:          # WCAG 准则映射
```

## 3. 重点模式详细契约

### 3.1 List Report 可访问性契约

```yaml
semanticStructure:
  root: { role: "region", ariaLabel: "订单列表" }
  filterRegion: { role: "search", ariaLabel: "筛选条件" }
  bulkActionBar: { role: "toolbar", ariaLabel: "批量操作", visibleWhen: "selectedCount > 0" }
  dataTable: { role: "grid", ariaLabel: "订单列表", ariaRowCount: "dynamic" }
  pagination: { role: "navigation", ariaLabel: "分页" }

keyboardContract:
  globalShortcuts:
    - { key: "Ctrl+F", action: "focusFilterRegion" }
    - { key: "Escape", action: "clearSelection", condition: "bulkSelected" }
  gridNavigation:
    - { key: "ArrowDown", action: "moveFocusToNextRow" }
    - { key: "ArrowUp", action: "moveFocusToPreviousRow" }
    - { key: "ArrowRight", action: "moveFocusToNextCell" }
    - { key: "ArrowLeft", action: "moveFocusToPreviousCell" }
    - { key: "Enter", action: "openObjectDetail" }
    - { key: "Space", action: "toggleRowSelection", condition: "checkboxColumn present" }
    - { key: "Home", action: "moveFocusToFirstRow" }
    - { key: "End", action: "moveFocusToLastRow" }
    - { key: "PageDown", action: "nextPage" }
    - { key: "PageUp", action: "previousPage" }
  focusManagement:
    - { trigger: "querySubmitted", action: "moveFocusToFirstRow" }
    - { trigger: "rowSelected", action: "preserveFocusOnSelectedRow" }
    - { trigger: "modalClosed", action: "returnFocusToTriggeringElement" }

screenReader:
  announcements:
    - { trigger: "queryLoading", announce: "正在查询...", politeness: "polite" }
    - { trigger: "querySuccess", announce: "查询完成，共 {rowCount} 条结果", politeness: "polite" }
    - { trigger: "queryFailure", announce: "查询失败：{errorMessage}。按 Enter 重试", politeness: "assertive" }
    - { trigger: "rowSelected", announce: "已选中 {selectedCount} 项", politeness: "polite" }
    - { trigger: "bulkActionComplete", announce: "{actionName}完成，成功 {successCount} 项，失败 {failCount} 项", politeness: "assertive" }
  statusBadgeTemplate: "{objectName}，{statusText}，{statusIcon}，{coreMetric}"

colorIndependence:
  statusEncoding: "状态必须同时使用文本+图标+颜色三者表达"
  riskEncoding: "风险级别必须用图标+文本+颜色表达，不只靠红色"
  focusIndicator: "2px 实线 outline，对比度 ≥ 3:1"

wcagMapping:
  - { criterion: "1.3.1 Info and Relationships (A)", testMethod: "axe-core" }
  - { criterion: "1.4.1 Use of Color (A)", testMethod: "截图分析+人工审查" }
  - { criterion: "2.1.1 Keyboard (A)", testMethod: "键盘遍历测试" }
  - { criterion: "4.1.2 Name, Role, Value (A)", testMethod: "axe-core" }
  - { criterion: "4.1.3 Status Messages (AA)", testMethod: "屏幕阅读器测试" }
```

## 4. 通用键盘契约原则

### 4.1 区域间导航

```
页面顶部
  ↓ Tab
筛选区 (role=search)
  ↓ Tab
工具栏 (role=toolbar)
  ↓ Tab
数据网格 (role=grid)
  ↓ Tab
分页导航 (role=navigation)
```

- `Tab` 在区域间移动。
- 区域内部用方向键导航，不消耗 `Tab`。
- `Shift+Tab` 反向导航。

### 4.2 模态容器焦点陷阱

`Modal Form` 和 `Drawer Form` 打开时：

1. 焦点移到容器的第一个可聚焦元素。
2. `Tab` 在容器内循环，不逃逸到背景。
3. `Escape` 关闭容器（若允许取消）。
4. 关闭后焦点返回触发元素。

### 4.3 虚拟滚动焦点管理

当 List Report 行数 > 1000 启用虚拟滚动时：

- 焦点行保持可见（滚动到焦点行）。
- 方向键导航到不可见行时，先滚动再移动焦点。
- 屏幕阅读器宣告当前可见范围。

## 5. 颜色独立三重编码库

### 5.1 状态编码

| 状态 | 文本 | 图标 | 颜色 |
|---|---|---|---|
| 草稿 | 草稿 | 📄 | gray |
| 待支付 | 待支付 | ⏰ | orange |
| 已支付 | 已支付 | ✓ | blue |
| 已发货 | 已发货 | 📦 | blue |
| 已完成 | 已完成 | ✓✓ | green |
| 已取消 | 已取消 | ✗ | gray |
| 退款中 | 退款中 | ↩ | orange |
| 已退款 | 已退款 | ↩✓ | red |

### 5.2 风险编码

| 风险级别 | 文本 | 图标 | 按钮样式 |
|---|---|---|---|
| 高风险 | 高风险 | ⚠ | dangerButton |
| 中风险 | 需确认 | ! | warningButton |
| 低风险 | — | — | defaultButton |

### 5.3 差异编码

| 方向 | 图标 | 文本格式 | 颜色 |
|---|---|---|---|
| 上升 | ▲ | +{value} | green |
| 下降 | ▼ | -{value} | red |
| 持平 | → | ±0 | gray |

## 7. 自动化测试生成

从可访问性契约自动生成以下测试：

### 7.1 axe-core 自动扫描

```javascript
// 从模式的 wcagMapping 生成 axe 规则
patterns.forEach(pattern => {
  pattern.a11yContract.wcagMapping.forEach(mapping => {
    if (mapping.testMethod === "axe-core") {
      axeRules.push({
        id: `${pattern.id}-${mapping.criterion}`,
        selector: pattern.a11yContract.semanticStructure.root.selector,
        tags: [mapping.criterion]
      });
    }
  });
});
```

### 7.2 键盘遍历测试

```javascript
// 从模式的 keyboardContract 生成键盘测试
patterns.forEach(pattern => {
  pattern.a11yContract.keyboardContract.forEach(contract => {
    keyboardTests.push({
      name: `${pattern.id} - ${contract.key} -> ${contract.action}`,
      steps: [
        `focus ${contract.region || 'root'}`,
        `press ${contract.key}`,
        `assert ${contract.action} executed`
      ]
    });
  });
});
```

### 7.3 屏幕阅读器宣告测试

```javascript
// 从模式的 screenReader.announcements 生成宣告测试
patterns.forEach(pattern => {
  pattern.a11yContract.screenReader.announcements.forEach(ann => {
    srTests.push({
      name: `${pattern.id} - ${ann.trigger}`,
      trigger: ann.trigger,
      expectedAnnouncement: ann.announce,
      politeness: ann.politeness
    });
  });
});
```

## 8. 与其他方向的关系

- **方向 1**：可访问性契约作为方向 1 规约的 `a11yContract` 属性，参与不变量校验。
- **方向 4 的不变量**：`A11Y-1`（所有交互有键盘等价）、`A11Y-2`（状态不只靠颜色）、`A11Y-3`（焦点可见）写入方向 1 的不变量规则库。
- **方向 7**：可访问性测试作为实证验证的必检项。
