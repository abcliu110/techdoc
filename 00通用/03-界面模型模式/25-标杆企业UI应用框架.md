# 标杆企业 UI 应用框架深度拆解

> 本文档拆解 SAP Fiori、Salesforce Lightning、Ant Design Pro、IBM Carbon、Microsoft Fluent、Google Material 六大标杆系统的 UI 应用框架架构，包括分层结构、组件体系、设计令牌、开发模型和与界面模式的关系。

```

│  ├───────────────────────────────────────────────┤  │
│  │            SAPUI5 (HTML5/JS UI 框架)           │  │
│  │  ┌─────────┐ ┌──────────┐ ┌────────────────┐ │  │
│  │  │基础控件库│ │Smart控件 │ │Fiori Elements │ │  │
│  │  │(200+)   │ │(智能控件)│ │(模板自动生成)  │ │  │
│  │  └─────────┘ └──────────┘ └────────────────┘ │  │
│  └───────────────────┬───────────────────────────┘  │
└──────────────────────┼──────────────────────────────┘
                       │ OData (RESTful JSON)
┌──────────────────────┼──────────────────────────────┐
│         SAP Fiori 前端服务器 (FES)                    │
│  ┌───────────────────┴───────────────────────────┐  │
│  │  UI5 资源库 · Launchpad 配置 · OData 路由      │  │
│  └───────────────────┬───────────────────────────┘  │
└──────────────────────┼──────────────────────────────┘

│         SAP 后端业务系统 (S/4HANA)                    │
│  ┌───────────────────┴───────────────────────────┐  │
│  │  CDS View → OData Service → 业务逻辑 → 数据库   │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

### 2.2 三层控件体系

| 层级 | 说明 | 示例 |
|---|---|---|
| **基础控件库** | 200+ 个独立 UI 控件，开发者手动组装 | Button, Input, Table, Dialog, Tree |
| **Smart 控件** | 绑定 OData 元数据的智能控件，自动生成列/筛选/操作 | SmartTable, SmartFilterBar, SmartChart, SmartForm |
| **Fiori Elements** | 基于 OData 注解自动生成完整页面模板，零前端编码 | List Report, Object Page, Overview Page, Worklist, Analytical List Page |

### 2.3 页面模板（与界面模式的一一对应）

| Fiori 模板 | 对应界面模式 | 核心特征 |
|---|---|---|
| List Report | List Report | Smart Filter Bar + Smart Table + 批量操作 |
| Object Page | Object Page | 对象头部 + 分区锚点导航 + Related Lists + Timeline |
| Overview Page | Dashboard | 全局筛选 + KPI 卡片 + Smart Chart |
| Worklist | Worklist | 按状态/角色过滤的任务队列 |
| Analytical List Page | Drill-down Report | Visual Filter + 图表明细联动 |
| Fact Sheet | Object Page (变体) | 业务对象全息页 + 搜索关联 |
| Wizard | Wizard | 分步表单 + 草稿 + 总览确认 |

### 2.4 主题与设计令牌

SAP Fiori 通过 **Theme Parameters** 实现主题切换：

- **Horizon**（默认主题，S/4HANA 2025）：更清晰的视觉层次，聚焦内容
- **Quartz / Belize**：旧版主题
- 主题参数定义颜色、字号、间距、圆角等视觉变量
- 支持企业自定义品牌主题

### 2.5 开发模型

| 模型 | 编码量 | 适用场景 |
|---|---|---|
| **Fiori Elements（免编码）** | 极少（仅 OData 注解） | 标准 CRUD 页面，SAP 最佳实践 |
| **Smart Controls（低编码）** | 少量 JS 配置 | 需要定制但基于 OData 的页面 |
| **Freestyle SAPUI5（全编码）** | 完整 JS/HTML | 高度定制化页面 |

### 3.2 四层 UI 体系

| 层级 | 说明 | 示例 |
|---|---|---|
| **Design Tokens** | 全局令牌（颜色/间距/字号）+ 组件级语义令牌 | `--slds-g-color-brand-base-50` |

| **Lightning Base Components** | 内置 SLDS 样式的 LWC 组件 | `<lightning-button>`, `<lightning-datatable>` |
| **Lightning Page Types + App Builder** | 页面类型模板，管理员拖拽组合 | Record Page, Home Page, Dashboard |

| Dashboard | Dashboard + Drill-down | Report Chart 组合 + 点击钻取到 Report |
| Path | Wizard (变体) | 阶段进度 + 关键字段 + 指南 |
| App Launcher | 导航骨架 | 应用宫格入口 |
| Report | Drill-down Report | 分组+筛选+钻取到记录 |

### 3.5 开发模型

| 模型 | 编码量 | 适用场景 |

## 七、六大框架的共性规律

### 7.1 共同的三层架构

所有标杆框架都采用类似的**三层架构**：

```
第一层：设计令牌
  颜色 · 字号 · 间距 · 圆角 · 阴影 · 动画
  ↓
第二层：基础组件
  Button · Input · Table · Dialog · Tabs · Tree ...
  ↓
第三层：业务页面模板/模式
  List Report · Object Page · Dashboard · Worklist ...
```

### 7.2 共同的组件演进路径

```
原子组件 → 组合组件 → 页面模板 → 自动生成

SAP:      基础控件 → Smart控件 → Fiori Elements → CDS注解自动生成
Salesforce: SLDS CSS → Base Components → App Builder → 拖拽自动生成
Ant Design: antd组件 → ProComponents → 页面模板 → 配置化生成
```

### 7.3 共同的设计令牌分层

|---|---|---|---|---|
| 全局令牌 | Theme Parameters | Global Tokens | Design Token | Global Tokens |
| 语义令牌 | — | Component Aliases | — | Semantic Tokens |
| 组件令牌 | — | Component Tokens | — | Component Tokens |

## 九、与界面模型模式体系的关系

标杆企业的 UI 框架是界面模式的**工程实现载体**：

- 界面模式定义"应该怎样设计"，UI 框架提供"怎样快速实现"
- 模式文档中的 25 个核心模式，在六大框架中都有对应的组件或模板
- 方向 1（形式化规约）的校验引擎，可以嵌入这些框架的开发工具中
- 方向 4（可访问性契约）的 ARIA 规范，这些框架已部分内置
- 方向 6（Agent-Native UI）的下一代模式，正在被 Salesforce Einstein / SAP Joule / MS Copilot 实践

**一句话：界面模式是设计语言的"语法"，标杆 UI 框架是"编译器"——语法指导设计，编译器加速实现。**
