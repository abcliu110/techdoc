# 自动化测试场景（平台执行版）

## 通用规则

- 只使用有手机号、有效会员卡、状态正常的会员。
- 每个用例使用独立账单，每单至少 5 个普通可售菜品。
- 明确选择 `bosswx` 或 `newshop`，打印本地和远端 URL。
- 规则和基础数据只读；配置、发券及业务操作使用原子能力。
- 输出账单、订单、会员、支付、券、权益变化和数据库证据。

### 会员权益规则命中与自动补跑

- 积分、消费赠券、消费返现分别记录规则快照、规则 ID、命中条件、命中状态和权益流水，不得仅根据权益增量推断规则命中。
- 单个业务用例未命中某项权益规则时，该项在本次账单中记为 `NOT_APPLICABLE`，不得判断为发放失败，也不得将其计为该项权益的命中覆盖。
- 若测试范围要求验证的积分、消费赠券或消费返现尚无命中证据，平台必须针对每个未命中的权益类型自动生成一个补充用例，使用新会员上下文和独立账单执行，不等待人工触发。
- 补充用例必须先只读查询当前有效规则，再按规则的门店、会员范围、菜品、消费金额、支付方式和生效时间组合测试数据；禁止创建、修改或放宽规则以制造命中。
- 补充用例至少点 5 个普通可售菜品；规则对金额或指定菜品有要求时，必须追加满足条件的菜品或金额，并在结账前输出预期命中的规则 ID。
- 每项权益默认只自动补跑 1 个独立用例，防止无限重试。补跑仍未命中、没有有效规则或无法构造满足条件的数据时，该项权益覆盖结果为 `FAIL`，并输出规则快照、未满足条件和证据缺口。
- 原业务用例结果和补充用例结果分别报告；测试套件只有在业务流程断言通过，且积分、消费赠券、消费返现各自至少存在一个明确命中的 `PASS` 证据时，才允许整体 `PASS`。
- 权益命中 `PASS` 必须同时具备：规则 ID、命中事件或任务记录、会员权益实际增量，以及对应数据库权益流水；任一证据缺失均不得判定为命中成功。

## 第一部分：只操作 POS

### POS-01 储值方案边界

- 前置：已有多档储值方案，每档送券和含多张券的券包。
- 步骤：分别在适用/不适用门店、品牌、日期打开 POS 储值方案。
- 断言：符合条件时显示并可用，不符合时不显示；记录方案和边界条件。

### POS-02 会员储值

- 前置：至少 3 个有手机号会员，已有多档储值方案。
- 步骤：分别执行各档方案储值和自定义金额储值。
- 断言：本金、赠送金额、积分、券、券包及储值流水正确。

### POS-03 现金支付会员权益

- 前置：已有积分、返现、赠券规则。
- 步骤：POS 开台，点至少 5 个普通菜，录入会员，满足规则后现金结账。
- 断言：结账成功，积分、返现、赠券按规则发放，数据库账单和支付正确。

### POS-04 会员卡支付会员权益

- 前置：会员余额足够，已有积分、返现、赠券规则。
- 步骤：POS 开台、点菜、录入会员，使用会员卡结账。
- 断言：会员余额扣减正确，积分、返现、赠券只发放一次。

### POS-05 混合支付会员权益

- 前置：会员余额足够，已有积分、返现、赠券规则。
- 步骤：POS 开台、点菜、录入会员，使用会员卡+现金结账。
- 断言：两种支付金额之和等于实收，会员余额和权益变化正确。

### POS-06 积分抵现

- 前置：会员积分足够，已有积分抵现规则。
- 步骤：POS 开台，点至少 5 个普通菜，录入会员，使用积分抵现结账。
- 断言：积分扣减、抵现金额、现金实付、账单和支付流水正确。

### POS-07 反结账权益回退

- 前置：建立一笔已产生积分、返现、赠券的 POS 账单。
- 步骤：记录结账后权益，执行反结账。
- 断言：账单和支付回退，积分、返现、赠券按规则撤销。

### POS-08 部分退款权益变化

- 前置：建立一笔已产生积分、返现、赠券的 POS 账单。
- 步骤：随机退 1-3 个普通菜并执行部分退款。
- 断言：退款金额、剩余菜品、积分、返现、赠券按规则重算。

### POS-09 结账、反结账、再结账、部分退款

- 前置：已有积分、返现、赠券规则。
- 步骤：POS 开台点菜并结账；反结账；再次结账；随机退 1-3 个菜。
- 断言：每阶段账单、支付和权益变化正确，权益不重复累计。

### POS-10 反结账、退菜、再结账

- 前置：建立一笔已产生会员权益的 POS 账单。
- 步骤：反结账，随机退 1-2 个菜，再次结账。
- 断言：最终应收、实收、积分、返现、赠券按剩余菜品重新计算。

### POS-11 整单退和部分退

- 前置：分别建立两笔已结账且产生会员权益的账单。
- 步骤：一笔执行整单退，另一笔执行部分退。
- 断言：退款流水、账单状态和权益回退/重算正确。

### POS-12 折扣、立减、免费实物券

- 前置：已有 `SWQ` 折扣券、立减券、免费券；券名包含券菜名；适用东莞店和对应菜品。
- 步骤：三类券分别独立开单；每单点 5 个普通菜+1 个券菜；原子发券；POS 查询、核销、保存、现金结账。
- 断言：类型分别为 `DISCOUNT/AMOUNT_OFF/FREE`；`write_off=1`；券菜匹配；`dwd_coupon/dwd_bill/dwd_pay/dwd_food` 正确。

### POS-13 多张实物券和整单折扣

- 前置：已有一张折扣实物券和一张立减实物券，均适用当前门店和券菜。
- 步骤：同单点至少 5 个普通菜及券菜，核销两张券，再加菜并尝试整单打折后结账。
- 断言：两张券各核销一次，实物券不被整单折扣重复打折，支付和会员权益正确。

## 第二部分：只操作小程序

### MINI-01 小程序会员支付

- 前置：桌台未开，有手机号会员可登录，已有积分、返现、赠券规则。
- 步骤：小程序扫码开台，点至少 5 个菜，满足规则后使用会员支付。
- 断言：订单结账成功，会员余额、积分、返现、赠券及数据库流水正确。

### MINI-02 小程序微信支付

- 前置：桌台未开，小程序支付环境可用。
- 步骤：小程序扫码开台，点至少 5 个菜，使用微信支付。
- 断言：支付成功，订单状态、实付金额、菜品和支付流水正确。

### MINI-03 小程序加菜和改数量

- 前置：桌台未开，有手机号会员可登录。
- 步骤：小程序扫码开台并点菜；继续加菜、修改数量；使用会员支付。
- 断言：最终菜品、数量、金额正确，会员权益只计算一次。

### MINI-04 小程序霸王餐支付

- 前置：桌台未开，已有可用霸王餐规则或券。
- 步骤：小程序扫码开台，点至少 5 个菜并满足规则，使用霸王餐支付。
- 断言：支付和券核销成功，账单金额、券状态和会员权益正确。

## 第三部分：操作小程序和 POS

### MIX-01 POS 开台，小程序点菜并支付

- 前置：桌台未开，有手机号会员可登录小程序。
- 步骤：POS 开台不点菜；小程序进入同一桌台，点至少 5 个菜并会员支付。
- 断言：两端关联同一账单，菜品、支付、积分、返现、赠券正确。

### MIX-02 POS 点菜，小程序加菜并支付

- 前置：桌台未开，有手机号会员可登录小程序。
- 步骤：POS 开台并点菜；小程序进入同一桌台继续加菜并会员支付。
- 断言：跨端菜品正确合并，支付成功，会员权益只产生一次。

### MIX-03 小程序点菜，POS 加菜，小程序支付

- 前置：桌台未开，有手机号会员可登录小程序。
- 步骤：小程序扫码开台并点菜；POS 向同一账单加菜；小程序会员支付。
- 断言：两端账单 ID 一致，菜品、金额、支付和会员权益正确。

### MIX-04 小程序点菜，POS 加菜，霸王餐支付

- 前置：桌台未开，已有可用霸王餐规则或券。
- 步骤：小程序开台点菜；POS 向同一账单加菜；小程序使用霸王餐支付。
- 断言：跨端账单一致，支付和券核销成功，金额及会员权益正确。

## 固定输出

```text
caseId / environment / memberPhone / billId / orderId
payment / couponNo / normalDishCount / couponDishCount
checkout / localDatabase / benefitLedger / evidenceReport / result
benefitType / ruleId / ruleHitStatus / benefitTransactionId
supplementalCaseId / sourceCaseId / unmetConditions / supplementalResult
```

只有必需能力、UI 断言、数据库断言和必需权益命中覆盖全部通过，结果才是 `PASS`。
