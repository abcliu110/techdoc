# 折扣券核销链路与折上折分析

**日期**: 2026-07-27  
**范围**: CRM 折扣券配置、POS 全单打折核销、账单重算  
**关联项目**: nms4cloud-biz-ui / nms4cloud-crm / nms4pos / nms4pos-ui  
**结论摘要**: 折扣券核销 = CRM 标记已核销 + POS 按绑定的折扣方案做全单打折；不会出现两个折扣率叠乘，但可能叠加优惠价/促销/现金券。

---

## 一、问题与范围

本文回答两个问题：

1. 后台配置的「折扣券」在 POS 如何核销、优惠金额从哪里来。
2. 核销后会不会形成「折上折」。

本文中的「折扣券」指 CRM 券类型 `CouponTypeEnum.DISCOUNT`，不是实物券上的单品优惠方式 `DishDiscountTypeEnum.DISCOUNT`。

| 概念 | 枚举/字段 | 含义 |
| --- | --- | --- |
| 折扣券 | `CouponTypeEnum.DISCOUNT` | 券类型，核销后触发全单打折 |
| 折扣类型 | 券模板字段 `dishCode` | 绑定运营折扣方案 `BizDiscount.lid` |
| 单品折扣方式 | `DishDiscountTypeEnum.DISCOUNT` | 实物券/菜品券的折扣计算方式，与本文主链路不同 |

## 二、配置侧：折扣券如何定义

### 2.1 后台页面

商户中心卡券营销新增优惠券：

- 模式：券
- 券类型：折扣券
- 折扣类型：下拉选择运营信息中的折扣方案

前端入口：

- `nms4cloud-biz-ui/src/pages/CrmCardMarketingMrg/components/CrmCoupon/components/CreateForm.tsx`
- 字段名：`dishCode`，展示名：折扣类型
- 选项来源：`listBizDiscount()` → `POST /api/pos4cloud/merchant/biz_discount/list`

### 2.2 折扣方案数据源

| 层级 | 位置 | 说明 |
| --- | --- | --- |
| 前端 API | `BizDiscount/service.ts` | `biz_discount/list` |
| 云端 Controller | `BizDiscountController.listBizDiscount` | 按 mid/sid 分页查询 |
| 云端 Service | `BizDiscountServicePlus.list` | 过滤 mid、sid、enable、name |
| 云端表 | `sc_mall_discount` | 老数据源；实体 `BizDiscount` |
| POS 本地表 | `biz_discount` | 门店同步后的折扣方案 |

下拉框：

- `label = name`
- `value = lid`

选中后会把折扣名称写到券模板 `dishName`。

### 2.3 关键配置结果

折扣券模板关键字段语义：

| 字段 | 语义 |
| --- | --- |
| `type/couponType = DISCOUNT` | 折扣券 |
| `dishCode` | 绑定的 `BizDiscount.lid` |
| `dishName` | 折扣方案名称（展示用） |
| 面值类字段 | 本类型不作为现金抵扣额 |

说明：折扣券不靠 CRM 面值直接减钱，靠 POS 读取折扣方案的 `discountRate` 重算账单。

## 三、核销主链路（POS 全单打折）

### 3.1 业务入口

POS 桌面端账单页「全单打折」弹窗：

- UI：`nms4pos-ui/app/pos4desktop/src/pages/Bill/component/Discount/All/index.tsx`
- 调用：`dwd_bill_ops_discountAll`
- 请求：只传账单 `lid` + `couponLid`

操作步骤：

1. 输入优惠券编号并查询。
2. 校验：
   - `type === 'DISCOUNT'`
   - `couponStatus === 'WHX'`
   - `available === true`
3. 用券上的 `dishCode` 匹配本地折扣方案列表。
4. 点击「核销优惠券」，提交 `couponLid`。

### 3.2 POS 后端处理

入口：

- Controller：`DwdBillOpsForBizController.discountAll`
- Service：`DwdBillOpsServiceImpl.discountAll`

处理顺序：

1. 查账单，校验可操作。
2. 若带 `couponLid`：
   - 调 CRM 查券详情 `getCrmCouponOrder`
   - 取 `discountLid = coupon.dishCode`
   - 组装 `writeOffOneDTO`（核销金额传 0）
3. 查本地 `BizDiscount`：
   - 必须存在且 `enable = true`
   - 取 `discountRate`
   - 若允许自定义折扣且请求带 rate，可用请求 rate 覆盖
4. 先调 CRM `writeOffSign` 核销券。
5. 再更新账单：
   - `discountLid`
   - `discountRate`
   - `discountRange`（折扣名称）
   - `discountByMan = true`
   - `discountBy / discountAt`
   - `channelOrderKeyTP = couponLid`（记录使用的券）

### 3.3 CRM 核销语义

入口：

- `CrmCouponOrderController.writeOffSign`
- `CrmCouponOrderServicePlus.writeOffOne`

只做状态流转，不计算折扣金额：

| 字段 | 变更 |
| --- | --- |
| `couponStatus` | `WHX` → `YHX` |
| `writeOffTime / usedTime` | 当前时间 |
| `writeOffStaff` | 操作人 |
| `usedShopCode / usedShop` | 门店 |
| `orderBillId` | POS 账单 saas 单号 |

条件：仅更新仍为 `WHX` 的券实例；更新行数必须 > 0。

### 3.4 链路总览

```text
CRM 配置折扣券
  dishCode = BizDiscount.lid
        |
        v
POS 全单打折弹窗
  查询券 -> 校验 DISCOUNT/WHX/available
        |
        v
dwd_bill_ops_discountAll(couponLid)
  |- getCrmCouponOrder
  |- discountLid = dishCode
  |- writeOffSign：券 WHX -> YHX
  +- 写账单 discountRate / discountLid / discountByMan=true
        |
        v
账单重算 GeneralCalcOrderServiceImpl
  成交价 x 折扣率 -> 折扣额 -> 实收
```

## 四、优惠金额如何计算

核销后真正算钱的是 POS 账单重算，不在 CRM 核销接口里。

核心类：`GeneralCalcOrderServiceImpl`

### 4.1 计算顺序

1. 自动打折（若账单已是人工/券打折则跳过）
2. 读取折扣方案可打折菜品清单
3. 促销规则处理
4. 重置菜品成交价
5. 重置菜品折扣率
6. 计算菜品金额与折扣额

### 4.2 折扣额公式

```text
discountRate 含义：保留比例
  1.0 = 不打折
  0.88 = 88 折

普通折扣额 = foodAmount * (1 - discountRate)
```

### 4.3 哪些菜会吃到折扣券

| 条件 | 结果 |
| --- | --- |
| 折扣方案未配置可打折菜品清单 | 视为全单可打（`discountAll=true`） |
| 配置了可打折菜品清单 | 仅清单内菜品打折 |
| 菜品绑定实物券/兑换券 | 不参与普通折扣（`discountRate=1`） |
| 菜品已单品人工打折 | 保留单品折扣，不再吃账单折扣率 |
| 菜品已自动打折标记 | 保留自动折扣，不覆盖 |

### 4.4 云端验券金额

`CheckCouponUtil` 对 `DISCOUNT` 类型直接返回优惠金额 `0`。

含义：

- 云端/小程序侧不把折扣券当现金抵扣。
- 折扣券主落地场景是 POS 全单打折。

## 五、会不会折上折

「折上折」要拆成两类口径。

### 5.1 两个折扣率叠乘：不会

账单维度只有一个 `order.discountRate`。

折扣券核销会写：

```text
discountByMan = true
```

`autoDiscount()` 看到 `discountByMan=true` 直接返回，因此以下自动折扣不会再叠：

- 会员自动打折
- 桌台类型自动打折
- 餐段/生日/周几等自动打折

同一道菜也不会先后乘两次折扣率（例如先 88 折再 9 折）。

同一账单再次全单打折，是**替换**当前 `discountRate`，不是两个折扣率连乘。

### 5.2 其他优惠叠加：可能

| 场景 | 是否叠加 | 说明 |
| --- | --- | --- |
| 会员特价/房台价/餐段价 + 折扣券 | 可能 | 先降成交价，再按折扣率打折 |
| 促销规则优惠 + 账单折扣 | 可能 | 促销额可并入折扣额口径 |
| 折扣券 + 现金券 | 可能 | 前者改账单折扣，后者走抵现/支付优惠 |
| 折扣券 + 会员自动折扣率 | 否 | 人工/券打折会挡住自动折扣 |
| 两张折扣券折扣率连乘 | 否 | 账单只保留一个折扣率 |

示例（优惠价后再打折）：

```text
原价 100
会员特价 80
折扣券 88 折
实付约 70.4
```

这是「优惠价 + 折扣」，不是「折扣率 x 折扣率」。

### 5.3 结论表

| 问题 | 结论 |
| --- | --- |
| 折扣券本身如何优惠 | 绑定折扣方案，按方案折扣率全单/限定菜打折 |
| 会不会 88 折后再 9 折 | 不会 |
| 会不会在会员价上再打折 | 会，若该菜走了特价成交价 |
| 会不会再叠现金券 | 通常可以，属于不同优惠通道 |
| 会不会叠会员自动折扣 | 不会，券核销后 `discountByMan=true` 阻止自动折扣 |

## 六、撤销与风险点

### 6.1 撤销全单打折

`discountCancelAll` 只清理账单折扣字段，例如：

- `discountRate / discountLid / discountRange / discountAt` 等

**不会**自动调用 CRM 取消核销。

风险：

```text
账单折扣已撤销，但券仍是 YHX
```

### 6.2 分布式一致性

核销顺序是：

1. 远程 CRM `writeOffSign`
2. 本地写账单折扣字段

若 CRM 已成功、本地写库失败，可能出现：

```text
券已核销，账单未落折扣
```

### 6.3 字段复用风险

券模板 `dishCode` 在折扣券场景表示折扣方案 lid；在实物券场景表示菜品。

读代码和做报表时必须先看 `couponType`，不能只看字段名。

## 八、一句话总结

折扣券不是「面额抵现券」，而是「核销凭证 + 折扣方案触发器」。

- 核销：CRM 改状态，POS 写账单折扣。
- 算钱：POS 按 `BizDiscount.discountRate` 重算。
- 折上折：不做折扣率叠乘；可能叠加优惠价、促销和现金券。
