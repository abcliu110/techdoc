# 01 - 业务全景

> **文档目的**：从业务角度全面理解打印系统「谁、在什么时候、打印什么」
> **读者定位**：业务分析师、产品经理、需要了解打印业务的全栈工程师

---

## 一、业务域定位

### 1.1 打印系统在 POS 中的位置

```
┌─────────────────────────────────────────────────────────────────┐
│                         POS 系统                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐   │
│   │   点餐    │→ │   收银    │→ │   打印    │→ │   结算    │   │
│   └───────────┘  └───────────┘  └─────┬─────┘  └───────────┘   │
│                                       │                        │
│                                       ▼                        │
│                               ┌───────────────┐                │
│                               │   后厨联动    │                │
│                               └───────────────┘                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**打印是结账的「最后一步」**：结账完成后必须打印小票给顾客，同时通知后厨准备出品。

### 1.2 业务价值

| 价值维度 | 说明 |
|----------|------|
| 顾客凭证 | 小票是顾客购物的重要凭证（退换货、报销） |
| 后厨指令 | 厨打单是厨房备餐的唯一依据 |
| 运营数据 | 打印记录可用于数据分析和审计 |
| 服务质量 | 打印速度影响顾客等待体验 |

## 二、核心角色

| 角色 | 操作 | 接触系统 |
|------|------|----------|
| **收银员** | 结账打印、补打、重打 | nms4pos-ui（前台） |
| **店长/运营** | 配置打印机、配置样式、开关管理 | nms4cloud-biz-ui（后台） |
| **厨师** | 接收厨打票据、催菜 | 打印机（硬件） |

## 四、核心用例

### UC-1：打印客单

```
用例编号：UC-1
用例名称：打印客单
参与者：收银员
前置条件：结账完成
基本流程：
  1. 收银员完成收款
  2. 系统自动创建打印任务
  3. 任务进入打印队列
  4. 打印机输出结账单
  5. 收银员将小票交付顾客
后置条件：顾客收到小票
异常处理：
  - 打印机离线 → 重试 3 次 + 告警
  - 纸张用完 → 告警 + 暂停
```

### UC-2：打印厨打票据

```
用例编号：UC-2
用例名称：打印厨打票据
参与者：服务员、后厨
前置条件：点菜完成
基本流程：
  1. 服务员完成点菜
  2. 系统按出品部门分组菜品
  3. 每个部门创建一个打印任务
  4. 任务分发到对应打印机
  5. 部门厨师接收票据
后置条件：后厨收到点菜单
异常处理：
  - 催菜 → 提高优先级立即打印
  - 打印机离线 → 重试 + 切换备用打印机
```

### UC-3：补打票据

```
用例编号：UC-3
用例名称：补打票据
参与者：收银员
前置条件：存在历史订单
基本流程：
  1. 收银员查找历史订单
  2. 点击「补打」按钮
  3. 系统获取原始订单数据
  4. 创建新的打印任务
  5. 打印机输出票据
后置条件：票据重现
业务规则：
  - 补打记录需审计
  - 补打次数有限制
```

### UC-4：配置打印样式

```
用例编号：UC-4
用例名称：配置打印样式
参与者：店长/运营
前置条件：拥有配置权限
基本流程：
  1. 进入打印管理中心
  2. 选择票据类型
  3. 编辑样式项（文本、图片、条码等）
  4. 预览效果
  5. 保存样式配置
后置条件：新样式生效
业务规则：
  - 同一门店同一票据类型只能有一个默认样式
  - 样式修改不影响已创建的任务
```

### UC-5：配置打印机

```
用例编号：UC-5
用例名称：配置打印机
参与者：店长/运营
前置条件：打印机已连接
基本流程：
  1. 进入设备管理
  2. 添加打印机
  3. 选择打印机型号（协议类型）
  4. 配置连接信息（IP/端口/USB）
  5. 测试连接
  6. 保存配置
后置条件：打印机就绪
业务规则：
  - 打印机型号决定使用的 Handler
  - 网络打印机需配置 IP 和端口
```

## 五、业务规则汇总

| 规则编号 | 规则内容 | 约束级别 |
|----------|----------|----------|
| BR-01 | 客单打印必须在结账完成后立即触发 | MUST |
| BR-02 | 厨打票据按出品部门分组，每部门一个打印任务 | MUST |
| BR-03 | 催菜打印优先级高于普通厨打 | SHOULD |
| BR-04 | 交班报告打印需等待交班确认 | MUST |
| BR-05 | 会员储值打印需验证储值成功 | MUST |
| SR-01 | 同一票据类型在同一门店只能有一个默认样式 | MUST |
| SR-02 | 样式修改不影响已创建的任务 | MUST |
| SR-03 | 样式删除前需解除关联任务 | MUST |

## 九、设计决策记录

| 决策 ID | 决策 | 选用的方案 | 被放弃的方案 | 放弃原因 |
|---------|------|-----------|-------------|----------|
| DEC-01 | 打印任务执行方式 | **异步队列 + 虚拟线程**：任务创建后立即返回，后台 Worker 异步执行 | 同步调用打印机 | 打印耗时 1-10 秒，同步调用会阻塞结账流程，影响收银效率 |
| DEC-02 | 任务存储策略 | **文件系统 + Redis 双存储**：文件保证可靠性，Redis 计数保证性能 | 仅用数据库 | 数据库写入延迟高，高并发下可能成为瓶颈；文件存储可离线使用 |
| DEC-03 | 主备切换机制 | **Worker 主动检测**：每个 Worker 在执行前检查打印机状态，故障时自动重定向 | 中心监控 + 推送 | 避免单点故障，Worker 自包含不依赖外部服务 |
| DEC-04 | 打印模板格式 | **JSON 行+列布局**：PosPrnStyleRow/Col 定义模板，支持占位符替换 | 固定模板（硬编码） | 不同门店需要不同格式，固定模板无法满足定制需求 |
| DEC-05 | 任务超时时间 | **30 分钟任务级超时 + 45 分钟队列级超时** | 5 分钟 | 大标签打印（如多联存酒单）可能需要更长时间，5 分钟太短 |
| DEC-06 | 重试策略 | **指数退避（1/2/4 分钟）最多 3 次** | 固定间隔重试 | 固定间隔可能加重网络负担；指数退避在网络抖动恢复后更快成功 |
| DEC-07 | 协议抽象方式 | **Handler Factory 模式**：根据打印机型号返回对应 Handler | 硬编码 if-else 分支 | 新增打印机类型时需修改核心代码，违反开闭原则 |
| DEC-08 | 云端/本地职责 | **nms4pos 本地执行 + nms4cloud 云端管理**：配置在云端，执行在本地 | 全云端执行 | 门店离线时需要继续打印，本地执行保证离线可用性 |
