## 二、API 交互

### 2.1 REST API

#### 打印任务 API

```
POST   /pos_prn_job/save           创建任务
GET    /pos_prn_job/{lid}          获取任务
POST   /pos_prn_job/list           查询任务列表
PUT    /pos_prn_job/update         更新任务
DELETE /pos_prn_job/{lid}          删除任务
POST   /pos_prn_job/reprint/{lid}  重打任务
POST   /pos_prn_job/archive       归档任务
GET    /pos_prn_job/export         导出任务
```
> **注意**：`/pos_prn_job/retry/{lid}` 重试端点不存在，重试通过 `put()` 延迟自动重入队实现

#### 打印样式 API

```
POST   /pos_prn_style/save           保存样式
GET    /pos_prn_style/{lid}          获取样式
POST   /pos_prn_style/list           查询样式列表
PUT    /pos_prn_style/update         更新样式
DELETE /pos_prn_style/{lid}          删除样式
POST   /pos_prn_style/copy           复制样式
```

#### 打印机 API

```
POST   /pos_printer/save           保存打印机
GET    /pos_printer/{lid}          获取打印机
POST   /pos_printer/list           查询打印机列表
PUT    /pos_printer/update         更新打印机
DELETE /pos_printer/{lid}          删除打印机
```
> **注意**：`/pos_printer/test` 测试连接端点不存在，状态通过 `getStatus()` 轮询获取

### 2.2 内部服务调用

```java
// 结账时触发打印
public class CloseMpScHandler {
    @Autowired
    private PosPrnJobServicePlus printJobService;

    public void closeBill(BillCloseDTO dto) {
        // 业务处理...

        // 触发客单打印
        PrintJobDTO job = PrintJobDTO.builder()
            .queueLid(getCashierQueueLid())
            .printerLid(getDefaultPrinterLid())
            .prnStyleLid(getCheckOutStyleLid())
            .orderBillLid(dto.getBillLid())
            .printData(serializeBill(dto))
            .build();
        printJobService.create(job);
    }
}
```

## 三、消息交互

> **设计偏差说明**：实际实现未使用消息队列，所有交互均为本地调用

### 3.1 实际消息机制

```java
// 打印任务创建 - 使用 Spring ApplicationEvent 本地发布
applicationEventPublisher.publishEvent(new PrintTaskCreatedEvent(this, jobLid));
// 注意：仅用于内部状态同步，未使用 RocketMQ

// 打印任务状态更新 - 直接内存更新
// 状态存储在 PrinterWorkerServiceOfflineImpl 内存 Map 中
// 无 MQ 广播，其他模块通过轮询获取状态

// 打印机状态变更 - 直接方法调用
printerStatusService.addPrinterStatus(lid, status);
// 无事件机制，直接调用 PrinterWorkerServiceOfflineImpl.addPrinterStatus()
```

## 四、流程优化建议

### 4.1 当前流程痛点

| 痛点 | 影响 | 建议优化 |
|------|------|----------|
| 串行打印厨打 | 慢 | 并行分发到多打印机 |
| 重试逻辑分散 | 难维护 | 统一 RetryService |
| 样式预览延迟 | 体验差 | 本地渲染预览 |

### 4.2 流程改进方向

1. **批量打印优化**：将同一订单的多个厨打任务并行分发
2. **智能重试**：根据错误类型自适应重试策略
3. **样式预览**：支持本地实时预览，无需等待云端
