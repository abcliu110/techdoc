## DM-01 打印任务（PrintJob）

### ① 身份

| 属性 | 内容 |
|------|------|
| 业务定义 | 一次打印操作的完整记录，从触发到完成的全生命周期载体 |
| 所属上下文 | 核心业务域（打印系统） |
| 同义词 | 业务术语"打印任务"、代码术语"PrintJob"/"PosPrnJob"、旧系统"打印记录" |
| 边界 | 不包含打印机硬件状态（属打印机对象），不包含模板定义（属打印模板对象） |

### ② 结构

| 属性 | 业务含义 | 不变量约束 |
|------|----------|------------|
| lid | 任务唯一标识（雪花算法） | 全局唯一 |
| mid / sid | 所属商户和门店 | 租户隔离 |
| queueLid | 所属打印队列 | 必须引用有效队列 |
| printerLid | 执行打印的打印机 | 必须引用有效打印机 |
| prnStyleLid | 使用的打印模板 | 必须引用有效模板 |
| jobStatus | 任务状态（PENDING/PRINTING/COMPLETED/FAILED/ARCHIVED） | 状态迁移合法 |
| retryCount / maxRetries | 已重试次数 / 最大重试次数 | retryCount ≤ maxRetries |
| printData | 打印内容（JSON 格式） | 必须与模板占位符匹配 |
| errorMsg | 失败原因 | 仅 FAILED 状态时有意义 |

### ③ 关系

| REL | 对方对象 | 方向/基数 | 业务语义 | 一致性策略 |
|-----|----------|-----------|----------|------------|
| REL-01 | 打印队列 | N:1 | 一个任务属于一个队列，一个队列包含多个任务 | 任务创建时指定队列 |
| REL-02 | 打印机 | N:1 | 一个任务由一台打印机执行，一台打印机执行多个任务 | 任务分配时指定打印机 |
| REL-03 | 打印模板 | N:1 | 一个任务使用一个模板，一个模板被多个任务引用 | 任务创建时引用模板 |
| REL-04 | 订单 | N:1 | 一个任务关联一个订单，一个订单可触发多个打印任务 | 任务创建时关联订单 |

### ④ 行为

**状态机摘要**：
```
PENDING ──(Worker 取出)──▶ PRINTING ──(成功)──▶ COMPLETED
                                 └──(失败)──▶ FAILED ──(归档)──▶ ARCHIVED
                                              └──(重试)──▶ PENDING
PRINTING ──(超时 30 分钟)──▶ FAILED
PENDING ──(队列超时 45 分钟)──▶ FAILED
```

**关键规则摘要**：
- BR-001：任务创建时自动分配到队列，不阻塞业务操作
- BR-002：失败任务自动重试最多 3 次，指数退避（1/2/4 分钟）
- BR-003：超过最大重试次数后标记 FAILED，需人工介入

### ⑤ 交互

| IX | 发起者→接收者 | 命令/事件 | 一致性时限 | 恢复责任 |
|----|-------------|-----------|------------|----------|
| IX-01 | 结账模块 → 打印系统 | 创建打印任务 | 即时 | 结账模块不依赖打印结果 |
| IX-02 | 打印系统 → 打印机 | 执行打印 | 30 分钟超时 | 打印系统负责重试 |
| IX-03 | 打印系统 → 文件系统 | 存储任务文件 | 即时 | 文件写入失败则任务创建失败 |
| IX-04 | 打印系统 → Redis | 计数 | 最终一致 | 计数丢失不影响打印 |

### ⑥ 生命（时间线叙事）

```text
收银员完成结账后，系统自动创建一个打印任务，状态为"等待中"。
→ 任务被投递到对应的打印队列，队列按业务类型（小票/后厨标签）分发。
→ 打印机的工作线程从队列取出任务，状态变为"打印中"。
→ 线程通过打印机协议驱动硬件打印，纸张从打印机吐出。
→ 打印成功：状态变为"成功"，任务结束。
→ 打印失败（缺纸/离线）：状态变为"失败"，系统自动重试（最多 3 次）。
→ 重试成功：状态变为"成功"。
→ 重试全部失败：状态保持"失败"，需人工修复后重新打印。
→ 如果 30 分钟未完成：系统强制标记为"失败"（超时保护）。
→ 已完成的失败任务可被归档，状态变为"已归档"。
```

### ⑦ 实现

| MAP | 表/服务/API/消息 | 位置 | 版本/范围 |
|-----|-----------------|------|-----------|
| 数据库表 | `pos_prn_job` | nms4cloud | 所有门店 |
| 服务 | `PosPrnJobServicePlus` | nms4pos-pos2plugin | 1132 行 |
| 服务 | `PosPrnJobServicePlus` | nms4cloud-pos | 云端管理 |
| API | `POST /pos_prn_job/save` | nms4cloud | 云端入口 |
| 文件 | `/print_jobs/{mid}/{sid}/{lid}.json` | 本地文件系统 | 可靠性保障 |
| 事件 | `PrintTaskCreatedEvent` | Spring Event | 内部状态同步 |

### ⑧ 失败

| 失败场景 | 检测方式 | 恢复路径 | 人工介入点 |
|----------|----------|----------|------------|
| 打印机缺纸 | Worker 执行失败 → 状态 FAILED | 自动重试 3 次 | 更换纸张后，在管理页面点击"重打" |
| 打印机离线 | 网络超时 → 状态 FAILED | 主备自动切换 | 检查网络/电源，恢复后手动重打 |
| 文件写入失败 | 异常抛出 → 任务创建失败 | 业务层重试 | 检查磁盘空间和权限 |
| 30 分钟超时 | 定时检测 → 强制 FAILED | 无自动恢复 | 确认打印机状态后手动重打 |
| 队列 45 分钟无人认领 | 定时检测 → 强制 FAILED | 无自动恢复 | 检查 Worker 是否运行 |

## DM-02 打印机（Printer）

### ① 身份

| 属性 | 内容 |
|------|------|
| 业务定义 | 物理打印机的系统抽象，包含设备信息和通信参数 |
| 所属上下文 | 核心业务域（打印系统） |
| 同义词 | 业务术语"打印机"、代码术语"PosPrnPrinter"、旧系统"打印设备" |
| 边界 | 不包含打印任务状态（属打印任务对象），不包含队列配置（属打印队列对象） |

### ② 结构

| 属性 | 业务含义 | 不变量约束 |
|------|----------|------------|
| lid | 打印机唯一标识 | 全局唯一 |
| devId | 关联的设备 ID | 可选，关联 PosDev |
| printerType | 打印机类型（票据/标签/报表） | 必须为有效枚举 |
| printerModel | 打印机型号枚举 | 对应特定协议 |
| ipAddress / port | 网络打印机地址 | 网络打印机必填 |
| usbPath | USB 路径 | USB 打印机必填 |
| serialPort / baudRate | 串口参数 | 串口打印机必填 |
| paperWidth | 纸宽（mm） | 影响打印布局 |
| status | 打印机状态（NORMAL/FAULT/OFFLINE） | 影响队列选择 |

### ③ 关系

| REL | 对方对象 | 方向/基数 | 业务语义 | 一致性策略 |
|-----|----------|-----------|----------|------------|
| REL-05 | 打印队列 | N:1 | 一台打印机属于一个队列（主或备），一个队列包含多台打印机 | 配置时绑定 |
| REL-06 | 打印任务 | 1:N | 一台打印机执行多个任务 | 运行时分配 |

### ④ 行为

**状态机摘要**：
```
NORMAL ──(故障)──▶ FAULT ──(修复)──▶ NORMAL
NORMAL ──(离线)──▶ OFFLINE ──(上线)──▶ NORMAL
```

**关键规则摘要**：
- BR-004：主打印机故障时，队列自动切换到备用打印机
- BR-005：无可用打印机时，任务标记 FAILED

### ⑤ 交互

| IX | 发起者→接收者 | 命令/事件 | 一致性时限 | 恢复责任 |
|----|-------------|-----------|------------|----------|
| IX-05 | 打印系统 → 打印机 | 发送打印指令 | 30 分钟超时 | 打印系统负责重试 |
| IX-06 | 管理员 → 打印系统 | 配置/测试打印机 | 即时 | 配置错误由管理员修正 |

### ⑥ 生命（时间线叙事）

```text
管理员在后台添加一台打印机，配置型号、IP、端口和纸张参数。
→ 打印机被绑定到某个打印队列，作为主打印机或备用打印机。
→ 日常使用中，打印队列将任务分配给这台打印机。
→ 如果打印机故障或离线，状态变为"故障"/"离线"，
   队列自动切换到备用打印机。
→ 管理员修复后，状态恢复为"正常"，继续接收打印任务。
→ 如果打印机不再使用，管理员可将其从系统中删除。
```

### ⑦ 实现

| MAP | 表/服务/API/消息 | 位置 |
|-----|-----------------|------|
| 数据库表 | `pos_prn_printer` | nms4cloud |
| 服务 | `PosPrinterService` | nms4cloud-pos |
| API | `POST /pos_printer/save` | nms4cloud |
| 前端 | `PosPrnPrinterPage` | nms4cloud-biz-ui |

### ⑧ 失败

| 失败场景 | 检测方式 | 恢复路径 | 人工介入点 |
|----------|----------|----------|------------|
| 打印机故障 | Worker 执行失败 → 状态 FAILED | 主备自动切换 | 修复打印机硬件 |
| 打印机离线 | 网络超时 | 主备自动切换 | 检查网络/电源 |
| 配置错误 | 测试打印失败 | 无自动恢复 | 管理员修正配置 |

## DM-03 打印队列（PrintQueue）

### ① 身份

| 属性 | 内容 |
|------|------|
| 业务定义 | 打印任务的分发渠道，按业务类型组织，管理主备打印机 |
| 所属上下文 | 核心业务域（打印系统） |
| 同义词 | 业务术语"打印队列"、代码术语"PosPrnQueue" |
| 边界 | 不包含打印机硬件状态（属打印机对象），不包含任务内容（属打印任务对象） |

### ② 结构

| 属性 | 业务含义 | 不变量约束 |
|------|----------|------------|
| lid | 队列唯一标识 | 全局唯一 |
| queueName | 队列名称（如"前台收银"、"后厨"） | 门店内唯一 |
| queueType | 队列类型 | 影响任务分发策略 |
| mainPrinterLid | 主打印机 | 必须引用有效打印机 |
| backupPrinterLid | 备用打印机 | 可选 |
| timeout | 队列超时（分钟） | 默认 45 分钟 |

### ③ 关系

| REL | 对方对象 | 方向/基数 | 业务语义 | 一致性策略 |
|-----|----------|-----------|----------|------------|
| REL-07 | 打印机 | 1:N | 一个队列包含多台打印机（主+备） | 配置时绑定 |
| REL-08 | 打印任务 | 1:N | 一个队列包含多个任务 | 运行时分配 |

### ④ 行为

**关键规则摘要**：
- BR-006：任务按队列类型分发到对应队列
- BR-007：主打印机故障时切换到备用打印机
- BR-008：队列内任务按 FIFO 顺序执行

### ⑤ 交互

| IX | 发起者→接收者 | 命令/事件 | 恢复责任 |
|----|-------------|-----------|----------|
| IX-07 | 打印系统 → 队列 | 投递任务 | 队列负责分发 |
| IX-08 | Worker → 队列 | 取出任务 | Worker 负责执行 |

### ⑥ 生命（时间线叙事）

```text
管理员在后台创建一个打印队列，指定队列名称、类型和超时时间。
→ 管理员为主打印机和备用打印机绑定到队列。
→ 日常运行中，打印任务被投递到队列，Worker 从队列取出执行。
→ 如果主打印机故障，队列自动切换到备用打印机。
→ 如果主备都故障，队列中的任务在超时后标记为"失败"。
```

### ⑦ 实现

| MAP | 表/服务/API/消息 | 位置 |
|-----|-----------------|------|
| 数据库表 | `pos_prn_queue` | nms4cloud |
| 服务 | `PosPrnQueueService` | nms4cloud-pos |
| API | `POST /pos_prn_queue/save` | nms4cloud |

### ⑧ 失败

| 失败场景 | 检测方式 | 恢复路径 | 人工介入点 |
|----------|----------|----------|------------|
| 主打印机故障 | Worker 检测状态 | 自动切换到备用 | 修复主打印机 |
| 主备都故障 | 任务超时 FAILED | 无自动恢复 | 管理员修复打印机或重建队列 |
| 队列无 Worker | 任务 45 分钟无人认领 | 无自动恢复 | 检查 Worker 进程 |

## DM-04 打印模板（PrintStyle）

### ① 身份

| 属性 | 内容 |
|------|------|
| 业务定义 | 定义打印内容的格式和布局，包括行、列、占位符和样式项 |
| 所属上下文 | 支撑业务能力（打印系统） |
| 同义词 | 业务术语"打印样式"、"打印模板"、代码术语"PosPrnStyle"、"PosPrnStyleRow" |
| 边界 | 不包含打印数据（属打印任务对象），不包含打印机配置（属打印机对象） |

### ② 结构

| 属性 | 业务含义 |
|------|----------|
| styleType | 样式类型（收银票据/后厨票据/报表/会员等） |
| styleContent | 样式内容（JSON 格式，定义行和列） |
| rows | 行列表，每行包含多个列 |
| columns | 列定义，包含占位符 {数据源ID,字段名} |
| copies | 打印份数 |
| isDefault | 是否默认样式 |

### ③ 关系

| REL | 对方对象 | 方向/基数 | 业务语义 |
|-----|----------|-----------|----------|
| REL-09 | 打印任务 | 1:N | 一个模板被多个任务引用 |
| REL-10 | 数据源 | N:N | 模板占位符引用数据源字段 |

### ④ 行为

**关键规则摘要**：
- BR-009：模板渲染时占位符替换为实际数据
- BR-010：表格行按数据列表长度动态生成行数

### ⑤ 交互

| IX | 发起者→接收者 | 命令/事件 | 恢复责任 |
|----|-------------|-----------|----------|
| IX-09 | 打印系统 → 模板引擎 | 渲染模板 | 模板引擎负责 |
| IX-10 | 管理员 → 打印系统 | 编辑模板 | 管理员负责验证 |

### ⑥ 生命（时间线叙事）

```text
管理员在后台创建一个打印模板，选择样式类型（如"顾客小票"）。
→ 管理员添加行和列，定义每行显示什么内容，
   使用占位符 {数据源ID,字段名} 引用实际数据。
→ 模板保存后，打印任务创建时引用该模板。
→ 模板引擎在打印时加载模板，将占位符替换为实际数据。
→ 如果模板内容需要调整，管理员可随时编辑。
→ 模板支持门店间复制，减少重复配置。
```

### ⑦ 实现

| MAP | 表/服务/API/消息 | 位置 |
|-----|-----------------|------|
| 数据库表 | `pos_prn_style`、`pos_prn_style_item` | nms4cloud |
| 服务 | `PosPrnStyleService` | nms4cloud-pos |
| API | `POST /pos_prn_style/save` | nms4cloud |
| 前端 | `PosPrnStyleRowPage` | nms4pos-ui |

### ⑧ 失败

| 失败场景 | 检测方式 | 恢复路径 | 人工介入点 |
|----------|----------|----------|------------|
| 模板缺失 | 渲染时找不到模板 | 使用默认模板 | 管理员配置模板 |
| 占位符不匹配 | 渲染时字段缺失 | 内容为空 | 管理员修正模板 |
| 格式错误 | JSON 解析失败 | 使用默认模板 | 管理员修正 JSON |
