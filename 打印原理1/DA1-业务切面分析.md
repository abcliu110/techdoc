## 一、业务价值定位

### 1.1 打印系统的核心价值

打印系统是餐饮 POS 的"最后一公里"——将数字订单转化为物理凭证，连接商家、后厨、顾客三个关键角色：

| 角色 | 打印产物 | 核心诉求 |
|------|----------|----------|
| **商家** | 结账单、交班报告 | 交易凭证、业绩统计 |
| **后厨** | 点菜单、催退单 | 快速出品、避免漏单 |
| **顾客** | 消费小票 | 消费记录、退换凭证 |

### 1.2 打印系统的业务边界

**输入**：订单数据、菜品数据、交易数据
**输出**：各类纸质票据
**边界约束**：
- 打印系统不产生业务数据，只消费业务数据
- 打印失败不影响主业务流程（异步化）
- 打印配置（样式、打印机）由商户自定义

### 2.2 关键业务规则

| 规则编号 | 规则内容 | 约束级别 |
|----------|----------|----------|
| BR-01 | 同一订单的厨打票据按出品部门分组，每组对应一个打印任务 | 必须 |
| BR-02 | 客单必须在结账完成后立即打印，不得延迟 | 必须 |
| BR-03 | 打印失败任务最多重试 3 次，间隔指数递增 | 必须 |
| BR-04 | 票据样式按商户+门店独立配置 | 必须 |
| BR-05 | 打印任务状态变更必须发布消息通知 | 必须 |
| BR-06 | 失败任务 24 小时后自动归档 | 宜 |
| BR-07 | 打印计数按队列维度统计，15 分钟 TTL | 宜 |

## 四、业务切面总结

### 4.1 切面特征

| 维度 | 特征 |
|------|------|
| **完整性** | 打印系统是业务系统的下游，不独立闭环 |
| **异步性** | 主业务流程不阻塞于打印结果 |
| **多样性** | 7 种协议、6 大类票据、4 类厨房区域 |
| **可靠性** | 重试+归档机制保障任务完成 |
| **可配置** | 商户自定义样式、打印机、开关 |

### 4.2 与其他系统边界

| 边界系统 | 关系类型 | 接口形式 |
|----------|----------|----------|
| 结账系统 | 上游 | 方法调用 |
| 厨打系统 | 上游 | 方法调用 |
| 报表系统 | 上游 | 方法调用 |
| 会员系统 | 上游 | 方法调用 |
| WMS 系统 | 上游 | 方法调用 |
| 设备硬件 | 下游 | 协议通信 |
