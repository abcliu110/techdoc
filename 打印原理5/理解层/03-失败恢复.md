# 03 - 失败恢复

> 故障处理与恢复流程
> 最后更新：2026-08-04

---

## 1. 故障分类

### 1.1 故障等级

| 等级 | 说明 | 影响范围 | 恢复方式 |
|------|------|----------|----------|
| P1 | 全部打印机不可用 | 所有打印任务 | 紧急启用备用机/人工处理 |
| P2 | 主打印机故障 | 部分任务延迟 | 自动切换备用机 |
| P3 | 单个任务打印失败 | 单个顾客 | 自动重试或手动重打 |
| P4 | 打印质量问题 | 输出不清晰 | 手动重打 |

### 1.2 故障场景

| 场景 | 原因 | 症状 |
|------|------|------|
| 缺纸 | 纸张用完 | 打印中途停止 |
| 卡纸 | 纸张卡住 | 打印机报错 |
| 离线 | 打印机断电/断网 | 无法连接 |
| 队列满 | 任务堆积 | 打印延迟 |
| 云打印失败 | 网络问题/服务商故障 | API 超时 |

### 2.2 故障转移

当主打印机故障时，系统自动切换到备用打印机：

```
PosPrnQueue 结构：
{
  "primary_printer": "lid1,lid2",  // 主打印机列表
  "standby_printer": "lid3"        // 备用打印机
}
```

**故障转移流程**：

1. PrinterWorker 检查主打印机状态
2. 发现状态 = FAULT
3. 查询队列的 standby_printer
4. 切换到备用打印机
5. 使用备用打印机执行打印

### 2.3 超时保护

| 参数 | 值 | 说明 |
|------|---|------|
| 超时阈值 | 30 分钟 | 任务从创建到执行不能超过 |
| 超时动作 | archiveFailed | 归档任务，记录原因 |
| 超时判断 | job_date vs 当前时间 | 基于创建时间 |

## 3. 恢复流程

### 3.1 打印失败恢复

**适用场景**：单个任务打印失败

**恢复步骤**：

1. **检查错误信息**
   ```bash
   # 查询失败任务
   SELECT * FROM pos_prn_job WHERE status = 3 AND deleted = 0;
   ```

2. **判断失败原因**
   - 缺纸/卡纸 → 修复打印机后重试
   - 网络问题 → 检查网络后重试
   - 内容问题 → 修复模板后重试

3. **执行重打**
   ```
   POST /api/pos4cloud/pos_prn_job/reprint
   {
     "jobLid": "123456789"
   }
   ```

### 3.2 批量任务失败恢复

**适用场景**：大量任务同时失败（打印机故障）

**恢复步骤**：

1. **定位故障打印机**
   ```sql
   SELECT * FROM pos_prn_printer WHERE status = 2;
   ```

2. **修复或更换打印机**
   - 检查电源、网络
   - 更换碳带/纸张
   - 重启打印机

3. **批量重打未完成任务**
   ```sql
   -- 查询超时/失败任务
   SELECT lid FROM pos_prn_job
   WHERE status IN (1, 3)
   AND created_time > DATE_SUB(NOW(), INTERVAL 2 HOUR);
   ```

4. **触发批量重打**
   - 通过管理后台批量重打
   - 或编写脚本批量调用 reprint 接口

### 3.3 服务重启恢复

**适用场景**：PrinterWorker 或服务重启

**恢复机制**：

1. **启动时恢复**
   - PrinterWorker 启动时从数据库加载 PENDING 状态任务
   - 任务重新入队

2. **队列恢复**
   ```java
   // PrinterWorker 启动时
   List<PosPrnJob> pendingJobs = posPrnJobMapper.selectByStatus(PENDING);
   for (PosPrnJob job : pendingJobs) {
     // 检查超时
     if (isTimeout(job)) {
       archiveFailed(job);
     } else {
       queue.put(job);
     }
   }
   ```

3. **内存队列丢失**
   - 内存队列（LinkedBlockingQueue）在进程重启后会丢失
   - 数据库是持久化保障

## 4. 监控与告警

### 4.1 关键监控指标

| 指标 | 告警阈值 | 说明 |
|------|----------|------|
| 待打印任务数 | > 100 | 队列堆积 |
| 失败任务数 | > 10/小时 | 打印失败率上升 |
| 超时任务数 | > 1 | 出现超时任务 |
| 打印机离线数 | > 0 | 打印机不可用 |

### 4.2 告警建议

```yaml
# 打印系统监控配置建议
alerts:
  - name: "打印队列堆积"
    condition: "pending_count > 100"
    severity: "warning"

  - name: "打印失败率上升"
    condition: "failed_count_1h > 10"
    severity: "warning"

  - name: "打印任务超时"
    condition: "timeout_count > 0"
    severity: "critical"

  - name: "打印机离线"
    condition: "offline_printer_count > 0"
    severity: "critical"
```

### 4.3 日志关键词

| 关键词 | 含义 |
|--------|------|
| `Print task timeout` | 任务超时归档 |
| `Paper Out` | 缺纸 |
| `printer fault` | 打印机故障 |
| `retry after` | 延迟重试 |

## 5. 预防措施

### 5.1 日常维护

| 维护项 | 频率 | 说明 |
|--------|------|------|
| 纸张检查 | 每班次 | 接班前检查纸张 |
| 打印机清洁 | 每周 | 清洁打印头 |
| 碳带检查 | 每日 | 检查碳带余量 |
| 网络检查 | 每日 | 检查网络连接 |

### 5.2 配置检查

| 检查项 | 说明 |
|--------|------|
| 备用打印机 | 确保每台主打印机都有备用 |
| 队列配置 | 验证 primary/standby 配置正确 |
| 超时阈值 | 确认 30 分钟阈值符合业务需求 |

### 5.3 容量规划

| 指标 | 建议值 | 说明 |
|------|--------|------|
| 单队列任务上限 | 500 | 超过时告警 |
| 单打印机日处理量 | 2000 | 考虑高峰期 |
| 备用机比例 | 1:3 | 每 3 台主打印机配 1 台备用 |

## 6. 故障应急手册

### 场景：打印机完全不打印

**快速排查步骤**：

```
1. 检查电源
   ├── 打印机是否开机
   └── 指示灯是否亮

2. 检查连接
   ├── USB/网线是否松动
   ├── 网络是否通畅 (ping)
   └── 驱动是否正常

3. 检查纸张
   ├── 是否有纸
   └── 是否卡纸

4. 检查队列
   ├── 是否有任务堆积
   └── 是否有失败任务

5. 检查服务
   ├── PrinterWorker 是否运行
   └── 服务日志是否有异常
```

**临时方案**：

1. 切换到备用打印机
2. 使用其他打印机临时打印
3. 手动记录任务，后续补打
