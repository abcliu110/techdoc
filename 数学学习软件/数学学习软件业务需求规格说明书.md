# 数学学习软件业务需求规格说明书

## 1. 业务目标

系统通过情境、操作、表示转换、猜想、验证、迁移和反思，培养小学到初中学生的数学思维，而不是以刷题数量为主要目标。

## 2. 用户角色

### 学生

使用学习活动形成数学思想，完成探索、表达、验证、迁移和反思。

### 家长

查看学习进展、能力变化、常见障碍和建议，不仅查看分数。

### 教师

查看班级或学生的思维证据，识别错误模式，布置思想主线和迁移任务。

### 内容专家

设计数学思想、学习单元、问题情境、提示、反例和评价标准。

## 3. 核心业务对象

- 数学思想：抽象、数形结合、转化、分类、归纳、方程、函数、建模、推理等。
- 能力维度：观察、表示、比较、猜想、验证、解释、迁移、反思。
- 知识点：课程内容中的可学习主题。
- 学习单元：围绕一个思想目标组织的完整学习活动。
- 学习会话：学生一次进入并完成或中断学习单元的过程。
- 学习证据：学生的操作、答案、解释、提示使用和迁移表现。
- 能力画像：根据长期证据形成的学生能力状态。

## 4. 业务原则

1. 先理解关系，再压缩为算法。
2. 同一思想必须在多个情境中出现。
3. 正例、反例和边界必须同时存在。
4. 学生的解释和迁移比单次答对更重要。
5. 提示是教学支架，不应直接替代思考。
6. 学习结果必须可恢复、可追踪、可解释。

## 5. 核心业务流程

```text
选择思想或知识点
 → 进入学习单元
 → 观察情境
 → 完成操作或表达
 → 形成猜想
 → 验证猜想
 → 比较方法
 → 抽象结论
 → 完成迁移任务
 → 反思
 → 生成证据和能力更新
```

## 6. 业务规则

- “看过”不等于“掌握”。系统区分浏览、完成操作、能够解释、能够应用和能够迁移。
- 学习单元完成必须满足其核心目标和最低证据要求。
- 重复学习不能产生重复进度记录，必须按产品策略合并为最佳表现、最新表现和历史表现。
- 学习中断后可以恢复草稿；明确放弃后不计为完成。
- 成就只能由真实业务事件触发，不能由页面临时计算替代。
- 每个能力结论必须能够追溯到具体学习证据。

## 7. 能力成长阶段

```text
L0 未接触
L1 能观察现象
L2 能描述关系
L3 能进行表示
L4 能解释方法
L5 能验证结论
L6 能迁移到新情境
L7 能比较方法并自主建模
```

## 8. 业务成功指标

- 学生能在不同表示之间转换。
- 学生能解释“为什么这样做”。
- 学生能识别并修正典型错误。
- 学生能把思想迁移到未见过的问题。
- 学生的能力画像能被教师和家长理解并用于下一步教学。
