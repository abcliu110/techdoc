# 数学学习软件目标架构设计

## 1. 架构目标

架构必须支持数学思想持续扩展、内容专家持续增加学习单元、不同学习流程复用同一会话引擎，并保证学习结果可追踪、可恢复、可解释。

## 2. 分层

```text
presentation   页面、组件、UI 状态
application    开始会话、提交动作、完成会话、生成报告
domain         学习会话、评分、证据、能力和成就规则
content        数学思想、知识点和活动资源
infrastructure 数据库、文件、日志和平台适配
```

依赖只能由上层指向接口，领域层不得依赖 React、Zustand、Tauri 或 SQL。

## 3. 核心领域模型

```text
ThoughtModel        数学思想
LearningUnit        学习单元
LearningActivity    思维活动
LearningSession     学习会话
Evidence            学习证据
AbilityProfile      能力画像
Achievement         成就
```

## 4. 会话状态机

```text
Created -> InProgress -> Paused -> InProgress
InProgress -> Completed
Created/InProgress/Paused -> Abandoned
```

所有状态变更通过命令处理，完成会话生成领域事件：`SessionCompleted`、`EvidenceRecorded`、`ProgressUpdated`、`AchievementUnlocked`。

## 5. 应用用例

- `StartSession`：加载固定版本的学习单元并建立会话。
- `SubmitActivityAction`：验证动作、更新当前活动并生成证据。
- `RequestHint`：记录提示并返回下一层支架。
- `CompleteSession`：事务性保存答案、证据、进度、统计和成就。
- `ResumeSession`：恢复未完成会话。
- `BuildAbilityReport`：聚合证据形成能力报告。
- `BuildReviewPlan`：根据错误和未稳定能力生成复习任务。

## 6. 扩展点

```ts
stepRendererRegistry
visualizationRegistry
validatorRegistry
diagnosticRegistry
achievementRegistry
contentRegistry
```

新增能力优先注册，不修改页面分支。所有注册项必须带类型、版本和能力声明。

## 7. 数据一致性

完成会话使用事务写入答案、证据、进度、每日统计和成就。每次结算带 `sessionId` 和幂等键，重复请求返回已有结果。

## 8. 迁移原则

先统一会话模型，再接入应用用例；先迁移一个知识点验证完整链路，再批量迁移内容；旧数据通过适配器读取，不在页面中保留两套业务规则。
