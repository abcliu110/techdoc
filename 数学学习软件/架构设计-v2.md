# 数学学习软件 - 架构设计 v2

## 概述

本文档定义数学学习软件的干净架构，遵循以下核心原则：
1. **组件能力决定数据结构** - 先明确组件能做什么，再设计数据格式
2. **隔离性** - 各步骤完全独立，不共享状态
3. **模块化** - 每个步骤类型独立管理，不超过 300 行

---

## 一、组件能力矩阵

| 步骤类型 | 揭示模式 | 选择模式 | 自动模式 | 可视化类型 |
|---------|---------|---------|---------|-----------|
| **ConcreteStep** | ✅ | ❌ | ✅ (部分 kind) | split, guess, animal, balance, segment |
| **PictorialStep** | ✅ | ✅ | ❌ | fraction, animal, segment, text |
| **VerbalStep** | ✅ | ❌ | ❌ | keywords, follow-up questions |
| **SymbolicStep** | ✅ | ❌ | ❌ | fraction, equation |
| **ApplicationStep** | ❌ | ✅ | ❌ | choice, input (变式练习) |
| **ReflectionStep** | ❌ | ✅ | ❌ | self-assessment, summary |

### 模式定义

```typescript
// 揭示模式 (reveal): 无需用户输入
// - 显示内容 → 点"查看答案/提示" → 显示结论 → 点"我理解了"

// 选择模式 (choice): 有选项
// - 显示题目 → 选择 → 提交 → 显示对错 → 点"继续"

// 自动模式 (auto): 直接完成
// - 显示内容 → 自动揭示 → 点"我理解了"
```

## 二、组件能力详情

### 1. ConcreteStep (具象操作)

**支持的可视化类型 (kind)**:
- `split` - 分割圆形，自动完成
- `guess` - 猜数游戏，揭示模式
- `animal` / `chicken` - 鸡兔同笼，自动揭示
- `balance` - 天平图示，揭示模式
- `segment` - 线段图示，揭示模式

**模式支持**:
- 自动模式: kind=split 时直接完成
- 揭示模式: kind=guess/balance/segment 时需要点击揭示

**数据结构约束**:
```typescript
interface ConcreteContent {
  type: 'concrete';
  scenario: {
    title: string;
    description: string;
    emoji: string;
  };
  interaction: {
    kind: 'drag' | 'tap' | 'draw' | 'split' | 'guess' | 'animal' | 'balance' | 'segment';
    target: string;
    onComplete?: string;
  };
}
```

### 2. PictorialStep (图示表达)

**支持的可视化类型**:
- `fraction` - 分数圆形图
- `animal` - 鸡/兔图标
- `segment` - 线段图
- `text` - 纯文本

**模式支持**:
- 揭示模式: 无 `visualOptions` 时
- 选择模式: 有 `visualOptions` 时

**数据结构约束**:
```typescript
interface PictorialContent {
  type: 'pictorial';
  fromRepresentation: string;
  toRepresentation: string;
  task: {
    instruction: string;
    allowInteraction: boolean;
    showAnswer: boolean;
  };
  visualOptions?: string[];  // 有选项时为选择模式，无选项时为揭示模式
}
```

### 3. VerbalStep (语言描述)

**模式**: 仅揭示模式

**数据结构约束**:
```typescript
interface VerbalContent {
  type: 'verbal';
  prompts: string[];
  expectedKeywords: string[];
  allowCustomAnswer: boolean;
  followUpQuestions?: string[];
}
```

### 4. SymbolicStep (符号表示)

**模式**: 仅揭示模式

**数据结构约束**:
```typescript
interface SymbolicContent {
  type: 'symbolic';
  fromPictorial: boolean;
  task: {
    instruction: string;
    exampleSymbol?: string;
    format?: string;
  };
}
```

### 5. ApplicationStep (灵活应用)

**模式**: 仅选择/填空模式

**数据结构约束**:
```typescript
interface ApplicationContent {
  type: 'application';
  variants: VariantItem[];
}

interface VariantItem {
  type: 'same-form' | 'different-scenario' | 'reverse' | 'comprehensive';
  instruction: string;
  question: {
    type: 'choice' | 'input';
    question: string;
    options?: string[];
    correctAnswer: string;
    explanation: string;
  };
}
```

### 6. ReflectionStep (反思内化)

**模式**: 选择 + 自我评估模式

**数据结构约束**:
```typescript
interface ReflectionContent {
  type: 'reflection';
  prompts: string[];
  selfAssessment: {
    enabled: boolean;
    scale: number;
  };
  summaryTemplate?: string;
}
```

## 三、隔离性原则

每个步骤组件必须满足以下隔离性要求：

### 3.1 状态隔离

```typescript
// 每个步骤的状态完全独立
interface ConcreteStepState {
  revealed: boolean;  // 仅当前步骤可见
}

interface PictorialStepState {
  selected: number | null;  // 仅当前步骤可见
  submitted: boolean;
  revealed: boolean;
}
```

### 3.2 渲染隔离

- **Pure 函数**: 给定相同数据，总有相同输出
- **无副作用**: 组件内不使用全局变量存储步骤状态
- **Props 驱动**: 组件之间的通信只通过 props/callbacks

### 3.3 验证隔离

- 每个步骤的 `completeCriteria` 验证只在本步骤内进行
- 不依赖其他步骤的状态

### 3.4 变量作用域

```typescript
// ✅ 正确：变量在组件作用域内
const ConcreteStep: React.FC<Props> = ({ content }) => {
  const kind = content.interaction.kind;  // 本地变量
  // ...
};

// ❌ 错误：使用全局变量
let globalRevealed = false;  // 禁止
```

## 四、模块化原则

### 4.1 目录结构

```
src/components/steps/
├── index.ts                    # 统一导出
├── StepContainer.tsx           # 状态管理钩子
├── StepProgress.tsx            # 进度条组件
├── ConcreteStep.tsx            # 具象操作 (< 300 行)
├── ConcreteStep.css            # 独立样式
├── PictorialStep.tsx           # 图示表达 (< 300 行)
├── PictorialStep.css           # 独立样式
├── VerbalStep.tsx              # 语言描述 (< 150 行)
├── VerbalStep.css              # 独立样式
├── SymbolicStep.tsx            # 符号表示 (< 150 行)
├── SymbolicStep.css            # 独立样式
├── ApplicationStep.tsx         # 灵活应用 (< 150 行)
├── ApplicationStep.css         # 独立样式
├── ReflectionStep.tsx          # 反思内化 (< 200 行)
├── ReflectionStep.css          # 独立样式
├── SplitCircle.tsx             # 可视化组件
├── SplitCircle.css             # 独立样式
└── BoxGuess.tsx                # 可视化组件
```

### 4.2 组件职责

| 组件 | 职责 | 行数限制 |
|-----|------|---------|
| ConcreteStep | 渲染具象操作场景 | < 350 行 |
| PictorialStep | 渲染揭示/选择模式 | < 270 行 |
| VerbalStep | 渲染引导问题 | < 150 行 |
| SymbolicStep | 渲染符号示例 | < 150 行 |
| ApplicationStep | 渲染变式练习 | < 150 行 |
| ReflectionStep | 渲染自我评估 | < 200 行 |

### 4.3 可视化组件隔离

可视化组件独立管理，不被步骤组件直接调用：

```
src/components/steps/
├── visualizations/             # 可视化组件目录
│   ├── SplitCircle.tsx         # 分割圆形
│   ├── SplitCircle.css
│   ├── BoxGuess.tsx            # 猜数游戏
│   ├── BoxGuess.css
│   ├── BalanceScale.tsx        # 天平图
│   ├── BalanceScale.css
│   ├── SegmentDiagram.tsx      # 线段图
│   └── SegmentDiagram.css
```

**重要**: 如果 `ConcreteStep.tsx` 超过 350 行，必须将内联的可视化逻辑拆分为独立的可视化组件。

## 五、数据结构定义

### 5.1 步骤数据格式

```typescript
interface LearningStep {
  id: string;
  type: StepType;
  name: string;
  instruction: string;
  content: StepContent;
  completionCriteria: CompletionCriteria;
  adaptive?: AdaptiveConfig;
}
```

### 5.2 模式检测

```typescript
function detectStepMode(content: StepContent): StepMode {
  // ConcreteStep
  if (content.type === 'concrete') {
    const kind = content.interaction.kind;
    if (kind === 'split') return { type: 'auto' };
    return { type: 'reveal' };
  }

  // PictorialStep
  if (content.type === 'pictorial') {
    return content.visualOptions?.length
      ? { type: 'choice' }
      : { type: 'reveal' };
  }

  // 其他步骤...
  return { type: 'reveal' };
}
```

## 六、渲染流程

```
用户进入学习页面
       ↓
获取知识点数据 (steps[])
       ↓
按六步顺序排序: concrete → pictorial → verbal → symbolic → application → reflection
       ↓
渲染当前步骤组件
       ↓
┌─────────────────────────────────────────────┐
│  ConcreteStep                               │
│  ├── kind=split → Auto → 自动完成            │
│  └── kind=guess → Reveal → 点击揭示          │
├─────────────────────────────────────────────┤
│  PictorialStep                              │
│  ├── 无 visualOptions → Reveal 模式         │
│  └── 有 visualOptions → Choice 模式         │
├─────────────────────────────────────────────┤
│  VerbalStep → Reveal 模式                   │
├─────────────────────────────────────────────┤
│  SymbolicStep → Reveal 模式                 │
├─────────────────────────────────────────────┤
│  ApplicationStep → Choice 模式              │
├─────────────────────────────────────────────┤
│  ReflectionStep → Assessment 模式           │
└─────────────────────────────────────────────┘
       ↓
步骤完成 → 显示结果 → 进入下一步
```

## 八、设计约束

### 8.1 禁止事项

1. **禁止**在数据中写"组件不支持"的内容
2. **禁止**在步骤组件内使用全局变量
3. **禁止**组件之间通过共享状态通信
4. **禁止**单个组件文件超过 350 行
5. **禁止**将多个可视化类型塞入同一个组件

### 8.2 必须事项

1. 每个步骤类型必须有独立的 CSS 文件
2. 每个步骤组件必须是 pure 函数
3. 验证逻辑必须在组件内部完成
4. 组件 Props 必须明确定义类型

## 九、后续改造建议

如果需要增强组件能力：

1. **ConcreteStep 拆分建议**: 当 `kind` 类型超过 5 种时，考虑拆分为：
   - `SplitCircleStep`
   - `GuessNumberStep`
   - `AnimalCageStep`
   - `BalanceScaleStep`
   - `SegmentDiagramStep`

2. **PictorialStep 拆分建议**: 当需要更多可视化类型时，考虑拆分为：
   - `PictorialRevealStep` - 揭示模式
   - `PictorialChoiceStep` - 选择模式

3. **验证框架**: 将 `completeCriteria` 验证逻辑抽取为独立模块：
   ```typescript
   // src/components/steps/validators/
   const validators = {
     concrete: validateConcreteStep,
     pictorial: validatePictorialStep,
     // ...
   };
   ```
