# 数学思维启发型学习系统业务设计

## 1. 产品使命

本软件不是题库、作业批改器或刷题排行榜，而是一个帮助小学到初中学生形成数学思维的交互式学习系统。

核心目标是让学生逐渐具备以下能力：

- 从具体现象中发现数量、空间和变化关系。
- 使用图形、语言、表格、符号等方式表示同一个问题。
- 通过比较、分类、归纳、猜想和验证形成概念。
- 将陌生问题转化为已知问题。
- 理解方法为什么成立，以及什么时候不成立。
- 用不同方法解决同一个问题。
- 发现错误原因并主动修正。
- 将数学思想迁移到新的题型和生活情境。

产品价值不以“做题数量”定义，而以学生是否形成可观察、可解释、可迁移的数学能力定义。

## 2. 核心业务闭环

```text
数学思想
  ↓
思维目标
  ↓
问题情境
  ↓
操作与观察
  ↓
多重表示
  ↓
比较、猜想与验证
  ↓
抽象为概念或模型
  ↓
变式与迁移
  ↓
表达、反思与诊断
  ↓
形成个人数学能力画像
```

每个学习单元都必须能够回答：学生正在理解什么思想、通过什么活动理解、如何证明已经理解、如何迁移到新问题。

## 3. 数学思想地图

### 3.1 数与运算

- 数感与量感。
- 单位统一。
- 分类与比较。
- 运算意义与逆运算。
- 整体与部分。
- 估算与合理性检验。
- 转化与化归。
- 数形结合。

### 3.2 关系与代数

- 抽象与符号化。
- 等量关系与平衡。
- 变量与对应。
- 变化与函数。
- 方程模型。
- 代数式的结构。
- 归纳与演绎。
- 逆向思考。

### 3.3 空间与图形

- 空间观念。
- 图形分解与组合。
- 位置和方向。
- 对称与变换。
- 度量与单位。
- 面积、周长、体积模型。
- 坐标与几何关系。
- 几何推理和证明。

### 3.4 数据与不确定性

- 数据收集与分类。
- 图表表示。
- 平均与比较。
- 趋势与波动。
- 样本与整体。
- 随机性与概率。
- 证据和结论。
- 数据误导识别。

### 3.5 逻辑、推理与建模

- 条件与结论。
- 必要条件与充分条件。
- 分类讨论。
- 假设与验证。
- 反例。
- 反证和排除。
- 数学模型。
- 方法迁移。

这些思想不是按年级割裂的知识点，而是贯穿小学和初中的能力主线。一个知识点可以连接多个思想，一个思想也必须在多个知识领域中反复出现。

## 4. 数学思想的多维拆解模型

每个数学思想至少从以下维度设计学习活动：

| 维度 | 业务问题 |
|---|---|
| 直观操作 | 学生能否看见、移动、分割或组合对象？ |
| 语言表达 | 学生能否用自己的话解释关系？ |
| 图形表示 | 学生能否画出或识别结构？ |
| 表格表示 | 学生能否整理数量和变化？ |
| 符号表示 | 学生能否把关系压缩为算式或方程？ |
| 比较变化 | 学生能否发现什么改变、什么不变？ |
| 逆向思考 | 学生能否从结果反推条件？ |
| 反例验证 | 学生能否找到不成立的情况？ |
| 方法比较 | 学生能否判断不同方法的优缺点？ |
| 迁移应用 | 学生能否在新情境中使用思想？ |
| 反思诊断 | 学生能否说出方法和错误原因？ |

只有同时覆盖多个维度，学习单元才可能形成理解，而不是停留在记忆算法。

## 5. 学习单元设计规范

每个单元使用统一的业务模板：

```text
单元名称
核心数学思想
关联思想
学习目标
前置经验
具体情境
操作任务
观察问题
表示转换
猜想任务
验证任务
抽象结论
反例任务
变式任务
迁移任务
常见误解
反思问题
评价证据
```

例如“分数大小比较”不应只设计为“比较两个分数并选择答案”，而应围绕以下主线：

```text
看图猜大小
  → 发现图形单位不同
  → 尝试统一单位
  → 比较同单位数量
  → 连接通分或交叉相乘
  → 讨论两种方法的共同本质
  → 设计容易误判的反例
  → 在面积、价格、速度中迁移
```

## 6. 软件中的学习活动类型

系统不以“题目类型”组织活动，而以“思维动作”组织活动。

### 6.1 观察活动

让学生从图形、动画、数据和情境中寻找变化和不变量。

### 6.2 表示活动

让学生把同一问题转换为图形、文字、表格、算式或方程。

### 6.3 比较活动

让学生比较多个例子、多个方法和多个表示，寻找本质差异。

### 6.4 猜想活动

让学生先预测规律或结果，再进行验证。系统应保留猜想，而不是只记录最终答案。

### 6.5 操作活动

通过拖动、分割、拼接、配对、调节参数和构造图形形成直观经验。

### 6.6 验证活动

通过代入、测量、画图、枚举、反例、推导或实验判断猜想是否成立。

### 6.7 多解活动

鼓励学生使用不同方法，并比较方法的适用条件、效率和解释力。

### 6.8 迁移活动

将已经形成的思想迁移到不同数字、图形、学科情境和生活问题中。

### 6.9 反思活动

让学生说明使用了什么思想、为什么有效、哪里可能失效、如何改进。

## 7. 学习流程设计原则

六步或八步都只能作为表现形式，不能成为业务目标。建议统一为以下可变流程：

```text
进入情境
  ↓
自主观察
  ↓
尝试表示
  ↓
提出猜想
  ↓
操作或验证
  ↓
比较方法
  ↓
抽象概括
  ↓
变式迁移
  ↓
表达反思
```

不同学生可以从不同入口开始，也不要求每个单元机械执行完全相同的步骤。流程应根据学习目标、学生表现和错误类型动态调整。

## 8. 反馈与个性化

反馈不应只说“正确”或“错误”，而应指出学生当前表现的思维层级：

```text
看到了现象
能够描述现象
能够表示关系
能够解释方法
能够验证结论
能够迁移方法
能够比较多种方法
```

系统需要区分以下情况：

- 不会开始：缺少观察入口。
- 表示错误：没有建立对应关系。
- 方法正确但无法解释：程序性掌握未形成概念理解。
- 当前题目正确但迁移失败：理解范围过窄。
- 反复出现同一错误：存在稳定的错误模式。
- 使用提示后完成：能力正在形成，但还不稳定。

个性化不是简单降低题目难度，而是改变支持方式：增加图形、提供比较对象、拆分关系、引入反例、减少无关信息或要求重新表达。

## 9. 评价体系

### 9.1 不以刷题量为核心指标

题数、时长和正确率只能作为辅助数据，不能代表数学理解。

### 9.2 评价思维证据

系统应记录：

- 是否主动选择表示方式。
- 是否能发现关系。
- 是否能解释关系。
- 是否能提出或修正猜想。
- 是否能使用反例。
- 是否能比较方法。
- 是否能迁移到新情境。
- 使用了多少提示。
- 错误是否重复出现。
- 是否能反思和自我纠正。

### 9.3 学生画像

学生报告应呈现能力结构，例如：

```text
优势：能够使用图形发现数量关系，能解释基本运算意义。
发展中：能够在熟悉题型中使用方程，但迁移到文字情境时不稳定。
常见障碍：比较分数时忽略单位统一，遇到变化问题时只关注静态结果。
下一步建议：通过面积、速度和比例情境继续训练单位统一和变化关系。
```

## 10. 产品信息架构

系统可以同时提供三种入口：

### 10.1 按内容学习

数与运算、代数、几何、统计与概率等课程路径。

### 10.2 按数学思想学习

抽象、数形结合、转化、分类、归纳、方程、函数、建模、推理等思想路径。

### 10.3 按个人问题学习

根据学生的错误模式、薄弱能力和未完成迁移任务生成学习路径。

知识点不是孤立卡片，而应是思想网络中的节点：

```text
一元一次方程
├── 抽象
├── 等量关系
├── 逆向思考
├── 转化
├── 模型
└── 验证
```

## 11. 业务上必须避免的问题

- 把动画数量误当成理解深度。
- 把“点击我理解了”当成掌握证据。
- 把八步流程机械套用到所有知识点。
- 用星星、排行榜和连续打卡驱动刷题行为。
- 只展示正确例子，不展示反例和边界。
- 只训练答案，不要求表达理由。
- 只在同一题型内练习，不安排跨情境迁移。
- 只统计对错，不记录错误原因和思维过程。
- 只按年级组织内容，不建立数学思想之间的联系。

## 12. 第一阶段落地范围

不建议一开始覆盖全部小学和初中内容。应先选择 3 至 5 条核心思想主线，做出完整闭环：

1. 数形结合。
2. 单位统一与比较。
3. 整体与部分。
4. 转化与化归。
5. 等量关系与方程。

每条主线选择数、式、图形和应用问题各一个单元，验证学生是否能从直观活动走向抽象表达，再迁移到新情境。

第一阶段的成功标准不是题库数量，而是：

- 学生能够解释核心思想。
- 学生能够在不同表示之间转换。
- 学生能够识别并修正典型错误。
- 学生能够将思想迁移到未见过的问题。
- 教师或家长能够看懂学生的能力变化。

## 13. 最终业务定义

这个软件的本质是一个“数学思想实验室”和“思维成长记录系统”。

它通过丰富情境让学生观察，通过多种表示让学生建立联系，通过猜想和验证让学生形成推理，通过变式和迁移让学生超越题型，通过反思和诊断让学生逐渐认识自己的思维方式。

软件的最终交付物不是一组题目和分数，而是学生逐步形成的数学思维结构：

```text
能观察
能表示
能比较
能抽象
能推理
能验证
能转化
能建模
能迁移
能反思
```
