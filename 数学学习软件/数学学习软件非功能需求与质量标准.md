# 数学学习软件非功能需求与质量标准

## 1. 可维护性

- 领域规则与 React、Zustand、SQLite 解耦。
- 新增步骤、可视化和数学思想通过注册接口扩展。
- 核心目录启用 TypeScript 严格模式，禁止新增无说明的 `any`。
- 每个公共业务接口有类型、错误模型和测试。
- 重大架构变化记录 ADR。

## 2. 可扩展性

- 内容模型支持版本化和 schema 校验。
- 学习单元不绑定固定六步或八步，步骤由内容配置决定。
- 渲染器、验证器、可视化和成就采用注册表。
- 知识点内容可按领域、年级和思想模块化加载。

## 3. 可靠性

- 学习结算多表写入具备事务或可恢复机制。
- 重复提交、重复解锁和重复结算必须幂等。
- 数据库失败时显示可恢复状态，不显示伪成功。
- 应用重启后恢复已保存会话和进度。

## 4. 性能

- 首屏不加载全部知识点和可视化组件。
- 学习页面首次可交互时间目标不超过 2 秒（目标设备范围另行定义）。
- 交互反馈在 100ms 内完成本地响应。
- 大型历史报告采用分页、聚合或缓存。

## 5. 安全与隐私

- 学习记录只能由对应用户访问。
- 生产环境不输出答案、完整反思文本和用户标识。
- 用户输入限制长度并经过规范化。
- 提供数据导出、删除和本地备份机制。

## 6. 可测试性

- 领域规则可脱离浏览器单元测试。
- 应用用例有数据库集成测试。
- 主流程有端到端测试。
- 内容 schema 校验纳入 CI。

## 7. 可观测性

- 记录会话开始、提交、失败、恢复和结算事件。
- 日志包含操作、会话 ID、知识点 ID和错误码。
- 日志不能包含不必要的隐私数据。

## 8. 国际化与无障碍

- 用户可见文案不得散落在业务逻辑中。
- 交互不能只依赖颜色、声音或动画。
- 支持键盘操作、文本替代和合理的动画减弱模式。
