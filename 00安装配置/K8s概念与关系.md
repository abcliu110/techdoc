# K8s + K3s + Rancher 概念与关系

## 一、容器技术概述

### 1.1 什么是容器

容器是一个轻量级的虚拟化技术，与虚拟机相比：
- 共享宿主机内核，启动快（秒级）
- 占用资源少（MB 级）
- 镜像小（KB~GB 级）

### 1.2 Docker 与容器运行时

Docker 是最流行的容器运行时：

```
应用 → Docker 容器 → 宿主机操作系统 → 硬件
```

**容器运行时职责**：
- 创建/删除容器
- 分配资源（CPU、内存）
- 网络管理
- 存储管理

常见容器运行时：Docker、containerd、CRI-O

---

## 二、Kubernetes（K8s）

### 2.1 什么是 Kubernetes

Kubernetes（K8s）是 Google 开源的**容器编排引擎**：

```
┌─────────────────────────────────────────────────┐
│                  Kubernetes 集群                   │
├─────────────────────────────────────────────────┤
│  Master 节点（控制平面）                          │
│  ├── API Server（API 入口）                      │
│  ├── etcd（数据存储）                            │
│  ├── Scheduler（调度器）                         │
│  └── Controller Manager（控制器管理器）            │
├─────────────────────────────────────────────────┤
│  Worker 节点                                    │
│  ├── kubelet（与 Master 通信）                   │
│  ├── kube-proxy（网络代理）                      │
│  └── 容器运行时（Docker/containerd）             │
└─────────────────────────────────────────────────┘
```

### 2.2 K8s 核心概念

#### Pod
- K8s 最小调度单元
- 由一个或多个容器组成
- 共享网络和存储

```
Pod
├── 容器1（Nginx）
└── 容器2（应用）
```

#### Deployment
- 管理 Pod 的副本数
- 支持滚动更新
- 支持回滚

#### Service
- 为 Pod 提供稳定的访问入口
- 负载均衡
- 服务发现

#### Ingress
- HTTP/HTTPS 路由
- 基于域名的访问控制

### 2.3 K8s 的价值

| 能力 | 说明 |
|------|------|
| **自愈** | 容器失败自动重启 |
| **扩缩容** | 根据负载自动调整副本数 |
| **滚动更新** | 零 downtime 更新应用 |
| **服务发现** | 自动注册和发现服务 |
| **负载均衡** | 内置 L4/L7 负载均衡 |

## 三、K3s

### 3.1 什么是 K3s

K3s 是 Rancher 开发的**轻量级 K8s 发行版**：

```
标准 K8s                    K3s
├── etcd                    ├── SQLite（默认）
├── Docker                  ├── containerd（内置）
├── kube-proxy              ├── kube-proxy（内置）
├── CNI                     ├── Flannel（内置）
├── Metrics Server          └── Metrics Server（内置）
└── ...                     └── 全部二进制 < 100MB
```

### 3.2 K3s vs 标准 K8s

| 特性 | 标准 K8s | K3s |
|------|----------|-----|
| 内存占用 | 2GB+ | 512MB |
| 磁盘占用 | 10GB+ | 1GB |
| 二进制大小 | 数百 MB | < 100MB |
| 安装复杂度 | 高 | 低（一行命令） |
| 适用场景 | 生产集群 | 开发/边缘/IoT/单节点 |

### 3.3 K3s 架构

```
K3s Server（Master）
├── API Server
├── Scheduler
├── Controller Manager
├── etcd/SQLite
├── containerd
└── Flannel CNI

K3s Agent（Worker）
├── kubelet
├── kube-proxy
└── containerd
```

## 四、Rancher

### 4.1 什么是 Rancher

Rancher 是一个**企业级 K8s 管理平台**，提供 Web UI：

```
┌─────────────────────────────────────────────────┐
│               Rancher Web UI                     │
├─────────────────────────────────────────────────┤
│  集群管理        │  用户管理                     │
│  工作负载        │  监控告警                     │
│  存储卷         │  权限控制                      │
│  网络/ Ingress   │  应用商店（Helm）              │
└─────────────────────────────────────────────────┘
```

### 4.2 Rancher 的价值

| 能力 | 说明 |
|------|------|
| **多集群管理** | 一个界面管理多个 K8s 集群 |
| **权限控制** | 基于角色的访问控制（RBAC） |
| **应用商店** | 一键部署常用应用 |
| **监控告警** | 内置 Prometheus/Grafana |
| **多云支持** | 支持 EKS/AKS/GKE 等云 K8s |

### 4.3 Rancher 与 K3s 的关系

```
Rancher
   │
   ├── 管理集群1（K3s）
   ├── 管理集群2（K3s）
   └── 管理集群3（标准 K8s）
```

Rancher 可以管理多个 K8s 集群，包括 K3s 和标准 K8s。

```
                              │

                             │ API
                             ▼
┌─────────────────────────────────────────────────────────────┐
│              Kubernetes（K8s/K3s）                          │

│    │  ├── API Server                                 │       │
│    │  ├── Scheduler                                 │       │
│    │  ├── Controller Manager                        │       │
│    │  └── etcd/SQLite（数据存储）                    │       │
│    └────────────────────────────────────────────────┘       │
│    ┌────────────────────────────────────────────────┐       │
│    │  Worker 节点                                    │       │
│    │  ├── kubelet（与 Master 通信）                  │       │
│    │  ├── kube-proxy（网络代理）                     │       │

│    └────────────────────────────────────────────────┘       │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│                   容器（Container）                          │
│              应用运行在隔离的环境中                           │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 数据流向

```
用户请求
   │
   ▼
Ingress/Nginx（入口）
   │
   ▼
Service（服务发现 + 负载均衡）
   │
   ▼
Pod（容器组）
   │
   ├── 容器1（应用）
   └── 容器2（辅助）
```

### 5.3 Rancher 安装依赖链

```
安装 Rancher 依赖：
1. Kubernetes（K3s）- 提供容器编排能力
2. cert-manager - 管理 TLS 证书
3. Rancher - 提供 Web 管理界面
```

## 六、类比记忆

### 6.1 操作系统类比

| 真实世界 | 容器技术 | 说明 |
|----------|----------|------|
| 手机系统 | Docker | 底层运行环境 |

### 6.2 物流类比

| 物流概念 | 容器概念 | 说明 |
|----------|----------|------|
| 集装箱 | Container | 标准化的货物包装 |
| 码头 | Docker | 装卸集装箱 |
| 物流调度中心 | Kubernetes | 规划运输路线 |
| 小型调度中心 | K3s | 资源受限环境 |
| 物流管理系统 | Rancher | 监控和调度 |

## 八、快速参考

### 8.1 组件对照表

| 组件 | 全称 | 作用 |
|------|------|------|
| Docker | - | 容器运行时（传统） |
| containerd | Container Daemon | K8s 默认容器运行时 |
| K3s | Kubernetes Less | 轻量级 K8s |
| etcd | - | K8s 分布式数据库 |
| kubelet | Kubernetes Agent | Node 代理 |
| kube-proxy | - | 网络代理 |
| Rancher | - | K8s 管理平台 |
| Helm | - | K8s 包管理器 |
| cert-manager | - | TLS 证书管理 |

### 8.2 端口要求

**Master 节点**：
- 6443: API Server
- 2379: etcd 客户端
- 2380: etcd 对等通信

**Worker 节点**：
- 10250: kubelet API
- 30000-32767: NodePort 范围

**Rancher**：
- 443: HTTPS 管理界面
- 80: HTTP 重定向
