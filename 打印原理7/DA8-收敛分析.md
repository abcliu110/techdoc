## 二、未覆盖项

| 项 | 原因 | 影响 |
|----|------|------|
| 微信物流打印机 | 属于微信小程序物流能力，与 POS 打印体系独立 | 不影响 POS 打印分析 |
| 排队打印消费 | 排队叫号场景，打印逻辑简单且独立 | 不影响 POS 打印分析 |
| WMS 打印单据 | 属于 WMS 库存模块，打印场景独立 | 不影响 POS 打印分析 |
| 短信任务 | 属于短信通知，非物理打印 | 不影响 POS 打印分析 |
| 物理打印机驱动 DLL 细节 | 限于接口说明，不涉及底层驱动开发 | 不影响业务理解 |
| 运行日志/Trace 验证 | 无运行环境访问权限 | 所有结论限定为"源码显示可能" |

## 三、风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| `.job` 文件磁盘空间满 | 低 | 高（新任务无法创建） | 需确认清理策略，建议定期清理已完成的 `.del` 文件 |
| 打印机状态检测不准确 | 中 | 中（任务分发到故障打印机） | 需确认状态检测机制，建议增加心跳检测 |
| 云打印机 API 变更 | 低 | 中（云打印不可用） | 第三方依赖，需监控 API 变更 |
| 打印样式配置错误导致内容缺失 | 中 | 低（容错策略默认显示） | 当前容错策略合理 |
| 并发打印任务积压 | 中 | 中（打印延迟） | 队列机制可缓冲，但需监控积压情况 |

## 四、深度八关自检（SC-P0：厨房联打印、结账顾客联打印）

### 厨房联打印

| 关 | 状态 | 说明 |
|---|------|------|
| ① 价值关 | ✅ | 厨房联确保厨师按单做菜，是餐饮 POS 核心履约环节，缺失会导致漏单、错菜 |
| ② 叙事关 | ✅ | 服务员点菜→系统按出品部门分发→厨房打印机出单→厨师按单做菜，删除技术名后仍完整 |
| ③ 轨迹关 | ✅ | 有事件（点菜/加菜/催菜/退菜）和状态变化（任务创建→初始化→分发→打印→完成） |
| ④ 规则关 | ✅ | 按出品部门分发、打印开关控制张数、条件过滤已退菜、主备打印机切换 |
| ⑤ 失败关 | ✅ | 打印机故障→切备机/重试/超时放弃；队列未配置→日志记录；样式不存在→日志记录 |
| ⑥ 影响关 | ✅ | 异步执行不阻塞核心业务；重打重新创建任务；修改配置热生效 |
| ⑦ 证据关 | ✅ | 所有关键断言有 E-SRC 证据，引用文件行号 |
| ⑧ 反例关 | ✅ | 竞争解释：是否所有菜品都需要厨房联？→ 打印开关可配置禁用；是否所有出品部门都有打印机？→ 部门必须配置队列 |

### 结账顾客联打印

| 关 | 状态 | 说明 |
|---|------|------|
| ① 价值关 | ✅ | 顾客小票是消费凭证，直接影响顾客信任和纠纷处理 |
| ② 叙事关 | ✅ | 收银员结账→系统按桌台/区域/桌型/PC 选队列→前台打印机出单→顾客接收小票→钱箱弹出 |
| ③ 轨迹关 | ✅ | 有事件（结账）和状态变化（支付完成→任务创建→分发→打印→钱箱弹出） |
| ④ 规则关 | ✅ | 顾客联队列优先级规则、打印开关控制张数、结账/点菜场景区分、条件过滤 |
| ⑤ 失败关 | ✅ | 打印机故障→切备机/重试；找不到设置→不打印（不影响结账）；打印失败→可重打 |
| ⑥ 影响关 | ✅ | 异步执行不影响结账完成；重打不改变已结账状态 |
| ⑦ 证据关 | ✅ | 所有关键断言有 E-SRC 证据 |
| ⑧ 反例关 | ✅ | 竞争解释：是否每次结账都需要顾客联？→ 开关可配置禁用；是否所有桌台都有对应设置？→ 找不到设置时跳过打印 |
