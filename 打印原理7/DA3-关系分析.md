# DA3 关系分析 — 打印子系统

> **分析视角**：从业务对象出发，不是从数据表出发
> **核心洞察**：最有价值的是对象之间的间接路径（3-4跳），而非表之间的直接引用（0跳）
> **模板依据**：SOP-00 §9.5.4 + §9.5.4a 合格范例（按 §0 执行前置强制对照）

## 一、业务对象识别

> 业务对象 ≠ 数据表，一个数据表可能承载多个业务对象

### 1.1 核心业务对象清单

| 对象编号 | 对象名称 | 业务定义 | 生命周期 | 边界 |
|----------|----------|----------|----------|------|
| BO-01 | 菜品 (DwdFood) | 顾客点的每道菜，决定"由哪个部门制作" | 点单创建→划菜→结账归档 | 不包含菜品基础资料（属菜品库），只含本单点菜事实 |
| BO-02 | 出品部门 (PosDept) | 后厨按菜系/制作方式划分的生产单元，是厨房联打印的分组边界 | 门店初始化创建→配置维护→停用 | 不包含传菜间/配菜间/利润部门（属 KDS/报表域） |
| BO-03 | 打印队列 (PosPrnQueue) | 一组主/备打印机的逻辑集合，是任务路由与容错的中间层 | 门店配置创建→维护→删除 | 不包含打印机物理状态（属打印机对象） |
| BO-04 | 打印机 (PosPrnPrinter) | 实际输出小票的物理设备，有健康状态 | 门店配置注册→运行→故障/删除 | 不包含打印任务内容（属任务对象） |
| BO-05 | 打印任务 (PosPrnJob) | 一次打印操作的完整记录，连接"业务事件"与"物理输出" | 业务触发创建→初始化→分发→打印完成 | 不包含模板定义（属样式对象） |
| BO-06 | 打印样式 (PosPrnStyleRow/Col) | 定义票据版式（行/列/条件/数据源），决定"打印成什么样" | 门店配置创建→编辑→删除 | 不包含打印数据（属任务对象） |
| BO-07 | 账单 (DwdBill) | 一桌顾客从开台到结账的消费记录，是顾客联打印的业务起点 | 开台创建→点菜→结账关闭 | 不包含支付流水（属支付域） |
| BO-08 | 顾客联设置 (PosCustomerBillSetting) | 决定"顾客联小票打印到哪个队列"，按桌台/区域/桌型/PC 分级 | 门店配置创建→维护→删除 | 不包含传菜联设置（属传菜域） |
| BO-09 | 传菜联设置 (PosWaiterBillSetting) | 决定"传菜小票打印到哪个队列"，按出品部门集合匹配 | 门店配置创建→维护→删除 | 不包含顾客联设置（属楼面域） |
| BO-10 | 打印开关 (PrintJobTypeSwitch) | 按单据类型控制"是否打印/打印几张"，是打印的闸门 | 门店配置创建→维护→删除 | 不包含样式版式（属样式对象） |

## 二、关键业务路径

> 必须包含至少 1 条 3 跳及以上的业务路径

### 2.1 核心业务路径图

```
菜品(BO-01) ──归属──▶ 出品部门(BO-02) ──关联──▶ 打印队列(BO-03) ──选择──▶ 打印机(BO-04)
     │                                                              │
     │                    业务起点：服务员点菜提交                    │
     └──────────────────────────────────────────────────────────────┘
                             输出：厨房小票（3跳路由）
```

### 2.2 路径与业务场景映射

| 路径编号 | 路径（对象→对象→...） | 跳数 | 关键业务场景 | 为什么需要这条路径 |
|----------|----------------------|------|-------------|-------------------|
| BP-01 | 菜品→出品部门→打印队列→打印机 | 3跳 | 厨房联打印：点菜后菜品按部门合单出票 | 按部门分组是后厨生产的自然边界，队列层提供主备容错 |
| BP-02 | 账单→顾客联设置→打印队列→打印机 | 3跳 | 顾客联打印：结账后按桌台/区域/桌型匹配出票 | 不同桌位区域需要不同打印机（前台/包间），不能账单直连打印机 |
| BP-03 | 账单→菜品→出品部门→打印队列→打印机 | 4跳 | 传菜联打印：划菜后按传菜间合并出票 | 一个账单含多部门菜品，需先按传菜间覆盖的部门集合分组再出票 |
| BP-04 | 业务事件→打印开关→打印任务→打印队列→打印机 | 4跳 | 开关闸门：类型被禁用（张数=0）则不产生任务 | 开关独立于业务代码，门店可随时启停某类票据 |

### 2.3 间接路径分析要点

**BP-01：菜品→出品部门→打印队列→打印机（3跳）**

1. **为什么需要经过中间对象**：
   - 出品部门承担**分组职责**：后厨按部门收单（热菜部/汤品部各打各的），菜品直连打印机无法按部门合单
   - 打印队列承担**路由与容错职责**：主/备打印机切换、负载均衡只能在队列层实现
2. **如果直接关联会怎样**：每道菜都要单独配打印机；新增/更换打印机要改所有菜；打印机故障无备机可切；无法按部门合单
3. **中间对象的业务语义**：出品部门=生产分组边界；打印队列=出单路由与容错点

## 四、关联关系详细契约

### REL-04：菜品 ↔ 打印机（间接关联，3 跳）【按 §9.5.4a 范例深度展开】

```
┌─────────────────────────────────────────────────────────────────┐
│ REL-04: 菜品 ↔ 打印机（间接关联，3 跳）                          │
├─────────────────────────────────────────────────────────────────┤
│ 【关系定义】                                                    │
│   类型：N:1（通过中间对象间接关联，运行时动态路由）              │
│   关联路径：直接（0跳）不存在，必须经过 3 跳                     │
│                                                                 │
│ 【关联路径】（共 3 跳）                                          │
│   菜品(DwdFood.prnDeptLid) → 出品部门(PosDept)                  │
│     → 打印队列(PosPrnQueue)                                     │
│     → 打印机(PosPrnPrinter)                                     │
│   证据：E-SRC: PrintJobGenerator.generateKitchenJob 中           │
│     1. 从 foods 读取 prnDeptLid → 查 posDeptServicePlus.listAll │
│     2. 部门.prnQueue 转换为 Set<Long> 队列 ID                   │
│     3. PosPrnQueueServicePlus.dispatchJob 选择健康打印机         │
│                                                                 │
│ 【为什么需要经过中间对象】（业务原因，至少 2 条）                │
│   1. 简化配置：只需为每个出品部门配置一个队列，而不是为每道菜    │
│      单独配置打印机；新菜只选部门即可，无需配打印机              │
│      （E-SRC: 菜品实体只有 prnDeptLid 字段，无 printer 字段）    │
│   2. 自然分组：同一部门的菜自动合打一张单，厨师按部门收单；      │
│      若菜品直连打印机，跨部门合单、换打印机都要改所有菜品        │
│   3. 故障转移：队列层配主/备打印机（primaryPrinter/standbyPrinter）│
│      ；若菜品直连打印机，打印机故障时无法自动切换（E-SRC:        │
│      PosPrnQueueServicePlus.selectHealthyPrinters）              │
│                                                                 │
│ 【如果直接关联（菜品→打印机）会怎样】                            │
│   新增/更换打印机需修改所有关联菜品配置；无法按部门合单；        │
│   打印机故障时无备机可切，只能靠重试                            │
│                                                                 │
│ 【中间对象职责】                                                │
│   出品部门：业务分组边界（什么菜归谁做，决定合单粒度）           │
│   打印队列：路由与容错（主/备打印机、随机负载均衡、健康过滤）    │
│                                                                 │
│ 【建立时机】                                                    │
│   配置时建立：菜品创建选部门、部门配置队列、队列绑定打印机       │
│   运行时路由：点菜提交时按部门动态分组并路由                     │
│                                                                 │
│ 【修改影响】                                                    │
│   修改菜品的部门 → 只影响新订单打印目标，历史任务不受影响        │
│   修改部门队列 → 热生效，下次厨房打印使用新队列                  │
│   修改队列打印机列表 → 新任务用新打印机，不影响在途任务          │
│                                                                 │
│ 【级联行为】                                                    │
│   删除菜品 → 不影响部门/队列/打印机                              │
│   删除部门配置 → 该部门菜品无法路由，分发失败（日志记录）        │
│   删除队列 → 关联部门菜品无法打印，任务失败                      │
│   删除打印机 → 队列自动切换备用，无备用则延迟重试                │
│                                                                 │
│ 【异常场景】                                                    │
│   场景1：菜品未配置部门（prnDeptLid 为空）→ 无法路由，跳过打印   │
│   场景2：部门未配置队列 → 分发日志"当前队列未设置打印机"         │
│   场景3：队列主备全故障 → 延迟 2 秒重试，45 分钟超时放弃         │
│                                                                 │
│ 【代码位置】                                                    │
│   后端：PrintJobGenerator.generateKitchenJob /                  │
│         PosPrnQueueServicePlus.dispatchJob / selectHealthyPrinters│
│   前端：PosDeptPage（部门→队列配置）                            │
└─────────────────────────────────────────────────────────────────┘
```

### REL-05：账单 ↔ 打印机（间接关联，3 跳）【顾客联打印核心路径】

```
┌─────────────────────────────────────────────────────────────────┐
│ REL-05: 账单 ↔ 打印机（间接关联，3 跳）                          │
├─────────────────────────────────────────────────────────────────┤
│ 【关系定义】                                                    │
│   类型：N:1（通过顾客联设置间接关联，运行时按优先级匹配）        │
│   关联路径：账单 → 顾客联设置 → 打印队列 → 打印机（3跳）         │
│                                                                 │
│ 【关联路径】                                                    │
│   账单(DwdBill.tableLid/areaLid/tableTypeLid + 设备 pc.lid)      │
│     → 顾客联设置(PosCustomerBillSetting)                         │
│     → 打印队列(prnQueue 逗号分隔队列ID)                          │
│     → 打印机(健康主/备)                                          │
│   证据：E-SRC: PrintJobGenerator.generateCustomerJob 中          │
│     1. 优先级匹配：桌台级 → 区域级 → 桌型级 → PC 级              │
│     2. 顾客来源 vs 非顾客来源使用不同优先级顺序                  │
│     3. forCheckout 区分结账/点菜场景                             │
│                                                                 │
│ 【为什么需要经过中间对象】（业务原因，至少 2 条）                │
│   1. 多级配置：不同桌台/区域/桌型需要不同打印机（大厅前台、      │
│      包间、外卖口），账单直连打印机无法表达这种分级配置          │
│   2. 场景区分：同一账单在"结账"和"点菜"场景可打印到不同队列，    │
│      由 forCheckout 字段区分                                    │
│                                                                 │
│ 【如果直接关联（账单→打印机）会怎样】                            │
│   每张桌/每个区域都要在账单上硬编码打印机；新增包间、调整区域    │
│   划分都要改账单逻辑；结账/点菜两种场景无法复用同一配置体系      │
│                                                                 │
│ 【中间对象职责】                                                │
│   顾客联设置：按业务场景（桌台/区域/桌型/PC + 结账/点菜）        │
│     解析出正确的打印队列集合                                    │
│   打印队列：主备容错与负载均衡                                   │
│                                                                 │
│ 【级联行为】                                                    │
│   删除顾客联设置 → 该桌台/区域找不到设置，不打印顾客联           │
│   （E-SRC: generateCustomerJob 找不到 setting 直接 return）      │
│   删除队列 → 设置引用的队列失效，分发失败                        │
│                                                                 │
│ 【异常场景】                                                    │
│   场景1：找不到任何顾客联设置 → 不打印顾客联（结账不受影响）     │
│   场景2：设置引用的队列未配打印机 → 分发失败，日志记录           │
│   场景3：打印机全故障 → 延迟重试（2秒），45分钟超时放弃          │
│                                                                 │
│ 【代码位置】                                                    │
│   后端：PrintJobGenerator.generateCustomerJob                    │
│   前端：PosCustomerBillSettingPage（nms4cloud-biz-ui）           │
└─────────────────────────────────────────────────────────────────┘
```

### REL-01：菜品 ↔ 出品部门（直接关系，0 跳）

```
┌─────────────────────────────────────────────────────────────────┐
│ REL-01: 菜品 ↔ 出品部门（直接关联）                              │
├─────────────────────────────────────────────────────────────────┤
│ 【关系定义】                                                    │
│   类型：N:1（归因链接：菜品指向其制作部门）                      │
│   关联路径：直接（0跳）                                          │
│   字段连接：DwdFood.prnDeptLid → PosDept.lid                     │
│                                                                 │
│ 【建立时机】                                                    │
│   点菜/加菜时由业务服务赋值（E-SRC: DwdFoodConvert/              │
│   DwdFoodOpsService），基础资料侧由菜品库配置                    │
│                                                                 │
│ 【约束条件】                                                    │
│   ✓ 一个菜品必须归属一个出品部门（否则厨房联无法路由）          │
│   ✓ 部门必须已配置打印队列（否则分发失败）                      │
│                                                                 │
│ 【使用方式】                                                    │
│   generateKitchenJob 遍历 foods 读取 prnDeptLid，按部门分组      │
│   创建打印任务                                                   │
│                                                                 │
│ 【修改影响】                                                    │
│   修改菜品部门：只影响新订单，历史任务使用创建时快照             │
│                                                                 │
```
