# 00-十分钟读懂 — 打印子系统

## 一句话业务本质

**NMS4Cloud 打印子系统是餐饮 POS 的"输出神经"——把业务事件（点菜、结账、交班）转化为物理小票，确保厨房按单做菜、顾客拿到凭证、收银有据可查。**

## 分析对象的业务位置

```
餐饮 POS 业务流：
点菜 → 厨房制作 → 传菜 → 结账 → 离店
  │        │          │       │
  └──┬─────┴─────┬────┴───┬──┘
     │           │        │
  厨房联       传菜联   顾客联
  (打印)       (打印)   (打印)
```

打印子系统不直接产生营收，但它是整个 POS 业务闭环的"最后一公里"——没有打印，厨房不知道做什么菜，顾客不知道付了多少钱，收银员无法交班。

## 范围与边界

**范围内**：
- 餐饮 POS 场景的打印：厨房联、传菜联、顾客联
- 打印配置管理：打印机、队列、样式、开关
- 打印任务监控

**范围外**：
- WMS 库存单据打印
- 排队叫号打印
- 短信通知
- 微信物流打印机

## 角色和责任

| 角色 | 在打印系统中做什么 |
|------|------------------|
| 服务员/收银员 | 点菜、结账时自动触发打印；查看打印状态、重打 |
| 厨师 | 接收厨房小票，按单做菜 |
| 传菜员 | 接收传菜小票，按单传菜 |
| 门店管理员 | 配置打印机、队列、样式、开关 |
| 顾客 | 接收小票 |

## 业务结果族

| 结果 | 谁触发 | 谁接收 | 失败后果 |
|------|--------|--------|---------|
| 厨房联 | 点菜/加菜/催菜 | 厨师 | 漏单、错菜 |
| 传菜联 | 划菜完成 | 传菜员 | 上错菜 |
| 顾客联 | 结账 | 顾客 | 投诉、纠纷 |
| 报表 | 交班/日结 | 店长 | 对账错误 |

## 一个主故事：厨房联打印

服务员小王在 POS 上给 3 号桌的客人点了"宫保鸡丁"和"酸辣汤"。

1. 小王提交点菜后，系统自动判断是否需要打印厨房联
2. 系统查看"宫保鸡丁"属于"热菜部"、"酸辣汤"属于"汤品部"
3. 系统为每个部门创建一个打印任务，发到对应的打印队列
4. 每个队列选择一台健康的打印机
5. 热菜部的打印机输出"宫保鸡丁"小票，汤品部的打印机输出"酸辣汤"小票
6. 两个部门的厨师同时看到小票，开始制作

整个过程不到 1 秒，小王继续为下一桌服务，完全不需要等待打印完成。

## 主要失败后果

- **打印机故障**：自动切换到备用打印机；全部故障时延迟重试，最多 45 分钟
- **打印任务失败**：不影响核心业务（点菜/结账），可在监控页面重打
- **配置错误**：样式或条件配置错误时，容错策略保证"宁可多打不可少打"

## 系统拥有与不拥有的事实

**系统拥有**：打印任务、打印队列、打印样式、打印机状态、打印次数
**系统不拥有**：业务订单数据（账单、菜品、支付）— 这些由业务模块维护
