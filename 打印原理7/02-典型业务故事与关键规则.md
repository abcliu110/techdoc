# 02-典型业务故事与关键规则 — 打印子系统

## 故事一：点菜后厨房联如何到达厨师

### 场景

中午 12 点，餐厅忙碌起来。服务员小王在 POS 机上给 3 号桌的 4 位客人点菜：宫保鸡丁、酸辣汤、回锅肉、米饭×2。

### 故事

小王在 POS 上选择菜品，点击提交。系统立即开始处理：

**第一步：判断要不要打印**

系统先检查"点菜单"这种类型的打印是否启用了厨房联。如果门店管理员在后台关掉了厨房联，或者设置了张数为 0，那就不打印。但今天没有关，默认打印 1 份。

**第二步：菜品分到哪个部门**

系统查看每道菜品的"出品部门"：
- 宫保鸡丁 → 热菜部
- 回锅肉 → 热菜部
- 酸辣汤 → 汤品部
- 米饭 → 主食部

每个出品部门都关联了一个打印队列。热菜部关联"热菜打印机"，汤品部关联"汤品打印机"，主食部关联"主食打印机"。

**第三步：创建打印任务**

系统为每个部门创建一个打印任务：
- 任务1：热菜部 → 打印"宫保鸡丁"和"回锅肉"
- 任务2：汤品部 → 打印"酸辣汤"
- 任务3：主食部 → 打印"米饭×2"

每个任务写入数据库，同时在本地磁盘生成一个 `.job` 文件。

**第四步：初始化任务内容**

系统加载"点菜单"的打印样式模板，把门店信息、账单信息、菜品明细填充到模板中，应用条件过滤（比如过滤掉已退菜的记录），生成最终的可打印行。

**第五步：分发到打印机**

系统查看热菜部的队列配置了哪些打印机。主打印机列表有 2 台，都正常，随机选一台。备打印机有 1 台，暂时用不上。

分发到选中的打印机 worker 线程。

**第六步：打印**

打印机 worker 读取 `.job` 文件，解析打印内容，通过打印机驱动发送指令。热菜部的打印机吐出小票，上面写着"3号桌 - 宫保鸡丁、回锅肉"。

汤品部和主食部的打印机也同时吐出各自的小票。

三个部门的厨师同时看到小票，开始制作。

整个过程不到 1 秒，小王已经去接待下一桌客人了。

### 关键规则

| 规则 | 说明 |
|------|------|
| 打印开关控制 | 门店可配置每种打印类型是否启用和张数 |
| 按出品部门分发 | 每个菜品属于一个部门，每个部门关联一个队列 |
| 主备打印机切换 | 主打印机故障时自动切换到备用打印机 |
| 异步执行 | 打印不阻塞点菜，创建任务后立即返回 |

### 失败场景

**如果热菜部的打印机坏了**：系统会自动切换到备用打印机。如果备用也坏了，系统会等 2 秒再试，持续 45 分钟。如果 45 分钟还不行，就放弃并记录日志。

**如果队列没配置打印机**：系统记录错误日志，任务无法打印。门店管理员需要在后台配置。

**如果打印内容不对**：可能是样式模板或数据源配置问题，管理员可以在后台调整。

## 故事二：结账后顾客小票如何打印

### 场景

3 号桌的客人吃完准备结账。收银员小张在 POS 上发起结账。

### 故事

小张选择结账方式（现金），系统完成支付处理后，触发打印：

**第一步：找顾客联设置**

系统先查看这个桌台（3号桌）有没有专门的顾客联设置。如果没有，看 3 号桌所在的区域有没有设置。再没有，看桌型有没有设置。最后看当前收银机有没有设置。

优先级：**桌台 > 区域 > 桌型 > PC**

今天 3 号桌属于"大厅"区域，区域有一个顾客联设置，指向"前台打印机"队列。

**第二步：判断打印张数**

系统检查"结账单"类型是否启用了顾客联。启用了，打印 1 份。

**第三步：创建任务**

创建两个任务：
1. 顾客联任务：类型"结账单"，打印到前台打印机
2. 钱箱弹出任务：类型"弹出钱箱"，不需要样式模板

**第四步：分发和打印**

前台打印机吐出结账单，上面有菜品明细、金额、支付方式、优惠信息。钱箱也同时弹开。

小张把账单递给客人，完成结账。

### 关键规则

| 规则 | 说明 |
|------|------|
| 顾客联优先级 | 桌台 > 区域 > 桌型 > PC（顾客来源时） |
| 结账/点菜区分 | 可配置不同场景使用不同设置 |
| 钱箱联动 | 结账时自动弹出钱箱 |

### 失败场景

**如果找不到顾客联设置**：系统直接跳过，不打印顾客联。结账正常完成，但顾客没有小票。

**如果前台打印机故障**：自动切换到备用打印机。如果全部故障，延迟重试。

## 故事三：传菜员如何拿到传菜小票

### 场景

厨房做好了菜，传菜员小李需要把菜送到对应桌台。

### 故事

厨师在 POS 上划菜（标记菜品制作完成），系统触发传菜联打印：

**第一步：找传菜联设置**

系统加载所有传菜联设置。每个传菜间设置包含：
- 覆盖哪些出品部门（比如"热菜部"和"汤品部"）
- 使用哪个打印队列

**第二步：匹配菜品**

系统遍历已完成的菜品，看它们的出品部门属于哪个传菜间。热菜部的菜归"1号传菜间"，汤品部的菜归"2号传菜间"。

**第三步：创建任务**

为每个传菜间创建一个打印任务，打印到对应队列的打印机。

**第四步：打印**

1号传菜间的打印机吐出小票："3号桌 - 宫保鸡丁、回锅肉"
2号传菜间的打印机吐出小票："3号桌 - 酸辣汤"

小李和小王分别拿到各自的小票，开始传菜。

### 关键规则

| 规则 | 说明 |
|------|------|
| 按传菜间分发 | 每个传菜间覆盖一组出品部门 |
| 菜品分组 | 同一传菜间的菜品合并打印 |

## 故事四：管理员如何配置打印样式

### 场景

新店开业，管理员需要配置打印样式。

### 故事

管理员登录 SaaS 后台，进入打印设置页面：

1. 选择"结账单"类型
2. 添加一行，数据源绑定"门店信息"，用于显示店名和地址
3. 添加一行，数据源绑定"账单信息"，显示桌号、人数、时间
4. 添加一行，数据源绑定"菜品明细"（TABLE类型），显示菜品名称、数量、单价、小计
5. 在菜品明细行添加条件：过滤掉已退菜的记录（foodStatus != "CANCELLED"）
6. 添加一行，数据源绑定"支付信息"，显示支付方式和金额
7. 添加汇总行，自动计算合计金额
8. 添加一行，只在结账时才显示二维码（条件：orderStatus = "CLOSED"）
9. 保存

下次结账时，新样式自动生效。

### 关键规则

| 规则 | 说明 |
|------|------|
| 数据源绑定 | 行绑定数据源，列从数据源取字段值 |
| 条件过滤 | 控制行或记录是否可见 |
| 汇总行 | 自动计算合计/小计 |
| 热生效 | 修改样式后下次打印立即生效 |
